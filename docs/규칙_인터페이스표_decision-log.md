### DL-IR-001 · CSV 형식을 BOM 없는 UTF-8, 쉼표 구분으로 정한다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_인터페이스표.md` IR-03
- **결정 주체:** 유지보수자 판단
- **배경:** 인터페이스 표의 원본 형식은 CSV로 정했으나(DL-SYS-014) 인코딩과 구분자의 세부는 정하지 않았다. 앞서 엑셀에서 한글이 깨질 수 있어 BOM 처리를 정해야 한다고 밝혔다.
- **검토한 대안:** (a) BOM 있는 UTF-8(엑셀에서 바로 열림) / (b) BOM 없는 UTF-8(엑셀에서는 가져오기에서 인코딩 지정)
- **결정:** (b).
- **이유:** BOM은 파이썬 등 도구와 git 차이 보기에서 첫 열 이름이 오염되는 문제를 일으킨다. 도구가 읽는 원본에서는 BOM이 없는 쪽이 안전하다. 엑셀 사용은 부수적이다.
- **영향:** 엑셀로 편집하려면 가져오기에서 UTF-8을 지정하고 저장할 때도 UTF-8로 저장해야 한다.
- **상태:** 검토 대기

### DL-IR-002 · 보내는 필드와 받는 쪽의 값 형식을 세 가지로 정한다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_인터페이스표.md` IR-04, IR-09, IR-10 (수정목록 C4, C5, C15)
- **결정 주체:** 유지보수자 판단
- **배경:** 인터페이스 표는 템플릿의 필드 키로 연결을 쓰기로 했으나, 04번 시범 시점에는 01~03번 템플릿이 없다(DL-SYS-014 영향). 또 샘플 README의 `입력`에는 이전 단계 산출물이 아닌 입력(프로젝트 자료, 외부 표준 목록, 일정·예산 같은 제약)이 있어 단계 사이의 연결만으로는 담을 수 없다.
- **검토한 대안:** (a) 필드 키가 없으면 줄을 만들지 않는다 / (b) 필드 키, 문서 수준 잠정 값, 외부 입력 세 형식을 허용한다 / (c) 외부 입력은 별도 표로 둔다
- **결정:** (b). 템플릿이 없는 단계는 단계 번호 `NN`으로 잠정 연결을 쓰고 템플릿이 생기면 필드 수준으로 바꾼다(IR-10). 외부 입력은 같은 표에 `EXT:<입력 이름>`으로 쓴다(IR-09).
- **이유:** (a)는 시범 단계에서 입력 관계를 아예 쓸 수 없다. (c)는 표가 두 개가 되어 입력을 한곳에서 볼 수 없다. 같은 표에 두면 단계별 입력을 한 번에 생성할 수 있다.
- **영향:** 잠정 줄 수를 검사 도구가 출력해(IR-K10) 필드 수준으로 바꿀 일이 남았는지 알 수 있다.
- **상태:** 검토 대기

### DL-IR-003 · 소비자가 없는 필드는 `최종 소비자 없음` 줄로 사유를 남긴다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_인터페이스표.md` IR-04, IR-07
- **결정 주체:** 유지보수자 판단
- **배경:** 정의서 8절은 "템플릿의 모든 필드는 소비자가 한 줄 이상 있거나 `최종 소비자 없음`+사유를 가진다"고 정했다. 이 줄을 CSV에서 어떻게 쓸지는 정하지 않았다. 모든 칸을 닫아야 하므로(CM-15) 받는 쪽·쓰이는 방식·필수·방향 칸을 어떻게 채울지 문제가 된다.
- **검토한 대안:** (a) 네 칸 모두에 `해당 없음`과 사유를 쓴다 / (b) 네 칸은 `해당 없음`으로 닫고 사유는 한 줄 설명 칸 하나에만 쓴다
- **결정:** (b). 공통 규칙 CM-15가 문서 종류별 닫는 말을 해당 규칙 문서가 정하도록 허용한 범위에서 정했다.
- **이유:** 같은 사유를 네 칸에 반복하는 것은 낭비이고 어긋나기 쉽다.
- **영향:** 해당 없음 — 이 형식은 인터페이스 표에만 적용된다.
- **상태:** 검토 대기

### DL-IR-004 · 방향은 단계 번호의 비교로 정하고 외부 입력은 제외한다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_인터페이스표.md` IR-05, IR-06
- **결정 주체:** 사용자 승인 (순행·환류의 정의와 번호 순서 검사는 이전에 승인됨). 같은 단계 안의 연결을 쓰지 않는다는 점과 외부 입력의 방향 처리는 이번에 더했다.
- **배경:** 순행은 보내는 단계 번호가 받는 단계보다 작은 연결, 환류는 뒤 단계의 결과가 앞 단계를 고치는 흐름으로 정했다(DL-SYS-014). 번호 비교와 방향 칸이 어긋나는 것을 막을 규칙이 필요했다.
- **검토한 대안:** (a) 방향을 사람이 자유롭게 쓴다 / (b) 번호 비교와 일치해야 한다고 정한다
- **결정:** (b). 같은 단계 안의 연결은 쓰지 않는다(표 순서는 템플릿 규칙 TP-16이 다룬다). 외부 입력은 번호가 없어 비교에서 제외하고 `순행`으로 쓴다.
- **이유:** 방향이 번호에서 기계적으로 정해지므로 검사 도구가 어긋남을 바로 잡는다.
- **영향:** 검사 IR-K05.
- **상태:** 유효

### DL-IR-005 · 읽기용 문서에 단계별 입력·쓰이는 곳 요약을 포함하고, 단계 정의의 열 구성은 사용자 판단을 기다린다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_인터페이스표.md` IR-11 (수정목록 C15의 후반부)
- **결정 주체:** 유지보수자 판단
- **배경:** 단계 정의는 샘플 README보다 열이 줄었다(`입력`과 `이 산출물이 쓰이는 곳` 열 없음). 사용자가 인터페이스 표가 나온 뒤 열 구성을 다시 판단하자고 했다(DL-SYS-027).
- **검토한 대안:** (a) 단계 정의에 두 열을 다시 넣는다 / (b) 인터페이스 표의 읽기용 문서(`단계_인터페이스.md`)에 단계별 요약(입력, 이 산출물이 쓰이는 곳)을 생성해 넣는다
- **결정:** 읽기용 문서의 (가) 단계별 요약에 샘플 README와 같은 정보(번호, 이름, 입력, 쓰이는 곳)를 생성하도록 규칙을 정했다. 단계 정의의 열 구성을 바꿀지는 이 요약을 실제로 본 뒤 사용자가 판단한다.
- **이유:** (a)는 같은 관계를 두 곳에 쓰는 것이다(CM-12). (b)는 정보를 잃지 않으면서 단일 출처를 지킨다.
- **영향:** 읽기용 문서가 생성되는 4단계 이후에 사용자가 단계 정의의 열 구성을 판단한다(수정목록 G5).
- **상태:** 검토 대기

### DL-IR-006 · 규칙_인터페이스표 v1.0 초안을 작성하고 기존 규칙의 이관을 기록한다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_인터페이스표.md` (작업 순서 2단계, 여섯 번째 규칙 문서)
- **결정 주체:** 사용자 승인 (작성 순서는 2단계 계획에서 승인됨). 세부 규칙은 DL-IR-001~005 각각의 결정 주체를 따른다.
- **배경:** 인터페이스 표의 규칙은 정의서 8절에 개요만 있었다. 기존 `템플릿_작성_규칙.md`의 검사 C8(ID 참조와 집계 숫자 일관)도 이 문서로 옮겨야 한다.
- **검토한 대안:** 해당 없음 — 2단계 계획에 따랐다.
- **결정:** 정의서 8절의 개요를 이 문서의 상세 규칙(IR-01~13)과 검사(IR-K01~10)로 풀어 정했다. 정의서 8절은 개요로 남고 상세는 이 문서가 단일 출처다.
- **이유:** 문서 종류별 규칙은 해당 규칙 문서가 갖는다는 계층에 맞춘다.
- **영향:** 샘플 규칙을 마지막으로 2단계의 규칙 문서 작성이 끝난다.
- **상태:** 유효
