### DL-CV-001 · 변환 분석서를 세 부분으로 구성하고 도메인 교체 시험 결과를 포함한다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_변환분석서.md` CV-05, CV-10~12
- **결정 주체:** 유지보수자 판단
- **배경:** 변환 분석서는 두 부분(샘플 해부, 누락 탐색)으로 정했다(DL-SYS-012). 정의서 6절의 변환 절차는 8번 단계로 "도메인 교체 시험"과 그 산출물 "시험 결과"를 두었으나 시험 결과를 어디에 남길지 정하지 않았다.
- **검토한 대안:** (a) 시험 결과를 결정 로그에 쓴다 / (b) 변환 분석서의 세 번째 부분으로 쓴다 / (c) 별도 문서를 둔다
- **결정:** (b). 누락 탐색의 도메인 대입은 머릿속 대입이고, 도메인 교체 시험은 실제로 산출물을 써 보는 것이어서 둘을 구분했다. 변환 시점은 시험까지 마친 때로 정한다(CV-03). 시험으로 쓴 산출물 자체는 문서에 넣지 않는다.
- **이유:** 시험은 일반화가 잘 되었는지에 대한 변환의 증거이므로 변환 증거의 집인 변환 분석서에 속한다(정의서 4절). 별도 문서(c)는 문서 수만 늘린다. 결정 로그(a)에는 개별 결정만 두고 시험 결과 전체를 두기엔 부피가 크다.
- **영향:** 정의서 6절 8번의 "시험 결과"가 변환 분석서 ③에 해당한다. 후속 템플릿 변경 뒤의 재시험 결과는 단계 결정 로그에 기록한다.
- **상태:** 검토 대기

### DL-CV-002 · 분류 4종을 유지하고 별도 `샘플 문제` 칸을 둔다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_변환분석서.md` CV-07, CV-08
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플 오류와 도메인 편향은 샘플에서 고치지 않고 변환 분석서에 기록하기로 했다(DL-SD-006). 정의서 6절의 분류는 `구조 유지` / `일반화 필요` / `값이라 제거` / `순서 오류라 수정`의 네 가지인데, 순서 오류 외의 오류를 담을 자리가 없었다.
- **검토한 대안:** (a) 분류에 `기타 오류`를 더한다 / (b) 분류 4종은 유지하고 `샘플 문제` 칸(`없음` / `도메인 편향` / `순서 오류` / `기타 오류`)을 별도로 둔다
- **결정:** (b).
- **이유:** 분류는 템플릿에서 어떻게 처리했는가이고, 샘플 문제는 샘플이 무엇이 잘못되었는가여서 서로 다른 축이다. (a)는 처리 방식과 문제 종류를 한 칸에 섞는다. 정의서의 분류 정의를 바꾸지 않아도 된다.
- **영향:** 해당 없음 — 정의서 6절은 그대로 유효하다.
- **상태:** 검토 대기

### DL-CV-003 · 샘플 요소는 원문 발췌로 인용하고 템플릿 대응은 표 키·필드 키로 쓴다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_변환분석서.md` CV-07, CV-14, CV-15
- **결정 주체:** 유지보수자 판단
- **배경:** 정의서 7절은 변환 분석서가 샘플을 가리킬 수 있되 샘플이 삭제되어도 읽을 수 있도록 필요한 발췌를 인용하라고 정했다(승인됨). 발췌의 형식과 템플릿과의 대응 방법은 정하지 않았다.
- **검토한 대안:** (a) 샘플 파일과 줄 번호로 가리킨다 / (b) 원문을 한 문장 이내로 발췌해 인용하고, 템플릿은 표 키·필드 키로 가리킨다
- **결정:** (b). 파일 이름만 적는 것은 인용으로 보지 않는다. 템플릿 대응에 표 키·필드 키(TP-24, TP-25)를 쓰면 도구가 대응을 확인할 수 있다(CV-K03, K04).
- **이유:** (a)는 샘플이 삭제되면 의미를 잃는다. 표 키·필드 키는 템플릿의 고유한 이름이라 검사에 쓰기 좋다.
- **영향:** 분석서를 쓰기 전에 템플릿의 표 키를 먼저 정해야 한다. 즉 템플릿 초안과 분석서가 오가며 만들어진다.
- **상태:** 검토 대기

### DL-CV-004 · 변환 분석서는 고정 문서로 두고 버전과 변경 이력 표를 두지 않는다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_변환분석서.md` CV-01, CV-03
- **결정 주체:** 유지보수자 판단
- **배경:** 결정 로그 규칙 DR-11은 버전을 올리는 문서에 변경 이력 표를 요구한다. 변환 분석서는 변환 시점에 고정되어 이후 갱신하지 않기로 했다(DL-SYS-012).
- **검토한 대안:** (a) 변경 이력 표를 두고 승인 후에도 고치게 한다 / (b) 승인 뒤에는 고치지 않으므로 버전과 변경 이력 표를 두지 않는다
- **결정:** (b). 상태가 `승인`이 되기 전의 수정은 자유롭고, 승인 뒤의 템플릿 변경은 단계 결정 로그에 쓴다.
- **이유:** 고정 문서에 변경 이력을 두면 고정이라는 성격과 모순된다. 이후 변화는 결정 로그가 이미 담당한다.
- **영향:** 결정 로그 규칙 DR-11의 대상(버전을 올리는 문서)에서 변환 분석서는 해당하지 않는다.
- **상태:** 검토 대기

### DL-CV-005 · 규칙_변환분석서 v1.0 초안을 작성한다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_변환분석서.md` (작업 순서 2단계, 다섯 번째 규칙 문서)
- **결정 주체:** 사용자 승인 (작성 순서는 2단계 계획에서 승인됨). 세부 규칙은 DL-CV-001~004 각각의 결정 주체를 따른다.
- **배경:** 변환 분석서의 내용은 지금까지 정의서 6절과 결정 로그(DL-SYS-012)에 흩어져 있었다.
- **검토한 대안:** 해당 없음 — 2단계 계획에 따랐다.
- **결정:** 그 내용을 이 문서로 모아 구성(머리말, 세 부분), 칸, 발췌 인용, 결정 로그와의 연결, 보존·삭제, 검사 8개(CV-K01~08)를 정했다. 정의서 6절은 절차의 개요로 남고, 변환 분석서의 작성 규칙은 이 문서가 단일 출처다.
- **이유:** 문서 종류별 규칙은 해당 규칙 문서가 갖는다는 계층(정의서 2절)에 맞춘다.
- **영향:** 기존 `템플릿_작성_규칙.md`에서 이관할 변환 분석서 관련 규칙은 없다. 정의서 6절과 이 문서가 겹치는 부분(분류 4종, 삭제 절차)은 정의서가 개요, 이 문서가 상세를 갖는다.
- **상태:** 유효

### DL-CV-006 · 분류에 `다른 곳이 담당`을 더하고 템플릿 대응 표기를 넓힌다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_변환분석서.md` CV-07 (v1.2), `docs/문서_체계_정의서.md` 6절
- **결정 주체:** 유지보수자 판단
- **배경:** 04번 시범에서 샘플을 해부하다 보니 기존 분류 4종에 들어가지 않는 요소가 많았다. 권한 개요, 페르소나, 조사 대상 표처럼 이 단계의 목적 밖이거나 다른 단계·인터페이스 표가 담당하는 내용이다. 또 제목이나 완료 체크처럼 표가 아닌 구성 요소는 템플릿 대응에 쓸 표 키가 없었다.
- **검토한 대안:** (a) 이런 요소를 `값이라 제거`에 넣는다 / (b) 다섯 번째 분류 `다른 곳이 담당`을 만든다
- **결정:** (b). 템플릿 대응에는 표가 아닌 구성 요소를 `구성: <이름>`으로 쓰고, `다른 곳이 담당`은 담당 문서를 함께 쓴다. 정의서 6절은 분류 종류를 나열하지 않고 규칙_변환분석서 CV-07을 가리키도록 고쳤다(같은 사실을 두 곳에 쓰지 않는다, CM-12).
- **이유:** (a)는 값을 지운 것과 담당 문서가 따로 있다는 것을 구분하지 못한다. 담당 문서를 기록해야 그 내용이 어디로 갔는지 추적된다.
- **영향:** 04번 변환 분석서가 이 분류를 쓴다. 정의서 v1.8.
- **상태:** 검토 대기
