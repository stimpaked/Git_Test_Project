# 템플릿·산출물 작성 규칙

> **더 이상 쓰지 않는다 (outdated):** 이 문서의 규칙은 정의서, 규칙_공통, 규칙_결정로그, 규칙_템플릿, 규칙_가이드, 규칙_변환분석서, 규칙_인터페이스표, 산출물_작성_guide로 옮겨졌다. 이관 대응은 각 문서의 결정 로그(DL-CM-002, DL-TP-008, DL-GD-006, DL-IR-006, DL-SD-008, DL-CG-002)에 있다. 현행 규칙으로 쓰지 않는다.

> 에이전트에게 문서 양식을 줄 때와 에이전트가 문서를 채울 때 지키는 규칙 모음.
> 목적: 근거 없는 값을 만들어 내지 않고, 샘플을 그대로 베끼지 않게 한다.
> 상태: v1.0 · 규칙 번호(P·T·H·V·O·C)는 다른 문서에서 인용할 수 있다.
> 구현 상태: 출처 유형·근거 등급·ID 일관성 검사는 `feature-list-sample/tools/verify.py`에 있다. 빈 양식(`templates/`)과 검사 C1~C7은 아직 만들지 않았다.

---

## 1. 원칙 (P)

| ID | 원칙 |
|---|---|
| P1 | 확인되지 않은 값을 확정된 것처럼 쓰지 않는다. |
| P2 | 뿌리 항목(가설·가정·유사 서비스·규제·기술 제약 등)은 밖에서 가져온다. 이미 있는 목록에서 거꾸로 만들지 않는다. |
| P3 | 예시는 값이 아니라 형식을 보여 준다. |
| P4 | 규칙은 선언만 하지 않고 검사 도구로 강제한다. |

## 2. 양식 구조 (T)

| ID | 규칙 |
|---|---|
| T1 | 기본 제공물은 **빈 양식 + 규칙 + 완료 체크리스트**다. 채워진 문서(샘플)는 필요할 때만 쓴다. |
| T2 | 힌트는 양식에 둔다. 의미·형식·범위 위주로 쓴다. 구체 값 예시는 H3를 지키거나 C5 검사를 받을 때만 허용한다. |
| T3 | 양식 안의 지침을 두 종류로 나눈다. **지속 지침**은 문서가 완성돼도 남는 규칙이다. **작성 지침**은 채운 뒤 지우는 안내다. |
| T4 | 선택 블록은 선택 블록이라고 표시한다. 고르지 않은 블록은 삭제한다. |
| T5 | 다른 문서와 이어지는 항목에는 연결 위치(문서 번호·ID 접두어)를 적는다. |
| T6 | 표의 기본 열은 `항목 / 힌트 / 내용 / 근거` 4개다. 예시가 많은 표는 `예시` 열을 따로 둘 수 있다. 모를 때의 처리 규칙은 열이 아니라 표 머리의 지속 지침으로 둔다. 힌트 형식은 `형식: …; 예시: …`다. |

## 3. 힌트 규칙 (H)

| ID | 규칙 |
|---|---|
| H1 | 구체 값이 아니라 형식과 범위를 쓴다. |
| H2 | 닫힌 선택지(예: 우선순위 M/S/C/L)만 값 후보로 나열한다. |
| H3 | 열린 값의 예시는 서로 다른 도메인에서 여러 개 쓰거나, 형식만 쓴다. |
| H4 | 빨리 낡는 숫자(점유율·시장 규모·버전)는 쓰지 않는다. |

## 4. 값 규칙 (V)와 칸 채우기

| ID | 규칙 |
|---|---|
| V1 | 값에는 근거와 출처를 적는다. |
| V2 | 가정이면 값을 쓰고 출처 유형을 `가정`으로 표시한다. |
| V3 | 모르면 `미정`을 쓰고 확인처·담당·기한을 함께 적는다. |
| V4 | 해당 개념이 없으면 `해당 없음`을 쓰고 사유를 적는다. |
| V5 | 추측해서 채우지 않는다. |

**빈칸 금지.** 어떤 칸도 비울 수 없다. 예시 칸도 예외가 아니다.

| 상황 | 쓰는 말 | 함께 적을 것 |
|---|---|---|
| 힌트가 필요 없을 만큼 자명함 | `자명함` | 없음 |
| 이 항목이 이 프로젝트에 없음 | `해당 없음` | 사유 |
| 아직 모름 | `미정` | 확인처·담당·기한 |

사유 없는 `해당 없음`, 확인처 없는 `미정`은 검사 실패다. 빈칸을 피하려고 `해당 없음`을 남발하는 것을 막기 위한 장치다.

### 출처 유형

| 유형 | 근거로 인정 |
|---|---|
| 조사 | 예 |
| 내부 자료 | 예 |
| 일반 지식(미검증) | 아니오 |
| 가정 | 아니오 |

기능의 근거 체인에 `조사`·`내부 자료`가 하나도 없으면 그 기능은 **미검증**이다.

## 5. 입력 순서 (O)

| ID | 규칙 |
|---|---|
| O1 | 프로젝트 자료를 먼저 읽고, 그다음에 양식을 본다. |
| O2 | 한 번에 한 단계씩 진행한다. |
| O3 | 샘플을 함께 줄 때는 "구조만 참고하고 값은 쓰지 말 것"이라고 명시한다. |
| O4 | 샘플을 줄 때는 서로 다른 도메인 2개 이상을 준다. |
| O5 | 경쟁작 비교표의 행은 경쟁작 자료에서 발견한 기능의 합집합이다. 우리 기능 목록에서 만들지 않는다. |

## 6. 검사 (C)

| ID | 검사 | 결과 | 상태 |
|---|---|---|---|
| C1 | 빈 칸이 없다. `미정`에 확인처, `해당 없음`에 사유가 있다. | 실패 | 미구현 |
| C2 | `근거` 열이 비어 있지 않다. | 실패 | 미구현 |
| C3 | 출처 유형이 4가지 중 하나다. | 실패 | 구현(뿌리 항목) |
| C4 | 값 칸에 지침 문구(`형식:`, `예시:`, 작성 지침)가 남아 있지 않다. | 실패 | 미구현 |
| C5 | 값이 같은 행의 예시와 같다. | 경고 | 미구현 |
| C6 | 새 프로젝트 문서에 샘플 고유 단어가 남아 있지 않다. | 실패 | 미구현 |
| C7 | 고르지 않은 선택 블록이 남아 있지 않다. | 실패 | 미구현 |
| C8 | ID 참조와 집계 숫자가 일관된다. | 실패 | 구현(`verify.py`) |
| C9 | `미정` 개수와 `미검증` 비율을 출력한다. | 정보 | 미구현(미검증 집계는 구현) |
