# 규칙 — 결정 로그

> 결정 로그를 어떻게 쓰는지 정하는 규칙이다(문서 계층의 중위, `docs/문서_체계_정의서.md` 2절).
> 상태: v1.0 초안 · 결정의 이유는 `docs/규칙_결정로그_decision-log.md`
> 규칙 ID는 `DR-nn`, 검사 ID는 `DR-Knn`이다. 공통 규칙(`docs/규칙_공통.md`)을 따른다.

## 1. 결정 로그란

문서를 **그렇게 정한 이유의 이력**이다. 정의서와 규칙 문서 등 상위·중위 문서마다 하나, 하위에서는 단계 세트마다 하나가 대응한다(정의서 2절). 읽는 사람은 유지보수자와 검토자이고, 작성 에이전트에게는 기본으로 주지 않는다(정의서 5절).

결정 로그에는 **구조가 따로 있는 템플릿 문서가 없으므로**, 항목의 형식은 이 규칙 문서가 정한다.

## 2. 무엇을 기록하나

| ID | 규칙 |
|---|---|
| DR-01 | 문서의 구조·규칙·범위·내용에 영향을 주는 결정을 기록한다. 다음 중 하나에 해당하면 기록한다: (1) 선택지가 둘 이상이었다 (2) 사용자가 판단하거나 승인했다 (3) 이전 결정을 바꾼다. 오탈자 수정과 의미가 바뀌지 않는 표현 다듬기는 기록하지 않는다. |
| DR-02 | 결정은 그 결정을 반영하는 변경과 **같은 시점에** 기록한다. 나중으로 미루지 않는다. |

## 3. 파일과 순서

| ID | 규칙 |
|---|---|
| DR-03 | 문서마다 로그 파일 하나를 둔다. 파일명은 정의서 9절을 따른다(`<대상 문서 이름>_decision-log.md`, 단계 세트는 `NN_이름_decision-log.md`). 항목은 ID 오름차순으로 쓴다. 항목을 묶는 소제목은 자유롭게 쓸 수 있다. |
| DR-04 | 결정은 한 곳의 로그에만 쓴다. 여러 문서에 걸치는 결정은 영향받는 문서들의 **가장 가까운 공통 상위 문서**의 로그에 쓰고, 영향받는 문서는 항목의 `영향` 칸에 이름을 적는다. 예: 템플릿 규칙과 가이드 규칙에 모두 영향을 주는 결정은 둘의 공통 상위인 정의서의 로그에 쓴다. |

## 4. 항목

### 4.1 형식

| ID | 규칙 |
|---|---|
| DR-05 | 항목은 아래 칸을 모두 갖는다. 칸마다 값을 쓰거나 공통 규칙 CM-04에 따라 닫는다. |

| 칸 | 내용 | 값 |
|---|---|---|
| 제목 | 항목 제목 줄. `### <ID> · <제목>` 형식 | 자유 서술 |
| 날짜 | 결정한 날 | `YYYY-MM-DD` |
| 대상 | 어느 문서(또는 항목)에 관한 결정인가 | 파일명 또는 규칙 ID |
| 결정 주체 | 누가 정했는가 | `사용자 결정` / `사용자 승인` / `유지보수자 판단` |
| 배경 | 왜 결정이 필요했나 | 자유 서술 |
| 검토한 대안 | 선택지가 둘 이상이었을 때 필수. 아니면 `해당 없음` + 사유 | 자유 서술 |
| 결정 | 무엇을 정했나 | 자유 서술 |
| 이유 | 왜 그렇게 정했나 | 자유 서술 |
| 영향 | 이 결정으로 고치거나 만들어야 하는 것. 없으면 `해당 없음` + 사유 | 자유 서술 |
| 상태 | 지금 유효한가 | `유효` / `대체됨(→ ID)` / `보류` / `검토 대기` |

**결정 주체의 뜻**
- `사용자 결정`: 사용자가 직접 정했다.
- `사용자 승인`: 유지보수자가 제안하고 사용자가 동의했다.
- `유지보수자 판단`: 제안을 승인받지 않고 유지보수자가 정했다. 이런 항목의 상태는 `검토 대기`로 두고, 사용자가 확인하면 `사용자 승인`으로 바꾸고 상태를 `유효`로 한다.

**상태의 뜻**
- `유효`: 현재 적용된다.
- `대체됨(→ ID)`: 새 결정이 이 결정을 바꿨다. 대체한 항목의 ID를 적는다.
- `보류`: 결정을 미루었다. 이유를 `결정` 칸에 쓴다.
- `검토 대기`: 사용자 확인을 기다린다.

### 4.2 ID

| ID | 규칙 |
|---|---|
| DR-06 | 항목 ID는 `DL-<코드>-nnn`이다. 코드는 로그의 대상 문서를 가리킨다. |

| 로그의 대상 | 코드 |
|---|---|
| 문서 체계 정의서 | `SD` |
| 단계 정의 | `ST` |
| 규칙 문서 | 규칙 ID의 문서 코드: 공통 `CM`, 결정 로그 `DR`, 템플릿 `TP`, 가이드 `GD`, 변환 분석서 `CV`, 인터페이스 표 `IR`, 샘플 `SP` |
| 단계 세트 | 단계 번호 두 자리 (예: 04번이면 `DL-04-001`) |
| 임시 로그 | `SYS` (임시 로그 `결정로그_체계.md`에서 시작한 항목. 옮겨도 ID는 바뀌지 않는다) |

ID는 모든 로그에 걸쳐 유일해야 한다. 항목을 다른 파일로 옮겨도 ID는 바꾸지 않는다.

## 5. 추가만 한다

| ID | 규칙 |
|---|---|
| DR-07 | 로그는 추가만 한다. 과거 항목의 내용은 고치지 않는다. 잘못 적었으면 새 항목으로 정정하고 이전 항목의 상태를 `대체됨(→ ID)`로 바꾼다. |
| DR-08 | 과거 항목에서 바꿀 수 있는 것은 **상태 칸**과 **이동 표시**뿐이다. 결정 주체가 `유지보수자 판단`이던 항목을 사용자가 확인했을 때의 변경(`검토 대기` → `유효`, 결정 주체 갱신)은 상태 변경에 속한다. |
| DR-09 | 이 규칙이 확정되기 전에 임시 형식으로 쓴 항목은, **확정 후 한 번에 한해** 내용을 바꾸지 않고 누락된 칸(날짜, 결정 주체)만 채울 수 있다. 채운 사실은 로그에 항목으로 기록한다. |
| DR-10 | 항목을 다른 로그로 옮길 때는 ID를 유지하고, 옮기는 쪽(원본)에는 본문을 그대로 두고 `상태`에 `이동됨 → <파일명>`을 덧붙인다. 이동한 뒤의 기준은 새 위치다. |

## 6. 문서 버전과의 연결

| ID | 규칙 |
|---|---|
| DR-11 | 버전을 올리는 문서(템플릿, 가이드, 규칙 문서, 정의서, 단계 정의)는 머리말 아래에 **변경 이력** 표를 둔다: `버전 \| 날짜 \| 요약 \| 결정 ID`. 결정 ID는 그 문서(또는 가까운 상위 문서)의 로그에 존재해야 한다. 기록 대상이 아닌 변경(DR-01)은 결정 ID 칸에 `해당 없음` + 사유를 쓴다. |
| DR-12 | 결정 로그의 이력 서술은 샘플을 언급할 수 있다. 다만 샘플이 삭제되어도 이해되도록 필요한 내용을 항목 안에 쓴다(정의서 7절). |

## 7. 검사

| ID | 검사 | 강제하는 규칙 | 결과 | 구현 상태 |
|---|---|---|---|---|
| DR-K01 | 모든 항목에 필수 칸이 있고 비어 있지 않으며, `결정 주체`와 `상태`가 허용된 값이다 | DR-05 | 실패 | 미구현 |
| DR-K02 | 항목 ID가 `DL-<코드>-nnn` 형식이고 모든 로그에 걸쳐 유일하다 | DR-06 | 실패 | 미구현 |
| DR-K03 | `대체됨(→ ID)`의 ID가 존재한다 | DR-07 | 실패 | 미구현 |
| DR-K04 | 이전 커밋과 비교해 과거 항목의 내용이 바뀌지 않았다(상태 칸과 이동 표시만 허용) | DR-07, DR-08 | 실패 | 미구현 |
| DR-K05 | 변경 이력 표의 결정 ID가 로그에 존재한다 | DR-11 | 실패 | 미구현 |
| DR-K06 | `이동됨 → <파일명>`이 있는 항목은 대상 파일에 같은 ID의 항목이 있다 | DR-10 | 실패 | 미구현 |
| DR-K07 | `검토 대기` 항목 개수를 출력한다 | DR-05 | 정보 | 미구현 |

구현은 작업 순서 4단계(`tools/`)에서 한다.
