## 2. 원칙

| ID | 원칙 |
|---|---|
| CM-01 | 확인되지 않은 값을 확정된 것처럼 쓰지 않는다. |
| CM-02 | 뿌리 항목(가설·가정·유사 서비스·규제·기술 제약처럼 다른 항목의 근거가 되는 항목)은 외부 자료나 내부 자료에서 가져온다. 이미 있는 목록에서 거꾸로 만들지 않는다. |
| CM-03 | 규칙은 선언에 그치지 않고 검사로 강제한다. 규칙 문서는 자기 규칙을 강제하는 검사를 "검사" 절에 ID와 함께 둔다. 검사는 그 검사가 강제하는 규칙과 같은 문서에 둔다. |
| CM-12 | 내용을 어느 문서에 쓸지는 정의서 4절의 귀속 기준을 따른다. 같은 사실을 두 곳에 쓰지 않는다. |
| CM-15 | 템플릿·가이드 등 다른 문서의 칸도 비워 두지 않는다. 그 문서 종류에서만 쓰는 닫는 말은 해당 규칙 문서가 정한다(예: 템플릿의 힌트 칸에 쓰는 `자명함`은 `규칙_템플릿.md` TP-14). |

## 3. 값 규칙

산출물의 칸에 값을 쓸 때 지키는 규칙이다. 여기서 **칸**은 표의 한 셀, **값**은 칸에 쓰는 내용, **근거**는 그 값이 어디서 왔는지를 적은 칸이다.

### 3.1 모든 칸은 닫는다

| ID | 규칙 |
|---|---|
| CM-04 | 산출물의 어떤 칸도 비워 두지 않는다. 아래 중 하나로 닫는다. |

| 상황 | 쓰는 말 | 같은 칸에 함께 적을 것 |
|---|---|---|
| 이 항목이 이 프로젝트에 없다 | `해당 없음` | 사유 |
| 아직 모른다 | `미정` | 확인처 · 담당 · 기한 |
| 값을 안다 | 값 | 근거 칸에 근거 |

- `해당 없음`은 그 항목의 **개념 자체가 이 프로젝트에 없을 때** 쓴다. 권한이 없다는 뜻의 `없음`과 구분한다.
- 사유는 구체적으로 쓴다. "동일", "N/A"만 쓰는 것은 사유가 아니다.

### 3.2 값, 근거, 추측

| ID | 규칙 |
|---|---|
| CM-05 | 값에는 근거와 출처를 적는다. 근거 칸은 비우지 않는다. |
| CM-06 | 확인하지 못했지만 계획을 위해 둔 값이면 값을 쓰고 출처 유형을 `가정`으로 표시한다. |
| CM-07 | 값을 아직 확정할 수 없으면 `미정`과 확인처·담당·기한을 적는다. 칸을 비우거나 추측으로 채우는 대신 확인할 곳을 남기는 것이다. |
| CM-08 | 해당 개념이 없으면 `해당 없음`과 사유를 적는다. |
| CM-09 | 추측해서 채우지 않는다. |

### 3.3 출처 유형

| ID | 규칙 |
|---|---|
| CM-10 | 값의 출처는 아래 네 유형 중 하나로 표시한다. `조사`와 `내부 자료`만 근거로 인정한다. |

| 유형 | 뜻 | 함께 적을 것 | 근거로 인정 |
|---|---|---|---|
| 조사 | 확인할 수 있는 외부 자료를 직접 확인한 것 | 출처(문서명·주소 등)와 확인일 | 예 |
| 내부 자료 | 조직 안의 문서·데이터·결정 | 어느 문서 또는 누구에게서 가져왔는지 | 예 |
| 일반 지식(미검증) | 출처를 대지 못했거나 이번에 확인하지 않은 일반적인 지식 | 없음 | 아니오 |
| 가정 | 확인 없이 계획을 위해 둔 전제 | 없음 | 아니오 |

| ID | 규칙 |
|---|---|
| CM-18 | **근거 칸은 근거를 `;`로 구분해 하나 이상 쓴다.** 근거 하나는 (가) `<출처 유형>: <내용>`이거나(유형은 위 네 가지, 내용은 위 표의 "함께 적을 것"), (나) 앞에서 쓴 항목을 가리키는 참조(ID, 필드 키, `NN <산출물 이름>`)로 시작한다. 별도의 출처 유형 열은 두지 않는다. |

### 3.4 근거 등급

| ID | 규칙 |
|---|---|
| CM-11 | 어떤 항목의 근거를 처음까지 거슬러 올라갔을 때(근거 체인) `조사` 또는 `내부 자료`가 하나도 없으면 그 항목은 **미검증**이다. 하나라도 있으면 **검증**이다. 근거 등급이 필요한 문서는 항목마다 등급을 표시한다. |

### 3.5 샘플과 예시에서 본 단어

| ID | 규칙 |
|---|---|
| CM-16 | 이 체계의 샘플이나 예시에서 본 서비스의 고유 단어(서비스 이름, 특정 업종을 전제하는 용어)를 산출물에 쓰지 않는다. 산출물의 내용은 해당 프로젝트의 자료에서 가져온다. |

## 4. 표기 규약

| ID | 규칙 |
|---|---|
| CM-13 | 문서 머리말에 버전(`vX.Y`)과 상태를 쓴다. 상태는 `초안` / `검토` / `승인` 중 하나다. 날짜는 `YYYY-MM-DD`로 쓴다. |
| CM-14 | 규칙 ID는 `<문서 코드>-nn` 형식이다. 문서 코드는 공통 `CM`, 결정 로그 `DR`, 템플릿 `TP`, 가이드 `GD`, 변환 분석서 `CV`, 인터페이스 표 `IR`다. 그 문서의 검사 ID는 `<문서 코드>-Knn`이다. |
| CM-17 | 샘플 고유 단어 목록은 `tools/data/sample_terms.txt`에 한 줄에 한 단어로 둔다. 샘플이 바뀌거나 새 샘플이 생기면 갱신한다. 샘플을 삭제한 뒤에도 목록은 남겨 검사(CM-K07, TP-K08, GD-K05)에 쓴다. |

용어는 정의서 12절을 따른다(이 문서에 따로 정의하지 않는다).

## 5. 검사

| ID | 검사 | 강제하는 규칙 | 결과 | 구현 상태 |
|---|---|---|---|---|
| CM-K01 | 산출물에 빈 칸이 없다 | CM-04 | 실패 | 구현 |
| CM-K02 | `미정`에 확인처·담당·기한이 있고 `해당 없음`에 사유가 있다 | CM-07, CM-08 | 실패 | 구현 |
| CM-K03 | 근거 칸이 비어 있지 않다 | CM-05 | 실패 | 구현 |
| CM-K04 | 근거 칸의 근거마다 출처 유형으로 시작하거나 참조로 시작한다(`미정`·`해당 없음`으로 닫은 칸 제외) | CM-10, CM-18 | 실패 | 구현 |
| CM-K05 | 문서에 적은 근거 등급과 집계가 항목의 근거 체인과 일치한다 | CM-11 | 실패 | 미구현(근거 등급을 표시하는 문서가 아직 없다. 생기면 구현) |
| CM-K06 | `미정` 개수와 `미검증` 후보 비율(근거가 모두 `일반 지식(미검증)`·`가정`인 행)을 출력한다 | CM-07, CM-11 | 정보 | 구현(근거 체인을 따라가지는 않고 한 행의 근거만 본다) |
| CM-K07 | 산출물에 샘플 고유 단어 목록의 단어가 없다. 같은 업종의 프로젝트에서는 정당하게 쓸 수 있으므로 사람이 판단한다 | CM-16 | 경고 | 구현 |

구현은 작업 순서 4단계(`tools/`)에서 한다. 샘플 전용 도구(`feature-list-sample/tools/`)의 일부 검사는 샘플의 구조에 묶여 있어 그대로 쓰지 않고 필요한 부분만 복사해서 쓴다.

## 6. 변경

이 문서를 바꿀 때는 `docs/규칙_공통_decision-log.md`에 항목을 추가하고 버전을 올린다. 이 문서가 바뀌면 영향받는 문서 종류를 재검사한다(정의서 10절).

## 7. 이 문서가 정하지 않은 것

- 템플릿의 구조·힌트·지침 표기 → 템플릿 규칙
- 가이드의 구성 → 가이드 규칙
- 결정 로그의 항목 형식 → 결정 로그 규칙
- 용어의 정의 → 정의서 12절
