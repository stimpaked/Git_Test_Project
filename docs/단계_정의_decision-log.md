# 결정 로그 — 단계 정의

> `docs/단계_정의.md`의 결정 이력이다. 항목은 추가만 하고 과거 항목은 고치지 않는다(`docs/규칙_결정로그.md`).
> 임시 로그 `결정로그_체계.md`에서 이 문서에 속하는 항목(DL-SYS-026, 027)을 옮겨 왔다. **항목 ID는 유지한다.** 옮겨 온 항목은 임시 형식이라 날짜·결정 주체가 없다(DR-09, 수정목록 C16).
> 단계 정의를 두기로 한 결정(DL-SYS-020)은 정의서에도 걸치므로 가장 가까운 공통 상위 문서의 로그인 `문서_체계_정의서_decision-log.md`에 있다(DR-04).

## A. 임시 로그에서 옮겨 온 항목

### DL-SYS-026 · 단계 정의 v1.0 초안을 작성한다
- **대상:** `docs/단계_정의.md` (작업 순서 1단계-b)
- **결정:** 36단계의 번호·이름·그룹·목적·산출물을 정의한다. 목적은 "이 단계가 없으면 무엇이 빠지는가"로, 산출물은 단계가 만드는 문서의 내용으로 쓴다. 입력 관계는 인터페이스 표에만 두므로 이 문서에 쓰지 않는다. 특정 서비스의 값과 ID는 쓰지 않는다. 번호·이름·그룹은 기존 샘플의 구성을 따르되 목적과 산출물은 일반 서술로 다시 썼고, 샘플을 참조하지 않는다. 출처 유형은 `일반 지식(미검증)`이며, 사용자 검토는 외부 근거가 아님을 명시했다.
- **이유:** 변환 분석서가 기준으로 삼을 단계 목적이 샘플과 독립된 공식 문서에 있어야 하고, 샘플이 삭제되어도 36단계 정보가 남아야 한다.
- **영향:** 단계의 추가·삭제·순서 변경 규칙은 2단계에서 정한다(수정목록 C14).
- **상태:** 유효 (검토 대기)

### DL-SYS-027 · 단계 정의의 목적 서술을 긍정형으로 바꾸고, 열 구성의 판단을 인터페이스 표 이후로 미룬다
- **대상:** `docs/단계_정의.md` 4절
- **배경:** 사용자가 검토에서 두 가지를 지적했다. (1) 목적 칸이 "이 단계가 없으면 빠지는 것"으로 쓰여 어색하다. (2) 샘플 `00_README.md`보다 열이 줄었다.
- **결정:** (1) 목적을 "~을(를) ~해, ~한다" 형태의 긍정형 문장으로 36단계 모두 다시 썼다. 열 제목은 "목적(이 단계가 하는 일)"로 바꿨다. (2) 샘플 표의 `입력`과 `이 산출물이 쓰이는 곳` 열은 관계 사실이라 인터페이스 표로 간 것이 맞다. 단계 정의의 열 구성(번호·이름·그룹·목적·산출물)이 충분한지는 인터페이스 표가 나온 뒤에 판단한다.
- **이유:** 목적은 하려는 일을 서술하는 것이 자연스럽다. 열 구성은 인터페이스 표가 어떤 형태로 단계별 입력·쓰임을 보여 주는지 확인한 뒤에야 판단할 수 있다.
- **영향:** 인터페이스 표를 설계할 때 샘플 표의 `입력`에 있던 단계 외부 입력(프로젝트 자료, 외부 표준 목록 등)의 처리 방식을 정해야 한다(수정목록 C15).
- **상태:** 유효 (열 구성 판단은 보류)

## B. 이 문서에서 새로 정한 항목

### DL-ST-001 · 단계 정의의 결정 로그를 만들고 변경 이력 표를 추가한다
- **날짜:** 2026-10-08
- **대상:** `docs/단계_정의_decision-log.md`, `docs/단계_정의.md` (v1.1)
- **결정 주체:** 사용자 승인 (잔여 이슈 정리 요청에서 승인됨)
- **배경:** 단계 정의의 결정(DL-SYS-026, 027)이 임시 로그에 남아 있었고, 단계 정의에는 결정 로그 규칙이 요구하는 변경 이력 표가 없었다(DR-11).
- **검토한 대안:** 해당 없음 — 결정 로그 규칙을 적용한 것이다.
- **결정:** DL-SYS-026, 027을 ID를 유지한 채 이 로그로 옮기고, 임시 로그의 원본에는 `이동됨` 표시를 덧붙였다. 단계 정의에 변경 이력 표를 추가하고, 목적 서술 수정이 반영된 버전을 v1.1로 정리했다.
- **이유:** 결정 로그 규칙(DR-04, DR-10, DR-11)의 적용.
- **영향:** 임시 로그에 남은 항목은 DL-SYS-002(3·30단계 가이드로), 003(샘플 규칙으로), 007·009(04번 세트로), 015(작업 순서, 갈 곳 미정)이다.
- **상태:** 유효

### DL-ST-002 · 01번 산출물 열에 서비스 한 줄 정의와 문제 정의를 더한다
- **날짜:** 2026-10-09
- **대상:** `docs/단계_정의.md` v1.3 (01번 행)
- **결정 주체:** 사용자 결정
- **배경:** 01번 세트(DL-01-011)가 템플릿에 서비스 한 줄 정의와 문제 정의 표를 두었는데 단계 정의의 산출물 열에는 없었다. 뒤 단계(02, 03, 04)가 이 두 표를 이미 읽는다. 사용자가 권장대로 더하기로 했다.
- **검토한 대안:** (a) 산출물 열에 더한다 / (b) 템플릿에서 뺀다
- **결정:** (a).
- **이유:** 뒤 단계가 읽는 표는 단계 정의의 산출물에 있어야 단계 정의와 템플릿이 어긋나지 않는다.
- **영향:** 단계 정의 v1.3. 템플릿과 인터페이스 표는 바뀌지 않는다.
- **상태:** 유효
