## A. 임시 로그에서 옮겨 온 항목

### DL-SYS-004 · 힌트는 양식에 두고, 표는 4열로 한다
- **대상:** 규칙 T2, T6, H1~H4 (현재 규칙: 규칙_템플릿 TP-12, TP-14, TP-18~23)
- **배경:** 힌트를 없앨지, 값 칸 옆에 둘지, 별도 열로 둘지 논의했다.
- **결정:** 힌트는 양식에 둔다(의미·형식·범위 위주). 표의 기본 열은 `항목 / 힌트 / 내용 / 근거`다. 힌트의 구체 값 예시는 여러 도메인이거나 형식만 허용한다.
- **이유:** 힌트는 칸의 의미를 알리는 역할이라 필요하고, 값 예시는 복사 위험이 있어 제한한다.
- **상태:** 유효 (열 구조는 DL-SYS-013의 기준으로 재검토 대상 → DL-TP-001~003에서 반영)

## B. 이 문서에서 새로 정한 항목

### DL-TP-001 · 힌트 열과 열 힌트 표를 산출물에도 남긴다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_템플릿.md` TP-13, TP-14
- **결정 주체:** 유지보수자 판단
- **배경:** DL-SYS-004는 힌트를 양식에 두기로 했으나 채운 뒤 힌트가 남는지는 정하지 않았다. 04 범용 초안에서는 힌트를 표 위 인용문(채운 뒤 삭제)으로 썼다.
- **검토한 대안:** (a) 힌트는 작성 지침이라 채운 뒤 삭제한다 / (b) 힌트 열과 열 힌트 표가 산출물에도 남는다
- **결정:** (b). 힌트가 필요 없을 만큼 자명하면 힌트 칸에 `자명함`을 쓴다(CM-04).
- **이유:** 공통 규칙이 힌트 칸의 닫는 말로 `자명함`을 두었다는 것은 힌트 칸이 완성된 문서에도 남는다는 전제다. 또 산출물을 읽는 사람이 각 칸의 뜻을 알 수 있다. 사용자가 보여 준 빈 양식 예시도 힌트가 표 안에 있었다.
- **영향:** 힌트는 산출물에 남아도 되는 내용(조건 없는 한 문장)만 담는다(TP-18).
- **상태:** 검토 대기

### DL-TP-002 · 작성 지침은 표기 안내에만 쓰고, 판단·절차는 가이드로 보낸다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_템플릿.md` TP-08, TP-09, TP-18
- **결정 주체:** 유지보수자 판단
- **배경:** 04 범용 초안은 작성 지침 안에 "후보를 한 줄에 하나씩 옮긴다", "하나라도 다르면 별도 액터" 같은 절차와 판단 기준을 많이 담았다. 정의서 4절은 조건이 있는 문장을 가이드로 보내도록 정했다.
- **검토한 대안:** (a) 작성 지침에 절차를 계속 담는다 / (b) 작성 지침은 자리표시·선택 블록·생성 블록의 표기 안내로 한정한다
- **결정:** (b). 힌트는 조건 없는 한 문장으로 제한한다(TP-18). 절차와 판단 기준은 가이드에서 다룬다.
- **이유:** 정의서 4절의 귀속 기준(조건이 있는 문장은 가이드)을 일관되게 적용하고, 템플릿이 항상 읽힐 때 같은 내용이 가이드와 중복되지 않게 한다.
- **영향:** 04번 세트 작성 때 04 범용 초안의 작성 지침을 가이드로 옮겨야 한다.
- **상태:** 검토 대기

### DL-TP-003 · 값 표를 속성 표와 목록 표 두 형식으로 정한다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_템플릿.md` TP-12, TP-13
- **결정 주체:** 유지보수자 판단
- **배경:** 4열(`항목/힌트/내용/근거`)은 한 대상의 속성을 적는 표에 맞는다. 여러 레코드를 행으로 쌓는 표(액터 목록 등)는 열이 필드라서 같은 4열을 쓸 수 없다. 04 범용 초안은 목록 표에 열 설명 표를 따로 두었다.
- **검토한 대안:** (a) 모든 표를 4열로 맞춘다 / (b) 속성 표는 4열, 목록 표는 열 힌트 표 + 마지막 열 `근거`로 한다
- **결정:** (b).
- **이유:** (a)는 목록 표를 레코드마다 속성 표로 쪼개야 해서 읽기 어렵다.
- **영향:** 해당 없음 — 4열 구조의 적용 범위를 확정한 것이고 다른 문서를 바꾸지 않는다.
- **상태:** 검토 대기

### DL-TP-004 · 칸 단위 필수/선택 구분을 두지 않고 선택은 블록 단위로 한다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_템플릿.md` TP-15, TP-17
- **결정 주체:** 사용자 승인
- **배경:** 정의서가 "필수 여부"를 구조 사실로 정했다. 그런데 공통 규칙은 모든 칸을 닫도록 했으므로(CM-04) 칸이 선택이라는 개념이 성립하지 않는다.
- **검토한 대안:** (a) 칸마다 필수/선택을 표시한다 / (b) 모든 칸을 필수로 하고, 선택은 블록 단위로 한다
- **결정:** (b). 값이 없는 칸은 `해당 없음`+사유로 닫는다. 선택 블록을 쓰지 않으면 지우고 `선택하지 않음: <사유>` 한 줄을 남긴다.
- **이유:** (a)는 빈칸 금지 규칙과 충돌한다. 선택하지 않은 이유도 기록으로 남는다.
- **영향:** 해당 없음 — 정의서의 구조 사실 예시에서 "필수 여부"는 이 결정으로 "모든 칸 필수"로 읽는다.
- **상태:** 유효

### DL-TP-005 · 표 키와 필드 키의 형식을 정한다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_템플릿.md` TP-24, TP-25 (수정목록 C7)
- **결정 주체:** 유지보수자 판단
- **배경:** 인터페이스 표가 템플릿의 필드를 가리키려면 고유한 이름이 필요하다.
- **검토한 대안:** (a) 필드 키를 자동 번호로 부여한다 / (b) `<단계 번호>.<표 키>.<필드 이름>`으로 사람이 읽을 수 있게 한다
- **결정:** (b). 표 위에 주석 `<!-- 표: <표 키> | 정의 ID: <접두어> -->`로 표 키와 그 표가 새로 부여하는 ID 접두어를 선언한다. 예: `04.액터목록.유형`.
- **이유:** 사람이 읽을 수 있어야 인터페이스 표의 한 줄이 어느 칸인지 바로 안다. 정의 ID 선언은 표 순서 검사(TP-K07)에 필요하다.
- **영향:** 인터페이스 표 규칙에서 `보내는 필드` 열이 이 필드 키를 쓴다.
- **상태:** 검토 대기

### DL-TP-006 · 템플릿의 문서 정보는 생성하고, 변경 이력은 작성 지침 구역에 둔다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_템플릿.md` TP-04, TP-06 (수정목록 C12)
- **결정 주체:** 유지보수자 판단
- **배경:** 입력과 이 산출물이 쓰이는 곳은 인터페이스 표에서 생성하기로 이미 정했다(DL-SYS-014). 단계 이름·목적이 어디서 오는지는 정하지 않았다. 결정 로그 규칙은 템플릿에도 변경 이력 표를 요구하는데(DR-11), 템플릿의 변경 이력은 채워진 산출물에 남으면 안 된다.
- **검토한 대안:** 단계 이름·목적은 (a) 템플릿마다 직접 쓴다 / (b) 단계 정의에서 생성한다. 변경 이력은 (c) 머리말 아래에 둔다 / (d) 작성 지침 구역에 둔다.
- **결정:** (b)와 (d). 문서 정보 블록(단계 번호·이름·목적, 입력, 쓰이는 곳)은 단계 정의와 인터페이스 표에서 도구가 생성하고, 템플릿의 변경 이력은 작성 지침 구역에 두어 채울 때 삭제한다.
- **이유:** 같은 사실을 두 곳에 쓰지 않는다(CM-12). 템플릿의 변경 이력은 템플릿을 관리하는 정보라 산출물에 필요하지 않다.
- **영향:** 도구 구현(수정목록 D6)에 단계 정의에서 단계 이름·목적을 읽는 기능이 필요하다. DR-11은 위치를 "머리말 아래"라고 하지만 템플릿은 TP-06이 예외를 정한다.
- **상태:** 검토 대기

### DL-TP-007 · 표는 작성 순서대로 배열한다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_템플릿.md` TP-16 (수정목록 B1, A6)
- **결정 주체:** 유지보수자 판단
- **배경:** 04 원본 샘플의 1번 표 `결과 액터`에 아직 부여되지 않은 액터 ID가 미리 적혀 있었다. 사용자가 "작성 시점에 ID가 없는데 어떻게 넣느냐"고 지적했다.
- **검토한 대안:** 해당 없음 — 지적된 오류를 규칙으로 막은 것이다.
- **결정:** 표는 작성 순서대로 배열하고, 앞 표는 뒤 표에서 만드는 ID를 참조하지 않는다. 각 표가 새로 부여하는 ID 접두어를 `정의 ID`로 선언해 검사한다(TP-K07).
- **이유:** 작성자가 위에서 아래로 채울 수 있어야 한다. 지적된 오류의 재발을 검사로 막는다(CM-03).
- **영향:** 해당 없음 — 04번 세트 작성 시 04 범용 초안에 이미 적용한 구조를 유지한다.
- **상태:** 검토 대기
