# 결정 로그 — 문서 체계 정의서

> `docs/문서_체계_정의서.md`의 결정 이력이다. 항목은 추가만 하고 과거 항목은 고치지 않는다(`docs/규칙_결정로그.md`).
> 임시 로그 `결정로그_체계.md`에서 이 문서에 속하는 항목 17개를 옮겨 왔다. **항목 ID는 유지한다.** 옮겨 온 항목은 임시 형식이라 날짜·결정 주체가 없다(DR-09, 수정목록 C16).
> DL-SYS-020(단계 정의)과 DL-SYS-016~019처럼 여러 문서에 걸친 결정은 가장 가까운 공통 상위 문서인 정의서의 로그에 둔다(DR-04).

---

## A. 임시 로그에서 옮겨 온 항목

### DL-SYS-006 · 규칙 문서는 `docs/`에 둔다
- **대상:** `docs/템플릿_작성_규칙.md`
- **결정:** 규칙 문서는 샘플(`feature-list-sample/`)과 분리해 `docs/`에 둔다.
- **이유:** 규칙이 샘플과 섞이면 규칙도 복사 대상으로 보인다.
- **상태:** 유효

### DL-SYS-008 · 문서 세트를 템플릿·가이드·결정 로그로 구성하고 가이드는 항상 읽는다
- **대상:** 문서 체계 전체
- **배경:** 템플릿만으로는 판단 기준과 작성 방법을 담기 어렵고, 가이드를 "필요할 때만" 읽게 하면 에이전트의 판단에 의존하게 된다.
- **결정:** 단계마다 템플릿·가이드·결정 로그 세트를 둔다. 가이드는 템플릿과 같이 **항상** 읽는다. 가이드의 초점은 "템플릿을 어떻게 채우는가"이며, 길이 상한을 둔다. 체계 전체의 결정은 이 공통 로그에 쓴다.
- **이유:** 읽을지 말지를 에이전트가 판단하지 않게 하고, "왜 그렇게 했는가"를 잃지 않기 위해.
- **영향:** 가이드는 항상 맥락에 올라가므로 예시 규칙을 더 엄격히 적용해야 한다.
- **상태:** 유효 (변환 분석서 추가는 DL-SYS-012)

### DL-SYS-010 · 문서 체계 정의서를 만든다
- **대상:** `docs/문서_체계_정의서.md`(작업 순서 1단계)
- **결정:** 문서 종류와 관계를 최상위 문서에서 정의한다.
- **이유:** 템플릿·가이드 등 각 문서의 역할 이해가 서로 달랐다.
- **상태:** 유효

### DL-SYS-011 · 기존 01~36번 문서는 "샘플"이라는 별도 종류다
- **대상:** `feature-list-sample/` 전체
- **배경:** 샘플은 범용으로 만들어진 것이 아니라 처음부터 가상 서비스 "이웃장터"로 만들어졌다.
- **결정:** 샘플은 별도 종류이고, 작성 에이전트에게 기본으로 주지 않는다. 샘플 1개마다 세트(템플릿·가이드·결정 로그·변환 분석서)가 대응한다. 샘플은 세트의 일부가 아니다.
- **이유:** 샘플은 특정 주제에 특화되어 있어 세트의 원본으로 그대로 쓸 수 없다.
- **상태:** 유효

### DL-SYS-012 · 샘플→템플릿 변환은 일반화이며, 중간에 변환 분석서를 둔다
- **대상:** 단계 세트, 문서 체계 정의서
- **배경:** 특정 주제 샘플을 범용 템플릿으로 한 번에 바꾸면 도메인 누출·누락·과일반화·구조 오류가 생긴다. 04번에서 실제로 소속·대리·감독 관점의 누락과 질문 편향, 작성 순서 오류가 확인됐다.
- **결정:** 단계마다 **변환 분석서**를 쓴다(1종, 두 부분: ① 샘플 해부=요소별 유지/일반화/제거/순서수정 분류, ② 누락 탐색=단계 목적과 성격이 다른 가상 도메인 대입). 템플릿의 변경은 분석서의 줄에 대응해야 한다. 변환 시점의 기록이므로 이후 갱신하지 않는다. 보존이 기본이며, 삭제는 허용한다(삭제 전 핵심을 결정 로그로 옮기고, 참조를 정리하고, 삭제 사실을 기록).
- **이유:** 누락은 샘플만 보아서는 보이지 않는다. 오류를 변환 단계에 가둔다.
- **상태:** 유효

### DL-SYS-013 · 내용 귀속 기준: 문장의 종류로 나눈다
- **대상:** 모든 문서 종류
- **배경:** 문서의 목적으로 나누면 템플릿·가이드·명세 사이에 내용이 겹치고 판단이 사람마다 달라진다.
- **결정:** 문장의 종류마다 집이 하나다.
  - 구조 사실(칸·열·필수 여부·값 종류·선택지·ID 형식·표 순서·완료 체크) → 템플릿
  - 절차·판단 지식(도출 절차·판단 기준·흔한 실수·칸 의미의 해설) → 가이드
  - 관계 사실(다른 단계와의 연결) → 인터페이스 표
  - 이력(결정 이유) → 결정 로그
  - 변환 증거 → 변환 분석서
  - 판별법: 기계 검사가 가능하면 구조·관계, 판단이 필요하거나 조건문("~이면")이 있으면 가이드. 템플릿 힌트는 조건 없는 한 줄 설명까지만 허용한다.
- **이유:** 목적 기준은 겹침이 구조적으로 생기고, 문장 종류 기준은 겹침을 막는다. 템플릿과 가이드를 나누는 가장 결정적인 이유는 수명이다(템플릿은 산출물로 남고 가이드는 남지 않음).
- **영향:** 규칙 문서에서 문서 종류마다 "담아도 되는 문장 종류"를 명시한다. 기존 템플릿 규칙(T2·T6)을 이 기준에 맞춰 재검토한다.
- **상태:** 유효 (DL-SYS-020이 여섯 번째 문장 종류 `절차 정의`를 추가함)

### DL-SYS-014 · 명세 문서를 두지 않고 인터페이스 표를 둔다
- **대상:** 단계 사이의 연결(관계 사실)
- **배경:** 명세를 별도 문서로 두면 구조 사실과 관계 사실이 섞이고, 같은 연결이 보내는 쪽과 받는 쪽 두 곳에 적힐 위험이 있다. 명세가 담으려던 내용 중 샘플 분류는 변환 분석서가, 필드 정의는 템플릿이 맡는다. 남는 고유 내용은 "필드의 이후 사용"뿐이었다.
- **검토한 대안:** (A) 단계마다 명세 문서 / (B) 체계 전체에 인터페이스 표 / (C) 템플릿에 "이후 사용" 열
- **결정:** (B). 필드 수준으로 한다. 연결은 한 번만 적는다. 원본은 CSV(UTF-8, 첫 줄 열 이름)이고 읽기용 문서와 템플릿의 입력·쓰이는 곳 블록은 도구가 생성한다(직접 수정 금지). 연결에는 `순행`과 `환류`를 구분한다. 환류는 뒤 단계 결과가 앞 단계 산출물을 고치게 하는 흐름이다. 템플릿의 모든 필드는 표에 소비자가 있거나 `최종 소비자 없음 + 사유`를 가져야 한다.
- **이유:** 연결의 단일 출처, 변경 영향의 양방향 추적, 필드 존재 이유의 강제.
- **영향:** 템플릿 필드에 키가 필요하다. 04번 시범 시점에는 01~03번 템플릿이 없으므로 01~03→04 연결은 문서 수준으로 두고, 해당 템플릿이 생기면 필드 수준으로 갱신한다.
- **상태:** 유효

### DL-SYS-016 · 문서 종류별 독자와 제공 범위를 정한다
- **대상:** `docs/문서_체계_정의서.md` 4절
- **결정:** 작성 에이전트는 해당 단계의 템플릿과 가이드, 이전 단계 산출물, 프로젝트 자료, 값을 채우는 규칙을 읽는다. 결정 로그·변환 분석서·샘플·인터페이스 표 원본은 기본으로 주지 않는다. 인터페이스 표는 템플릿의 생성 블록으로만 노출한다.
- **이유:** 맥락 비용과 앵커링 위험을 줄인다.
- **상태:** 유효

### DL-SYS-017 · 단계 세트 파일을 역할별 디렉터리에 같은 파일명으로 둔다
- **대상:** `docs/문서_체계_정의서.md` 7절
- **결정:** `templates/`, `guides/`, `decision-logs/`, `conversions/` 아래에 샘플과 같은 `NN_이름.md` 파일명을 쓴다. 같은 파일명은 같은 단계의 문서다. 체계 공통 문서는 `docs/`에 둔다. 인터페이스 표 원본과 체계 도구의 위치는 4단계에서 확정한다.
- **이유:** 파일명만으로 같은 단계 세트를 묶어 볼 수 있고, 검사 도구가 존재 여부를 쉽게 확인한다.
- **상태:** 유효 (도구·CSV 위치는 DL-SYS-022에서 확정. 절 번호는 DL-SYS-024 참고)

### DL-SYS-018 · 문서 체계 정의서 v1.0 초안을 작성한다
- **대상:** `docs/문서_체계_정의서.md` (작업 순서 1단계)
- **결정:** 문서 종류 9개의 정의, 내용 귀속 기준, 독자 표, 샘플→세트 변환 절차, 인터페이스 표 요약, 파일 위치, 변경 절차, 용어를 담는다. 세부 규칙은 2단계로 넘긴다.
- **상태:** 유효

### DL-SYS-019 · 문서를 상위·중위·하위 3층으로 나눈다
- **대상:** `docs/문서_체계_정의서.md` 2절
- **배경:** 문서 종류가 늘면서 어느 문서가 어느 문서를 따르는지가 분명하지 않았다. 사용자가 상위(정의서), 중위(공통 및 문서 타입별 작성 규칙과 결정 로그), 하위(36단계 세트)의 3층 구조를 제안했다.
- **결정:** 3층으로 정한다. 윗층이 정하고 아랫층이 따른다. 인터페이스 표는 하위의 공유 문서로 두되 규칙은 중위의 인터페이스 표 규칙에서 받는다. 결정 로그는 상위·중위의 문서마다, 하위는 단계마다 대응한다. 여러 문서에 걸친 결정은 영향받는 문서들의 가장 가까운 공통 상위 문서의 로그에 쓴다. 현재는 임시로 `결정로그_체계.md` 하나가 상위·중위 결정을 담고, 2단계에서 문서별로 재배치한다(항목 ID 유지, 내용 삭제 금지).
- **이유:** 층마다 같은 원칙("문서에는 상응하는 로그가 있다")을 적용하고 파생 관계를 분명히 한다.
- **영향:** 정의서 v1.1에 2절 추가. 2단계에서 규칙 문서와 로그를 층별로 재배치.
- **상태:** 유효

### DL-SYS-020 · 단계 정의를 상위 층의 별도 문서로 두고 문장 종류에 `절차 정의`를 추가한다
- **대상:** `docs/단계_정의.md`(신규), 정의서 4절
- **배경:** 변환 분석서가 "단계의 목적을 기준으로 삼는다"고 했는데, 그 목적이 적힌 공식 문서가 없었다. 36단계 정보는 샘플의 `00_README.md`에만 있었고, 샘플은 장기 삭제 대상이다. 또한 기존 다섯 문장 종류에는 단계의 목적이 들어갈 곳이 없었다.
- **결정:** 단계 정의를 상위 층에 별도 문서로 둔다. 문장 종류를 여섯으로 늘려 `절차 정의`(단계 번호·이름·그룹·목적·산출물이 무엇인가)를 추가하고 집을 단계 정의로 한다. 단계 사이의 입력 관계는 담지 않고 인터페이스 표에만 둔다. 36단계는 이 프로젝트에서 도출한 절차이며 외부 검증된 표준이 아니라는 점을 문서에 명시한다. 작업 순서에 **1단계-b: 단계 정의 문서 작성**을 추가한다.
- **이유:** 모든 세트가 이 문서에서 파생되므로 정의서와 같은 급의 기준이다. 정의서(문서 체계)와 변경 이유가 다르다. 입력 관계는 인터페이스 표와 중복하지 않는다.
- **영향:** 정의서 v1.1. 단계 정의 문서 작성(수정목록 C9).
- **상태:** 유효

### DL-SYS-021 · 샘플은 계층 밖의 입력 자료이며 장기 삭제 대상이다
- **대상:** 샘플 전체, 정의서 7절, 중위의 샘플 규칙
- **배경:** 샘플은 특정 주제로 만들어진 것이라 공식 문서의 기준이 될 수 없다. 사용자가 샘플은 장기적으로 삭제될 것이고 공식 문서에 영향을 주어서는 안 된다고 정했다.
- **결정:** 샘플은 계층 밖의 입력 자료다. 공식 문서는 샘플을 참조하거나 샘플에 의존하지 않는다. 변환 분석서는 예외로 샘플을 가리킬 수 있고, 샘플이 삭제되어도 읽을 수 있도록 필요한 발췌를 분석서 안에 인용한다. 결정 로그도 샘플을 언급할 수 있되 독립적으로 이해되도록 쓴다. 중위에 샘플 규칙을 둔다.
- **이유:** 샘플이 사라져도 공식 문서가 끊기지 않게 한다.
- **영향:** 정의서가 `00_README.md`를 가리키던 부분을 제거. 변환 분석서 규칙에 발췌 인용 요구를 추가(2단계).
- **상태:** 유효

### DL-SYS-022 · 검사 도구는 하위 층의 가장 아래에 두고, 체계 도구는 샘플 폴더 밖에 둔다
- **대상:** 검사 도구, 인터페이스 표 CSV, 수정목록 C6
- **배경:** 도구는 규칙(중위)을 구현하고 템플릿·가이드·인터페이스 표(하위)를 읽으므로 둘 모두에 의존한다. 또 도구가 샘플 폴더 안에 있으면 샘플을 지울 때 함께 사라진다.
- **결정:** 도구를 하위 층의 가장 아래로 본다. 체계 도구는 루트 `tools/`, 인터페이스 표 CSV는 `tools/data/interfaces.csv`에 둔다. `feature-list-sample/tools/`는 샘플 전용으로 남기고 삭제해도 된다. 템플릿·규칙·인터페이스 표를 바꾸면 검사 도구도 확인한다.
- **이유:** 의존 방향에 맞는 계층 위치와, 샘플 삭제에 영향받지 않는 위치.

- **결정:** (b). 가이드를 **공통 가이드**(산출물 작성 가이드, 체계 전체 하나, 중위)와 **단계 가이드**(단계마다, 하위)로 나눈다. 둘 다 작성 에이전트가 항상 읽는다. 세트는 템플릿·단계 가이드·결정 로그·변환 분석서이며 공통 가이드는 세트에 속하지 않는다. 파일명은 `산출물_작성_guide.md`와 `산출물_작성_guide_decision-log.md`이다. 모든 단계에 공통인 절차·판단은 공통 가이드에, 한 단계에 특정한 것은 단계 가이드에 쓴다(귀속 기준 판별법 4).

### DL-SD-003 · 산출물은 템플릿을 복사해 채우지 않고 참고해서 새로 쓴다
- **날짜:** 2026-10-08
- **대상:** `docs/문서_체계_정의서.md` 3, 4, 12절 (v1.3), `docs/규칙_템플릿.md` (v1.1), 공통 가이드(산출물 작성 가이드)
- **결정 주체:** 사용자 승인
- **배경:** 산출물에 힌트를 남길지(DL-TP-001)를 논의하면서, 이 질문이 "템플릿을 물리적으로 복사해 채운다"는 전제 위에 있다는 점이 드러났다. 사용자가 복사 후 채우기와 템플릿을 참고해 새로 쓰기 중 에이전트에게 어느 쪽이 나은지 물었다.
- **검토한 대안:** (a) 복사 후 채우기(힌트는 삭제 또는 유지) / (b) 참고해서 새로 쓰기 + 구조 일치 검사
- **결정:** (b). 산출물은 템플릿의 제목, 버전 줄, 값 표(표 키 주석 포함), 지속 지침, 완료 체크의 구조를 따라 새로 쓴다. 힌트(힌트 열·열 힌트 표), 작성 지침, 자리표시, 생성 블록, 템플릿 변경 이력은 산출물에 쓰지 않는다. 표 순서·표 키·항목 이름·열 이름은 템플릿과 같아야 하며, 도구가 템플릿의 구조와 산출물의 구조를 비교해 검사한다(TP-26, TP-27, TP-K13).
- **이유:** (a)는 힌트·지침·자리표시·변경 이력이 산출물에 따라와 정리 절차와 그 검사가 필요하고, 힌트의 예시가 후속 단계의 입력을 오염시킬 수 있다. (b)는 산출물이 깨끗하다. (b)의 위험인 구조 흐트러짐은 이름을 그대로 쓰는 규칙과 구조 일치 검사로 막는다. 이 비교 검사는 (a)에서도 필요하다.
- **영향:** 정의서 v1.3(산출물·템플릿과 가이드를 나누는 이유·작성 에이전트의 정의). 규칙_템플릿 v1.1: TP-06(변경 이력 위치를 작성 지침 구역에서 문서 정보 블록 아래로), TP-08·10·12·14·17 수정, TP-26·27 추가, 검사 TP-K09~K11 수정과 TP-K13 추가. 규칙_템플릿의 DL-TP-001은 이 항목으로 대체되고, DL-TP-006의 변경 이력 위치 부분도 대체된다. 공통 가이드는 "산출물을 정리하는 절차"가 아니라 "템플릿과 단계 가이드를 읽고, 구조를 따라 쓰고, 완료 체크와 검사를 실행하는 절차"를 다룬다. 수정목록 C20 해소, 도구 D8 추가.
- **상태:** 유효
