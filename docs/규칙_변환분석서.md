## 1. 변환 분석서란

샘플을 템플릿으로 바꿀 때의 **분석 기록**이다(정의서 3절, 6절). 샘플은 특정 주제로 만들어졌으므로 값만 지운다고 범용 템플릿이 되지 않는다. 변환 분석서는 샘플의 어떤 요소를 어떻게 처리했고 샘플에 없던 무엇을 보완했는지를 남겨, 템플릿의 모든 변경이 근거를 갖게 한다.

읽는 사람은 유지보수자이고, 작성 에이전트에게는 기본으로 주지 않는다(정의서 5절). 파일은 `conversions/NN_이름_conversion.md`이다(정의서 9절).

| ID | 규칙 |
|---|---|
| CV-01 | 변환 분석서는 단계마다 하나다. **변환 시점의 기록**이며, 상태가 `승인`이 된 뒤에는 내용을 고치지 않는다. 승인 이후의 템플릿 변경은 단계 결정 로그에 기록한다. 이 문서에는 버전과 변경 이력 표를 두지 않는다. |
| CV-02 | 변환의 기준은 샘플이 아니라 **단계 정의의 목적**이다. 머리말에 어느 버전의 단계 정의를 기준으로 했는지 쓴다. |
| CV-03 | 변환 시점은 도메인 교체 시험까지 마친 때다. 시험을 마치기 전에는 상태를 `초안`이나 `검토`로 둔다. |

## 3. 구성

| ID | 규칙 |
|---|---|
| CV-05 | 본문은 세 부분을 이 순서로 갖는다: ① 샘플 해부, ② 누락 탐색, ③ 도메인 교체 시험. |

### 3.1 샘플 해부

| ID | 규칙 |
|---|---|
| CV-06 | 샘플의 모든 요소를 빠짐없이 한 줄씩 적는다. 요소는 섹션, 표, 열, 질문, 규칙·지침 문장, ID 체계, 값이다. 값은 표 단위로 묶어 한 줄로 적을 수 있다. |
| CV-07 | 한 줄의 칸은 아래와 같다. |

| 칸 | 내용 |
|---|---|
| ID | `SA-01`부터 연번 |
| 샘플 요소 | 요소를 식별할 수 있는 **원문 발췌**(CV-14) |
| 분류 | `구조 유지` / `일반화 필요` / `값이라 제거` / `순서 오류라 수정` / `다른 곳이 담당` 중 하나 |
| 샘플 문제 | `없음` / `도메인 편향` / `순서 오류` / `기타 오류` 중 하나 |
| 이유 | 분류와 샘플 문제의 이유 한 문장 |
| 템플릿 대응 | 표 키 또는 필드 키. 표가 아닌 구성 요소는 `구성: <이름>`(제목, 버전 줄, 문서 정보, 지속 지침, 완료 체크 등). `값이라 제거`이면 `해당 없음`과 사유. `다른 곳이 담당`이면 담당하는 문서를 쓰고, 템플릿에 그것을 보여 주는 구성 요소가 있으면 함께 쓴다 |

| 분류 | 뜻 |
|---|---|
| 구조 유지 | 도메인과 무관한 구조라 그대로 쓴다 |
| 일반화 필요 | 도메인 가정이 섞여 있어 일반화해서 쓴다 |
| 값이라 제거 | 특정 서비스의 값이라 템플릿에 쓰지 않는다 |
| 순서 오류라 수정 | 작성 순서가 어긋나 있어 고쳐 쓴다 |
| 다른 곳이 담당 | 이 단계의 목적 밖이거나 다른 종류의 문서(다른 단계의 템플릿, 인터페이스 표, 단계 가이드 등)가 담당하는 내용이다 |

| ID | 규칙 |
|---|---|
| CV-08 | 샘플의 오류와 도메인 편향은 **샘플 문제 칸에만** 기록하고 샘플은 고치지 않는다(DL-SD-006). |
| CV-09 | `일반화 필요`의 이유에는 어떤 도메인 가정이 있었고 어떻게 일반화했는지를 쓴다. |

### 3.2 누락 탐색

샘플에 없는 것을 샘플 밖에서 찾는다. 샘플만 보아서는 샘플에 없는 것이 보이지 않는다.

| ID | 규칙 |
|---|---|
| CV-10 | 누락 탐색은 두 가지 점검을 모두 한다. (가) **목적 대비**: 단계 정의의 목적과 산출물에 비추어 이 단계에 필요한데 샘플에 없는 것을 찾는다. (나) **도메인 대입**: 성격이 다른 가상 도메인을 **2개 이상** 대입해 칸이 부족하거나 의미가 어긋나는 곳을 찾는다. 도메인은 가상이며 실제 서비스 이름을 쓰지 않는다. |
| CV-11 | 발견한 것은 한 줄씩 적는다: `OM-01`부터 연번, 발견 내용, 발견 방법(`목적 대비` 또는 `도메인 대입: <도메인 이름>`), 처리(템플릿에 반영한 표 키·필드 키, 또는 `반영하지 않음`과 사유). 발견이 하나도 없으면 `해당 없음`과 어떤 점검을 했는지를 쓴다. |

### 3.3 도메인 교체 시험

| ID | 규칙 |
|---|---|
| CV-12 | 템플릿과 단계 가이드로 서로 성격이 다른 가상 도메인 2개 이상에서 실제로 산출물을 써 보고, 도메인마다 아래 세 가지를 확인해 결과를 한 줄씩 적는다: `DT-01`부터 연번, 도메인 이름, 확인 항목(`샘플 단어 누출` / `칸 부족·의미 어긋남` / `빈칸 규칙 위반`), 결과, 조치. 시험으로 쓴 산출물 자체는 이 문서에 넣지 않는다. |

## 4. 결정 로그와의 연결

| ID | 규칙 |
|---|---|
| CV-13 | 분석서의 중요한 판단은 단계 결정 로그의 항목으로 올리고, 로그 항목은 분석서의 줄 ID(`SA-nn`, `OM-nn`, `DT-nn`)를 `배경`에 적어 가리킨다(정의서 6절 7번). |

## 5. 샘플 발췌 인용

샘플은 장기적으로 삭제되므로 변환 분석서가 샘플이 없어도 읽혀야 한다(정의서 7절).

| ID | 규칙 |
|---|---|
| CV-14 | 샘플 요소 칸에는 요소의 **원문을 한 문장 이내로 발췌**한다. 파일 이름과 위치만 적는 것은 인용이 아니다. 발췌만으로 무엇을 가리키는지 알 수 있어야 한다. |
| CV-15 | 샘플의 값을 인용할 때는 무엇의 값인지만 알 수 있을 정도로 짧게 줄인다. |

## 6. 보존과 삭제

| ID | 규칙 |
|---|---|
| CV-16 | 변환 분석서는 보존이 기본이고 삭제는 허용한다. 삭제 절차는 정의서 6절을 따른다. 폐기 접미사는 붙이지 않는다(정의서 11절). |

도메인이 정말 서로 성격이 다른지(CV-K05, K06)와 누락 탐색이 충분한지는 도구로 검사할 수 없어 사람이 검토한다.
