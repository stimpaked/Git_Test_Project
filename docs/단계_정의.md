# 단계 정의

> 신규 앱·웹 서비스의 기능 목록을 도출하는 36단계 절차에서, **각 단계가 무엇이고 무엇을 만드는가**를 정의하는 상위 문서다.
> 상태: v1.0 초안 · 문서 계층의 상위(`docs/문서_체계_정의서.md` 2절) · 결정의 이유는 현재 임시 로그 `docs/결정로그_체계.md`(DL-SYS-020)에 있다.

---

## 1. 이 문서가 다루는 것과 다루지 않는 것

| 다룬다 | 다루지 않는다 |
|---|---|
| 단계의 번호, 이름, 그룹, 목적, 산출물이 무엇인가(절차 정의) | 단계 사이의 입력 관계 → 인터페이스 표 |
| | 칸·열·선택지 등 산출물의 구조 → 템플릿 |
| | 산출물을 채우는 방법 → 가이드 |

**목적 칸은 "이 단계가 없으면 무엇이 빠지는가"를 서술한다.** 산출물 칸은 단계가 만드는 문서의 내용을 서술한다. 특정 서비스의 값이나 ID는 쓰지 않는다.

## 2. 출처

- **출처 유형:** 일반 지식(미검증). 이 36단계는 외부의 검증된 표준이나 조사에서 가져온 것이 아니라, 이 프로젝트의 대화에서 도출하고 사용자가 검토·수정한 절차다. 검토는 외부 근거가 아니다.
- 단계의 번호·이름·그룹은 기존 샘플(`feature-list-sample/`)의 36개 문서 구성을 따랐다. 목적과 산출물은 특정 서비스의 값 없이 일반 서술로 다시 썼다. 샘플의 내용을 참조하지 않으며, 샘플이 삭제되어도 이 문서는 독립해 있다.
- 단계 구성을 바꾸거나 외부 자료로 검증하면 이 절의 출처 유형을 갱신하고 결정 로그에 기록한다.

## 3. 그룹

| 그룹 | 이름 | 단계 | 하는 일 |
|---|---|---|---|
| A | 프레임·근거 | 1~3 | 목표·범위를 세우고 외부 근거를 모은다 |
| B | 주체 | 4~5 | 서비스와 관계된 모든 주체(사람, 사람이 아닌 것)를 나열한다 |
| C | 행동 | 6~10 | 주체의 행동과 목표를 흐름으로 드러낸다 |
| D | 대상 | 11~16 | 서비스가 다루는 데이터와 그 상태·시간·권한·사건을 정리한다 |
| E | 구조 | 17~21 | 화면·플랫폼·외부 연동을 정리하고 기능을 담을 영역을 정한다 |
| F | 제약·횡단 | 22~25 | 품질·규제·보안·데이터 수명처럼 모든 기능에 걸치는 요구를 다룬다 |
| G | 운영·사업 | 26~28 | 운영·수익·성장 측면의 기능을 도출한다 |
| H | 대조(외부 기준) | 29~30 | 표준 목록과 유사 서비스에 대조해 빠진 후보를 찾는다 |
| I | 통합·관리 | 31~33 | 후보를 하나의 기능 목록으로 통합하고 계층·ID·의존성을 붙인다 |
| J | 검증·확정 | 34~36 | 검증하고, 우선순위와 릴리스를 정해 기준선을 확정한다 |

## 4. 36단계

| 번호 | 이름 | 그룹 | 목적 (이 단계가 없으면 빠지는 것) | 산출물 (이 단계가 만드는 것) |
|---|---|---|---|---|
| 01 | 목표·가치 | A | 서비스가 달성하려는 것과 사용자에게 주는 가치가 측정 가능하게 정해지지 않아, 이후 모든 판단의 기준이 없다 | 목표(측정 지표 포함), 가치제안, 핵심 가설, 수익 모델 방향, 이해관계자 기대, 초기 리스크 |
| 02 | 범위·제약 | A | 무엇을 하고 무엇을 하지 않는지, 어떤 제약 안에서 하는지 정해지지 않아 기능 후보의 경계가 없다 | 포함·제외·후속 목록(각각 사유), 플랫폼 후보, 제약·가정·의존성·리스크 목록 |
| 03 | 근거 수집 | A | 가설과 범위를 외부 자료로 확인하지 않아, 이후 단계의 값이 추측에 기대게 된다 | 사용자 인사이트, 유사 서비스 기능표, 규제·정책 목록, 기술 제약 메모(항목마다 출처 유형) |
| 04 | 액터 목록(사람) | B | 서비스를 쓰거나 운영하거나 영향받는 사람이 빠짐없이 나열되지 않아, 이후 단계가 특정 사람만 보게 된다 | 사람 액터 목록(역할 단위) |
| 05 | 액터 목록(비사람) | B | 서비스와 상호작용하는 외부 시스템·시간 같은 사람이 아닌 주체가 나열되지 않아, 연동·배치 기능이 빠진다 | 사람이 아닌 액터 목록, 서비스 경계를 보여 주는 컨텍스트 다이어그램 |
| 06 | 저니 격자 | C | 액터가 서비스를 만나는 전 과정(발견에서 탈퇴까지, 문제 상황과 운영 업무 포함)이 칸으로 나뉘지 않아, 행동의 빈 곳이 드러나지 않는다 | 액터×여정 단계 매트릭스(행동·접점·불편, 핵심 구간 표시) |
| 07 | 목표 목록 | C | 매트릭스의 칸마다 액터가 이루려는 목표가 정해지지 않아, 플로우로 그릴 단위가 없다 | 목표 목록(액터·단계·칸과 연결) |
| 08 | 액터 공통·고유 | C | 여러 액터가 같은 방식으로 하는 일과 특정 액터만 하는 일이 가려지지 않아, 같은 것을 중복 설계한다 | 공통·고유 태그가 붙은 목표 목록 |
| 09 | 유저 플로우 | C | 목표마다 사용자의 행동 흐름이 그려지지 않아, 흐름 위의 분기와 미결 질문이 기능 후보로 드러나지 않는다 | 플로우 다이어그램, 미결 질문 목록(기능 후보), 플로우에 등장한 명사·상태·화면 |
| 10 | 시나리오 5유형 | C | 정상 경로만 그리면 놓치는 대안·예외·오남용·복구 상황이 점검되지 않는다 | 플로우×5유형(정상·대안·예외·오남용·복구) 점검표, 추가 질문(기능 후보) |
| 11 | 엔티티 | D | 서비스가 다루는 데이터 대상이 정리되지 않아, 이후 표의 행으로 쓸 기준 목록과 용어가 없다 | 엔티티 목록, 용어집 |
| 12 | CRUD 매트릭스 | D | 엔티티마다 생성·조회·수정·삭제 같은 처리가 누구에게 어디서 제공되는지 확인되지 않아, 빠진 기능이 드러나지 않는다 | 엔티티×처리 매트릭스(빈 칸은 기능 후보 또는 해당 없음+사유) |
| 13 | 상태 전이 | D | 엔티티가 가지는 상태와 그 사이를 움직이는 계기가 정리되지 않아, 계기 없는 전이와 막다른 상태가 남는다 | 엔티티별 상태도, 전이 계기 목록 |
| 14 | 시간·주기 | D | 시간이 계기가 되는 동작(만료·갱신·알림·배치)이 정리되지 않아, 사용자가 일으키지 않는 기능이 빠진다 | 시간 기반 기능 목록 |
| 15 | 소유·권한 | D | 누가 무엇을 보고 바꿀 수 있는지, 데이터의 소유·공유·위임·승인 규칙이 정해지지 않아, 접근 제어 기능이 빠진다 | 권한 매트릭스, 사용자 상태별 제한 표, 소유·공유·위임·승인 규칙 |
| 16 | 이벤트 | D | 서비스 안의 사건과 그것을 받아 처리하는 기능(알림·기록·분석 등)이 정리되지 않아, 후속 처리 기능이 빠진다 | 이벤트 목록(발생 기능·소비 기능) |

## 5. 용어 메모

- **저니 격자:** 액터×여정 단계의 매트릭스를 가리킨다. "격자"와 "매트릭스"의 용어 통일은 아직 정하지 않았다(수정목록 G2). 통일되면 06번의 이름을 함께 정한다.
- **미결 질문:** 06~09번 등에서 플로우를 그리다 나오는 "이 경우는 어떻게 되는가"의 질문이며, 기능 후보로 취급한다.
- **기능 후보:** 31번에서 병합되기 전의 기능 단위 후보를 가리킨다.

## 6. 이 문서가 정하지 않은 것

- 단계의 추가·삭제·순서 변경 규칙(번호가 파일명에 쓰이므로 번호 재부여의 영향이 크다). 규칙 문서에서 정한다.
- 템플릿 머리말에 단계 이름·목적을 반영하는 방식(수정목록 C12).
- 단계 사이의 입력 관계(인터페이스 표)와 산출물의 구조(템플릿).
