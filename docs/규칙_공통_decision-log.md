# 결정 로그 — 규칙 공통

> `docs/규칙_공통.md`의 결정 이력이다. 항목은 추가만 하고 과거 항목은 고치지 않는다.
> **임시 형식:** 항목 구조는 결정 로그 규칙(작업 순서 2단계)에서 확정하기 전의 임시안이다. 확정되면 맞춰 정리한다.
> 임시 로그 `결정로그_체계.md`에서 이 문서에 속하는 항목(DL-SYS-001, 005)을 옮겨 왔다. **항목 ID는 유지한다.**

## A. 임시 로그에서 옮겨 온 항목

### DL-SYS-001 · 출처 유형과 근거 등급 도입
- **대상:** 샘플 01~03번, 32·36번, `tools/verify.py` (현재 규칙: 규칙_공통 CM-10, CM-11)
- **배경:** 샘플의 가설·가정·경쟁작 표가 출처 없이 만들어진 값이었다. 근거 없이 목록을 만드는 것과 다르지 않다는 지적이 있었다.
- **결정:** 뿌리 항목마다 출처 유형(`조사` / `내부 자료` / `일반 지식(미검증)` / `가정`)을 적는다. `조사`·`내부 자료`만 근거로 인정한다. 기능은 근거 체인에 이 둘이 없으면 `미검증`이다.
- **이유:** 가상 값은 가상이라고 밝히고, 실제 프로젝트에서 어느 값이 확인되었는지 구분하기 위해.
- **영향:** 샘플 146개 기능이 모두 `미검증`으로 집계됨. 검사 도구에 출처·등급 검사 추가.
- **상태:** 유효

### DL-SYS-005 · 빈칸 금지와 세 가지 닫는 말
- **대상:** 규칙 V3, V4, C1 (현재 규칙: 규칙_공통 CM-04, CM-07, CM-08)
- **배경:** `미정`이 "채우지 말라"로 읽힐 수 있고, 예시 칸만 비워도 되는 예외가 생기는 문제를 논의했다.
- **결정:** 어떤 칸도 비울 수 없다. `자명함`(힌트 칸), `해당 없음`(사유 필수), `미정`(확인처·담당·기한 필수)으로 닫는다. 예시 칸도 예외가 아니다.
- **이유:** 예외를 만들지 않고, `해당 없음` 남발은 사유 요구로 막는다.
- **상태:** 유효

## B. 이 문서에서 새로 정한 항목

### DL-CM-001 · 규칙_공통 v1.0 초안을 작성한다
- **대상:** `docs/규칙_공통.md` (작업 순서 2단계, 첫 규칙 문서)
- **배경:** 기존 `템플릿_작성_규칙.md`를 문서 종류별로 나누기로 했다(DL-SYS-019). 공통 규칙은 모든 문서 종류에 적용되는 규칙을 모은다.
- **결정**
  1. **값 규칙은 공통 규칙에 둔다.** 값 규칙은 템플릿이 아니라 산출물의 칸을 채울 때 적용되고 작성 에이전트가 읽어야 하며, 단계 정의의 출처 유형처럼 다른 문서도 쓴다. 3절은 다른 절 없이 이해되게 쓰고, 작성 에이전트에게는 3절만 제공한다(수정목록 C8 해소).
  2. **검사는 그 검사가 강제하는 규칙과 같은 문서에 둔다.** 이에 따라 기존 검사 C1(빈칸·`미정`·`해당 없음`)과 C2(근거 열)는 빈칸 금지와 근거 규칙을 강제하므로 템플릿이 아니라 공통에 둔다. 앞서 사용자에게 알린 이동 안(C1·C2는 템플릿)을 바꾼 것이다. C1은 둘로 나눈다(빈 칸 없음 `CM-K01`, `미정`·`해당 없음`의 부속 정보 `CM-K02`).
  3. **출처 유형의 뜻과 함께 적을 것을 정의한다.** 조사는 출처와 확인일, 내부 자료는 어느 문서·누구에게서 가져왔는지를 함께 적는다. 기존 규칙에는 이 구체 요건이 없었고 이번에 더했다.
  4. **근거 등급을 일반화한다.** 기존에는 기능에만 적용되던 검증/미검증 판정을 "어떤 항목이든 근거 체인에 조사·내부 자료가 있는가"로 일반화했다.
  5. **문서 상태 값을 `초안` / `검토` / `승인` 세 가지로 정했다.** 날짜 형식은 `YYYY-MM-DD`다. 기존 샘플의 상태 표기를 따랐으나 규칙으로 정한 것은 이번이 처음이다.
  6. **규칙 ID 체계를 정했다.** 규칙은 `<문서 코드>-nn`, 검사는 `<문서 코드>-Knn`. 문서 코드는 공통 CM, 결정 로그 DR, 템플릿 TP, 가이드 GD, 변환 분석서 CV, 인터페이스 표 IR, 샘플 SP.
  7. **용어는 공통 규칙에 두지 않는다.** 정의서 12절이 단일 출처다. 이에 따라 수정목록 B2("예시 앵커링" 등 용어 정리)는 정의서 12절에 이미 반영되어 있으므로 해소한다.
- **이유:** 사용자가 승인한 이동 안(DL-SYS-019, 2단계 계획)을 실행하되, 같은 사실을 두 곳에 쓰지 않는다는 원칙(CM-12)과 규칙·검사의 같은 문서 배치 원칙(CM-03)을 일관되게 적용한다.
- **영향:** 템플릿 규칙은 C4(지침 문구 잔존)·C5(예시 복사)·C7(선택 블록 잔존)을 맡고, 샘플 규칙은 C6(샘플 단어 잔존)을, 인터페이스 표 규칙은 C8(ID 일관성)을 맡는다.
- **상태:** 유효 (사용자 승인 2026-10-08)

### DL-CM-003 · 근거 칸의 형식을 규칙으로 정한다 (CM-18)
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_공통.md` CM-18, CM-K04~K06
- **결정 주체:** 사용자 결정
- **배경:** 출처 유형을 어떻게 담을지 DL-SD-011에서 근거 칸의 형식으로 정했다.
- **검토한 대안:** 해당 없음 — DL-SD-011에서 검토했다.
- **결정:** CM-18을 더했다. CM-K04는 근거마다 접두어를 보고, CM-K06은 `미정` 개수와 `미검증` 후보 비율을 출력한다. CM-K05(등급 표시와 근거 체인의 일치)는 등급을 표시하는 문서가 아직 없어 구현하지 않는다.
- **이유:** 근거 체인을 따라가는 검사는 단계 사이 연결이 필드 단위로 완성된 뒤에야 의미가 있다.
- **영향:** 04 템플릿 v1.1의 지속 지침, 공통 가이드 v1.1.
- **상태:** 유효

### DL-CM-004 · 한 칸에 값과 `미정`을 함께 쓰는 것을 허용한다 (CM-07)
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_공통.md` CM-07, CM-K02, CM-K06
- **결정 주체:** 사용자 결정
- **배경:** 도메인 교체 시험에서 한 칸의 일부는 알고 일부는 모르는 경우(예: 학교 소속 교직원이 있다는 것은 알지만 계정을 학교 단위로 묶는지는 모름)에 쓸 형식이 없었다(04번 변환 분석서 DT-02, DL-04-011).
- **검토한 대안:** (a) 허용하지 않고 행을 나눈다 / (b) 아는 값을 쓰고 모르는 부분만 `미정`(확인처·담당·기한)으로 이어 쓰게 허용한다
- **결정:** (b). 속성 표는 행이 고정이라 행을 나눌 수 없다. 이어 쓸 때도 `미정`에는 확인처·담당·기한이 붙는다.
- **이유:** 칸 전체를 `미정`으로 닫으면 아는 정보가 사라지고, 값으로 닫으면 모르는 부분이 추측이 된다.
- **영향:** 규칙_공통 v1.5, 공통 가이드 v1.3, 검사 도구(DL-TL-003).
- **상태:** 유효
