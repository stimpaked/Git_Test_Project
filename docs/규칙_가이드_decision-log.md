### DL-GD-001 · 가이드 길이 상한을 잠정으로 정한다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_가이드.md` GD-06, GD-07 (수정목록 B6)
- **결정 주체:** 유지보수자 판단
- **배경:** 가이드는 작성 에이전트가 항상 읽으므로 항상 맥락에 올라간다(DL-SD-001). 길이 상한이 없으면 가이드가 계속 길어진다.
- **검토한 대안:** (a) 상한을 두지 않는다 / (b) 줄 수 상한을 둔다 / (c) 템플릿 길이의 배수로 정한다
- **결정:** (b). 빈 줄을 제외한 줄 수로 세며 잠정 상한은 공통 가이드 150줄, 단계 가이드 200줄이다. 04번 시범을 마친 뒤 실제 길이를 보고 조정한다.
- **이유:** 줄 수는 도구가 쉽게 확인한다. 아직 가이드를 하나도 쓰지 않아 숫자의 근거는 없고, 시범 후 조정한다고 못 박아 두었다. (c)는 템플릿 크기와 가이드 필요량이 비례한다는 근거가 없다.
- **영향:** 해당 없음 — 가이드가 아직 없다. 04번 시범 후 이 항목을 대체하는 새 항목을 쓴다.
- **상태:** 검토 대기

### DL-GD-002 · 공통 가이드와 단계 가이드의 필수 절을 정한다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_가이드.md` GD-08, GD-09
- **결정 주체:** 유지보수자 판단
- **배경:** 가이드의 구성이 정해져 있지 않으면 단계마다 모양이 달라지고, 검사 도구가 확인할 수 없다.
- **검토한 대안:** (a) 구성을 자유롭게 둔다 / (b) 필수 절을 고정한다
- **결정:** (b). 공통 가이드는 일곱 절(읽는 순서와 진행, 템플릿을 따라 쓰는 방법, 칸을 닫는 판단, 이전 단계 산출물을 쓰는 법, 예시와 샘플을 만났을 때, 완료 전 점검, 흔한 실수), 단계 가이드는 여섯 절(입력을 읽는 법, 작성 절차, 항목별 해설, 누락 점검, `미정`·`해당 없음` 판단, 흔한 실수)을 이 순서로 갖는다.
- **이유:** 이 대화에서 논의된 내용(읽는 순서, 템플릿을 따라 쓰는 방법, 칸을 닫는 판단, 예시를 만났을 때, 누락 점검)을 빠짐없이 담을 자리를 만들고, 구조 일치 검사를 가능하게 한다.
- **영향:** 산출물 작성 가이드와 모든 단계 가이드가 이 절 구성을 따른다.
- **상태:** 검토 대기

### DL-GD-003 · 단계 가이드의 해설을 템플릿 표 키로 대응시킨다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_가이드.md` GD-10, GD-11, GD-12
- **결정 주체:** 유지보수자 판단
- **배경:** 템플릿과 가이드는 둘 다 항상 읽히며 한쪽이 바뀌면 다른 쪽이 어긋나기 쉽다. 수정목록 D3은 템플릿 항목과 가이드 해설의 대응 검사를 요구했으나 대응 지점이 없었다.
- **검토한 대안:** (a) 사람이 대응을 확인한다 / (b) 해설 소제목 위에 템플릿의 표 키를 주석으로 가리키게 한다
- **결정:** (b). 템플릿의 값 표마다 해설 소제목을 하나씩 두고 `<!-- 해설: <표 키> -->`로 가리킨다. 해설이 필요 없는 표는 `해설 없음: <사유>`를 쓴다. 머리말에 `대상 템플릿 vX.Y`를 쓰고 일치 여부를 검사한다.
- **이유:** 표 키(TP-24)는 이미 템플릿의 고유 이름이므로 그대로 쓰면 도구가 대응을 확인할 수 있다.
- **영향:** 단계 가이드를 쓸 때 템플릿의 표 키를 알아야 한다. 검사 GD-K02, GD-K06.
- **상태:** 검토 대기

### DL-GD-004 · 가이드의 예시 규칙을 정한다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_가이드.md` GD-13~17
- **결정 주체:** 유지보수자 판단
- **배경:** 가이드는 항상 읽히는 문서라 가이드 안의 예시가 산출물로 복사될 위험이 더 크다(DL-SD-001). 기존 규칙에는 예시에 관한 규칙이 힌트(H3), 샘플 제공(O4), 예시는 값이 아니라 형식(P3)으로 흩어져 있었다.
- **검토한 대안:** (a) 가이드에 예시를 쓰지 않는다 / (b) 예시를 쓰되 표시와 제한 규칙을 둔다
- **결정:** (b). 예시는 `예시(형식 시연, 값이 아님):`으로 시작하고, 서로 다른 도메인 2개 이상에서 가져오며, 실제 서비스 이름과 빨리 낡는 숫자와 샘플의 특정 서비스 단어를 쓰지 않는다. 공통 가이드 5절은 예시를 값으로 쓰지 않는다는 문장을 포함한다. 이미 사용자가 승인한 내용(여러 도메인에서 가져온다, 낡는 숫자 금지, 예시는 값이 아니라 형식)을 가이드에 적용하고, 형식 시연 표시와 공통 가이드 문장 요건은 새로 더했다.
- **이유:** 예시가 필요한 곳(판단 기준의 설명)이 있고, 없애면 가이드가 추상적이 된다. 표시와 제한으로 복사 위험을 낮춘다.
- **영향:** 검사 GD-K04, GD-K05. 예시의 도메인 수는 도구로 검사할 수 없어 사람이 검토한다.
- **상태:** 검토 대기

### DL-GD-005 · 단계 가이드는 단계의 목적을 쓰지 않는다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_가이드.md` GD-01, GD-09
- **결정 주체:** 유지보수자 판단
- **배경:** 정의서 4절의 귀속 기준에 따라 단계의 목적은 절차 정의로서 단계 정의가 갖는다. 템플릿의 문서 정보 블록(생성)에 목적이 이미 있다. 가이드를 항상 함께 읽으므로 목적을 또 쓰면 중복이다.
- **검토한 대안:** (a) 가이드 첫 절에 목적을 반복한다 / (b) 목적은 쓰지 않는다
- **결정:** (b).
- **이유:** 같은 사실을 두 곳에 쓰지 않는다(CM-12).
- **영향:** 해당 없음 — 가이드가 아직 없다. 검사 GD-K07.
- **상태:** 검토 대기

### DL-GD-006 · 규칙_가이드 v1.0 초안을 작성하고 기존 규칙의 이관을 기록한다
- **날짜:** 2026-10-08
- **대상:** `docs/규칙_가이드.md` (작업 순서 2단계, 네 번째 규칙 문서)
- **결정 주체:** 사용자 승인 (작성 순서는 2단계 계획에서 승인됨). 세부 규칙은 DL-GD-001~005 각각의 결정 주체를 따른다.
- **배경:** 기존 규칙 중 가이드와 관계된 것(O1, O2, P3 등)을 정리하고 가이드를 어떻게 쓰는지 정한다.
- **검토한 대안:** 해당 없음 — 이관은 2단계 계획을 따랐다.
- **결정:** 아래 대응표대로 정리한다. 기존 O1, O2는 "가이드를 어떻게 쓰는가"가 아니라 "산출물을 어떻게 쓰는가"에 대한 절차 문장이므로 규칙 문서가 아니라 공통 가이드의 내용이다. 이에 규칙_가이드는 공통 가이드가 이 내용을 담을 절(1절)을 요구하는 데 그친다. 2단계 계획에서 O1, O2를 가이드 규칙으로 옮긴다고 한 것을 이렇게 바로잡는다.
- **이유:** 정의서의 귀속 기준에 따르면 절차·판단 문장의 집은 가이드이지 규칙 문서가 아니다.
- **영향:** 산출물 작성 가이드를 쓸 때 O1, O2를 1절에 담는다.
- **상태:** 유효
