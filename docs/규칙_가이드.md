## 1. 가이드란

산출물을 쓰는 **작성 에이전트가 항상 읽는** 문서로, 템플릿을 어떻게 채우는지의 절차와 판단을 담는다(정의서 3절). 두 층이다.

| 층 | 문서 | 파일 | 범위 |
|---|---|---|---|
| 공통 가이드 | 산출물 작성 가이드 | `docs/산출물_작성_guide.md` | 모든 단계에 공통인 작성 절차 |
| 단계 가이드 | 단계마다 하나 | `guides/NN_이름_guide.md` | 한 단계의 칸을 채우는 방법 |

| ID | 규칙 |
|---|---|
| GD-01 | 가이드는 **절차·판단 지식**만 담는다: 도출 절차, 판단 기준, 흔한 실수, 모를 때의 처리, 입력을 읽는 법, 칸 의미의 해설. 구조 사실(칸 이름, 열 순서 등), 관계 사실, 이력, 단계의 목적은 쓰지 않는다. 그런 내용은 각각 템플릿, 인터페이스 표, 결정 로그, 단계 정의가 갖는다(정의서 4절). |
| GD-02 | 가이드는 **정답이 아니라 찾는 방법**을 쓴다. 특정 프로젝트나 서비스의 값을 쓰지 않는다. |
| GD-03 | 공통 규칙(값 규칙)을 가이드에서 다시 쓰지 않는다. 필요하면 어디를 보라고 가리킨다(공통 규칙 CM-12). 가이드는 규칙을 **어떻게 적용해 판단하는지**를 쓴다. |
| GD-04 | 문장은 작성 에이전트가 따를 수 있는 서술("~한다.")로 쓴다. 한 문장에 판단 기준은 하나만 담는다. |
| GD-05 | 가이드의 판단 기준과 프로젝트 자료의 사실이 충돌하면 **프로젝트 자료의 사실을 따르고**, 그 사실을 근거 칸에 쓴다. |

## 2. 길이

가이드는 항상 맥락에 올라가므로 길이를 제한한다.

| ID | 규칙 |
|---|---|
| GD-06 | 길이는 **빈 줄을 제외한 줄 수**로 센다. 잠정 상한: 공통 가이드 150줄, 단계 가이드 200줄. 04번 시범(작업 순서 3단계)을 마친 뒤 실제 길이를 보고 조정한다. |
| GD-07 | 상한을 넘기면 내용을 줄인다. 줄일 수 없으면 단계 가이드의 해설 중 모든 단계에 공통인 것을 공통 가이드로 옮기거나, 결정 로그에 상한 조정을 기록한다. |

## 3. 구성

### 3.1 공통 가이드

| ID | 규칙 |
|---|---|
| GD-08 | 공통 가이드는 아래 일곱 절을 이 순서로 갖는다. |

| 절 | 내용 |
|---|---|
| 1. 읽는 순서와 진행 | 프로젝트 자료, 이전 단계 산출물, 템플릿, 단계 가이드를 읽는 순서. 한 번에 한 단계씩 진행한다 |
| 2. 템플릿을 따라 쓰는 방법 | 구조(표 순서, 표 키, 항목·열 이름)를 그대로 따르고, 힌트·작성 지침·자리표시·생성 블록은 쓰지 않는 절차. 선택 블록의 처리 |
| 3. 칸을 닫는 판단 | 값을 쓸지, `미정`을 쓸지, `해당 없음`을 쓸지 고르는 기준. 근거 쓰기와 출처 유형 고르기 |
| 4. 이전 단계 산출물을 쓰는 법 | 이전 산출물을 근거로 인용하는 방법. 새 사실을 만들어 내지 않는 법 |
| 5. 예시와 샘플을 만났을 때 | 예시를 값으로 가져가지 않는 법 |
| 6. 완료 전 점검 | 완료 체크를 실행하고 검사를 돌리는 절차 |
| 7. 흔한 실수 | 단계에 상관없이 자주 나오는 실수 |

### 3.2 단계 가이드

| ID | 규칙 |
|---|---|
| GD-09 | 단계 가이드는 아래 여섯 절을 이 순서로 갖는다. 단계의 **목적은 쓰지 않는다**(절차 정의의 집은 단계 정의이고, 템플릿의 생성 블록에 이미 있다). |
| GD-10 | 머리말에 `대상 템플릿 vX.Y`를 쓴다. 템플릿의 버전이 바뀌면 가이드를 확인하고 이 버전을 갱신한다. |

| 절 | 내용 |
|---|---|
| 1. 입력을 읽는 법 | 이 단계에서 이전 단계 산출물과 프로젝트 자료의 어디를 어떤 관점으로 보는가(입력 목록 자체는 템플릿의 생성 블록에 있다) |
| 2. 작성 절차 | 템플릿의 표 순서대로 무엇을 먼저 하고 다음에 무엇을 하는가 |
| 3. 항목별 해설 | 템플릿의 표마다 무엇을 어떻게 판단해 채우는가, 판단 기준, 흔한 실수 |
| 4. 누락 점검 | 이 단계 산출물에서 빠지기 쉬운 것을 찾는 질문 |
| 5. `미정`·`해당 없음` 판단 | 이 단계에서 값을 못 정할 때와 해당 개념이 없을 때의 구체적 기준 |
| 6. 흔한 실수 | 이 단계에서 자주 나오는 실수 |

### 3.3 템플릿과의 대응

| ID | 규칙 |
|---|---|
| GD-11 | 단계 가이드의 "항목별 해설" 절은 템플릿의 **값 표마다 하나의 소제목**을 갖고, 소제목 위에 주석 `<!-- 해설: <표 키> -->`로 템플릿의 표 키를 가리킨다. 해설이 필요 없는 표는 소제목 아래에 `해설 없음: <사유>`를 쓴다. 템플릿에 없는 표에 대한 해설은 두지 않는다. 규칙_템플릿 TP-29의 **표 없는 필수 블록**에는 해설 주석을 달지 않고, "항목별 해설" 절에 그 블록의 소제목만 둔다(해설 내용은 쓸 수 있다). |
| GD-12 | 해설의 기준은 가이드에만 쓴다. 템플릿의 힌트는 조건 없는 한 문장이므로(TP-18), 해설과 힌트가 충돌하지 않게 한다. |

## 4. 예시

| ID | 규칙 |
|---|---|
| GD-13 | 가이드의 예시는 `예시(형식 시연, 값이 아님):`으로 시작한다. |
| GD-14 | 예시는 서로 다른 도메인 2개 이상에서 가져온다. 한 도메인의 예시만 쓰지 않는다. |
| GD-15 | 예시에 실제 서비스 이름과 빨리 낡는 숫자(점유율·시장 규모·버전 등)를 쓰지 않는다(템플릿 규칙 TP-23과 같은 기준). |
| GD-16 | 예시에 샘플의 특정 서비스를 전제하는 단어를 쓰지 않는다(정의서 7절). |
| GD-17 | 공통 가이드 5절은 예시를 값으로 쓰지 않는다는 문장을 반드시 포함한다. |

## 5. 검사

| ID | 검사 | 강제하는 규칙 | 결과 | 구현 상태 |
|---|---|---|---|---|
| GD-K01 | 공통 가이드가 일곱 절, 단계 가이드가 여섯 절을 순서대로 갖는다 | GD-08, GD-09 | 실패 | 구현 |
| GD-K02 | 템플릿의 모든 값 표에 대응하는 해설(또는 `해설 없음: 사유`)이 있고, 템플릿에 없는 표의 해설이 없다 | GD-11 | 실패 | 구현 |
| GD-K03 | 길이가 상한 이내다 | GD-06 | 실패 | 구현 |
| GD-K04 | 예시가 모두 `예시(형식 시연, 값이 아님):`으로 시작한다 | GD-13 | 실패 | 구현 |
| GD-K05 | 가이드에 샘플 고유 단어가 없다 | GD-16 | 경고 | 구현 |
| GD-K06 | 머리말의 `대상 템플릿 vX.Y`가 현재 템플릿 버전과 일치한다 | GD-10 | 경고 | 구현 |
| GD-K07 | 단계 가이드에 단계의 목적 절이 없다 | GD-09 | 실패 | 구현 |

예시의 도메인 수(GD-14)와 구조 사실·관계 사실이 섞여 있는지(GD-01)는 도구로 검사할 수 없어 사람이 검토한다.

구현은 작업 순서 4단계(`tools/`)에서 한다.

## 6. 변경

이 문서를 바꿀 때는 `docs/규칙_가이드_decision-log.md`에 항목을 추가하고 버전을 올린다. 이 문서가 바뀌면 모든 가이드를 재검사한다(정의서 10절).

- 단계 가이드의 실제 내용 → 단계 세트 작성(3단계 이후)
- 샘플 고유 단어 목록의 관리 → 규칙_공통 CM-17
