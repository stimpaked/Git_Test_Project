## 1. 인터페이스 표란

단계 사이의 연결을 **필드 수준**으로 모은 표다(정의서 8절). 연결은 **관계 사실**이므로 이 표에만 쓰고 템플릿에는 직접 쓰지 않는다(정의서 4절).

| 대상 | 위치 | 누가 고치나 |
|---|---|---|
| 원본 | `tools/data/interfaces.csv` | 사람 |
| 읽기용 문서 | `docs/단계_인터페이스.md` | 도구가 생성한다. 직접 고치지 않는다 |
| 템플릿의 문서 정보 블록 중 입력과 쓰이는 곳 | 각 템플릿 | 도구가 생성한다. 직접 고치지 않는다 |

| ID | 규칙 |
|---|---|
| IR-01 | 같은 연결(보내는 필드, 받는 단계, 받는 쪽 필드 또는 용도의 조합)은 한 줄에만 쓴다. |
| IR-02 | 줄은 연결 ID 오름차순으로 둔다. |

## 2. CSV 형식

| ID | 규칙 |
|---|---|
| IR-03 | 인코딩은 BOM 없는 UTF-8, 구분자는 쉼표, 첫 줄은 열 이름이다. 쉼표나 줄바꿈이 들어 있는 값은 큰따옴표로 감싼다. 엑셀에서 열 때는 가져오기에서 UTF-8을 지정한다. |
| IR-04 | 열은 아래 아홉 개이며 이 순서를 지킨다. 어떤 칸도 비우지 않는다(공통 규칙 CM-15). |

```
연결 ID,보내는 필드,받는 단계,받는 쪽 필드 또는 용도,쓰이는 방식,한 줄 설명,필수,방향,근거
```

| 열 | 값 |
|---|---|
| 연결 ID | `IF-<보내는 단계 두 자리>-<연번 세 자리>`. 외부 입력(IR-09)은 `IF-EX-<연번 세 자리>` |
| 보내는 필드 | 템플릿의 필드 키(TP-25), 문서 수준 잠정 값 `NN`(IR-10), 또는 외부 입력 `EXT:<입력 이름>`(IR-09) |
| 받는 단계 | 단계 번호 두 자리, 또는 `최종 소비자 없음`(IR-07) |
| 받는 쪽 필드 또는 용도 | 받는 단계 템플릿의 필드 키, 문서 수준 잠정 값 `NN`, 또는 `용도: <받는 단계에서 쓰는 곳>`. `최종 소비자 없음` 줄은 `해당 없음` |
| 쓰이는 방식 | `축(행·열)` / `참조(ID)` / `집계` / `판단 입력` / `제약` / `근거 인용` 중 하나. `최종 소비자 없음` 줄은 `해당 없음` |
| 한 줄 설명 | 받는 쪽이 이것을 어떻게 쓰는지 조건 없는 한 문장. `최종 소비자 없음` 줄은 **사유** |
| 필수 | `예`(받는 쪽이 이것 없이는 진행할 수 없다) / `아니오`. `최종 소비자 없음` 줄은 `해당 없음` |
| 방향 | `순행` / `환류`(IR-05). `최종 소비자 없음` 줄은 `해당 없음` |
| 근거 | 이 연결을 정한 근거: 변환 분석서 줄 ID, 결정 로그 항목 ID, 또는 출처 유형(공통 규칙 CM-10) |

`최종 소비자 없음` 줄에서 `해당 없음`으로 닫은 칸의 사유는 **한 줄 설명 칸 하나에** 쓴다(공통 규칙 CM-15가 허용하는 문서 종류별 닫는 말).

## 3. 순행과 환류

| ID | 규칙 |
|---|---|
| IR-05 | 방향은 단계 번호의 비교와 일치해야 한다. 보내는 단계 번호가 받는 단계 번호보다 작으면 `순행`, 크면 `환류`다. **환류**는 뒤 단계의 결과가 앞 단계 산출물을 고치게 하는 흐름이다. 같은 단계 안의 연결은 쓰지 않는다. 외부 입력은 번호 비교에서 제외하고 방향을 `순행`으로 쓴다. |
| IR-06 | 환류가 일어났을 때 앞 단계의 템플릿이나 산출물의 버전을 올리고 결정 로그에 기록하는 절차는 정의서 10절을 따른다. |

## 4. 소비자

| ID | 규칙 |
|---|---|
| IR-07 | 템플릿의 모든 필드는 표에서 **보내는 필드로 한 줄 이상** 나온다. 뒤 단계가 쓰지 않는 필드(사람이 읽는 설명 등)는 받는 단계를 `최종 소비자 없음`으로 하고 한 줄 설명에 사유를 쓴다. |
| IR-08 | 보내는 필드와 받는 쪽 필드의 필드 키는 실제로 존재하는 템플릿 필드여야 하고, 필드 키의 단계 번호가 각각 보내는 단계, 받는 단계와 같아야 한다. |

## 5. 외부 입력

단계 사이의 연결이 아닌 입력, 즉 프로젝트 자료나 외부에서 가져오는 표준 목록, 일정·예산 같은 제약 정보가 있다.

| ID | 규칙 |
|---|---|
| IR-09 | 외부 입력은 같은 표에 쓴다. 보내는 필드는 `EXT:<입력 이름>`이고 연결 ID는 `IF-EX-nnn`이다. 입력 이름은 한글·영문·숫자·밑줄로 쓰고 모든 외부 입력에 걸쳐 유일해야 한다. 받는 단계와 받는 쪽은 일반 연결과 같이 쓴다. 근거 칸에는 이 입력이 그 단계에 필요하다고 판단한 근거를 쓴다. |

## 6. 문서 수준 잠정 연결

| ID | 규칙 |
|---|---|
| IR-10 | 보내는 단계나 받는 단계의 템플릿이 아직 없어 필드 키를 쓸 수 없는 연결은 필드 키 대신 단계 번호 `NN`으로 쓴다. 이 줄은 **잠정**이다. 해당 템플릿이 생기면 필드 수준의 줄로 바꾸고 잠정 줄은 삭제한다. |

## 7. 생성물

| ID | 규칙 |
|---|---|
| IR-11 | `docs/단계_인터페이스.md`는 CSV에서 도구가 생성한다. 구성은 세 부분이다: (가) **단계별 요약** — 단계마다 번호, 이름, 입력(보내는 단계와 외부 입력 목록), 이 산출물이 쓰이는 곳(받는 단계 목록) / (나) **연결 전체 목록** / (다) **집계** — 줄 수, 잠정 줄 수, 환류 줄 수, 외부 입력 수, `최종 소비자 없음` 줄 수. |
| IR-12 | 템플릿의 문서 정보 블록 중 입력과 쓰이는 곳은 CSV에서 도구가 생성한다(TP-04). 입력은 보내는 단계의 번호·이름과 보내는 필드 이름 목록, 외부 입력은 입력 이름으로 쓴다. 쓰이는 곳은 받는 단계의 번호·이름으로 쓴다. |
| IR-13 | 생성물은 같은 CSV에서 언제나 같은 내용이 나오도록 만든다(생성 시각 등 매번 달라지는 값을 넣지 않는다). |

## 8. 검사

| ID | 검사 | 강제하는 규칙 | 결과 | 구현 상태 |
|---|---|---|---|---|
| IR-K01 | 첫 줄의 열 이름이 IR-04와 같고, 모든 칸이 닫혀 있으며, 쓰이는 방식·필수·방향이 허용된 값이다 | IR-03, IR-04 | 실패 | 구현 |
| IR-K02 | 연결 ID가 형식에 맞고 유일하며 보내는 단계 번호가 일치한다 | IR-04 | 실패 | 구현 |
| IR-K03 | 보내는 필드가 존재하는 템플릿 필드, 문서 수준 잠정 값, 외부 입력 형식 중 하나다 | IR-08, IR-09, IR-10 | 실패 | 구현 |
| IR-K04 | 받는 쪽의 필드 키가 존재하고 필드 키의 단계 번호가 받는 단계와 같다 | IR-08 | 실패 | 구현 |
| IR-K05 | 방향이 번호 비교와 일치한다(외부 입력 제외) | IR-05 | 실패 | 구현 |
| IR-K06 | 같은 연결이 중복되지 않는다 | IR-01 | 실패 | 구현 |
| IR-K07 | 템플릿의 모든 필드가 보내는 필드로 한 줄 이상 나온다 | IR-07 | 실패 | 구현 |
| IR-K08 | 외부 입력 이름이 유일하다 | IR-09 | 실패 | 구현 |
| IR-K09 | 재생성한 읽기용 문서가 현재 파일과 같다 | IR-11, IR-13 | 실패 | 구현 |
| IR-K10 | 잠정 줄 수와 환류 줄 수를 출력한다 | IR-05, IR-10 | 정보 | 구현 |

템플릿의 문서 정보 블록이 CSV와 일치하는지는 템플릿 규칙의 TP-K12가 확인한다.

구현은 작업 순서 4단계(`tools/`)에서 한다.

## 9. 변경

이 문서를 바꿀 때는 `docs/규칙_인터페이스표_decision-log.md`에 항목을 추가하고 버전을 올린다. 인터페이스 표의 연결을 바꾸는 것은 이 문서의 변경이 아니라 CSV의 변경이며, 정의서 10절의 변경 절차를 따른다.

## 10. 이 문서가 정하지 않은 것

- 필드 키의 형식 → 템플릿 규칙 TP-24, TP-25
- 인터페이스 표의 실제 연결 내용 → CSV(작업 순서 3단계 이후 단계별로 채운다)
- 생성 도구의 구현 → 작업 순서 4단계
