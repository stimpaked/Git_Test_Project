# 결정 로그 — 체계 공통

> 템플릿·가이드 문서 체계 전체에 관한 결정을 기록한다. 단계별 결정은 단계 세트의 결정 로그에 쓴다.
> **임시 형식:** 항목 구조는 규칙 문서(작업 순서 2단계)에서 확정하기 전의 임시안이다. 확정되면 이 문서도 맞춰 정리한다.
> **쓰는 법:** 항목은 추가만 한다. 과거 항목은 고치지 않고, 결정이 바뀌면 새 항목을 쓰고 이전 항목의 상태를 `대체됨(→ DL-SYS-nnn)`으로 바꾼다.
> 이 문서는 유지보수자·검토자용이며, 작성 에이전트에게 기본으로 주지 않는다.

**항목 열 설명:** 대상 = 어느 문서·규칙에 관한 결정인가 / 영향 = 이 결정으로 만들거나 고쳐야 하는 것 / 상태 = `유효` · `대체됨` · `보류`

## A. 규칙 문서 수립 단계에서 정한 것 (2026-10-07 이전)

### DL-SYS-001 · 출처 유형과 근거 등급 도입
- **대상:** 샘플 01~03번, 32·36번, `tools/verify.py`
- **배경:** 샘플의 가설·가정·경쟁작 표가 출처 없이 만들어진 값이었다. 근거 없이 목록을 만드는 것과 다르지 않다는 지적이 있었다.
- **결정:** 뿌리 항목마다 출처 유형(`조사` / `내부 자료` / `일반 지식(미검증)` / `가정`)을 적는다. `조사`·`내부 자료`만 근거로 인정한다. 기능은 근거 체인에 이 둘이 없으면 `미검증`이다.
- **이유:** 가상 값은 가상이라고 밝히고, 실제 프로젝트에서 어느 값이 확인되었는지 구분하기 위해.
- **영향:** 샘플 146개 기능이 모두 `미검증`으로 집계됨. 검사 도구에 출처·등급 검사 추가.
- **상태:** 유효 (이동됨 → `규칙_공통_decision-log.md`)

### DL-SYS-002 · 경쟁작 비교표의 행은 경쟁작 자료에서 모은다
- **대상:** 샘플 03·30번, 규칙 O5
- **배경:** 비교표 행을 우리 기능 목록에서 가져오면 순환이다(우리 목록은 아직 없다).
- **결정:** 행은 경쟁작 자신의 자료에서 발견한 기능의 합집합이다. 우리 후보와의 비교는 30번에서 한다.
- **이유:** 순환 논리 제거.
- **영향:** 03번 행 재구성은 실제 경쟁작 자료 확보 후 수행(수정목록 E1).
- **상태:** 유효

### DL-SYS-003 · 기본 제공물은 빈 양식이다
- **대상:** 규칙 T1, O3, O4
- **배경:** 에이전트에게 채워진 샘플을 주면 내용을 그대로 가져다 쓴다.
- **결정:** 기본 제공물은 빈 양식 + 규칙 + 완료 체크리스트다. 채워진 샘플은 필요할 때만 쓰고, 줄 때는 "구조만 참고" 표시와 서로 다른 도메인 2개 이상을 지킨다.
- **이유:** 예시 앵커링·복사 편향 방지.
- **상태:** 유효 (DL-SYS-011로 샘플의 종류가 확정됨)

### DL-SYS-004 · 힌트는 양식에 두고, 표는 4열로 한다
- **대상:** 규칙 T2, T6, H1~H4
- **배경:** 힌트를 없앨지, 값 칸 옆에 둘지, 별도 열로 둘지 논의했다.
- **결정:** 힌트는 양식에 둔다(의미·형식·범위 위주). 표의 기본 열은 `항목 / 힌트 / 내용 / 근거`다. 힌트의 구체 값 예시는 여러 도메인이거나 형식만 허용한다.
- **이유:** 힌트는 칸의 의미를 알리는 역할이라 필요하고, 값 예시는 복사 위험이 있어 제한한다.
- **상태:** 유효 (열 구조는 DL-SYS-013의 기준으로 재검토 대상)

### DL-SYS-005 · 빈칸 금지와 세 가지 닫는 말
- **대상:** 규칙 V3, V4, C1
- **배경:** `미정`이 "채우지 말라"로 읽힐 수 있고, 예시 칸만 비워도 되는 예외가 생기는 문제를 논의했다.
- **결정:** 어떤 칸도 비울 수 없다. `자명함`(힌트 칸), `해당 없음`(사유 필수), `미정`(확인처·담당·기한 필수)으로 닫는다. 예시 칸도 예외가 아니다.
- **이유:** 예외를 만들지 않고, `해당 없음` 남발은 사유 요구로 막는다.
- **상태:** 유효 (이동됨 → `규칙_공통_decision-log.md`)

### DL-SYS-006 · 규칙 문서는 `docs/`에 둔다
- **대상:** `docs/템플릿_작성_규칙.md`
- **결정:** 규칙 문서는 샘플(`feature-list-sample/`)과 분리해 `docs/`에 둔다.
- **이유:** 규칙이 샘플과 섞이면 규칙도 복사 대상으로 보인다.
- **상태:** 유효

## B. 문서 체계 설계 단계에서 정한 것 (2026-10-08)

### DL-SYS-007 · 04번 범용 양식을 새 파일로 먼저 만든다
- **대상:** `feature-list-sample/04_액터목록_사람_범용.md`
- **배경:** 범용 템플릿이 어떤 모양인지 보기 위해 04번을 시험적으로 변환했다.
- **결정:** 원본을 고치지 않고 `_범용` 접미사의 새 파일로 만든다. 도출 질문은 직접 이용·가치 제공·비용 부담·소속·대리·운영·현장·외부 연동·감독·제3자·상태 변형·개방 질문의 12개 관점으로 한다. 질문에 ID(AQ-)를 둔다.
- **이유:** 원본의 질문은 마켓플레이스에 치우쳤고, 1번 표 `결과 액터`에 아직 부여되지 않은 ID가 미리 적혀 작성 순서가 어긋났다.
- **영향:** 이 파일은 규칙 수립 전의 **초안**이다. 04번 세트 작성(작업 순서 3단계) 때 흡수하고 7단계에서 처리한다.
- **상태:** 유효 (초안)

### DL-SYS-008 · 문서 세트를 템플릿·가이드·결정 로그로 구성하고 가이드는 항상 읽는다
- **대상:** 문서 체계 전체
- **배경:** 템플릿만으로는 판단 기준과 작성 방법을 담기 어렵고, 가이드를 "필요할 때만" 읽게 하면 에이전트의 판단에 의존하게 된다.
- **결정:** 단계마다 템플릿·가이드·결정 로그 세트를 둔다. 가이드는 템플릿과 같이 **항상** 읽는다. 가이드의 초점은 "템플릿을 어떻게 채우는가"이며, 길이 상한을 둔다. 체계 전체의 결정은 이 공통 로그에 쓴다.
- **이유:** 읽을지 말지를 에이전트가 판단하지 않게 하고, "왜 그렇게 했는가"를 잃지 않기 위해.
- **영향:** 가이드는 항상 맥락에 올라가므로 예시 규칙을 더 엄격히 적용해야 한다.
- **상태:** 유효 (변환 분석서 추가는 DL-SYS-012)

### DL-SYS-009 · 서비스 유형별 액터 카탈로그를 가이드에 넣지 않는다
- **대상:** 04번 가이드
- **배경:** 04 범용 초안의 "서비스 유형별 놓치기 쉬운 액터" 표는 사실상 채워진 예시다. 가이드를 항상 읽게 하면 해당하지 않는 유형의 액터를 가져올 위험이 크다.
- **결정:** 카탈로그는 넣지 않는다. 12개 질문을 "어떻게 답을 찾는가" 해설로 풀어 쓴다.
- **상태:** 유효

### DL-SYS-010 · 문서 체계 정의서를 만든다
- **대상:** `docs/문서_체계_정의서.md`(작업 순서 1단계)
- **결정:** 문서 종류와 관계를 최상위 문서에서 정의한다.
- **이유:** 템플릿·가이드 등 각 문서의 역할 이해가 서로 달랐다.
- **상태:** 유효

### DL-SYS-011 · 기존 01~36번 문서는 "샘플"이라는 별도 종류다
- **대상:** `feature-list-sample/` 전체
- **배경:** 샘플은 범용으로 만들어진 것이 아니라 처음부터 가상 서비스 "이웃장터"로 만들어졌다.
- **결정:** 샘플은 별도 종류이고, 작성 에이전트에게 기본으로 주지 않는다. 샘플 1개마다 세트(템플릿·가이드·결정 로그·변환 분석서)가 대응한다. 샘플은 세트의 일부가 아니다.
- **이유:** 샘플은 특정 주제에 특화되어 있어 세트의 원본으로 그대로 쓸 수 없다.
- **상태:** 유효

### DL-SYS-012 · 샘플→템플릿 변환은 일반화이며, 중간에 변환 분석서를 둔다
- **대상:** 단계 세트, 문서 체계 정의서
- **배경:** 특정 주제 샘플을 범용 템플릿으로 한 번에 바꾸면 도메인 누출·누락·과일반화·구조 오류가 생긴다. 04번에서 실제로 소속·대리·감독 관점의 누락과 질문 편향, 작성 순서 오류가 확인됐다.
- **결정:** 단계마다 **변환 분석서**를 쓴다(1종, 두 부분: ① 샘플 해부=요소별 유지/일반화/제거/순서수정 분류, ② 누락 탐색=단계 목적과 성격이 다른 가상 도메인 대입). 템플릿의 변경은 분석서의 줄에 대응해야 한다. 변환 시점의 기록이므로 이후 갱신하지 않는다. 보존이 기본이며, 삭제는 허용한다(삭제 전 핵심을 결정 로그로 옮기고, 참조를 정리하고, 삭제 사실을 기록).
- **이유:** 누락은 샘플만 보아서는 보이지 않는다. 오류를 변환 단계에 가둔다.
- **상태:** 유효

### DL-SYS-013 · 내용 귀속 기준: 문장의 종류로 나눈다
- **대상:** 모든 문서 종류
- **배경:** 문서의 목적으로 나누면 템플릿·가이드·명세 사이에 내용이 겹치고 판단이 사람마다 달라진다.
- **결정:** 문장의 종류마다 집이 하나다.
  - 구조 사실(칸·열·필수 여부·값 종류·선택지·ID 형식·표 순서·완료 체크) → 템플릿
  - 절차·판단 지식(도출 절차·판단 기준·흔한 실수·칸 의미의 해설) → 가이드
  - 관계 사실(다른 단계와의 연결) → 인터페이스 표
  - 이력(결정 이유) → 결정 로그
  - 변환 증거 → 변환 분석서
  - 판별법: 기계 검사가 가능하면 구조·관계, 판단이 필요하거나 조건문("~이면")이 있으면 가이드. 템플릿 힌트는 조건 없는 한 줄 설명까지만 허용한다.
- **이유:** 목적 기준은 겹침이 구조적으로 생기고, 문장 종류 기준은 겹침을 막는다. 템플릿과 가이드를 나누는 가장 결정적인 이유는 수명이다(템플릿은 산출물로 남고 가이드는 남지 않음).
- **영향:** 규칙 문서에서 문서 종류마다 "담아도 되는 문장 종류"를 명시한다. 기존 템플릿 규칙(T2·T6)을 이 기준에 맞춰 재검토한다.
- **상태:** 유효 (DL-SYS-020이 여섯 번째 문장 종류 `절차 정의`를 추가함)

### DL-SYS-014 · 명세 문서를 두지 않고 인터페이스 표를 둔다
- **대상:** 단계 사이의 연결(관계 사실)
- **배경:** 명세를 별도 문서로 두면 구조 사실과 관계 사실이 섞이고, 같은 연결이 보내는 쪽과 받는 쪽 두 곳에 적힐 위험이 있다. 명세가 담으려던 내용 중 샘플 분류는 변환 분석서가, 필드 정의는 템플릿이 맡는다. 남는 고유 내용은 "필드의 이후 사용"뿐이었다.
- **검토한 대안:** (A) 단계마다 명세 문서 / (B) 체계 전체에 인터페이스 표 / (C) 템플릿에 "이후 사용" 열
- **결정:** (B). 필드 수준으로 한다. 연결은 한 번만 적는다. 원본은 CSV(UTF-8, 첫 줄 열 이름)이고 읽기용 문서와 템플릿의 입력·쓰이는 곳 블록은 도구가 생성한다(직접 수정 금지). 연결에는 `순행`과 `환류`를 구분한다. 환류는 뒤 단계 결과가 앞 단계 산출물을 고치게 하는 흐름이다. 템플릿의 모든 필드는 표에 소비자가 있거나 `최종 소비자 없음 + 사유`를 가져야 한다.
- **이유:** 연결의 단일 출처, 변경 영향의 양방향 추적, 필드 존재 이유의 강제.
- **영향:** 템플릿 필드에 키가 필요하다. 04번 시범 시점에는 01~03번 템플릿이 없으므로 01~03→04 연결은 문서 수준으로 두고, 해당 템플릿이 생기면 필드 수준으로 갱신한다.
- **상태:** 유효

### DL-SYS-015 · 작업은 04번 시범을 먼저 하고 한 번에 한 단계씩 진행한다
- **대상:** 진행 순서
- **결정:** 0 기록 보존 → 1 문서 체계 정의서 → 2 규칙 문서 → 3 04번 시범(변환 분석서→템플릿→가이드→인터페이스 표→결정 로그) → 4 검사 도구 → 5 도메인 교체 시험 → 6 05번부터 복제 → 7 마무리. 한 번에 다 하지 않고 단계마다 확인받는다.
- **이유:** 04번에서 규칙의 결함을 먼저 잡아야 35개 문서로 퍼지지 않는다.
- **상태:** 유효

### DL-SYS-016 · 문서 종류별 독자와 제공 범위를 정한다
- **대상:** `docs/문서_체계_정의서.md` 4절
- **결정:** 작성 에이전트는 해당 단계의 템플릿과 가이드, 이전 단계 산출물, 프로젝트 자료, 값을 채우는 규칙을 읽는다. 결정 로그·변환 분석서·샘플·인터페이스 표 원본은 기본으로 주지 않는다. 인터페이스 표는 템플릿의 생성 블록으로만 노출한다.
- **이유:** 맥락 비용과 앵커링 위험을 줄인다.

### DL-SYS-021 · 샘플은 계층 밖의 입력 자료이며 장기 삭제 대상이다
- **대상:** 샘플 전체, 정의서 7절, 중위의 샘플 규칙
- **배경:** 샘플은 특정 주제로 만들어진 것이라 공식 문서의 기준이 될 수 없다. 사용자가 샘플은 장기적으로 삭제될 것이고 공식 문서에 영향을 주어서는 안 된다고 정했다.

- **영향:** 정의서가 `00_README.md`를 가리키던 부분을 제거. 변환 분석서 규칙에 발췌 인용 요구를 추가(2단계).
