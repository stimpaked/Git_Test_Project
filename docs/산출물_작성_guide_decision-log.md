### DL-CG-001 · 길이 상한을 적용하지 않고 먼저 쓴 뒤 실제 길이를 잰다
- **날짜:** 2026-10-08
- **대상:** `docs/산출물_작성_guide.md`, `docs/규칙_가이드.md` GD-06
- **결정 주체:** 사용자 결정
- **배경:** 규칙_가이드의 잠정 상한은 공통 가이드 150줄이다(DL-GD-001). 이 상한은 근거 없이 정한 숫자였다. 공통 가이드를 쓰기 전에 사용자가 상한을 적용하지 않고 먼저 필요한 만큼 쓴 뒤 길이를 보자고 했다.
- **검토한 대안:** (a) 150줄 상한에 맞춰 쓰고 넘치는 부분을 본다 / (b) 상한을 적용하지 않고 먼저 쓴다
- **결정:** (b). 이 가이드는 빈 줄을 제외한 줄 수가 **65줄**이다(작성 시점 실측).
- **이유:** 실제로 필요한 분량을 알아야 상한의 근거가 생긴다.
- **영향:** 65줄은 잠정 상한 150줄과 비교해 상한 이내다. 04번 시범 뒤 단계 가이드의 길이와 함께 상한을 다시 본다.
- **상태:** 유효

### DL-CG-002 · 산출물 작성 가이드 v1.0 초안을 작성하고 기존 규칙의 이관을 기록한다
- **날짜:** 2026-10-08
- **대상:** `docs/산출물_작성_guide.md` (작업 순서 2단계의 마지막 문서)
- **결정 주체:** 사용자 승인 (작성 순서는 수정된 진행 순서에서 승인됨). 새로 더한 판단 기준은 DL-CG-003이 따로 다룬다.
- **배경:** 기존 O1·O2는 가이드를 쓰는 규칙이 아니라 산출물을 쓰는 절차라서 공통 가이드의 내용이라고 정했다(DL-GD-006). 규칙_가이드의 GD-08이 정한 7절 구성을 따라 쓴다.
- **검토한 대안:** 해당 없음 — 규칙_가이드가 정한 구성을 따랐다.
- **결정:** 7절(읽는 순서와 진행, 템플릿을 따라 쓰는 방법, 칸을 닫는 판단, 이전 단계 산출물을 쓰는 법, 예시와 샘플을 만났을 때, 완료 전 점검, 흔한 실수)로 쓴다. 공통 규칙(값 규칙)은 다시 쓰지 않고 적용 판단만 쓴다(GD-03). 예시는 서로 다른 두 도메인에서 가져왔다(GD-13, GD-14).
- **이유:** 규칙 문서가 정한 구성과 원칙을 지키는 첫 가이드를 만든다.
- **영향:** 기존 `템플릿_작성_규칙.md`의 이관이 O1, O2까지 끝나 `_outdated` 표시가 가능해진다(수정목록 F4). 표시 시점은 사용자에게 확인한다.
- **상태:** 유효

**이관 대응표**

| 기존 | 새 위치 |
|---|---|
| O1 (프로젝트 자료를 먼저 읽는다) | 1절 |
| O2 (한 번에 한 단계씩) | 1절 |
| O3 (샘플을 줄 때 "구조만 참고") | 5절 (작성 에이전트 쪽), 정의서 5절 (제공하는 쪽) |
| P3 (예시는 값이 아니라 형식) | 5절 |

### DL-CG-003 · 공통 가이드의 새 판단 기준을 정한다
- **날짜:** 2026-10-08
- **대상:** `docs/산출물_작성_guide.md` 1, 3, 4, 6절
- **결정 주체:** 유지보수자 판단
- **배경:** 기존 규칙에는 값을 쓸지 `미정`이나 `해당 없음`을 쓸지 고르는 판단 기준, 이전 산출물을 쓰는 법, 마무리 절차가 없었다.
- **검토한 대안:** (a) 규칙만 두고 판단은 에이전트에게 맡긴다 / (b) 판단 기준을 가이드에 쓴다
- **결정:** (b). 정한 내용: (1) 칸마다 근거 → 가정 → `미정` → `해당 없음` 순으로 판단하고, 모르는 것은 `미정`, 있을 수 없는 것은 `해당 없음`으로 구분한다. 출처 유형은 모르겠으면 더 약한 쪽을 고른다. (2) 필요한 입력이 없으면 해당 칸을 `미정`으로 닫고, 표 하나도 못 채우면 쓰기를 멈추고 알린다. (3) 이전 산출물의 `미정`은 함께 `미정`으로 닫고, 이전 산출물의 오류는 직접 고치지 않고 알린다(환류). (4) 마무리에 `미정`·`가정` 목록을 사용자에게 알린다.
- **이유:** 가이드가 항상 읽히므로 공통 규칙이 적용되는 방식을 한 번 정해 두면 단계마다 판단이 달라지지 않는다. 약한 쪽을 고르는 것은 검증되지 않은 값이 검증된 것처럼 보이는 것을 막으려는 것이다.
- **영향:** 04번 시범에서 실제로 쓰면서 어색한 기준을 조정한다.
- **상태:** 검토 대기

### DL-CG-004 · 근거 칸의 형식을 3절과 예시에 반영한다
- **날짜:** 2026-10-08
- **대상:** `docs/산출물_작성_guide.md` 3절, 5절
- **결정 주체:** 사용자 승인 (근거 형식은 DL-SD-011에서 사용자가 정함)
- **배경:** 근거 칸의 형식이 규칙_공통 CM-18로 정해졌다.
- **검토한 대안:** 해당 없음 — 규칙의 적용 방법을 옮기는 변경이다.
- **결정:** 3절의 근거 칸 설명과 5절의 근거 칸 예시를 `<출처 유형>: <문서·위치>` 형식으로 바꿨다.
- **이유:** 가이드가 규칙을 적용하는 방법을 항상 읽는 문서에 둔다는 원칙(정의서 3절)을 따른다.
- **영향:** 단계 가이드는 대상 템플릿 버전만 맞춘다.
- **상태:** 유효

### DL-CG-005 · 도메인 교체 시험에서 나온 공통 가이드 수정을 반영한다
- **날짜:** 2026-10-08
- **대상:** `docs/산출물_작성_guide.md` 2절, 3절
- **결정 주체:** 유지보수자 판단
- **배경:** 두 시험에서 2절의 "열 이름은 한 글자도 바꾸지 않는다"와 "힌트 열은 쓰지 않는다"가 부딪혔고, 쓰지 않는 선택 블록의 제목을 두는지가 불분명했으며, 입력에 언급이 없는 항목을 `해당 없음`으로 닫을지(한 시험은 닫고 다른 시험은 `미정`) 갈렸다(04번 변환 분석서 DT-02~06).
- **검토한 대안:** 해당 없음 — 문장 보완이다.
- **결정:** 속성 표의 산출물 열은 `항목 | 내용 | 근거`임을 밝혔고, 쓰지 않는 선택 블록은 제목을 두고 `[선택]`만 뺀다고 했으며, 언급이 없다는 사실만으로는 `해당 없음`이 아니라고 했고, `미정` 칸의 근거와 담당 쓰는 법을 더했다.
- **이유:** 같은 입력에서 작성자마다 다른 산출물이 나오는 곳을 줄인다.
- **영향:** 공통 가이드 v1.2.
- **상태:** 검토 대기

### DL-CG-007 · 이전 산출물이 인용한 원 자료를 쓰는 형식을 정한다
- **날짜:** 2026-10-08
- **대상:** `docs/산출물_작성_guide.md` 4절
- **결정 주체:** 유지보수자 판단
- **배경:** 재시험의 두 작성자가 03 근거 수집이 인용한 면담 메모를 근거 칸에 `내부 자료:`로 쓸지 `03 …`으로 참조할지 서로 다르게 판단했다(04번 변환 분석서 DT-09, DT-11).
- **검토한 대안:** (a) 항상 원 자료를 `내부 자료:`로 쓴다 / (b) 직접 읽은 것만 직접 인용하고 요약으로만 받았으면 이전 산출물을 참조한다
- **결정:** (b).
- **이유:** 읽지 않은 자료를 직접 읽은 것처럼 인용하면 근거 등급이 실제보다 높게 보인다(CM-11).
- **영향:** 공통 가이드 v1.4.
- **상태:** 검토 대기

### DL-CG-008 · 근거 칸을 쓰는 법을 보완한다
- **날짜:** 2026-10-08
- **대상:** `docs/산출물_작성_guide.md` 3절, 4절
- **결정 주체:** 유지보수자 판단
- **배경:** 3차 시험의 세 도메인 중 둘에서 근거 칸에 설명 문장을 `;`로 나눈 별도 조각으로 써 검사 CM-K04가 실패했다. 규칙(CM-18)에는 있었으나 가이드가 설명하지 않았다. 가정이 여러 칸일 때 근거가 길어지는 문제와 참조 뒤에 원 자료 이름을 덧붙여도 되는지도 갈렸다(04번 변환 분석서 DT-15, DT-18, DT-20).
- **검토한 대안:** 해당 없음 — 문장 보완이다.
- **결정:** `;`는 근거와 근거를 나눌 때만 쓰고 설명은 근거 뒤에 이어 쓴다고 했다. 같은 이유의 `가정`은 한 조각으로 묶어도 된다고 했다. 산출물 참조 뒤 괄호에 원 자료 이름과 날짜를 덧붙일 수 있다고 했다.
- **이유:** 검사가 잡아 주는 실수를 가이드 단계에서 줄인다.
- **영향:** 공통 가이드 v1.5.
- **상태:** 검토 대기

### DL-CG-010 · 근거 칸 `;`의 잘못된 모양과 맞는 모양을 보인다
- **날짜:** 2026-10-08
- **대상:** `docs/산출물_작성_guide.md` 3절
- **결정 주체:** 유지보수자 판단
- **배경:** 11~16번 시험에서 거의 모든 단계의 첫 검사가 근거 칸의 `;` 뒤 설명 조각으로 실패했다. 문장 규칙만으로는 놓치기 쉬웠다(11~16번 변환 분석서 DT).

- **이유:** 규칙 문장보다 모양을 비교하는 예가 작성 실수를 더 잘 막는다.
- **영향:** 공통 가이드 v1.7.
- **상태:** 검토 대기
