## 1. 템플릿이란

단계 산출물이 따르는 **빈 양식**이다(정의서 3절). 산출물은 템플릿을 복사해 채우는 것이 아니라 **템플릿의 구조를 따라 새로 쓴다**(TP-26). 읽는 사람은 작성 에이전트(항상)와 유지보수자이다.

| ID | 규칙 |
|---|---|
| TP-01 | 템플릿은 **구조 사실**만 담는다: 칸 이름, 열 순서, 값의 종류, 선택지, ID 형식, 표 순서, 완료 체크. 절차·판단 지식(조건이 있는 문장)은 가이드로, 단계 사이의 관계는 인터페이스 표로, 결정 이유는 결정 로그로 보낸다(정의서 4절). |
| TP-02 | 템플릿은 특정 서비스나 업종을 전제하는 표현을 쓰지 않는다. |

## 2. 문서 구성

템플릿은 아래 순서로 구성한다.

```
# NN. <단계 이름>

<!-- 생성 시작: 문서 정보 -->
(단계 번호·이름·목적, 입력, 이 산출물이 쓰이는 곳 — 도구가 생성한다)
<!-- 생성 끝 -->

**템플릿 변경 이력** (산출물에는 쓰지 않는다)
(표: 버전 | 날짜 | 요약 | 결정 ID)

템플릿 vX.Y · 산출물 v{{버전}} · 상태 {{상태}} · 작성일 {{YYYY-MM-DD}}

## 1. <표 제목>
> 지속 지침: <한 줄>
<!-- 표: <표 키> | 정의 ID: <접두어> -->
(표)

## 완료 체크 (NN)
- [ ] ...
```

| ID | 규칙 |
|---|---|
| TP-03 | 위 순서를 지킨다: 제목, 문서 정보(생성), 템플릿 변경 이력, 버전 줄, 본문 표들(작성 순서대로), 완료 체크. |
| TP-04 | 문서 정보 블록은 단계 정의와 인터페이스 표에서 **도구가 생성**한다. 시작·끝 표시 주석 사이는 직접 수정하지 않는다. 문서 정보는 단계 번호·이름·목적(단계 정의), 입력과 이 산출물이 쓰이는 곳(인터페이스 표)을 담는다. |
| TP-05 | 버전 줄에는 템플릿 버전과 산출물 버전, 상태, 작성일을 쓴다(공통 규칙 CM-13). 템플릿 버전은 산출물에 남아, 산출물이 어느 양식으로 만들어졌는지 알려 준다. |
| TP-06 | 템플릿의 변경 이력 표(결정 로그 규칙 DR-11)는 문서 정보 블록 아래에 둔다. 산출물에는 쓰지 않는다(TP-26). |
| TP-07 | 마지막에 **완료 체크**를 둔다. 모든 템플릿에 공통인 항목(모든 칸이 닫혔다, `{{`가 남지 않았다, 작성 지침과 선택하지 않은 블록이 정리되었다)과 그 단계의 완료 조건을 `- [ ]` 형식으로 쓴다. 산출물에서는 확인한 항목을 `[x]`로 표시하고, 확인하지 못한 항목은 `[ ]`로 남기고 사유를 쓴다. |

## 3. 지침과 자리표시

| ID | 규칙 |
|---|---|
| TP-08 | 양식 안의 지침은 두 종류다. **지속 지침**은 산출물에도 쓰는 규칙 안내다. **작성 지침**은 템플릿에서만 쓰고 산출물에는 쓰지 않는 안내다. 지속 지침은 `> 지속 지침:`, 작성 지침은 `> 작성 지침:`으로 시작하는 인용 블록으로 쓴다. |
| TP-09 | 작성 지침은 **표기 안내**(자리표시, 선택 블록, 생성 블록)에만 쓴다. 채우는 절차나 판단 기준은 쓰지 않는다. 그런 내용은 가이드의 몫이다(TP-01). |
| TP-10 | 값이 들어갈 칸은 템플릿에서 `{{칸 이름}}` 형식의 자리표시로 둔다. 산출물에는 `{{`를 쓰지 않는다. |
| TP-11 | 모든 값 표(값을 적는 표) 바로 위에 지속 지침을 한 줄 둔다: "칸은 값 / `해당 없음`(사유) / `미정`(확인처·담당·기한) 중 하나로 닫고, 근거는 `<출처 유형>: <문서·위치>` 또는 앞 항목의 ID로 쓴다 → `docs/규칙_공통.md` 3절". |

## 4. 표

| ID | 규칙 |
|---|---|
| TP-12 | 값 표는 두 형식 중 하나다. **속성 표**는 한 대상의 속성을 행으로 두며 열이 `항목 \| 힌트 \| 내용 \| 근거`다. **목록 표**는 여러 레코드를 행으로 두며 열이 필드이고 마지막 열이 `근거`다. 이것은 템플릿 기준이며, 산출물의 속성 표는 힌트 열을 뺀 `항목 \| 내용 \| 근거`다. |
| TP-13 | 목록 표는 바로 위에 **열 힌트 표**(`열 \| 힌트`)를 둔다. 열 힌트 표의 열 이름은 목록 표의 열 이름과 같다. |
| TP-14 | **힌트 열과 열 힌트 표는 템플릿에만 있고 산출물에는 쓰지 않는다.** 힌트가 필요 없을 만큼 자명하면 템플릿의 힌트 칸에 `자명함`을 쓴다(공통 규칙 CM-15). |
| TP-15 | 모든 칸은 닫아야 하므로 칸 단위의 필수/선택 구분은 없다. 선택은 블록 단위로만 한다(TP-17). 값이 없는 경우는 `해당 없음`+사유로 닫는다. |
| TP-16 | 표는 **작성 순서대로** 배열한다. 앞 표는 뒤 표에서 만드는 ID를 참조하지 않고, 뒤 표가 앞 표의 ID를 참조한다. |
| TP-17 | **선택 블록**은 템플릿에서 제목에 `[선택]`을 붙인다. 산출물에서 쓰면 `[선택]` 표시를 빼고 쓰고, 쓰지 않으면 같은 자리에 `선택하지 않음: <사유>` 한 줄을 쓴다. |

## 5. 힌트

| ID | 규칙 |
|---|---|
| TP-18 | 힌트는 **조건 없는 한 문장**이다. 조건("~이면", "~일 때")이 들어가면 가이드로 보낸다(TP-01). |
| TP-19 | 힌트는 **값의 종류**로 시작한다: `자유 서술` / `선택지` / `ID 참조` / `날짜` 등 형식을 먼저 밝힌 뒤 필요한 범위를 쓴다. |
| TP-20 | 힌트는 구체 값이 아니라 형식과 범위를 쓴다. |
| TP-21 | 닫힌 선택지는 힌트에 모두 나열한다. 선택지만 값 후보로 쓸 수 있다. |
| TP-22 | 열린 값의 예시는 서로 다른 도메인에서 여러 개를 쓰거나, 형식만 쓴다. 한 도메인의 예시만 쓰지 않는다. |
| TP-23 | 빨리 낡는 숫자(점유율·시장 규모·버전 등)는 쓰지 않는다. |

## 6. 표 키와 필드 키

인터페이스 표가 템플릿의 필드를 가리키려면 이름이 필요하다.

| ID | 규칙 |
|---|---|
| TP-24 | 모든 값 표 위에 주석으로 **표 키**와 정의 ID를 선언한다: `<!-- 표: <표 키> \| 정의 ID: <접두어> -->`. 표 키는 한 문서 안에서 유일하고 공백 없이 한글·영문·숫자·밑줄로 쓴다. 이 표가 새로 부여하는 ID가 없으면 `정의 ID: 없음`이다. |
| TP-25 | **필드 키**는 `<단계 번호>.<표 키>.<필드 이름>`이다. 속성 표의 필드 이름은 `항목` 칸의 값, 목록 표의 필드 이름은 열 이름이다. 예: `04.액터목록.유형`. 필드 키는 모든 템플릿에 걸쳐 유일하다. |

## 7. 산출물이 템플릿을 따르는 방식

| ID | 규칙 |
|---|---|
| TP-26 | 산출물은 템플릿을 **복사해 채우지 않고 참고해서 새로 쓴다**. 템플릿의 제목, 버전 줄, 값 표(표 키 주석 포함), 지속 지침, 완료 체크의 구조를 따른다. 힌트(힌트 열·열 힌트 표), 작성 지침, 자리표시, 생성 블록, 템플릿 변경 이력은 산출물에 쓰지 않는다. |
| TP-27 | 산출물의 표 순서, 표 키, 항목 이름, 열 이름은 템플릿과 **같아야** 한다. 필드 키(TP-25)가 이 이름에서 나오고 인터페이스 표가 필드 키로 연결되기 때문이다. 이름을 바꾸거나, 표를 빼거나, 순서를 바꾸지 않고, 템플릿에 없는 표나 열을 더하지 않는다. 목록 표의 행 수는 자유롭다. |
