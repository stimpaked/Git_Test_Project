## 1. 입력을 읽는 법

- **후보 풀**이 가장 중요한 입력이다. 후보를 낸 앞 단계 산출물의 후보 표를 모두 읽는다. 유저 플로우의 질문 목록, 시나리오 5유형의 추가 질문, CRUD 매트릭스·상태 전이·시간·주기·소유·권한·이벤트·화면·UI 상태·플랫폼·채널·외부 연동의 후보 표, 도메인 공통·고유의 신규 후보, 비기능·품질부터 성장·측정까지의 후보 표(방어 후보와 도구 후보 포함), 표준 카탈로그 대조의 갭 후보, 유사 서비스 대조의 갭 목록이다.
- 후보 표마다 ID 접두어와 열 이름이 다르다. 후보 ID, 후보 문장(도메인 공통·고유의 신규 후보는 `기능 후보` 열), 구분, 공통·고유(잠정), 출처 다섯 열을 찾는다. 풀의 후보를 고쳐 쓰거나 이 단계에서 새로 정의하지 않는다.
- 후보 ID는 입력의 것을 한 글자도 바꾸지 않고 옮긴다. 입력의 ID에 공백이나 괄호가 붙어 있으면 ID 형식에 맞는 부분만 칸에 쓰고 원래 표기는 근거 칸에 적는다.
- 후보 표가 한 줄 `해당 없음`으로 닫혀 있으면 그 줄은 후보가 아니다. 후보 표가 하나도 없으면 쓰기를 멈추고 알린다(공통 가이드 1절).
- **엔티티**: 용어집의 표준 용어와 사용하지 않는 동의어는 기능명을 통일하는 기준이다. 용어집에 없는 말은 표준 용어로 삼지 않는다.
- **영역·모듈**: 영역 목록의 영역(`Z-` ID, 설명, 공통·고유)과 엔티티·목표·공통 기능 배정은 기능의 영역을 정하는 기준이고, 배치 방침의 운영 기능 배치는 운영 기능을 어느 영역에 두는지의 기준이다.
- **도메인 공통·고유**: 후보 판정의 판정과 공통 기능 ID는 기능의 공통·고유와 병합 단서다. 같은 공통 기능 ID를 가리키는 후보는 한 기능으로 묶을 단서가 된다.
- 후보를 낸 단계가 병합의 단서를 따로 준다. 시간·주기의 관련 후보, 보안·어뷰징 위협 목록의 기존 방어 후보와 대응 방침(수용하거나 후속으로 미룬 위협은 방어 기능으로 합치지 않는다), 성장·측정 성장 지점의 현재 대응과 후보의 유형(성장 기능과 측정 기능은 합치지 않는다), 유사 서비스 대조의 후보, 표준 카탈로그 대조의 공통 기능과 환류 대상이다. 이벤트의 알림·로그·분석·후속 처리 칸과 비기능·품질 요구 목록의 처리 칸은 후보가 풀에 합류했는지 대조하는 데 읽는다.
- 범위·제약은 이 단계의 입력이 아니다. 풀의 후보가 범위·제약의 제외 항목과 같아 보여도 이 단계가 범위를 판정하지 않는다(5절).
- 판단의 재료는 후보 문장이다. 읽히는 만큼만 같은 기능인지 판단하고 읽히지 않는 것을 그럴 것이라고 채우지 않는다.

## 2. 작성 절차

1. 후보 표를 모두 찾아 표마다 후보 ID가 있는 행의 수를 센다.
2. 구분이 설계 기준이나 프로세스인 후보를 제외 목록에 후보마다 한 행씩 쓴다. ID는 `FE-001`부터 부여한다.
3. 남은 후보의 문장에서 용어집의 사용하지 않는 동의어를 찾아 용어 정리에 쓴다.
4. 남은 후보를 구분, 영역, 공통·고유로 먼저 가른 뒤 그 안에서 같은 목표와 대상과 동작의 후보를 묶어 기능 목록에 쓴다. ID는 `FN-001`부터 부여한다.
5. 표별 소진을 쓰고 후보 수를 맞춘다. 집계를 세고 4절의 누락 점검과 완료 체크를 확인한다.

## 3. 항목별 해설

<!-- 해설: 제외목록 -->
### 3.1 제외 목록

- **한 행은 기능 목록에 넣지 않는 후보 하나**다. 대상은 구분이 설계 기준이나 프로세스인 후보뿐이다. 입력의 구분을 바꾸지 않는다. 기능 후보나 후속 후보인데 기능이 아닌 것처럼 보이면 제외하지 않고 기능 목록에 두고 근거에 그 의심을 쓴 뒤 사용자에게 알린다.
- **후보 ID**는 입력의 표기 그대로 하나만 쓴다. **후보 문장**은 입력의 문장을 줄이거나 고치지 않고 그대로 옮긴다.
- **구분**은 입력 후보의 구분을 그대로 옮긴다.
- **사유**는 기능이 아닌 이유와 이 후보를 대신 다루는 곳을 한 문장으로 쓴다. 입력 ID만 쓰지 않고 그 ID가 말하는 내용을 문장으로 쓴다. 설계 기준이면 어느 기준을 다루는 앞 단계 산출물의 항목에서 관리하는지, 프로세스이면 코드로 만들지 않는 절차이고 누가 어디서 하는지를 쓴다. 대신 다루는 곳을 모르면 아는 이유에 `미정`(확인처·담당·기한)을 이어 쓴다.
- **근거**는 후보 ID로 시작한다. 구분을 정한 앞 단계의 행과 사유를 확인한 산출물의 위치를 이어 쓴다.
- 예시(형식 시연, 값이 아님): 스마트 온실 모니터링 서비스라면 "측정값은 서버 기준 시각으로 기록한다"는 설계 기준이라 사유는 `기능이 아니라 모든 기록에 적용하는 규칙이며 품질 요구 목록의 시각 기준 요구에서 관리한다`처럼 쓴다. 병원 예약 서비스라면 "개인정보 처리 위탁 계약을 갱신한다"는 프로세스라 사유는 `코드로 만들지 않는 법무 절차이며 규제 매핑의 법무 확인 사항에서 관리한다`처럼 쓴다.
- 제외할 후보가 하나도 없으면 한 줄만 쓴다. ID 칸에는 `FE-001`을 쓰고 나머지 칸은 `해당 없음`과 같은 사유(풀에 구분이 설계 기준이나 프로세스인 후보가 없다)로 닫으며 근거에는 훑은 후보 표의 이름을 쓴다.

<!-- 해설: 용어정리 -->
### 3.2 용어 정리

- **한 행은 표준 용어와 그것으로 바꾼 말의 쌍 하나**다. 용어집의 사용하지 않는 동의어 칸에 있는 말이 후보 문장에 쓰였을 때만 행을 쓴다.
- **표준 용어**는 용어집의 표현을 그대로 쓴다. **바꾼 말**은 후보 문장에서 찾은 말 하나다.
- **나온 후보**는 그 말이 쓰인 후보의 ID를 하나씩 쉼표로 쓴다. 범위 표기(`~`)를 쓰지 않는다. 제외 목록에 쓴 후보도 포함한다.
- 후보 문장은 고치지 않는다. 기능명과 설명에서 표준 용어를 쓰는 것이 이 표의 결과다.
- 용어집에 없는 말은 두 말이 같은 뜻처럼 보여도 바꾸지 않고 행으로 쓰지 않는다. 그런 쌍은 사용자에게 알려 용어집을 보완하게 한다.
- **근거**는 용어집에서 표준 용어와 사용하지 않는 동의어를 확인한 위치로 시작한다.
- 예시(형식 시연, 값이 아님): 병원 예약 서비스라면 표준 용어 `진료`, 바꾼 말 `상담`처럼 쓴다. 어린이 독서 앱이라면 표준 용어 `독서 기록`, 바꾼 말 `읽은 책 메모`처럼 쓴다.
- 바꿀 말이 하나도 없으면 한 줄만 쓴다. 표준 용어 칸에 `해당 없음`과 사유(용어집의 사용하지 않는 동의어가 후보 문장에 없다)를 쓰고 나머지 칸도 같은 사유로 닫으며 근거에는 훑은 용어집의 위치를 쓴다.

<!-- 해설: 기능목록 -->
### 3.3 기능 목록

- **한 행은 후보를 병합한 기능 하나**다. 모든 후보는 한 번만 나온다. 후보 없이 기능을 만들지 않는다.
- **병합 기준**은 같은 목표, 같은 대상, 같은 동작이다. 이름이 달라도 사용자나 운영자가 얻는 결과가 같으면 같은 동작이다. 쓰는 사람과 목표가 다른 후보(사용자가 하는 일과 운영자가 그 결과를 처리하는 일)는 합치지 않는다.
- **입도가 갈리면 합치지 않는다.** 나뉜 기능은 역추적 검증 단계에서 합칠 수 있지만 합친 기능은 근거를 잃는다. 아래 중 하나라도 맞으면 후보를 합치지 않는다.
  - 구분이 다르다(기능 후보와 후속 후보).
  - 영역이 다르다.
  - 공통·고유가 다르다. 도메인 공통·고유의 판정이 혼합인 후보도 다른 후보와 합치지 않는다.
  - 도메인 공통·고유 후보 판정이 서로 다른 공통 기능을 가리킨다.
  - 우선순위를 따로 매기거나 따로 테스트할 수 있다.
- **합치는 단서**: 같은 공통 기능 ID를 가리키는 후보, 관련 후보나 기존 방어 후보나 현재 대응이 가리키는 후보다. 같은 후보가 갭 후보와 환류 대상 표에 둘 다 있으면 후보 ID가 다르므로 둘 다 한 기능의 병합 후보에 쓴다. 대상 종류만 다르고 설정으로 구분되는 후보는 합치고 종류를 설명에 쓴다.
- **ID**는 임시 번호다. 지운 번호는 다시 쓰지 않고, 계층·ID·태그 단계가 대응을 남긴 뒤에는 번호를 바꾸지 않는다.
- **기능명**은 대상과 동작으로 쓰고 용어집의 표준 용어를 쓴다. 기간, 횟수, 한도, 주기 같은 정책 값은 기능명에 넣지 않고 후보 문장에 있는 값만 설명에 쓴다. 이름이 동작을 셋 이상 나열하면 합친 입도가 큰지 다시 본다. 같은 기능명을 두 행에 쓰지 않는다.
- **설명**은 병합한 후보에서 읽히는 만큼 이 기능이 하는 일과 범위를 한 문장으로 쓴다. 후보에 없는 동작을 더하지 않는다.
- **영역**은 아래 순서로 따지고 먼저 답이 나오는 쪽을 쓴다. (1) 운영 기능은 배치 방침을 따른다. (2) 판정이 공통이고 공통 기능 ID가 달린 후보는 공통 기능 배정을 따른다. (3) 기능이 다루는 대상의 책임 영역(엔티티 배정). (4) 후보가 나온 목표의 영역(목표 배정). 판정이 혼합인 후보는 (3)부터 따진다. 대상이 두 영역에 걸치면 주된 대상의 영역을 쓰고 다른 영역은 근거에 쓴다. 영역 목록의 `Z-` ID를 쓴다.
- **공통·고유**는 병합한 후보의 도메인 공통·고유 후보 판정을 따른다. 후보 판정에 없으면 후보 표의 잠정 값을 쓰고 근거에 밝힌다. 판정이 혼합인 후보는 `고유`로 쓰고 근거에 혼합 판정과 공통 기능 ID를 쓴다. 영역 목록의 공통·고유와 어긋나면 근거에 쓴다.
- **구분**은 후보의 구분이 기능 후보이면 `기능`, 후속 후보이면 `후속`이다.
- **병합 후보**는 합친 후보의 ID를 입력의 표기 그대로 하나씩 쉼표로 쓴다. 범위 표기(`~`)나 줄임(`…`)을 쓰지 않는다. 후보 문장이 `미정`인 후보는 다른 후보와 합치지 않고 그 후보 하나로 행을 만들며 기능명과 설명을 `미정`(확인처: 그 후보를 낸 앞 단계 담당 역할)으로 닫는다.
- **근거**는 병합 후보의 ID로 시작하는 조각(같은 목표·대상·동작이라 본 이유), 영역 ID로 시작하는 조각, `20 도메인 공통·고유 2번 표` 같은 참조 조각을 `;`로 나눠 쓴다. 규제나 정책 후보에서 온 병합이면 그 후보의 출처를 인용한다.
- 예시(형식 시연, 값이 아님): 병원 예약 서비스라면 근거는 `FQ-004, FQ-021, 예약 시간을 바꾸는 같은 동작; Z-02, 대상 엔티티의 책임 영역; 20 도메인 공통·고유 2번 표, 판정이 고유`처럼 쓴다. 사내 휴가 신청 도구라면 `HQ-003, CF-009, 신청서를 되돌리는 같은 동작`처럼 쓴다.
- 예시(형식 시연, 값이 아님): 어린이 독서 앱의 "독서 목표 달성 알림"은 여러 영역이 쓰는 알림 발송 후보와 공통·고유가 다르므로 합치지 않고 별도 행으로 쓴다.

<!-- 해설: 표별소진 -->
### 3.4 표별 소진

- **한 행은 후보 표 하나**다. 표 칸은 `NN.표 키` 모양으로 쓰고, 후보를 낸 앞 단계 산출물의 후보 표를 하나도 빠뜨리지 않는다.
- **후보 수**는 후보 ID가 있는 행의 수다. 한 줄 `해당 없음`으로 닫은 표는 0이다. **기능 병합 수**와 **기능 아님 수**는 그 표의 후보 ID가 기능 목록의 병합 후보와 제외 목록에 나오는 횟수를 센다. 세 수는 후보 수 = 기능 병합 수 + 기능 아님 수가 되어야 한다.
- 맞지 않으면 후보가 빠졌거나 두 번 쓰였으므로 기능 목록과 제외 목록을 고친다. 수를 맞추려고 후보를 만들거나 지우지 않는다.
- **근거**는 후보를 낸 앞 단계 산출물 이름과 표 위치(`NN <산출물 이름> N번 표`)로 시작한다.

### 3.5 집계

- 숫자는 표의 행을 세어 쓴다. 근거는 센 표를 가리키는 참조(`31 통합·정규화 3번 표`처럼 `NN 산출물 이름`)로 시작한다.
- 입력 후보 수는 표별 소진의 후보 수의 합이다. 합계는 기능 아님 후보 수와 병합된 후보 수의 합이며 입력 후보 수와 같아야 한다. 다르면 행이 빠졌거나 두 번 적혔다.
- 병합된 후보 수는 기능 목록의 병합 후보에 쓴 ID의 총 수다. 기능 수는 기능 목록의 행 수다. 후속 기능 수, 공통 기능 수, 고유 기능 수는 해당 칸의 행을 센다.
- 후보 하나인 기능 수와 최대 병합 후보 수는 입도를 점검하는 값이다. 최대 병합 후보 수의 근거에는 그 기능의 ID를 쓴다.
- 기능이 없는 영역 수는 영역 목록의 영역마다 기능 목록의 영역 칸에 나오는지 확인해 센다. 0이어도 `0`을 쓴다.

## 4. 누락 점검

- 후보를 낸 앞 단계마다 후보 표를 훑었는가. 표별 소진에 한 행씩 있는가.
- 후보 ID가 제외 목록과 기능 목록의 병합 후보 가운데 정확히 한 곳에 한 번만 나오는가. 범위 표기나 줄임이 있는가.
- 구분이 설계 기준이나 프로세스인 후보가 기능 목록에 섞이지 않았는가. 후속 후보가 기능 후보와 합쳐지지 않았는가.
- 영역 목록의 영역마다 기능이 있는가. 기능이 없는 영역은 영역 정의의 문제인지 그 영역의 후보가 풀에서 빠진 것인지 사용자에게 알린다.
- 영역에 사용자가 처음부터 끝까지 따라가는 정상 경로의 기능이 후보로 하나도 없어 보이면 이 단계에서 기능을 만들지 않고 사용자에게 알린다. 후보를 내는 앞 단계의 일이다.
- 도메인 공통·고유의 공통 기능마다 그것을 가리키는 후보가 어느 기능의 병합 후보에 들어 있는가. 가리키는 후보가 모두 설계 기준이나 프로세스라 제외 목록에 있으면 그 공통 기능을 구현하는 기능이 없는 것이므로 기능을 만들지 않고 사용자에게 알린다.
- 이벤트의 알림·로그·분석·후속 처리 칸에 쓴 소비 기능이 기능 목록에 대응하는 행을 갖는가.
- 최대 병합 후보 수의 기능과 이름이 동작을 셋 이상 나열한 기능을 나누어 볼 수 있는가. 나눌 수 있으면 나눈다.
- 용어집의 사용하지 않는 동의어가 기능명에 남아 있지 않은가. 같은 기능명이 두 번 나오지 않는가.

## 5. `미정`·`해당 없음` 판단

- **선택지 칸, ID 칸, 숫자 칸**: 값을 모르면 추측하지 않고 `미정`(확인처·담당·기한)으로 닫는다. 칸의 일부만 알면 아는 값에 `미정`을 이어 쓴다.
- **영역**: 영역 목록이 없거나 엔티티·목표·공통 기능 배정으로 정할 수 없으면 `미정`(확인처: 영역·모듈 담당 역할)이다. 영역을 추측해 채우지 않는다.
- **공통·고유**: 도메인 공통·고유 후보 판정과 후보 표의 잠정 값이 모두 없을 때만 `미정`이다.
- **구분과 제외 목록의 구분**은 입력 후보의 구분을 옮기므로 `미정`을 쓰지 않는다.
- **병합 후보**는 `미정`이나 `해당 없음`으로 닫지 않는다. 후보가 없는 기능은 만들지 않는다.
- **기능명과 설명**은 후보 문장이 `미정`일 때만 `미정`이다.
- **용어 정리**: 용어집이 `미정`이면 한 줄을 `미정`(확인처: 엔티티 담당 역할)으로 닫는다. 용어집이 있고 바꿀 말이 없을 때만 `해당 없음`을 쓴다. 입력에 언급이 없다는 사실만으로 `해당 없음`을 쓰지 않는다.
- **제외 목록**: 구분이 설계 기준이나 프로세스인 후보가 풀에 없을 때만 한 줄 `해당 없음`이다.
- **범위 판정**: 풀의 기능 후보가 범위·제약의 제외 항목과 같아 보이면 제외 목록에 넣지 않고 기능 목록에 둔 채 근거에 어긋남을 쓰고 사용자에게 알린다.

## 6. 흔한 실수

- 후보 표를 일부만 읽고 후보 수를 센다. 표별 소진을 쓰지 않는다.
- 후보 ID를 `Q-001~Q-007`처럼 범위로 쓰거나 줄이거나 입력의 표기를 바꾼다.
- 설계 기준이나 프로세스 후보를 기능으로 만든다. 입력의 구분을 마음대로 바꿔 후보를 제외한다.
- 입도가 갈리는데 합친다. 구분, 영역, 공통·고유가 다른 후보를 한 기능에 넣는다.
- 후보 없이 기능을 만들거나 후보 문장에 없는 동작을 설명에 더한다.
- 기간이나 횟수 같은 정책 값을 기능명에 넣는다. 기능명에 동작을 여럿 나열한다.
- 용어집에 없는 동의어를 새 표준 용어로 정한다. 후보 문장을 표준 용어로 고쳐 쓴다.
- 영역을 추측하거나 영역 목록에 없는 말로 쓴다.
- 근거 칸을 설명으로 시작한다. 맞는 모양은 `내부 자료: 요구사항 메모 2절, 입력에 언급 없음`처럼 쉼표로 이어 쓰는 것이다.
- 샘플이나 예시의 기능 이름과 후보 ID를 값으로 옮긴다.
