## 1. 입력을 읽는 법

- **근거 수집**이 가장 중요한 입력이다. 비교 기능은 대조표와 기능 성격 표의 행을 정하고, 유사 서비스는 제공 서비스의 서비스 ID와 확인 한계를 준다. 기능별 제공 현황의 제공 여부와 차이는 제공 현황의 재료이고, 사용자 조사의 인사이트(종류, 빈도, 영향 영역)는 인사이트 대조의 행이며 성격의 근거다. 우리 범위의 기능 목록에서 거꾸로 행을 만들지 않는다.
- **범위·제약**: 포함·제외·후속 목록은 닫힌 목록이고 판정의 기준이다. 결정 규칙은 유사 서비스에만 있는 기능을 범위에 둘지 가리는 기준이다. 제외와 후속 항목의 사유와 재검토 조건은 판정의 사유와 재검토 조건의 출처다.
- **후보 풀**: 후보를 낸 앞 단계 산출물의 후보 표를 모두 읽는다. 후보 표마다 ID 접두어와 열 이름이 다르므로 후보 ID, 후보 문장, 구분 세 열을 찾는다. 도메인 공통·고유 단계가 새로 올린 후보와 표준 카탈로그 대조의 갭 목록도 풀의 일부다. 풀의 후보를 고쳐 쓰거나 이 단계에서 새로 정의하지 않는다.
- 후보 ID는 입력의 것을 한 글자도 바꾸지 않고 옮긴다. 입력의 ID에 공백이나 괄호가 붙어 있으면 ID 형식에 맞는 부분만 칸에 쓰고 원래 표기는 근거 칸에 적는다.
- 판정의 재료는 후보 문장이다. 읽히는 만큼만 기능의 일치를 판단하고, 읽히지 않는 것을 그럴 것이라고 채우지 않는다.
- 유사 서비스의 기능 제공 여부, 서비스 이름, 사용자의 말을 입력에 없이 만들어 쓰지 않는다.
- 근거 수집의 유사 서비스·비교 기능 표가 `미정`이면 외부 기준이 없다. 5절을 따른다. 후보 표가 하나도 없으면 쓰기를 멈추고 알린다(공통 가이드 1절).

## 2. 작성 절차

1. 근거 수집의 비교 기능을 위에서 아래로 훑어 대조표에 행을 만든다. ID는 `CP-01`부터 부여한다.
2. 비교 기능마다 후보 풀을 훑어 기능을 다루는 후보를 찾고, 범위·제약의 제외·후속 목록과 맞대어 판정을 닫는다.
3. 같은 비교 기능으로 기능 성격 표에 행을 쓴다. 제공 서비스, 제공 현황, 사용자 조사를 먼저 쓰고 분류 근거와 성격을 닫는다.
4. 근거 수집의 인사이트마다 인사이트 대조에 행을 쓴다.
5. 판정이 갭이거나 풀에 후보가 없는 후속인 행마다 갭 목록에 후보를 올린다. ID는 `CPG-01`부터 부여한다.
6. 집계를 세고 입력 수와 맞춘다. 4절의 누락 점검을 하고 완료 체크를 확인한다.

## 3. 항목별 해설

<!-- 해설: 대조표 -->
### 3.1 대조표

- **한 행은 비교 기능 하나의 판정 하나**다. 기능과 서비스를 곱한 행을 만들지 않는다. 서비스별 제공 여부는 기능 성격 표가 요약한다.
- **비교 기능**은 근거 수집의 `MF-` ID 하나다. 기능 이름을 다시 쓰지 않는다. 비교 기능이 모두 한 번씩 나와야 한다.
- **후보**는 풀에서 이 기능을 다루는 후보의 ID다. 이름이 달라도 사용자가 얻는 것이 같으면 같은 기능으로 본다. 항목의 일부만 덮으면 판정을 `채택`으로 쓰고 덮는 부분을 근거에, 덮지 못한 부분을 갭 목록의 후보로 올린다(29번과 같다). 풀의 후보가 이름이나 영역만 닮고 같은 기능인지 갈리면 `갭`으로 쓰고 닮은 후보의 ID를 근거의 첫 조각에 쓴다. 풀을 모두 훑었는데 없으면 `해당 없음`(사유: 훑은 후보 표의 이름)이다.
- **판정**은 하나만 고른다. 아래 순서로 따지고 먼저 답이 나오는 쪽을 쓴다.
  1. 범위·제약의 제외 목록에 같은 기능이 있다. `제외`다.
  2. 풀에 후보가 있다. 후보의 구분이 모두 후속 후보이면 `후속`, 하나라도 기능 후보·설계 기준·프로세스이면 `채택`이다.
  3. 풀에 후보가 없고 후속 목록에 같은 기능이 있다. `후속`이다.
  4. 풀에도 제외·후속 목록에도 없다. `갭`이다.
  제외·후속 목록과 풀이 어긋나면(후속 목록의 기능이 풀에 기능 후보로 있는 경우) 범위·제약의 목록을 따르고 어긋남을 근거에 쓴다. 제외 목록을 읽을 수 없거나 근거가 없어 판정을 못 하면 5절을 따른다.
- 갭은 근거 수집이 확인한 범위 안에서만 찾는다. 갭을 쓸 때와 갭이 하나도 없을 때 근거에 근거 수집의 확인 한계를 가리켜, 확인하지 못한 범위에는 누락이 남아 있을 수 있음을 밝힌다.
- **범위 항목**은 포함 `OI-`, 제외 `OX-`, 후속 `OL-` 항목 가운데 이 기능에 해당하는 ID다. 근거 수집이 적은 값을 옮기되 범위·제약의 목록에서 직접 확인한다. 목록을 확인했는데 같은 기능이 없으면 `해당 없음`(사유: 확인한 목록)이다.
- **사유**는 판정의 이유를 한 문장으로 쓴다. 입력 ID만 쓰지 않고 그 ID가 말하는 내용을 문장으로 쓴다. 채택도 이유를 쓴다.
- **재검토 조건**은 판정을 다시 따지게 되는 사건이나 지표의 상태다. 제외와 후속 행은 반드시 값이거나 `미정`(확인처·담당·기한)이고 `해당 없음`을 쓰지 않는다. 범위·제약의 해당 항목에 재검토 조건이 있으면 그것을 옮긴다. 채택과 갭 행은 `해당 없음`(사유: 채택은 재검토 조건을 두지 않는다)으로 닫아도 된다.
- **근거**는 판정을 정한 후보 ID와 범위·제약 항목 ID로 시작하는 조각, 출처 유형으로 시작하는 조각을 `;`로 나눠 쓴다.
- 예시(형식 시연, 값이 아님): 병원 예약 서비스라면 근거는 `MF-03, 유사 서비스 둘이 제공; QC-004, 같은 알림을 다룬다; OX-02, 제외 목록의 같은 항목`처럼 조각마다 ID로 시작한다. 사내 휴가 신청 도구라면 `내부 자료: 범위 메모 2절, 후속으로 미룬다고 적혀 있다`처럼 쓴다.

<!-- 해설: 기능성격 -->
### 3.2 기능 성격

- 행 하나는 비교 기능 하나다. 대조표와 같은 기능을 같은 순서로 쓴다. 판정이 제외나 후속인 기능도 성격을 쓴다.
- **제공 서비스**는 근거 수집의 기능별 제공 현황에서 `제공`이나 `일부 제공`인 유사 서비스의 `MS-` ID를 쉼표로 쓴다. 확인하지 못한 칸이 있으면 아는 ID에 `미정`을 이어 쓴다.
- **제공 현황**은 제공하는 서비스 수와 확인한 서비스 수, 일부 제공의 범위를 한 문장으로 쓴다. 근거 수집의 차이 칸을 옮기고 새 사실을 더하지 않는다.
- **사용자 조사**는 이 기능이 있을 때나 없을 때 사용자가 느끼는 바를 말한 인사이트의 `MI-` ID다. 영향 영역이 이 기능을 가리키거나 문장이 이 기능이 푸는 일을 말하는 것만 쓴다. 없으면 `해당 없음`(사유: 영향 영역이 이 기능을 가리키는 인사이트가 없다)이다. 사용자 조사가 `미정`이면 `미정`이다.
- **분류 근거**는 성격을 무엇으로 가렸는지다. 제공 서비스와 제공 현황이 값이면 `제공 현황`, 인사이트가 값이면 `사용자 조사`, 둘 다 값이면 `둘 다`다. 둘 다 없으면 `미정`이다.
- **성격**은 사용자가 이 기능에 반응하는 방식이다.
  - `기본`: 없으면 불만이 크고 있어도 만족이 늘지 않는다. 확인한 서비스 대부분이 제공하거나, 인사이트가 없어서 이탈하거나 불안했다고 말한다.
  - `기대`: 있고 나을수록 만족한다. 일부 서비스가 제공하고 서비스마다 범위나 수준이 다르거나, 인사이트가 바라는 모습으로 말한다.
  - `매력`: 없어도 불만은 없으나 있으면 만족이 크게 는다. 인사이트의 기대·욕구가 근거에 있어야 쓴다. 제공하는 서비스가 적다는 사실만으로 매력이라 하지 않는다.
- `대부분`과 `일부`의 숫자 기준은 확인한 서비스 수에 따라 달라 이 가이드가 정하지 않는다. 몇 곳 중 몇 곳인지와 그렇게 가른 이유를 근거에 쓴다. 확인한 서비스가 하나뿐이면 비율로 가를 수 없으므로 제공 현황만으로는 `미정`이다.
- 제공 현황과 인사이트가 서로 다른 성격을 가리키거나 조사 대상 역할마다 갈리면 `미정`(확인처: 사용자 조사 담당)이다. 모든 서비스가 법령 때문에 제공하는 기능은 근거에 그 규제 항목 ID를 쓰고 제공 현황만으로 `기본`이라 단정하지 않는다.
- **근거**는 비교 기능 ID와 인사이트 ID로 시작하는 조각을 `;`로 나눠 쓴다.
- 예시(형식 시연, 값이 아님): 병원 예약 서비스라면 근거는 `MF-02, 확인한 서비스 3곳 중 3곳 제공; MI-04, 없으면 예약을 포기한다고 말함`이고 성격은 `기본`이다. 어린이 독서 앱이라면 `MF-05, 확인한 서비스 4곳 중 1곳 제공; MI-07, 있으면 좋겠다고 말함`이고 분류 근거는 `둘 다`, 성격은 `매력`이다.

<!-- 해설: 인사이트대조 -->
### 3.3 인사이트 대조

- 행 하나는 인사이트 하나다. 근거 수집의 사용자 조사 행을 모두 쓴다.
- **후보**는 풀에서 인사이트가 말하는 불편·위험·기대를 푸는 후보의 ID다. 인사이트의 문장은 해법이 아니므로 후보가 그 불편이나 기대를 실제로 다루는지 영향 영역과 함께 읽고 판단한다. 없으면 `해당 없음`(사유: 훑은 후보 표의 이름)이다.
- **판정, 범위 항목, 사유, 재검토 조건, 근거**는 대조표와 같은 순서와 기준으로 쓴다. 인사이트와 같은 기능이 제외 목록에 있으면 `제외`다.
- 종류가 `현재 방식`이나 `사실 정보`이고 기능으로 풀 불편이나 기대가 문장에 없으면 판정을 `해당 없음`(사유: 종류와 기능으로 이어질 불편이 없다는 것)으로 닫는다. 종류가 `현재 방식`이나 `사실 정보`라도 문장 안에 기능으로 풀 요구(수신자가 여럿이다, 열람 방식을 아직 모른다 등)가 담겨 있으면 `해당 없음`으로 닫지 않고 채택이나 갭으로 판정하며 근거에 그 요구를 쓴다. 종류가 불편·위험, 이탈 계기, 기대·욕구이면 이 사유를 쓰지 않고 판정한다.
- 갭이면 갭 목록에 후보를 올린다. 출처에 이 인사이트의 ID를 쓴다.
- 예시(형식 시연, 값이 아님): 사내 휴가 신청 도구라면 "잔여 일수를 몰라 신청을 미룬다"는 인사이트에 잔여 일수를 보여 주는 후보가 있으면 판정은 `채택`이다. 어린이 독서 앱이라면 보호자가 기록을 볼 수 없어 불안하다는 인사이트에 후보가 없고 제외 목록에도 없으면 `갭`이다.

<!-- 해설: 갭목록 -->
### 3.4 갭 목록

- 후보를 풀로 돌려보내는 표다. 판정이 갭인 대조표 행과 인사이트 대조 행, 풀에 후보가 없는 후속 행에서 후보를 올린다. 판정이 채택이나 제외인 행에서는 올리지 않는다. 같은 기능을 여러 행이 요구하면 후보 하나에 출처를 쉼표로 모은다.
- **후보 문장**은 해법을 정하지 않고 무엇을 정의해야 하는지 한 문장으로 쓴다. 비교 기능의 이름을 사용자 관점으로 풀어 쓰고 유사 서비스의 이름과 고유 용어를 쓰지 않는다.
- **구분**은 이렇게 고른다.
  - `기능 후보`: 이번 범위에서 정의가 필요한 기능이다. 판정이 갭인 행의 후보는 이것을 기본으로 한다.
  - `후속 후보`: 풀에 후보가 없는 후속 행에서 나온 기능이다. 근거에 후속 목록 ID를 쓴다.
  - `설계 기준`: 여러 기능이 따라야 하는 규칙이다.
  - `프로세스`: 코드로 만들지 않는 절차다.
  구분을 고르기 어려우면 `미정`을 쓰지 않고 `기능 후보`를 쓴다.
- **공통·고유(잠정)**는 서비스 종류를 바꿔도 필요한 기능이면 `공통`, 이 서비스의 업무에서만 나오면 `고유`다. 갈리면 `고유`를 고른다. 후보 문장으로 가를 근거가 없으면 `미정`(확인처·담당·기한)이다.
- **출처**는 후보가 나온 대조표의 `CP-`와 인사이트 대조의 `MI-`를 쉼표로 쓴다.
- **성격**은 출처가 대조표 행이면 기능 성격 표의 같은 기능의 성격을 그대로 옮긴다. 출처가 인사이트뿐이면 기능 성격 표에 행이 없으므로 `미정`(확인처: 사용자 조사 담당)이다.
- **근거**는 출처 행의 ID로 시작하고 후보 풀에서 찾지 못한 사실을 이어 쓴다. 풀을 훑은 후보 표의 이름을 쓴다.
- 풀이나 표준 카탈로그 대조의 갭 목록에 같은 기능이 이미 있으면 새 후보로 올리지 않는다. 그 행의 판정은 `채택`이고 후보 칸에 그 ID를 쓴다.
- 올릴 후보가 하나도 없으면 한 줄만 쓴다. ID 칸에는 `CPG-01`을 쓰고 나머지 칸은 `해당 없음`과 같은 사유(판정이 갭인 행도 풀에 후보가 없는 후속 행도 없다)로 닫으며 근거에는 점검한 표를 쓴다.
- 예시(형식 시연, 값이 아님): 병원 예약 서비스라면 "예약 전에 대기 순번을 알려 준다"를 `기능 후보`, `고유`로 올린다. 사내 휴가 신청 도구라면 후속 목록의 "대리 승인"에 풀의 후보가 없을 때 `후속 후보`로 올리고 근거에 후속 목록의 ID를 쓴다.

### 3.5 집계

- 숫자는 표의 행을 세어 쓴다. 근거는 센 표를 가리키는 참조(`30 유사 서비스 대조 1번 표`처럼 `NN 산출물 이름`)로 시작한다.
- 입력 비교 기능 수는 근거 수집의 비교 기능 표의 행 수다. 근거에 `03 근거 수집`의 표를 가리킨다.
- 판정 미정 수는 판정 칸이 `미정`인 행의 수다. 0이어도 `0`을 쓴다. 성격 미정 수도 같다.
- 합계는 채택, 후속, 제외, 갭, 판정 미정의 합이고 입력 비교 기능 수와 같아야 한다. 성격 네 수의 합도 입력 비교 기능 수와 같아야 한다. 다르면 행이 빠졌거나 두 번 적혔으므로 표를 고친다.
- 갭 판정 수에는 인사이트 대조의 갭을 더하지 않는다. 인사이트 대조의 개수는 이 표에 두지 않는다.

## 4. 누락 점검

- 근거 수집의 비교 기능과 인사이트가 모두 한 번씩 나오는가. 표마다 행 수를 맞춰 보았는가.
- 후보 풀의 후보 표를 모두 훑었는가. 후보를 낸 앞 단계 산출물마다 훑었는지 확인한다.
- 이름이 달라서 같은 기능을 풀에서 놓치고 갭으로 쓰지 않았는가.
- 제외와 후속 행마다 사유와 재검토 조건이 값이거나 `미정`인가. 범위·제약의 항목 ID를 가리키는가.
- 성격이 값인 행마다 분류 근거가 값이고, 매력에 인사이트가 있는가.
- 판정이 갭이거나 풀에 후보가 없는 후속인 행이 모두 갭 목록에 후보를 가지는가.
- 근거 수집의 확인 한계에 걸리는 범위를 갭이 없다는 근거로 쓰지 않았는가.

## 5. `미정`·`해당 없음` 판단

- **외부 기준이 없을 때**: 근거 수집의 유사 서비스나 비교 기능 표가 `미정`이면 대조표를 한 줄로 닫는다. ID 칸에는 `CP-01`을 쓰고 나머지 칸은 모두 `미정`(확인처: 근거 수집 담당 역할)이며 근거에 근거 수집의 해당 표를 쓴다. 기능 성격과 집계의 칸도 같게 닫고 갭 목록은 한 줄 `해당 없음`으로 닫는다. 서비스를 지어내지 않는다.
- **사용자 조사가 없을 때**: 근거 수집의 사용자 조사가 `미정`이면 인사이트 대조를 한 줄 `미정`으로 닫는다. 기능 성격의 사용자 조사 칸도 `미정`이고 성격은 제공 현황만으로 가린다.
- **판정**: 풀에 후보가 없고 범위·제약의 제외·후속 목록을 읽을 수 없으면 갭인지 제외인지 알 수 없으므로 `미정`(확인처: 범위·제약 담당 역할)이다. 입력에 언급이 없다는 사실만으로 `제외`나 `해당 없음`을 쓰지 않는다.
- **제외**: 범위·제약의 제외 목록 항목을 가리키지 못하면 `제외`를 쓰지 않는다. 판정을 `미정`으로 닫고 확인처에 제외 목록 담당을 쓴다.
- **재검토 조건**: 제외와 후속 행에 `해당 없음`을 쓰지 않는다. 조건을 모르면 `미정`(확인처: 범위·제약 담당 역할)이다.
- **성격**: 성격이 `미정`이면 분류 근거도 `미정`이다. 제공 현황과 인사이트가 있어도 성격을 가를 수 없으면 둘 다 `미정`으로 닫고 근거에 가를 수 없는 이유를 쓴다. 칸의 일부만 알면 아는 값에 `미정`을 이어 쓴다.
- **선택지 칸, ID 칸, 숫자 칸**: 값을 모르면 추측하지 않고 `미정`(확인처·담당·기한)으로 닫는다. 구분은 `미정`을 쓰지 않고 `기능 후보`를 쓴다.
- **`해당 없음`**: 후보 칸은 풀에서 못 찾았을 때, 범위 항목 칸은 확인한 목록에 없을 때, 인사이트 판정은 기능으로 이어지지 않는 종류일 때 쓰고 사유에 확인한 곳을 쓴다.

## 6. 흔한 실수

- 후보 풀을 훑지 않고 우리 범위의 기능 목록에서 판정을 가져온다.
- 입력에 언급이 없다는 이유로 `제외`나 `해당 없음`을 쓴다.
- 기능 이름이 다르다는 이유로 풀에 있는 기능을 갭으로 쓴다.
- 풀의 후보를 고쳐 쓰거나 이미 있는 기능을 새 후보로 올린다.
- 제외 행의 사유를 입력 ID만으로 쓰거나 재검토 조건에 `해당 없음`을 쓴다.
- 제공하는 서비스가 적다는 이유만으로 `매력`을 쓴다.
- 분류 근거 없이 성격을 쓰고 서비스 하나만 확인하고도 비율로 성격을 가른다.
- 근거 칸을 설명으로 시작한다. 맞는 모양은 `내부 자료: 범위 메모 2절, 입력에 언급 없음`처럼 쉼표로 이어 쓰는 것이다.
- 유사 서비스의 이름과 고유 용어를 후보 문장에 쓴다.
- 샘플이나 예시의 기능을 값으로 옮긴다.
