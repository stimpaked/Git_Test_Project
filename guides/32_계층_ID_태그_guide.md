## 1. 입력을 읽는 법

- **통합·정규화**가 가장 중요한 입력이다. 기능 목록의 행 하나가 기능 트리의 행 하나가 된다. 임시 번호(`FN-`), 기능명, 설명, 영역, 공통·고유, 구분, 병합 후보, 근거를 읽는다. 기능을 더하거나 지우거나 합치거나 쪼개지 않는다. 제외 목록에 있는 후보(기능이 아니라고 가른 것)는 트리에 넣지 않는다. 기능 목록이 없거나 기능이 하나도 없으면 쓰기를 멈추고 알린다.
- **영역·모듈**: 영역 목록의 `Z-` ID, 영역, 공통·고유를 읽는다. L1은 이 목록 그대로이며 새 표를 만들지 않는다. 기능 목록의 영역 칸이 `Z-` ID가 아니라 영역 코드나 이름이면 영역 목록에서 같은 영역을 찾아 `Z-`로 바꿔 쓴다. 배치 방침의 운영 기능 배치는 운영 기능 칸의 기준이다.
- **태그의 재료**: 액터는 사람 액터 목록과 비사람 액터 목록의 ID와 액터 공통·고유의 목표 판정, 저니 단계는 저니 매트릭스의 여정 단계, 플랫폼은 플랫폼·채널의 플랫폼 목록과 기능 후보의 적용 플랫폼, 화면은 화면·UI 상태의 화면 인벤토리, 공통·고유는 도메인 공통·고유의 판정을 읽는다.
- **근거의 재료**: 기능 목록의 병합 후보 ID로 후보를 낸 앞 단계 산출물의 후보 표를 찾고, 후보의 출처와 근거 칸이 가리키는 항목에 닿는다. 닿는 항목은 목표, 지표, 가설, 범위, 사용자 조사, 규제, 요구, 위협, 정책, 업무, 수익·성장 지점, 대조 행이다.
- 입력에 없는 ID, 액터, 화면, 플랫폼을 만들어 쓰지 않는다. 입력의 ID는 한 글자도 바꾸지 않는다. ID에 공백이나 괄호가 붙어 있으면 ID 형식에 맞는 부분만 칸에 쓰고 원래 표기는 근거 칸에 적는다.
- 입력 산출물이 없으면 그 입력에 기대는 칸을 `미정`으로 닫고 확인처에 없는 입력의 이름을 쓴다.

## 2. 작성 절차

1. 영역 목록을 위에서 아래로 읽고 영역마다 기능 목록에서 그 영역의 기능을 모아 업무 단위로 묶어 기능군 표에 쓴다. ID는 `FG-01`부터 부여한다.
2. 기능 목록의 기능마다 기능 트리에 행을 쓴다. 기능 ID는 `F-001`부터 부여한다. 임시 번호, 기능군, 기능명, 설명, 공통·고유, 구분을 옮긴다.
3. 운영 기능, 액터, 저니 단계, 플랫폼, 화면을 정한다.
4. 근거 ID를 찾고, 근거 체인을 따라가 근거 등급을 정한 뒤, 근거 칸을 쓴다.
5. 결번을 쓰고 집계를 세어 입력 기능 수와 맞춘다.
6. 누락 점검을 하고 완료 체크를 확인하고 검사 도구를 돌린다.

## 3. 항목별 해설

<!-- 해설: 기능군 -->
### 3.1 기능군

- 기능군은 L2다. 같은 영역 안에서 사용자나 운영자가 하나의 업무 단위로 인식하는 묶음이다. 메뉴나 화면군이 있으면 그것이 보통 한 기능군이고, 화면이 없는 기능(배치, 장치 연동)은 같은 업무 목적의 기능과 묶는다.
- 기능군은 정확히 한 영역에 속한다. 영역 칸에는 영역 목록의 `Z-` ID를 쓴다. 영역을 가르는 일은 영역 목록이 했으므로 여기서 영역을 만들거나 나누지 않는다.
- **기능군** 이름은 명사로 쓴다. 영역 이름을 되풀이하거나 기능 하나의 이름을 그대로 쓰지 않는다. 기능이 하나뿐인 기능군도 허용한다. 다만 기능의 이름만 되풀이한다면 다른 기능군과 합칠 수 있는지 본다.
- 묶는 단서는 기능명과 설명이 같은 대상을 다루는지, 같은 목표를 이루는지, 같은 화면군에 놓이는지다. 입도를 맞추려고 기능을 합치거나 쪼개지 않는다.
- **설명**은 이 기능군이 담는 범위를 한 문장으로 쓴다. 속한 기능의 이름을 나열하지 않는다.
- **근거**는 기능군을 둔 이유가 된 기능의 임시 번호로 시작하고 근거마다 `;`로 나눈다.
- 예시(형식 시연, 값이 아님): 근거 칸은 `FN-003, 같은 대상을 다루는 기능 셋; Z-02, 영역 목록의 설명`처럼 임시 번호나 ID로 시작한다. 병원 예약 서비스라면 기능군을 "예약 변경과 취소"처럼 업무 단위의 명사로, 스마트 온실 모니터링 서비스라면 화면이 없는 기능을 "측정값 수집과 보관"처럼 업무 목적으로 쓴다.

<!-- 해설: 기능트리 -->
### 3.2 기능 트리

- 행 하나는 기능 하나다(L3). 기능은 독립적으로 우선순위를 매기고 테스트할 수 있는 최소 단위이며 이 단계는 입도를 바꾸지 않는다. 표는 영역 목록의 영역 순서, 기능군 `FG-` 순서, 임시 번호 순서로 늘어놓는다.
- **기능 ID**는 `F-001`부터 부여하는 연번이고 이 표의 첫 열이다. 번호는 기능 트리의 첫 작성에서 임시 번호 순서대로 붙인다. 영역, 기능군, 순서의 뜻을 갖지 않으므로 영역이 바뀌어도 기능 ID는 바꾸지 않고, 영역이 `미정`이어도 기능 ID는 붙는다. 결번의 번호와 겹치지 않게 하고 삭제한 번호를 다시 쓰지 않는다. 뒤 단계가 기능을 더하면 기능 트리와 결번에서 가장 큰 번호의 다음 번호를 붙인다.
- **임시 번호**는 기능 목록의 `FN-`를 한 글자도 바꾸지 않고 쓴다. 이 산출물을 만든 뒤에 뒤 단계가 더한 기능은 `해당 없음`(사유: 더한 단계와 근거)으로 닫는다.
- **기능군**은 1번 표의 `FG-` ID다. **기능명**과 **설명**은 기능 목록의 값을 옮긴다. 이름에 정책 값이 있거나 입도가 이상해 보여도 고치지 않고 사용자에게 알린다.
- **공통·고유**는 기능 목록의 값을 옮기고 영역 목록의 영역 구분과 맞는지 본다. 어긋나면 값을 바꾸지 않고 근거에 어긋남을 쓰고 사용자에게 알린다.
- **구분**은 기능 목록의 구분(기능 / 후속)을 옮긴다. 후속이어도 행을 지우지 않는다. 후속 표시는 뒤 단계가 걸러 보는 태그다.
- **운영 기능**은 액터가 모두 서비스를 운영하는 역할이면 `예`, 이용자나 비사람 액터가 하나라도 있으면 `아니오`다. 영역·모듈의 운영 기능 배치가 소속 영역 안에 두고 태그로 표시하는 방침이면 이 칸이 그 태그이고, 별도 영역 방침이어도 같은 기준으로 쓴다.
- **액터**는 이 기능을 직접 쓰거나 일으키는 액터의 `A-`와 `X-` ID를 쉼표로 쓴다. 후보가 나온 목표의 액터와 권한을 읽는다. 모든 기능에는 액터가 있으므로 `해당 없음`을 쓰지 않는다.
- **저니 단계**는 기능이 직접 일어나는 여정 단계 `JS-`를 쉼표로 쓴다. 여러 단계에 걸치면 근거에 이유를 쓰고 모든 단계에 걸치면 `전체`다. 액터가 모두 비사람이라 저니 매트릭스에 칸이 없으면 `해당 없음`(사유: 비사람 액터만 쓰는 기능이라 저니 매트릭스에 칸이 없다)이다. **플랫폼**은 기능이 동작하거나 보이는 플랫폼의 `LP-`를 쉼표로 쓰고 후보의 적용 플랫폼을 읽는다. 플랫폼 목록에 이 기능이 동작하는 곳이 없으면(서버 안에서 시간이나 사건으로만 일어나는 기능 등) `해당 없음`(사유: 확인한 플랫폼 목록)이다.
- **화면**은 기능이 쓰는 화면의 `U-`를 쉼표로 쓰고 모든 화면에 걸치면 `전체`다. 액터가 모두 비사람이거나 설명이 사용자 조작 없는 처리를 말하고 화면 인벤토리에도 없으면 `해당 없음`(사유: 이 기능이 쓰는 화면이 인벤토리에 없고 사용자 조작이 없다)이다. 사용자가 조작하는 기능인데 화면을 못 찾으면 `미정`(확인처: 화면 담당 역할)이다.
- **근거 ID**는 이 기능이 있어야 하는 이유를 보여 주는 앞 단계 산출물 항목의 ID를 하나씩 쉼표로 쓴다(범위 표기 금지). 후보의 근거가 `T-01~T-08`처럼 범위로 적혀 있으면 입력 산출물에서 범위를 풀어 개별 ID로 쓴다. 병합 후보 ID로 후보 행을 찾아 그 행의 출처와 근거가 가리키는 가장 가까운 항목과, 그 항목이 직접 인용한 뿌리 항목(목표, 가설, 규제, 사용자 조사)의 ID를 쓴다. 후보 ID와 임시 번호는 근거 ID가 아니다. 못 찾으면 `해당 없음`이 아니라 `미정`(확인처: 후보를 낸 단계의 담당 역할)이다. 근거 없는 기능은 역추적 검증이 과잉으로 가려낸다.
- **근거 등급**은 근거 ID의 항목에서 그 항목의 근거 칸을 처음까지 거슬러 올라간 체인으로 가른다. 참조로 시작하는 근거는 그 참조를 따라 한 단계 더 올라간다. 체인에 `조사:`나 `내부 자료:`로 시작하는 근거가 하나라도 있으면 `검증`이다. 다만 그 항목이 있다는 사실을 뒷받침하는 조각만 센다. `입력에 언급 없음`, `덮는 후보 없음`처럼 없다는 사실만 적은 조각은 세지 않는다. 센 조각이 하나도 없고 체인을 끝까지 읽었는데 `일반 지식(미검증):`과 `가정:`뿐이면 `미검증`이다. 근거 ID가 `미정`이거나 체인을 읽을 수 없으면 `미정`이다.
- **근거**는 임시 번호로 시작해 기능군과 태그를 정한 자료를 근거마다 `;`로 나눠 쓴다. 기능 ID(`F-…`)로 시작하는 조각은 쓰지 않는다. 근거 등급이 검증이면 닿은 `조사:`나 `내부 자료:` 근거를 하나 쓴다.
- 예시(형식 시연, 값이 아님): 근거 칸은 `FN-012, 기능 목록의 한 행; FG-03, 같은 화면군; 08 액터 공통·고유 목표판정, 목표 G-04의 액터`처럼 쓴다. 사내 휴가 신청 도구라면 승인 기능의 액터가 `A-02`, 근거 ID가 목표의 `G-04`이고 체인이 `내부 자료: 요구사항 메모 2절`에 닿으면 근거 등급은 `검증`이다. 스마트 온실 모니터링 서비스라면 근거가 `가정:`뿐인 수집 기능의 근거 등급은 `미검증`이다.

<!-- 해설: 결번 -->
### 3.3 결번

- 삭제한 기능이 없는 첫 작성에서는 한 줄만 쓴다. 기능 ID, 임시 번호, 사유 칸을 `해당 없음`과 같은 사유(삭제한 기능이 없다)로 닫고 근거에는 확인한 표를 쓴다.
- 뒤 단계가 기능을 삭제하면 기능 트리에서 그 행을 지우고 결번에 한 줄을 더한다. 기능 ID는 지운 기능의 ID 그대로, 임시 번호는 기능 목록에서 왔으면 그 `FN-`이고 아니면 `해당 없음`(사유)이다. 사유는 한 문장, 근거는 삭제를 정한 산출물의 문서와 위치다. 이때 산출물 버전을 올린다.
- 결번에 적은 번호는 어떤 영역에서도 다시 쓰지 않는다.

<!-- 해설: 집계 -->
### 3.4 집계

- 숫자는 표의 행을 세어 쓴다. 근거는 센 표를 가리키는 참조(`32 계층·ID·태그 2번 표`처럼 `NN 산출물 이름`)로 시작한다. 0도 `0`으로 쓴다.
- 입력 기능 수는 기능 목록 표의 행 수다. 근거에 `31 통합·정규화`의 표를 가리킨다. 기능 수는 기능 트리의 행 수다. 후 단계 추가 수는 임시 번호가 `해당 없음`인 행의 수이고 처음 쓸 때는 0이다. 결번 수는 기능 ID가 값인 행의 수이고 한 줄을 `해당 없음`으로 닫았으면 0이다.
- 기능이 없는 영역 수는 영역 목록의 영역 가운데 기능군이 없는 영역의 수다. 0이 아니면 기능 목록에 그 영역의 기능이 없으므로 사용자에게 알린다.
- 공통·고유 세 수의 합과 근거 등급 세 수의 합은 기능 수와 같아야 한다. 기능 수에서 후 단계 추가 수를 빼고 결번 가운데 임시 번호가 값인 행의 수를 더하면 입력 기능 수와 같아야 한다. 다르면 행이 빠졌거나 두 번 적혔으므로 표를 고친다.

## 4. 누락 점검

- 기능 목록의 `FN-`가 모두 기능 트리에 한 번씩 나오는가. 행 수를 세어 입력 기능 수와 맞춰 보았는가.
- 모든 기능군에 기능이 있고 모든 영역에 기능군이 있는가. 기능이 없는 영역이 있으면 사용자에게 알렸는가.
- 기능군의 영역과 기능 목록의 영역이 같은가. 기능 ID가 겹치거나 결번의 번호를 쓰지 않았는가.
- 공통 영역에 고유 기능이, 고유 영역에 공통 기능이 들어 있지 않은가.
- 후속 기능이 행으로 남아 있고 구분이 후속인가.
- 액터, 저니 단계, 플랫폼, 화면, 근거 ID가 모두 입력 산출물에 있는 ID인가. 비사람 액터가 하는 기능에 사람 액터만 붙이지 않았는가.
- 운영 기능이 예인 행의 액터가 모두 운영 역할인가.
- 근거 ID가 후보 ID나 임시 번호가 아니라 앞 단계 항목의 ID인가. 근거 등급이 체인과 맞는가.
- 기능명에 정책 값이 있거나 입도가 이상한 기능을 사용자에게 알렸는가.

## 5. `미정`·`해당 없음` 판단

- **`해당 없음`**: 임시 번호(뒤 단계가 더한 기능), 화면(화면 인벤토리에 없고 사용자 조작이 없는 기능), 저니 단계와 플랫폼(3.2절의 조건일 때), 결번의 한 줄에만 쓴다. 입력에 언급이 없다는 사실만으로는 `해당 없음`이 아니다. 기능 목록은 닫힌 목록이므로 목록에 없는 기능을 더하지 않는다.
- **`미정`**: 액터, 저니 단계, 플랫폼, 근거 ID, 운영 기능, 공통·고유, 구분을 입력으로 정할 수 없을 때 쓴다. 선택지 칸과 ID 칸에서도 값을 모르면 추측하지 않고 `미정`(확인처·담당·기한)으로 닫는다. 확인처는 그 태그를 낸 앞 단계의 담당 역할, 기한은 이 문서의 완료 전으로 쓴다.
- 칸의 일부만 모르면 아는 ID를 쓰고 모르는 부분을 `미정`(확인처·담당·기한)으로 이어 쓴다. 근거 ID에서 닿은 항목 하나는 알고 다른 하나를 모르면 아는 ID에 `미정`을 잇는다.
- 근거 ID가 `미정`이면 근거 등급도 `미정`이다. 근거 ID는 알아도 그 항목이 `미정`이거나 근거 칸을 읽을 수 없으면 근거 등급을 `미정`으로 닫고 근거에 읽을 수 없는 이유를 쓴다.
- 입력이 얇아 `미정`이 많은 것은 구조의 결함이 아니다. 칸 수를 줄이려고 규칙에 없는 묶음이나 생략을 만들지 않는다.

## 6. 흔한 실수

- 기능 목록에 없는 기능을 더하거나 후속 기능의 행을 지운다. 기능명과 설명을 다시 쓴다.
- 기능군을 영역에 걸쳐 쓰거나 영역 목록에 없는 영역을 만든다.
- 번호를 영역이나 기능군 순서의 뜻으로 붙이거나 영역이 바뀌었다고 기능 ID를 바꾸거나, 삭제한 번호를 다시 쓴다.
- 임시 번호를 바꿔 쓰거나 근거 ID에 후보 ID를 쓴다. 근거 ID를 범위로 쓴다.
- 입력에 없는 액터, 화면, 플랫폼을 쓴다. 화면이 없다는 이유로 액터와 근거를 `해당 없음`으로 닫는다.
- 근거 체인을 따라가지 않고 모든 기능을 `미검증`이나 `검증`으로 쓴다.
- 근거 칸을 설명으로 시작한다. 맞는 모양은 `FN-012, 기능 목록의 한 행`처럼 임시 번호나 ID로 시작해 쉼표로 이어 쓰는 것이다.
- 샘플이나 예시의 영역 이름, 코드, 기능을 값으로 옮긴다.
