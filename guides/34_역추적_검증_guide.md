## 1. 입력을 읽는 법

- **기능 트리**(계층·ID·태그 산출물)와 **결번**이 검증 대상이다. 기능 ID, 근거 ID, 근거 등급, 액터·저니 단계·플랫폼·화면 태그, 구분(기능 / 후속)을 읽는다. 기능 트리가 없으면 쓰기를 멈추고 알린다(공통 가이드 1절).
- **의존성** 산출물의 호출, 선후행, 공통 기능 검사와 집계(방향 위반 수, 정의되지 않은 참조 수, 순환 수, 호출 대상 미정 수, 과잉 의심 판정 수)는 의존성 무결성 규칙의 입력이다.
- **통합·정규화** 산출물의 기능 목록(병합 후보), 제외 목록, 표별 소진은 후보가 기능으로 합쳐졌는지 제외됐는지 따라가는 길이다. 후보의 임시 번호는 기능 트리의 임시 번호로 기능 ID에 닿는다.
- **앞 단계 산출물 전부**가 규칙의 대상 항목을 준다. 규칙 종류별로 읽는 표는 이렇다.
  - 목표: 목표·가치의 목표 지표, 목표 목록(사람이 아닌 액터의 목표 포함), 액터 공통·고유의 공통 목표와 목표 판정, 유저 플로우의 목표 매핑. 사람 액터 목록과 비사람 액터 목록은 액터 ID의 기준이다.
  - 저니: 저니 매트릭스의 여정 단계와 매트릭스, 목표 목록의 대응 점검.
  - 후보 소진: 후보 표를 가진 모든 앞 단계(유저 플로우부터 유사 서비스 대조까지, 시나리오 5유형과 도메인 공통·고유의 신규 후보 포함).
  - 상태·이벤트·타이머: 상태 전이의 전이표, 이벤트의 이벤트 목록, 시간·주기의 타이머와 입력 대응.
  - 규제: 근거 수집의 규제·정책, 규제·정책의 규제 매핑과 설계 결정.
  - 화면: 화면·UI 상태의 화면 인벤토리와 비정상 상태, 운영·백오피스의 업무 목록(기존 화면).
  - 대조 판정: 표준 카탈로그 대조와 유사 서비스 대조의 대조표, 인사이트 대조, 갭 후보. 카탈로그 정보의 이름과 확보 방식은 근거에 인용한다.
  - 영역 배정: 영역·모듈의 영역 목록, 엔티티 배정, 목표 배정, 공통 기능 배정. 엔티티 산출물과 외부 연동 산출물은 배정 대상과 연동 액터의 기준이다.
  - 제외: 범위·제약의 제외·후속 목록, CRUD 매트릭스의 제외 방침, 플랫폼·채널의 차이 점검, 수익 모델의 지점 점검, 성장·측정의 지표 매핑, 대조 단계의 제외 판정은 앞 단계가 이미 기능으로 잇지 않기로 한 항목이다.
  - 의미 대조의 재료: 소유·권한의 권한 매트릭스, CRUD 매트릭스의 처리 칸, 보안·어뷰징의 위협 목록, 데이터 생애의 생애 정책.
- 입력의 ID는 한 글자도 바꾸지 않는다. ID에 공백이나 괄호가 붙어 있으면 ID 형식에 맞는 부분만 칸에 쓰고 원래 표기는 근거 칸에 적는다. 범위 표기(`A-01~A-05`)는 입력에서 풀어 하나씩 쓴다.
- 앞 단계 산출물이 틀렸거나 부족해 보이면 직접 고치지 않는다. 갭 로그에 상류 단계 환류로 올린다.
- 앞 단계 산출물이 없으면 그 입력에 기대는 규칙의 수를 `미정`으로 닫고 확인처에 없는 입력의 이름을 쓴다(5절).

## 2. 작성 절차

1. 기능 트리와 결번에서 기능 ID 목록을 만든다. 이 단계 동안 기능 트리는 바뀌지 않는다. 조치가 반영된 기능 트리는 재실행 때 입력으로 받는다.
2. 검증 규칙 표를 쓴다. 3.1의 최소 규칙을 모두 쓰고 이 프로젝트에 맞는 규칙을 `추가`로 더한다.
3. 추적 표를 쓴다. 규칙마다 대상 항목을 입력 표의 순서대로 한 행씩 쓴다. 이은 항목을 찾고 판정한다.
4. 검증 규칙 표의 대상 수, 통과 수, 갭 수를 추적 표에서 센다.
5. 갭 로그를 쓴다. 판정이 갭인 행마다 원인을 찾고 조치 유형을 정한다. 의미 대조로 찾은 갭도 추적 행을 먼저 더하고 같은 방식으로 쓴다.
6. 의도적 제외 표를 쓴다. 조치 유형이 의도적 제외인 갭과 앞 단계가 이미 제외한 항목을 모두 올린다.
7. 집계를 세고 4절의 누락 점검을 한 뒤 완료 체크를 확인한다.
8. 조치가 반영된 입력(고쳐진 기능 트리와 앞 단계 산출물)을 받으면 1~7을 되풀이한다. 재실행 횟수를 하나 올리고 갭 로그의 상태를 고친다.

## 3. 항목별 해설

<!-- 해설: 검증규칙 -->
### 3.1 검증 규칙

- 행 하나는 규칙 하나다. 규칙은 같은 방식으로 판정하는 대상 항목의 묶음이다. 작성자는 아래 최소 규칙을 줄일 수 없고 더할 수 있다. 앞 단계 표가 없어도 행을 지우지 않는다.
- 최소 규칙(종류, 방향, 대상, 통과 조건):
  - 목표 · 역방향 · 비즈니스 목표 · 기능이 하나 이상 이어진다.
  - 목표 · 역방향 · 사용자 목표(사람이 아닌 액터의 목표 포함) · 기능이 이어지거나 의도적 제외로 사유가 있다.
  - 저니 · 역방향 · 핵심 구간으로 표시된 여정 단계의 매트릭스 칸 · 칸의 목표를 거쳐 기능이 이어진다.
  - 후보 소진 · 역방향 · 앞 단계 후보 표의 후보(원래 후보 표만 센다. 도메인 공통·고유의 후보 판정은 같은 후보를 되풀이하므로 세지 않는다) · 기능의 병합 후보에 있거나 제외 목록에 사유가 있다. 대상 수는 통합·정규화의 표별 소진의 후보 수 합과 같아야 한다.
  - 후보 소진 · 역방향 · 22~30번 후보 표의 후보 · 도메인 공통·고유의 후보 판정에 행이 있다(환류가 끝났는지 본다. 행이 없으면 갭이고 상류 단계 환류로 올린다).
  - 상태·이벤트·타이머 · 역방향 · 전이, 이벤트, 타이머를 각각 한 행씩(셋) · 담당 후보를 거쳐 기능이 이어진다.
  - 규제 · 역방향 · 규제 항목 · 기능이 이어지거나 프로세스로 닫혀 의도적 제외에 있다.
  - 화면 · 역방향 · 화면 · 기능이 하나 이상 이어진다.
  - 화면 · 순방향 · 화면이 필요한 기능(후속 기능과 화면이 필요 없는 기능은 뺀다) · 화면이 이어진다.
  - 대조 판정 · 역방향 · 표준 카탈로그 항목, 유사 서비스 비교 기능, 인사이트 · 판정이 있고 채택한 항목은 후보로 이어진다.
  - 의존성 무결성 · 무결성 · 호출과 선후행의 행, 공통 기능 검사의 행 · 기능 ID가 기능 트리에 있고 방향 위반과 순환이 없으며 결번의 기능을 가리키지 않고, 검사 행의 판정이 `과잉 의심`이나 `미정`이 아니다.
  - 영역 배정 · 무결성 · 기능, 엔티티, 목표를 각각 한 행씩(셋) · 영역이 정확히 하나다.
  - 기능 근거 · 순방향 · 기능 트리의 모든 기능 · 근거 ID가 하나 이상이고 입력에 있는 ID다. 근거 ID가 없는 기능은 과잉이다.
- 더할 만한 규칙(종류는 `추가`, 방법은 보통 의미 대조): CRUD 매트릭스의 처리 칸이 기능의 액터에 닿는가, 권한 매트릭스가 허용한 행위가 기능의 액터에 닿는가, 같은 공통 목표가 액터마다 따로 기능이 되지 않았는가.
- **방향**은 역방향(앞 단계 항목 → 기능), 순방향(기능 → 근거나 화면), 무결성(참조와 배정이 어긋나지 않는가) 중 하나다. **검사 방법**은 ID를 찾아 맞춰 보면 ID 대조, 설명을 읽어 맞춰야 하면 의미 대조다.
- **규칙**은 대상 하나가 통과하는 조건 한 문장이다. **대상 표**는 `NN.표 키`로 쉼표 구분하며 단계 번호와 표 키는 템플릿을 따른다.
- **대상 수**, **통과 수**, **갭 수**는 추적 표에서 그 규칙의 행을 세어 쓴다. 대상 수는 통과 수와 갭 수의 합이다. 기능 근거 규칙의 대상 수는 입력 기능 수와 같다. 의도적 제외로 닫은 갭도 판정이 갭이므로 갭 수에 든다.
- **근거**는 대상 수를 센 앞 단계 표의 위치로 시작한다. 근거마다 `;`로 나누고 `NN <산출물 이름>` 참조나 `<출처 유형>: <문서·위치>`로 시작한다. 대조 판정 규칙의 근거에는 카탈로그의 이름과 확보 방식을 인용하고, 확보 방식이 작성자 초안이면 그 대조에서 나온 판정을 미검증으로 읽는다고 쓴다.
- 예시(형식 시연, 값이 아님): 병원 예약 서비스라면 규제 규칙의 규칙을 "규제 항목마다 기능이 이어지거나 프로세스로 닫혀 의도적 제외에 있다"로, 스마트 온실 모니터링 서비스라면 화면 규칙의 대상에서 장치 연동 기능을 뺀다고 규칙에 쓴다.

### 3.2 추적

- 행 하나는 규칙의 대상 항목 하나다. 한 항목이 여러 규칙의 대상이면 규칙마다 행을 쓴다. 대상이 수백이어도 행을 묶거나 대표로 줄이지 않고 입력 표의 순서대로 전수를 쓴다.
- **ID**는 `KT-001`부터 부여한다. **규칙**은 1번 표의 `KV-` ID다.
- **대상**은 항목의 ID 하나다. 매트릭스의 칸처럼 ID가 행과 열의 쌍인 항목은 행 ID와 열 ID를 ×로 이어 쓰고, 행 ID가 없는 선후행은 후행 기능 ID와 선행 기능 ID를 ×로 이어 쓴다. 순방향 규칙의 대상은 기능 ID다. 기능 트리의 기능 ID가 `미정`인 기능도 한 행을 갖는다. 대상을 `미정`(확인처: 영역·모듈 담당 역할)으로 닫고 근거의 첫 조각을 `31 통합·정규화 기능 목록 FN-007`처럼 임시 번호를 가리키는 참조로 써서 행을 구별한다.
- **이은 항목**은 대상과 이어진 반대편 항목의 ID를 쉼표로 모두 쓴다. 역방향 규칙은 기능 ID, 순방향 규칙은 근거 ID나 화면 ID, 영역 배정은 영역 ID다. 무결성 규칙은 대상 행이 참조하는 기능 ID나 영역 ID를 쓴다. 후보는 기능 목록의 병합 후보에서 임시 번호를 거쳐 기능 ID에 닿는다. 앞 단계가 제외로 닫은 항목은 그 제외 항목의 ID를 쓴다. 연결을 하나도 못 찾으면 `해당 없음`(사유: 이어진 기능이 없다)이고 판정은 갭이다. 기능 목록을 닫힌 목록으로 보고 찾았을 때만 쓴다. 반대로 상류 항목이 기능이 필요 없다고 이미 닫혀 있으면(대조 단계의 `개념 없음`·`제외`·`후속` 판정, 저니 매트릭스의 `해당 없음` 칸) 이어진 기능이 없어도 판정은 통과이고 이은 항목은 그 판정이나 제외 항목의 ID, 없으면 `해당 없음`(사유: 상류 항목이 기능이 필요 없다고 닫혀 있다)이다. 이은 기능의 기능 ID가 `미정`(영역이 `미정`)이면 이은 항목에 임시 번호(`FN-`)를 쓰고 근거에 영역이 `미정`이라 기능 ID가 없다고 쓴다. 화면 규칙에서 기능이 모든 화면에 걸치면 `전체`를 쓴다.
- **판정**은 이은 항목이 있고 규칙의 통과 조건을 채우면 `통과`다. 연결이 없거나 조건을 채우지 못하면 `갭`이다. 앞 단계 산출물의 값이 `미정`이어서 이어졌는지 판정하지 못한 항목도 통과가 아니라 `갭`으로 쓰고 갭 로그에 상류 단계 환류로 올린다. 후속 기능은 근거 규칙에는 넣고 화면이 필요한 기능 규칙에서는 뺀다.
- **근거**는 이은 경로의 중간 항목으로 시작한다(예: 칸에서 목표를 거쳐 기능에 닿았다면 목표 ID). 기능 ID로 조각을 시작하지 않고 `32 기능 트리 기능 F-AAA-003`처럼 산출물을 가리키는 참조 뒤에 이어 쓴다. 근거마다 `;`로 나눈다.
- 예시(형식 시연, 값이 아님): 어린이 독서 앱의 규제 항목 한 행은 이은 항목에 기능 셋의 ID를 쉼표로 쓰고 판정이 통과다. 사내 휴가 신청 도구의 사용자 목표 중 기능이 없는 한 행은 이은 항목이 `해당 없음`(사유: 이어진 기능이 없다), 판정이 갭이다.

<!-- 해설: 갭로그 -->
### 3.3 갭 로그

- 행 하나는 갭 하나다. 갭은 추적 표에서 판정이 갭인 행에서 나온다. 같은 원인으로 생긴 여러 추적 행은 한 갭으로 묶고 추적 행에 쉼표로 모두 쓴다. 조치가 둘 이상 필요하면 행을 나눈다. 한 항목이 규칙 둘에 걸려 갭이면 규칙마다 갭 행을 쓴다.
- **ID**는 `KG-01`부터 부여한다. **규칙**은 갭을 드러낸 규칙의 `KV-` ID, **추적 행**은 `KT-` ID다. 갭이 해소돼 추적 행의 판정이 통과로 바뀌었어도 갭을 드러냈던 행으로 남긴다.
- **갭**은 드러난 누락이나 과잉을 한 문장으로, **원인**은 앞 단계가 놓친 이유를 한 문장으로 쓴다. 원인을 모르면 `미정`(확인처: 후보를 낸 단계의 담당 역할)이다.
- **조치 유형**은 하나를 고른다.
  - 기능 추가: 근거가 있고 범위 안인데 이어진 기능이 없다.
  - 태그 수정: 기능은 있는데 액터, 화면, 플랫폼, 저니 단계, 근거 ID 같은 태그가 빠졌거나 틀렸다.
  - 기능 삭제: 근거가 없거나 다른 기능과 같은 것이라 지운다.
  - 의도적 제외: 기능으로 만들 수 없거나(프로세스, 설계 기준) 범위 밖이라 잇지 않는다.
  - 상류 단계 환류: 원인이 기능 트리가 아니라 앞 단계 산출물의 누락이나 오류다.
- **대상 기능 ID**는 기능 추가에서는 새로 붙일 기능 ID(기능 트리와 결번에서 그 영역 코드의 가장 큰 번호 다음 번호), 태그 수정과 기능 삭제에서는 기존 기능 ID이고 같은 원인의 기능이 여럿이면 쉼표로 모두 쓴다. 의도적 제외와, 기능과 상관없는 상류 단계 환류는 `해당 없음`(사유)이다.
- **조치 내용**은 고칠 내용 한 문장이다. 기능 추가는 `기능명: …, 설명: …, 영역: Z-xx`로 쓰고 아는 만큼 액터, 화면, 플랫폼, 저니 단계를 이어 쓴다. 모르는 부분은 `미정`(확인처·담당·기한)으로 이어 쓴다. 태그 수정은 고칠 태그와 값, 기능 삭제는 지우는 이유를 쓴다.
- **상류 항목**은 기능으로 이어지지 않은 앞 단계 항목의 ID를 쉼표로 쓴다. 기능 추가에서는 이 값이 새 기능의 근거 ID가 된다. 과잉 기능을 지우는 갭과 순방향 규칙의 갭은 `해당 없음`(사유: 기능에 근거 ID가 없다)이다.
- **환류 대상 단계**는 앞 단계 번호를 쉼표로 쓴다. 기능 추가, 태그 수정, 기능 삭제는 계층·ID·태그 단계를 쓰고 기능 추가와 기능 삭제는 의존성 단계도 쓴다. 상류 단계 환류는 고칠 산출물의 단계다. 의도적 제외는 `해당 없음`(사유: 앞 단계를 고치지 않는다)이다.
- **상태**는 조치가 반영된 입력으로 같은 규칙을 다시 돌려 통과를 확인한 갭만 `해소`다. 의도적 제외로 닫은 갭은 의도적 제외 표에 행이 있으면 `해소`다. 그 밖은 `미해소`다.
- **근거**는 갭을 드러낸 앞 단계 표의 위치로 시작하고 조치를 정한 자료를 이어 쓴다.
- 예시(형식 시연, 값이 아님): 병원 예약 서비스라면 화면은 있는데 기능이 없는 갭을 조치 유형 기능 추가, 조치 내용 `기능명: 예약 변경 내역 조회, 설명: …, 영역: Z-02`, 환류 대상 단계 `32, 33`으로 쓴다. 스마트 온실 모니터링 서비스라면 순환 의존을 상류 단계 환류로 쓰고 환류 대상 단계에 의존성 단계를 쓴다.

### 3.4 의도적 제외

- 행 하나는 기능으로 잇지 않기로 한 앞 단계 항목 하나다. 두 출처가 있다. 갭 로그의 조치 유형이 의도적 제외인 갭이 하나, 앞 단계가 이미 제외한 항목이 다른 하나다. 앞 단계가 제외한 항목은 모두 올린다(통합·정규화의 제외 목록, 범위·제약의 제외·후속 목록, 제외 방침, 제외로 닫은 대조 판정 같은 것).
- **ID**는 `KX-01`부터 부여한다. **제외 항목**은 앞 단계 항목의 ID 하나다. 통합·정규화의 제외 목록 항목은 `FE-` 행 ID를, 범위·제약의 제외·후속 항목은 `OX-`·`OL-` ID를, 그 밖은 입력의 ID를 쓴다. 후보 ID는 `FE-` 행의 후보 ID 칸에서 찾는다. 이름과 설명은 앞 단계가 갖는다. 대조 단계의 `개념 없음` 판정은 기능이 필요 없는 항목이라 추적에서 통과로 닫으므로 이 표에 올리지 않는다.
- **유형**은 설계 기준(기능이 아닌 설계 결정), 프로세스(출시·법무·운영 절차), 범위 밖(기능이지만 이번 범위가 아님) 중 하나다. 우선순위·릴리스 단계가 프로세스를 출시 게이트로, 범위 밖을 후속으로 읽는다.
- **갭**은 이 단계가 제외로 정한 갭이면 `KG-` ID다. 앞 단계가 이미 제외했으면 `해당 없음`(사유: 앞 단계가 제외했다)이다.
- **사유**는 앞 단계의 사유를 옮기거나 이 단계의 이유를 한 문장으로 쓴다. 사유 없이 '위와 같음'이라고 쓰지 않는다. **재검토 조건**은 다시 기능 후보로 보는 조건이다. 설계 기준과 프로세스처럼 기능이 될 일이 없으면 `해당 없음`(사유)이다. 앞 단계가 조건을 적었으면 옮긴다.
- **처리 위치**는 이 항목을 대신 다루는 산출물의 문서와 위치다. 프로세스를 출시 게이트로 넘길 때도 이 칸에 쓴다. 대신 다루는 곳을 모르면 `미정`(확인처·담당·기한)이다.
- **근거**는 제외를 정한 앞 단계 항목의 ID로 시작한다. 범위·제약의 어느 항목에 근거하는지도 쓴다.
- 예시(형식 시연, 값이 아님): 사내 휴가 신청 도구의 보안 심사 절차는 유형 프로세스, 재검토 조건 `해당 없음`(사유: 기능이 될 일이 없는 절차다). 어린이 독서 앱의 후속 기능은 유형 범위 밖, 재검토 조건에 후속 릴리스 계획을 쓴다.

<!-- 해설: 집계 -->
### 3.5 집계

- 숫자는 표의 행을 세어 쓴다. 근거는 센 표를 가리키는 참조(`34 역추적 검증 1번 표`)로 시작한다. 0이어도 `0`을 쓴다.
- 대상 수 합계, 통과 수 합계, 갭 수 합계는 1번 표의 수를 더한 값이다. 대상 수를 `미정`이나 `해당 없음`으로 닫은 행은 더하지 않는다. 대상 수 미정 규칙 수는 `미정`으로 닫은 행의 수다.
- 입력 기능 수는 이 단계가 검증한 기능 트리의 기능 행 수다. 근거에 계층·ID·태그 산출물의 기능 트리를 가리킨다. 미검증 기능 수는 기능 트리의 근거 등급이 미검증인 행의 수다.
- 갭 로그 수는 조치 유형별 다섯 수의 합과 같고 해소 수와 미해소 수의 합과 같다. 의도적 제외 조치 수는 갭 로그에서, 의도적 제외 수는 4번 표의 행에서 센다. 둘은 다를 수 있다(앞 단계가 제외한 항목이 있다).
- 재실행 횟수는 조치가 반영된 입력으로 검증을 다시 돌린 횟수다. 처음 쓸 때는 0이다.

## 4. 누락 점검

- 최소 규칙이 모두 행으로 있는가. 상태·이벤트·타이머와 영역 배정과 화면은 행이 각각 몇 개여야 하는지 맞는가.
- 앞 단계의 후보 표가 하나도 빠지지 않고 후보 소진의 대상에 들어갔는가. 표별 소진의 후보 수와 후보 소진 규칙의 대상 수가 맞는가.
- 기능 트리의 모든 기능이 기능 근거 규칙에 한 번씩 있는가. 결번의 기능이 추적 표에 있지 않은가.
- 판정이 갭인 행이 모두 갭 로그의 추적 행에 있는가. 갭 로그의 조치 유형마다 필요한 칸(대상 기능 ID, 환류 대상 단계)이 닫혔는가.
- 앞 단계가 제외한 항목이 의도적 제외 표에 빠짐없이 있는가. 제외 항목이 두 번 나오지 않는가.
- 기능 추가와 기능 삭제 갭의 환류 대상 단계에 의존성 단계가 있는가.
- 사람이 대조해야 찾는 갭(권한, CRUD 칸, 중복 정의)을 위한 `추가` 규칙을 검토했는가.
- 근거가 미검증인 기능의 수를 집계에 셌는가.

## 5. `미정`·`해당 없음` 판단

- **`해당 없음`**: 앞 단계의 개념이 이 프로젝트에 없다고 닫힌 목록으로 확인했을 때 규칙의 수 세 칸에 쓴다. 규제·정책 산출물에 규제 항목이 하나도 없다고 닫혀 있으면 규제 규칙의 대상 수, 통과 수, 갭 수를 사유가 같은 `해당 없음`으로 닫고 행은 지우지 않는다. 앞 단계에 표가 있고 행이 없으면 `해당 없음`이 아니라 `0`이다.
- 판정이 갭인 행이 하나도 없으면 갭 로그를 한 줄로 쓴다. ID 칸에 `KG-01`을 쓰고 나머지 칸을 `해당 없음`과 같은 사유(갭이 없다)로 닫는다. 이 줄은 갭 로그 수에 세지 않는다. 의도적 제외 표도 제외할 항목이 하나도 없으면 같은 방식으로 `KX-01` 한 줄을 쓴다.
- 입력에 언급이 없다는 사실만으로는 `해당 없음`이 아니다. 기능 트리와 앞 단계 산출물을 닫힌 목록으로 보고 그 목록이 개념을 배제할 때만 쓴다. 이은 항목의 `해당 없음`도 기능 트리를 찾아본 뒤에만 쓴다.
- **`미정`**: 앞 단계 산출물이 없거나 `미정`이어서 수를 셀 수 없을 때 쓴다. 대상 수, 통과 수, 갭 수를 모두 `미정`(확인처: 없는 입력을 만드는 단계의 담당 역할, 담당, 기한: 이 문서의 완료 전)으로 닫는다. 선택지 칸, ID 칸, 숫자 칸에서도 값을 모르면 `미정`(확인처·담당·기한)으로 닫는다. 칸의 일부만 모르면 아는 값을 쓰고 모르는 부분을 `미정`(확인처·담당·기한)으로 이어 쓴다.
- 판정하지 못한 항목은 `미정`이 아니라 `갭`이다. 판정은 통과 / 갭 둘뿐이고 갭은 갭 로그가 받는다.
- 입력이 얇아 `미정`이 많아지는 것은 구조의 결함이 아니다. 수를 채우려고 행을 지어내지 않고, 칸 수를 줄이려고 규칙이나 행을 묶지 않는다.
- 종료 조건의 판정은 워크스루 리뷰 단계의 몫이다. 이 단계는 미해소 갭이 0인지까지만 확인한다.

## 6. 흔한 실수

- 최소 규칙을 줄이거나 앞 단계 표가 없다고 규칙 행을 지운다. 규칙 하나에 대상을 섞어 한 행으로 센다(기능, 엔티티, 목표의 영역 배정을 한 행으로 쓰는 것).
- 대상 수를 추적 표의 행을 세지 않고 앞 단계의 개수에서 옮겨 쓴다.
- 이은 항목을 일부만 쓰고 `…`로 줄인다. 대상 하나에 이은 기능을 한 개만 쓴다.
- 판정하지 못한 항목을 통과로 쓴다. 갭을 지우는 대신 해소로 쓴다.
- 조치가 앞 단계 산출물에 반영되기 전에 상태를 `해소`로 쓴다.
- 과잉 기능을 갭 로그에 올리지 않고 기능 트리에서 직접 지운다. 앞 단계 산출물을 직접 고친다.
- 조치 유형을 둘 이상 한 행에 쓴다. 의도적 제외에 환류 대상 단계를 쓴다.
- 앞 단계가 제외한 항목을 의도적 제외 표에 올리지 않는다. 사유를 `위와 같음`으로 쓴다.
- 기능 ID로 근거 조각을 시작한다. 맞는 모양은 `32 기능 트리 기능 F-AAA-003, 근거 ID가 없다`처럼 산출물을 가리키는 참조 뒤에 쉼표로 잇는 것이다.
- 근거 칸을 설명으로 시작한다. 맞는 모양은 `내부 자료: 기능 목록 설명 3행, 입력에 언급 없음`처럼 쉼표로 이어 쓰는 것이다.
- 샘플이나 예시의 규칙, 기능, ID를 값으로 옮긴다.
