## 1. 입력을 읽는 법

- **엔티티 목록**: 모든 엔티티가 매트릭스의 행 축이다. 엔티티마다 이름과 뜻, 다른 엔티티와의 관계(입력에 있으면)를 읽는다. 누가 만들고 누가 보는 데이터인지 뜻에서 드러나면 칸을 판단하는 데 쓴다.
- **액터 목록(사람)**: 주체의 후보다. 유형이 `운영·지원`인 액터는 데이터를 관리하는 처리(수정, 삭제, 보관·숨김, 복원, 내보내기)의 주체 후보로 읽는다.
- **액터 목록(비사람)**: 시간 트리거는 사람의 조작 없이 일어나는 처리(만료, 보존 기간 뒤 삭제)의 주체다. 외부 시스템과 장치는 서비스 밖에서 데이터를 들여오거나 갱신하는 처리의 주체다.
- **유저 플로우**: 이미 있는 처리를 찾는 곳이다. 노드와 미결 질문에서 엔티티를 다루는 처리를 찾고, 등장 화면과 접점은 접점 칸의 출처로 읽는다. 목표 매핑에서 플로우 없이 이 단계가 처리하기로 넘긴 목표는 반드시 매트릭스에 반영한다.
- **목표 목록**과 **저니 매트릭스**: 플로우가 닿지 않은 곳의 처리를 찾을 때 읽는다. 액터가 이루려는 목표에 엔티티를 만들거나 바꾸는 일이 들어 있는지 본다.
- **범위·제약**: 제외·후속으로 둔 항목은 제외 방침(범위 밖)의 출처다. **근거 수집**의 규제·정책 목록은 제외 방침(정책·규제)의 출처다.
- 입력에 없는 처리, 접점, 방침을 일반적으로 그럴 것이라는 이유로 만들어 쓰지 않는다. 주체와 접점의 이름도 입력에서 가져온다.

## 2. 작성 절차

1. 엔티티 목록의 엔티티를 모두 나열한다. 엔티티 하나가 처리 열두 가지의 칸을 갖는다.
2. 제외 방침을 쓴다. 입력이 제공하지 않기로 밝힌 처리를 먼저 모으면 3단계에서 `제외`를 입력 없이 고르지 않게 된다. ID는 `CR-01`부터 부여한다.
3. 매트릭스를 쓴다. 엔티티 순서대로, 엔티티마다 처리 열두 가지를 3.2의 순서로 쓴다. 칸마다 앞 단계 산출물에서 그 처리를 찾아 `제공`을 쓰고, 찾지 못하면 `후보`나 `제외`를 정한다.
4. 후보 목록을 쓴다. 판정이 `후보`인 행을 기능 단위로 묶어 `CF-01`부터 ID를 부여한다.
5. 4절의 누락 점검을 하고 완료 체크를 확인한 뒤 검사 도구를 돌린다.

## 3. 항목별 해설

<!-- 해설: 제외방침 -->
### 3.1 제외 방침

- 같은 이유로 여러 칸을 제공하지 않기로 했을 때 그 이유를 한 번만 쓰는 표다. 매트릭스의 제외 행은 이 표의 ID를 근거로 가리킨다.
- **유형**은 이렇게 고른다.
  - `정책·규제`: 서비스가 스스로 정했거나 법·규정이 요구해서 제공하지 않는다. 근거에 그 정책이나 규정이 나온 자료의 문서와 위치를 쓴다.
  - `범위 밖`: 범위·제약의 제외·후속 목록에 있어 이번에는 제공하지 않는다. 근거에 그 목록의 항목을 쓴다.
- **방침**은 어떤 엔티티의 어떤 처리를 왜 제공하지 않는지를 한 문장으로 쓴다. 엔티티 하나와 처리 하나에만 걸려도 되고 여러 엔티티나 여러 처리에 걸쳐도 된다.
- 입력에서 찾지 못한 방침을 만들어 쓰지 않는다. 입력이 제공하지 않는다고 밝히지 않은 칸은 방침이 아니라 매트릭스 칸에서 `후보`나 `미정`으로 닫는다.
- 엔티티의 성질상 성립하지 않는 칸(3.2)은 방침으로 모으지 않는다. 칸마다 사유가 다르기 때문이다.
- 제외 방침이 하나도 없으면 한 줄만 쓴다. ID 칸에는 `CR-01`을 쓰고 나머지 칸은 `해당 없음`과 같은 사유로 닫으며 근거에는 확인한 범위·제약과 정책 자료를 쓴다.
- 예시(형식 시연, 값이 아님): 병원 예약 서비스라면 "진료 기록의 삭제는 법령이 정한 보존 기간 때문에 제공하지 않는다"(정책·규제), 사내 휴가 신청 도구라면 "휴가 신청서의 내보내기는 후속 목록에 있어 이번에는 제공하지 않는다"(범위 밖)처럼 쓴다.

### 3.2 처리 매트릭스

- 행은 엔티티와 처리의 조합(칸)마다 한 행 이상이다. 칸이 하나도 빠지지 않아야 빈 곳이 드러난다. 엔티티 순서대로 묶고 그 안에서 아래 순서로 쓴다.

| 처리 | 뜻 |
|---|---|
| 생성 | 새 데이터를 한 건 만든다. 지난 것을 복사해 만드는 것도 여기에 쓴다 |
| 조회 | 한 건을 열어 본다 |
| 수정 | 이미 있는 데이터의 값이나 상태를 바꾼다. 승인·반려·취소처럼 상태를 바꾸는 처리도 여기에 쓰고, 상태가 움직이는 순서는 상태 전이 단계가 정한다 |
| 삭제 | 데이터를 없앤다. 언제 없애는지는 데이터 생애 단계가 정한다 |
| 목록 | 여러 건을 훑어 본다. 기간을 정해 훑는 것도 목록이다 |
| 검색 | 조건을 주고 찾는다 |
| 보관·숨김 | 지우지 않고 보이지 않게 하거나 보관 상태로 옮긴다 |
| 복원 | 삭제, 보관, 숨김을 되돌린다 |
| 가져오기 | 서비스 밖의 파일이나 시스템에서 여러 건을 한꺼번에 들여온다 |
| 내보내기 | 여러 건을 서비스 밖으로 한꺼번에 내보낸다 |
| 공유 | 다른 사용자나 서비스 밖에 보여 주도록 한다 |
| 감사 기록 | 누가 언제 무엇을 바꿨는지 남긴다. 주체는 기록 대상이 되는 처리를 일으키는 액터다 |

- 열두 가지 밖의 처리는 가장 가까운 처리 칸에 쓴다. 일괄 처리는 단건 처리와 같은 칸에 두고 접점에 일괄이라고 쓴다. 소유자를 바꾸는 일은 소유·권한 단계의 몫이다.
- **판정**은 행 단위로 정한다. 한 칸에 `제공` 행과 `후보` 행이 함께 있어도 된다.
  - `제공`: 앞 단계 산출물에서 그 주체가 그 엔티티에 그 처리를 하는 것을 찾았다. 근거에 그 항목의 ID나 필드 키를 쓴다.
  - `후보`: 앞 단계 산출물에서 찾지 못했지만 이 엔티티에 이 처리를 할 주체가 있어야 한다고 판단한다. 왜 있어야 하는지를 근거에 쓴다.
  - `제외`: 이 칸의 처리를 하지 않는다. 입력이 제공하지 않는다고 밝혔거나(제외 방침), 엔티티의 성질상 성립하지 않는다.
- `제외`는 칸 전체를 제공하지 않을 때만 쓰고 같은 칸의 다른 판정 행과 함께 쓰지 않는다. 특정 주체에게만 허용하지 않는 처리는 제외가 아니라 그 주체의 행을 쓰지 않는 것이다.
- **주체**는 처리를 일으키는 액터의 ID만 쓴다. 사람은 액터 목록(사람)의 ID, 사람이 아닌 주체는 액터 목록(비사람)의 ID다. 주체마다 접점이나 판정이 다르면 행을 나눈다.
  - 사용자의 조작에 딸려 일어나는 처리(알림 만들기, 감사 기록)는 그 조작을 하는 액터를 쓴다.
  - 시간이 일으키는 처리는 시간 트리거 액터를 쓴다.
  - `본인`, `시스템`, `서비스`는 액터가 아니므로 쓰지 않는다. 자기 것만 다루는지는 소유·권한 단계가 정한다. 일으키는 액터를 찾지 못하면 `미정`으로 닫고 확인처에 빠진 비사람 액터가 있는지 쓴다.
- **접점**은 이 처리가 제공되는 화면, 채널, 장소, 기능의 이름이다. 유저 플로우의 등장 화면이나 저니 매트릭스의 접점에서 가져온다. 새 화면 이름을 지어내지 않고, 이름이 아직 없으면 기능의 이름으로 쓴다.
- 판정이 `후보`인 행의 접점은 대개 정해진 곳이 없다. 이때 `미정`(확인처: 화면·UI 상태 단계의 담당, 기한: 이 문서의 완료 전)으로 닫는다.
- **근거**는 판정을 정한 자료다. `제공`은 플로우 ID, 질문 ID, 목표 ID 같은 앞 단계 항목으로 시작한다. `후보`는 같은 엔티티의 다른 처리가 있다는 사실이나 `가정:`으로 쓴다. `제외`는 제외 방침의 ID나 엔티티의 뜻을 확인한 자료로 시작한다. 근거마다 `;`로 나누고 설명만으로 된 조각을 따로 두지 않는다.
- 예시(형식 시연, 값이 아님): "FL-02 첫 분기; 내부 자료: 유저 플로우 등장 화면 표"(제공), "가정: 사용자가 만든 데이터는 사용자가 지울 수 있어야 한다고 본 것; 같은 엔티티의 생성이 FL-01에 있다"(후보), "CR-01"(제외)처럼 쓴다.
- 예시(형식 시연, 값이 아님): 스마트 온실 모니터링 서비스라면 측정값의 생성 주체는 장치 액터, 보존 기간 뒤 삭제의 주체는 시간 트리거 액터다. 측정값의 수정은 성질상 성립하지 않아 `제외`로 쓰고 주체와 접점을 `해당 없음`(기록은 고치지 않고 새로 쌓는다)으로 닫는다.

<!-- 해설: 후보목록 -->
### 3.3 후보 목록

- 매트릭스에서 판정이 `후보`인 행을 기능 단위로 묶어 쓴다. 한 기능이 여러 칸을 채우면 한 행에 쓰고 **칸**에 엔티티 ID 뒤에 처리 이름을 공백으로 이어 쓴 것을 쉼표로 나눈다.
- **기능 후보**는 그 칸에서 정의가 필요한 기능을 한 문장으로 쓴다. 해법을 정해 쓰지 않고 무엇을 정해야 하는지 쓴다.
- **잠정 도메인 구분**은 서비스 종류를 바꿔도 거의 모든 서비스에 있는 기능이면 `공통`, 이 서비스의 업무에만 있으면 `고유`다. 갈리면 `고유`를 고른다. 근거가 없으면 `미정`으로 닫고 확인처는 도메인 공통·고유 단계의 담당으로 쓴다. 확정은 뒤 단계가 한다.
- **근거**에는 후보를 도출한 칸과 입력 자료를 쓴다. 칸은 매트릭스의 엔티티 ID와 처리 이름으로 가리킨다.
- 후보가 하나도 없으면 한 줄만 쓴다. ID 칸에는 `CF-01`을 쓰고 나머지 칸은 `해당 없음`과 같은 사유로 닫으며 근거에는 점검한 매트릭스를 쓴다. 이때 매트릭스에 `후보` 행이 없어야 한다.
- 예시(형식 시연, 값이 아님): 어린이 독서 앱이라면 "읽은 기록 목록을 기간으로 걸러 본다", 병원 예약 서비스라면 "예약 변경 내역을 담당자가 조회한다"처럼 한 문장으로 쓴다.

## 4. 누락 점검

- 엔티티 목록의 모든 엔티티가 매트릭스에 나오고, 엔티티마다 처리 열두 가지가 모두 있는가.
- 사용자가 만든다고 한 엔티티에 수정이나 삭제를 하는 주체가 하나도 없지 않은가. 만드는 주체는 있는데 지우거나 고치는 주체가 없는 엔티티는 빠진 기능이다.
- 조회 행이 있는 엔티티에 목록이나 검색 행이 있는가. 한 건을 여는 길만 있고 찾는 길이 없는 엔티티를 확인한다.
- 사용자가 만드는 엔티티에 운영 액터가 다루는 행(조치, 숨김, 복원)이 있는가. 운영 액터가 있는데 이 엔티티에는 주체로 한 번도 나오지 않으면 점검한다.
- 삭제나 숨김이 있으면 복원 행도 따져 보았는가.
- 모든 `제공` 행의 주체가 액터 목록에 있고 접점이 입력의 이름인가. 접점을 입력에 없는 화면 이름으로 쓰지 않았는가.
- 판정이 `후보`인 행이 후보 목록에 모두 있고, 후보 목록의 칸이 매트릭스에 모두 `후보` 행으로 있는가.
- 유저 플로우에서 이 단계가 맡기로 한 목표가 매트릭스의 `제공` 행이나 `후보` 행으로 나오는가.
- 칸을 채우다 엔티티 목록에 없는 데이터 대상이 필요해 보이면 직접 고치지 않는다. 어느 대상이 왜 필요한지 사용자에게 알리고, 그 대상에 기대는 칸은 `미정`으로 닫는다.
- 판정이 `미정`인 행이 한 엔티티나 한 처리에 몰려 있지 않은가. 몰려 있으면 입력이 부족한 곳이다.

## 5. `미정`·`해당 없음` 판단

- 닫는 말은 판정이 `제외`인 행의 주체와 접점 칸에 쓴다. 사유는 둘 중 하나로 구체적으로 쓴다.
  1. 제외 방침이 있다. 사유에 방침의 ID와 요지를 쓴다.
  2. 엔티티의 성질상 처리가 성립하지 않는다. 사유에 엔티티가 어떤 것이어서 성립하지 않는지를 쓴다.
- "동일", "해당 없음"만 쓰는 것은 사유가 아니다. 입력에 언급이 없다는 이유만으로 `제외`나 `해당 없음`을 쓰지 않는다. 범위·제약과 정책 자료의 닫힌 목록이 배제하거나 엔티티의 뜻이 배제한다고 확인될 때만 쓴다. 그렇지 않으면 이 엔티티에 이 처리가 있어야 하는지 따져 `후보`나 `미정`으로 닫는다.
- **`미정`**은 이 칸의 처리가 필요한지, 누가 하는지, 어디서 하는지 입력으로 알 수 없을 때 쓴다.
  - 필요 여부를 모르면 판정, 주체, 접점을 모두 `미정`으로 닫는다.
  - 판정은 알지만 주체나 접점만 모르면 아는 칸은 값으로 쓰고 모르는 칸만 `미정`으로 닫는다. 주체의 일부만 알면 아는 ID를 먼저 쓰고 모르는 부분을 `미정`(확인처·담당·기한)으로 이어 쓴다.
- 삭제, 보관·숨김, 복원, 가져오기, 내보내기, 공유는 규제·정책, 소유·권한, 데이터 생애 같은 뒤 단계가 정하는 일에 기댄다. 이 단계에서 정책을 모르면 `제외`로 단정하지 말고 `미정`으로 닫는다. 확인처는 그 정책을 정하는 단계의 담당, 기한은 이 문서의 완료 전이다.
- 엔티티 목록 입력이 통째로 없으면 쓰기를 멈추고 사용자에게 알린다.

## 6. 흔한 실수

- 칸을 빠뜨린다. 엔티티마다 열두 처리를 모두 쓴다.
- 주체에 `본인`, `시스템`, `서비스` 같은 액터가 아닌 말을 쓴다.
- 앞 단계에서 찾지 못했는데 `제공`으로 쓴다. 찾지 못하면 `후보`다.
- 입력에 언급이 없다는 이유만으로 `제외`와 `해당 없음`을 쓴다.
- `제외` 행을 같은 칸의 `제공` 행이나 `후보` 행과 함께 쓴다.
- 제외 행의 근거에 방침 ID 없이 이유만 길게 쓴다.
- 접점에 입력에 없는 화면 이름을 지어낸다.
- 아직 정해지지 않은 삭제·내보내기 정책을 `제외`로 단정한다.
- 후보 목록의 칸이 매트릭스의 `후보` 행과 어긋난다.
- 근거에 설명만으로 된 조각을 `;`로 따로 둔다.
- 후보의 기능 문장에 해법이나 화면 설계를 쓴다.
- 샘플이나 예시의 엔티티와 처리를 값으로 옮긴다.
