## 1. 입력을 읽는 법

- **후보를 낸 앞 단계 산출물**: 유저 플로우의 미결 질문 목록, 시나리오 5유형의 추가 질문, CRUD 매트릭스의 후보 목록, 상태 전이의 후보 목록, 시간·주기의 기능 후보, 소유·권한의 접근 제어 기능 후보, 이벤트의 기능 후보가 후보 표다. 화면·UI 상태, 플랫폼·채널, 외부 연동 산출물에 후보 표가 있으면 그것도 읽는다. 후보마다 ID, 기능 후보 문장, 잠정 구분을 본다.
- 후보 표마다 ID 접두어가 다르다. 후보 ID는 입력의 것을 한 글자도 바꾸지 않고 옮긴다.
- 입력의 `구분` 열이 후속 후보나 설계 기준인 후보도 판정 대상이다. 구분을 이유로 빼지 않는다.
- **소유·권한 산출물**: 소유·공유·위임·승인 규칙의 구분과 모든 액터에게 허용된 행위는 권한·역할을 공통 기능으로 가를 때 읽는다. 해당 규칙과 행위의 ID를 공통 기능의 근거로 쓴다.
- 판정의 재료는 후보 문장이다. 프로젝트 자료에서 읽히는 만큼만 보태고, 읽히지 않는 것을 일반적으로 그럴 것이라고 채우지 않는다.
- 이 단계의 판정은 **기능을 기준으로 한다.** 여러 액터가 같은 방식으로 하는 목표인지는 액터 공통·고유 단계가 따로 판정했고 여기서 다시 쓰지 않는다. 두 판정은 다른 축이라 한쪽이 공통이어도 다른 쪽은 고유일 수 있다.
- 영역은 영역·모듈 단계가 정한다. 이 단계에서 영역 이름을 짓거나 후보를 영역에 배정하지 않는다.

## 2. 작성 절차

1. 후보 표를 모두 모아 후보 수를 센다. 후보 표마다 따로 센다.
2. 후보를 훑으며 같은 종류의 장치를 따로 필요로 하는 후보를 묶어 본다. 묶음은 판단하는 데 쓰는 메모이고 산출물에는 묶음 이름을 쓰지 않는다.
3. 묶음과 후보마다 3.2의 판정 질문을 순서대로 따진다.
4. 공통이나 혼합으로 판정한 후보가 가리킬 공통 기능을 공통 기능 표에 정의하고 `DC-01`부터 ID를 부여한다.
5. 후보 판정 표에 입력 후보마다 한 행을 쓰고 판정과 근거를 닫는다.
6. 혼합 후보 때문에 새로 정의할 기능이나 규칙이 있으면 신규 후보 표에 올리고 `DF-01`부터 ID를 부여한다. 공통 장치가 고유 정책을 받아 쓰는 접점과 입력 후보에 없는 고유 정책이 그 경우다.
7. 혼합 후보마다 혼합 분리 표에 고유 정책을 쓴다.
8. 집계를 세고 입력 후보 수와 맞춘다. 4절의 누락 점검을 하고 완료 체크를 확인한다.

## 3. 항목별 해설

<!-- 해설: 공통기능 -->
### 3.1 공통 기능

- 이 표는 여러 후보가 필요로 하는 기능을 **한 번만 정의하는 곳**이다. 뒤 단계는 공통 기능 하나를 한 번만 설계한다.
- **공통 기능**은 후보 문장에서 가져온 기능 이름으로 쓴다. 업종의 단어, 제품 이름, 구현 방식(어떤 인증 방식, 어떤 저장 방식)을 이름에 넣지 않는다. 입력에 방식이 정해져 있지 않으면 정하지 않는다.
- 공통 기능은 후보 판정 표에서 그 ID를 가리키는 후보가 한 개 이상 있어야 한다. 후보에 없는 범용 기능이 떠올라도 이 표에 쓰지 않는다. 표준 목록 대조 단계가 찾는다.
- **대표 호출 후보**는 이 기능을 부르는 후보 중 판정이 고유인 후보의 ID를 대표로 쓴다. 이 서비스의 고유 후보 대부분이 부르면 `전체`를 쓴다. 호출 관계 전체는 의존성 단계가 정하므로 빠짐없이 쓰지 않아도 된다. 부르는 후보가 하나뿐이어도 판정은 달라지지 않는다. 일부만 알면 아는 ID에 `미정`을 이어 쓴다.
- **근거**는 이 기능을 공통으로 본 후보의 ID로 시작하고 3.2의 질문 번호를 이어 쓴다. 다른 서비스에도 쓰인다는 사실을 입력에서 확인하지 못하면 `일반 지식(미검증)` 조각을 따로 쓴다.
- 예시(형식 시연, 값이 아님): 공통 기능의 근거는 `CF-003, 질문 2 예; VC-005, 같은 장치를 요구한다; 일반 지식(미검증): 다른 서비스에도 쓰이는 기능`처럼 조각마다 후보 ID나 출처 유형으로 시작한다.
- 예시(형식 시연, 값이 아님): 병원 예약 서비스라면 "예약 전 알림을 보낸다"와 "예약 변경을 알린다"가 서로 다른 앞 단계의 후보여도 공통 기능 "알림을 보낸다" 하나를 가리킨다. 사내 휴가 신청 도구라면 "첨부 파일을 올린다"가 공통 기능이 되고 대표 호출 후보는 신청과 증빙 후보의 ID다.

<!-- 해설: 후보판정 -->
### 3.2 후보 판정

- 입력 후보마다 한 행을 쓴다. 후보 ID와 기능 후보는 입력에서 그대로 옮긴다. 문장에 표를 깨는 세로선이 있으면 `/`로 바꾸고 근거에 원래 후보 ID를 쓴다. 입력의 ID 뒤에 설명이 붙어 있으면 ID만 옮긴다.
- **잠정 구분**은 입력 산출물이 붙인 값을 옮긴다. 입력의 값이 `미정`이면 이 칸도 `미정`(확인처·담당·기한)으로 닫는다. 후보를 낸 산출물에 잠정 구분 칸이 없으면 `해당 없음`과 그 사실(산출물 이름과 칸이 없음)을 사유로 쓴다.
- **판정**은 하나만 고른다. 아래 질문을 순서대로 따지고 먼저 답이 나오는 쪽을 쓴다.
  1. 후보 하나 안에 이 서비스의 업무 개념 없이 쓸 수 있는 부분과 이 서비스만의 정책이 함께 있고, 두 부분을 각각 한 문장으로 쓸 수 있는가. 그렇다면 `혼합`이다.
  2. 이 서비스의 업무 개념(서비스가 다루는 데이터 대상, 거래나 심사 같은 업무의 이름) 없이 정의되고 다른 서비스에 그대로 가져다 쓸 수 있는가. 그렇다면 `공통`이다.
  3. 서로 다른 업무 개념을 다루는 고유 후보가 둘 이상 부르며 부르는 방식이 일반적인가(대상 종류를 인자로 받는 것처럼). 그렇다면 `공통`이다.
  4. 모두 아니면 `고유`다.
- 질문 1의 `혼합`은 정책이 장치 안에 설정이나 등록으로 들어갈 수 있을 때만 쓴다. 규칙이 기능의 본질이라 떼어 내면 남는 것이 없으면 분리하지 않고 `고유`로 두고, 분리하지 않은 사유를 근거에 쓴다.
- 공통과 고유 사이에서 갈리면 `고유`를 고르고 갈린 이유를 근거에 쓴다. 공통이라는 근거 없이 공통으로 두지 않는다. 후보 문장이 너무 짧아 질문에 답할 수 없을 때만 `미정`(확인처·담당·기한)으로 닫는다.
- 잠정 구분과 판정이 다르면 근거에 어느 질문의 답이 달랐는지 쓴다.
- 같은 종류의 장치를 필요로 하는 후보는 낸 앞 단계가 달라도 같은 공통 기능 ID를 쓴다. 후보를 하나로 합치지는 않는다. 병합은 통합·정규화 단계가 한다.
- **공통 기능 ID**는 판정이 공통이면 그 후보가 가리키는 공통 기능, 혼합이면 공통 부분의 공통 기능을 쓴다. 고유이거나 `미정`이면 `해당 없음`과 판정(고유 또는 판정 미정)을 사유로 쓴다.
- **근거**는 후보 ID로 시작하고 판정 질문의 번호와 답을 쉼표로 이어 쓴다. 비교한 다른 후보가 있으면 그 ID로 시작하는 조각을 `;`로 나눠 더한다. `;`는 근거와 근거를 나눌 때만 쓴다.
- 예시(형식 시연, 값이 아님): 근거 칸은 `HQ-004, 질문 2 예: 문장에 업무 개념이 없다; TC-002, 같은 알림 장치를 요구한다`처럼 쓴다. 모든 조각이 후보 ID나 출처 유형으로 시작한다.
- 예시(형식 시연, 값이 아님): 어린이 독서 앱의 "보호자 동의를 받고 기록한다"는 질문 1에서 동의 받기·철회·이력(업무 개념 없음)과 연령 구간별 요건(이 서비스의 규칙)이 함께 있어 혼합이다. 스마트 온실 서비스의 "온실별 목표 온도 범위를 정한다"는 질문 2가 아니오, 질문 3이 아니오라 고유다. 병원 예약 서비스의 "진료 일정 목록을 본다"는 잠정 구분이 공통이어도 문장에 진료과가 들어 있어 질문 2가 아니오이고, 바뀐 이유를 근거에 쓴다.

<!-- 해설: 신규후보 -->
### 3.3 신규 후보

- 혼합 분리에서 새로 정의가 필요해진 기능이나 규칙을 쓴다. 입력 후보에 이미 있으면 올리지 않고 혼합 분리 표의 고유 정책 후보에 그 ID를 쓴다.
- 신규 후보가 생기는 경우는 둘이다. 공통 장치가 고유 정책을 받아 쓰려면 새로 필요한 접점(대상 종류를 인자로 받기, 문구나 한도를 등록하기)과, 혼합 후보의 고유 정책을 담은 후보가 입력에 없는 경우의 그 정책이다.
- **출처**는 이 후보가 나온 혼합 후보의 ID다.
- **구분**은 앞 단계들과 같은 뜻이다. 기능으로 정의할 것은 `기능 후보`, 장치를 어떻게 구성할지의 결정이고 기능이 아닌 것은 `설계 기준`이다. `후속 후보`는 입력 산출물이 후속으로 미룬 항목에서 나온 경우에만 쓴다. 구분을 고르기 어렵다고 `미정`을 쓰지 않고 `기능 후보`를 쓴다.
- **공통·고유(확정)**는 공통 장치 쪽 접점이면 `공통`, 이 서비스의 정책이면 `고유`다. 갈리면 `고유`다.
- 혼합 후보가 없거나 새 후보가 필요 없으면 한 줄을 쓰고 모든 칸을 `해당 없음`과 같은 사유(혼합 판정이 없다, 입력 후보로 충분하다)로 닫는다.
- 예시(형식 시연, 값이 아님): 사내 휴가 신청 도구라면 "승인 장치가 결재선을 등록받는 접점"은 `공통`, 스마트 온실 서비스라면 "기준 값을 넘을 때 알리는 규칙을 정한다"는 고유 정책을 담은 후보가 입력에 없어 `고유`로 올린다.

<!-- 해설: 혼합분리 -->
### 3.4 혼합 분리

- 판정이 혼합인 후보마다 한 행 이상을 쓴다. 고유 정책이 여럿이면 정책마다 행을 나눈다.
- 공통 부분은 후보 판정 표의 공통 기능 ID가 가리키므로 여기에 다시 쓰지 않는다.
- **고유 정책**은 공통 부분을 떼어 내고 남는 이 서비스만의 규칙을 정책, 문구, 한도, 대상 범위 중 무엇인지 드러나게 한 문장으로 쓴다.
- **고유 정책 후보**는 그 정책을 이미 담은 입력 후보의 ID이거나 3.3에서 올린 신규 후보의 ID다. 둘 다 아니면 `미정`(확인처·담당·기한)으로 닫는다.
- **근거**에는 공통 부분과 고유 부분을 가른 후보 문장의 위치를 쓴다.
- 혼합 후보가 하나도 없으면 한 줄을 쓰고 모든 칸을 `해당 없음`과 같은 사유(후보 판정 표에 혼합 판정이 없다)로 닫는다.
- 예시(형식 시연, 값이 아님): 어린이 독서 앱이라면 고유 정책 "연령 구간별로 보호자 동의가 필요한 기능이 다르다", 병원 예약 서비스라면 "예약 전날 알림 문구는 진료과마다 다르다"처럼 정책과 문구를 구분해 쓴다.

<!-- 해설: 집계 -->
### 3.5 집계

- 숫자는 후보 판정 표의 행을 세어 쓴다. 근거는 센 표를 가리키는 참조(`20 도메인 공통·고유 2번 표`처럼 `NN 산출물 이름`)로 시작한다.
- 판정 미정 후보 수는 판정 칸이 `미정`인 행의 수다. 0이어도 `0`을 쓴다.
- 입력 후보 수는 입력 산출물의 후보 표 행을 모두 더한 값이다. 근거에 후보 표마다 `NN 산출물 이름 n번 표`로 시작하는 조각으로 행 수를 쓴다.
- 합계는 앞의 네 수를 더한 값이고 입력 후보 수와 같아야 한다. 다르면 후보가 빠졌거나 두 번 적혔으므로 판정 표를 고친다.

## 4. 누락 점검

- 입력 산출물의 모든 후보가 판정 표에 한 번씩 있는가. 후보 표마다 행 수를 맞춰 보았는가.
- 같은 종류의 장치(알림, 파일, 동의, 기록, 예약 실행 등)를 서로 다른 앞 단계의 후보가 따로 요구하는데 고유로 따로 남겨 두지 않았는가.
- 한 후보 안에 정책과 장치가 섞인 문장을 공통이나 고유 하나로 쓰지 않았는가.
- 공통으로 둔 후보 문장에 업종의 단어나 서비스의 업무 개념이 들어 있지 않은가.
- 공통 기능마다 가리키는 후보가 있고, 후보에 없는 기능을 만들어 넣지 않았는가.
- 대표 호출 후보의 ID가 모두 판정이 고유인 후보인가.
- 혼합 후보마다 고유 정책이 혼합 분리 표에 있고, 그 정책을 담은 후보나 신규 후보가 있는가.
- 소유·권한 산출물이 넘긴 규칙과 행위 중 공통 기능이 될 것을 놓치지 않았는가.

## 5. `미정`·`해당 없음` 판단

- **`미정`**: 후보 문장이 너무 짧아 판정 질문에 답할 수 없는 후보의 판정, 입력에서 `미정`인 잠정 구분, 부르는 후보를 알 수 없는 대표 호출 후보, 담은 후보도 신규 후보도 정하지 못한 고유 정책 후보에 쓴다. 선택지 칸, ID 칸에서도 값을 모르면 `미정`으로 닫는다. 확인처는 후보를 낸 앞 단계 산출물이나 그 담당 역할, 기한은 이 문서의 완료 전으로 쓴다.
- 칸의 일부만 모르면 아는 값에 `미정`(확인처·담당·기한)을 이어 쓴다. 칸 전체를 `미정`으로 닫지 않는다.
- 입력 후보 표가 하나도 없으면 표를 채울 수 없으므로 쓰기를 멈추고 알린다(공통 가이드 1절). 입력이 얇아 `미정`이 많은 것은 구조의 문제가 아니다. 칸을 줄이려고 행을 묶거나 생략하지 않는다.
- **`해당 없음`**: 공통 기능 ID는 판정이 고유이거나 `미정`일 때 쓴다. 입력에 언급이 없다는 사실만으로 `해당 없음`을 쓰지 않는다. 공통 기능 표는 공통이나 혼합 판정이 하나도 없을 때만 한 줄을 쓰고 모든 칸을 `해당 없음`과 같은 사유(판정 표에 공통과 혼합이 없다)로 닫는다.
- `해당 없음`은 칸마다 `해당 없음(사유)` 모양으로 쓴다. 한 줄을 통째로 닫을 때도 모든 칸에 사유를 괄호로 쓴다.
- 공통 판정이 하나도 없으면 후보를 다시 훑는다. 같은 장치를 요구하는 후보를 고유로 따로 둔 것이 아닌지 본다.

## 6. 흔한 실수

- 후보 문장이 흔한 기능처럼 보인다는 이유만으로 공통으로 판정한다. 문장에 업무 개념이 없는지 질문으로 확인한다.
- 질문 1을 건너뛰고 공통이나 고유로 끝낸다. 섞인 후보는 두 부분이 모두 남아야 한다.
- 후보 하나하나를 판정하지 않고 범위나 묶음으로 판정한다.
- 영역이나 묶음 이름을 산출물에 쓴다.
- 공통 기능 이름에 구현 방식이나 제품 이름을 넣는다.
- 공통 기능을 가리키는 후보 없이 공통 기능을 만든다.
- 액터 공통·고유의 판정을 가져와 기능의 공통·고유로 쓴다.
- 근거 칸을 후보 ID로 시작하지 않고 설명 문장으로 시작한다. 맞는 모양은 `내부 자료: 요구사항 메모 2절, 입력에 언급 없음`처럼 쉼표로 이어 쓰는 것이다.
- 잠정 구분과 판정이 달라졌는데 이유를 쓰지 않는다.
