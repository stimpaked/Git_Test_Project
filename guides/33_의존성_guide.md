## 1. 입력을 읽는 법

- **기능 트리**(계층·ID·태그 산출물)가 가장 중요한 입력이다. 행마다 기능 ID, 영역, 공통·고유 구분, 후속 표시, 근거 ID, 저니 단계를 본다. 이 단계의 모든 기능 칸은 여기 있는 최종 기능 ID이고 한 글자도 바꾸지 않는다. 임시 번호나 후보 ID를 기능 ID 칸에 쓰지 않고, 기능 트리에 없는 기능을 만들어 쓰지 않는다. 기능 트리가 없으면 쓰기를 멈추고 알린다(공통 가이드 1절).
- **기능 목록**(통합·정규화 산출물)은 기능의 설명과 병합한 후보 ID를 준다. 이벤트, 외부 연동, 품질 같은 앞 단계 입력은 기능이 아니라 후보 ID로 기능을 가리키므로 병합 후보 칸에서 그 후보를 찾아 기능 ID로 바꾼다. 기능 설명은 호출과 선행을 읽어 내는 재료이다.
- **공통 기능 목록**(도메인 공통·고유 산출물)은 호출받는 쪽의 기준이다. 항목의 `DC-` ID와 대표 호출 후보(그 공통 기능을 부르는 고유 후보)를 본다. 후보 판정 표의 공통 기능 ID가 후보와 공통 기능을 잇는다. 혼합 분리 표의 고유 정책은 주입 정책의 재료이다.
- **영역·모듈**의 호출 방향 원칙과 영역의 공통·고유 구분은 호출과 선후행이 지킬 방향이다. 영역의 구분과 기능 트리의 구분이 어긋나면 기능 트리를 따르고 어긋남을 근거에 쓴다.
- **이벤트**의 발생 기능과 알림·로그 소비 기능, **외부 연동**의 연동 기능과 연동 대상 액터, **비기능·품질**에서 기능으로 올린 후보는 호출의 단서이다. 입력은 단서일 뿐이고 호출은 기능 설명에서 필요가 읽힐 때만 쓴다.
- 기능 이름이나 영역이 닮았다는 이유로, 또는 저니 단계의 앞뒤만 보고 호출이나 선행을 만들지 않는다. 입력에 없는 호출, 선행, 기능을 지어 쓰지 않는다.
- 입력의 ID에 공백이나 괄호가 붙어 있으면 ID 형식에 맞는 부분만 칸에 쓰고 원래 표기는 근거 칸에 적는다.

## 2. 작성 절차

1. 기능 트리를 위에서 아래로 읽고 공통·고유가 공통인 기능을 가려 둔다.
2. 호출 표를 쓴다. 입력의 단서에서 시작해 기능 설명으로 필요를 확인하고 행마다 `DP-01`부터 ID를 부여한다.
3. 선후행 표를 쓴다. 호출로 쓸 수 없는 필요를 모은다.
4. 호출과 선후행을 함께 따라가며 방향 위반, 기능 트리에 없는 ID, 순환을 찾는다.
5. 웨이브 표를 쓴다. 기능 트리의 모든 기능에 한 행씩 쓰고 `DW-01`부터 ID를 부여한다.
6. 공통 기능 검사 표를 쓴다. 공통 기능마다 한 행이다.
7. 집계를 세고 4절의 누락 점검을 한 뒤 완료 체크를 확인한다.

## 3. 항목별 해설

<!-- 해설: 호출 -->
### 3.1 호출

- 호출은 한 기능이 공통 기능의 동작을 쓰는 것이다. 행 하나는 호출 기능과 호출받는 기능의 쌍 하나이다. 공통 기능이 다른 공통 기능을 부르는 것도 호출이다. 화면이나 액터가 기능을 쓰는 것은 호출이 아니다.
- **호출 기능**은 기능 트리의 기능 ID 하나이다. 호출하는 쪽의 구분은 묻지 않는다.
- **호출받는 기능**은 공통·고유가 공통인 기능의 ID이다. 고유 기능을 호출받는 쪽에 쓰지 않는다. 고유 기능이 다른 고유 기능을 필요로 하는 것은 호출이 아니라 선후행이다. 필요한 공통 기능이 기능 트리에 없으면 기능을 만들어 쓰지 않고 이 칸을 `미정`(확인처: 기능 목록 담당 역할)으로 닫고 호출 이유에 필요한 기능을 한 문장으로 쓴다. 이 행이 정의 없는 호출이다.
- **공통 기능**은 호출받는 기능이 구현하는 공통 기능 목록의 `DC-` ID 하나이다. 호출받는 기능의 병합 후보에 달린 공통 기능 ID에서 찾는다. 기능 하나가 항목 여럿을 걸치면 이 호출이 쓰는 항목을 쓴다. 반대로 항목 하나를 기능 여럿이 나눠 구현하면 호출받는 기능에는 호출 후보의 동작을 구현하는 기능을 쓰고, 동작으로 가를 수 없으면 `미정`(확인처: 기능 목록 담당 역할)으로 닫는다. 그 항목을 구현하는 기능이 하나도 없으면(후보가 모두 설계 기준이나 프로세스라 제외되었다) 호출 행을 만들지 않고 사용자에게 알린다. 어느 항목도 찾지 못하면 `미정`(확인처: 공통·고유를 판정한 단계의 담당 역할)으로 닫고 근거에 찾아본 표를 쓴다.
- **주입 정책**은 호출 기능이 설정이나 템플릿으로 넘기는 고유 정책이다. 혼합 분리 표에 호출받는 기능의 공통 기능이 오르고 그 고유 정책을 호출 기능에 병합된 후보가 담고 있으면 고유 정책을 한 문장으로 옮긴다. 아니면 `해당 없음`(사유: 혼합 분리 표에 이 호출이 넘기는 정책이 없다)이다. 고유 정책을 담은 후보가 병합된 기능이 그 공통 기능을 부르면 그 기능이 호출 기능이고 정책은 이 칸에 쓴다. 정책 후보를 따로 호출 행으로 내지 않는다. 입력의 정책을 고쳐 쓰거나 지어 쓰지 않는다.
- **호출 이유**는 호출 기능이 호출받는 기능에서 얻는 것을 한 문장으로 쓴다. 같은 쌍을 둘 이상의 이유로 부르면 행을 나누지 않고 이유를 한 문장으로 모은다. 호출받는 기능이 연동 기능이면 어느 외부 액터와 이어지는지를 이유에 쓴다. 외부 액터는 기능이 아니므로 기능 칸에 쓰지 않는다.
- **근거**는 호출을 보여 준 입력으로 시작한다. 이벤트 행, 대표 호출 후보, 연동 기능 후보 같은 입력의 ID나 `NN <산출물 이름>` 참조를 쓰고 `;`로 나눈다. 기능 ID는 조각의 첫머리에 두지 않고 `32 기능 트리`처럼 산출물을 가리키는 참조 뒤에 쉼표로 이어 쓴다.
- 예시(형식 시연, 값이 아님): 병원 예약 서비스라면 근거는 `16 이벤트 이벤트 목록의 예약 확정 행, 알림 소비 기능이 확정 안내를 보낸다; DC-02, 알림 공통 기능`이고 호출 이유는 "예약 확정을 환자에게 알리려고 알림을 보낸다"이다. 어린이 독서 앱이라면 `내부 자료: 기능 목록 설명 3행, 표지 사진을 올린다`로 시작해 사진 올리기 공통 기능을 부르는 행을 쓴다.

<!-- 해설: 선후행 -->
### 3.2 선후행

- 선후행은 기능을 하려면 먼저 있어야 하는 다른 기능이다. 행 하나는 후행 기능과 선행 기능의 쌍 하나이다.
- 호출로 쓴 쌍은 호출받는 기능이 호출 기능보다 먼저 있어야 한다는 뜻이 웨이브에 이미 담기므로 선후행에 다시 쓰지 않는다. 호출이 아닌 필요, 곧 고유 기능 사이의 필요나 공통 기능이 공통 기능을 먼저 요구하는 필요만 쓴다.
- **후행 기능**이 공통이면 **선행 기능**도 공통이어야 한다. 공통 기능이 고유 기능을 선행으로 요구하면 쓰지 않고 구분이 맞는지 기능 트리를 다시 본다. 구분이 틀렸다고 판단하면 사용자에게 알리고 직접 고치지 않는다.
- **선행 이유**는 선행 기능이 없으면 후행 기능이 동작하지 않는 이유를 한 문장으로 쓴다. 기능 설명에서 필요가 읽히지 않으면 행을 만들지 않는다.
- 선행이 필요한 것은 확실한데 어느 기능인지 모르면 선행 기능을 `미정`(확인처·담당·기한)으로 닫고 행을 둔다.
- 예시(형식 시연, 값이 아님): 사내 휴가 신청 도구라면 승인 기능이 신청 기능을 선행으로 삼고 이유는 "승인할 신청이 먼저 있어야 한다"이다. 병원 예약 서비스라면 예약 취소가 예약 생성을 선행으로 삼는다.

<!-- 해설: 웨이브 -->
### 3.3 웨이브

- 행 하나는 기능 트리의 기능 하나이다. 모든 기능이 정확히 한 행에 나온다. 후속 기능도 같은 규칙으로 쓴다.
- **웨이브**는 구현 순서의 번호이다. 선행이 없으면 0이다. 선행이 있으면 선행 기능의 웨이브 가운데 가장 큰 값에 1을 더한 값이다. 선행은 이 기능을 호출 기능으로 삼은 호출 행의 호출받는 기능과 이 기능을 후행 기능으로 삼은 선후행 행의 선행 기능이다. 선행의 웨이브를 먼저 정한 뒤에 계산한다. 같은 웨이브의 기능은 병렬로 만들 수 있다.
- **기준 선행**은 웨이브를 정한 가장 늦은 웨이브의 선행 기능 하나이다. 같은 웨이브에 선행이 여럿이면 ID가 가장 앞선 것을 쓴다. 선행이 없으면 `해당 없음`(사유: 호출과 선후행에서 이 기능이 뒤에 오는 행이 없다)이다.
- 선행 기능이 `미정`이거나 선행의 웨이브가 `미정`이거나 순환에 든 기능은 웨이브를 정할 수 없다. 웨이브와 기준 선행을 `미정`(확인처·담당·기한)으로 닫고 근거에 원인이 된 행을 쓴다. 선행이 없는 것처럼 0을 쓰지 않는다.
- 기능 트리의 기능 ID가 `미정`(영역이 `미정`)인 기능도 한 행을 갖는다. 기능 칸을 `미정`(확인처: 영역·모듈 담당 역할)으로 닫고 근거의 첫 조각을 `31 통합·정규화 기능 목록 FN-007`처럼 임시 번호를 가리키는 참조로 써서 행을 구별한다. 웨이브는 정할 수 있는 만큼 정한다.
- **ID**는 웨이브 번호가 작은 행부터, 같은 웨이브 안에서는 기능 ID 순으로 부여한다. `미정` 행은 맨 뒤에 둔다.
- **근거**는 기준 선행이 나온 호출 행의 `DP-` ID로 시작한다. 선후행 행이면 `33 의존성 2번 표`처럼 표를 가리키는 참조로 시작하고 쉼표로 행을 설명한다.
- 예시(형식 시연, 값이 아님): 병원 예약 서비스라면 선행이 없는 알림 발송 기능은 웨이브 0이고 기준 선행이 `해당 없음`이다. 그 기능을 부르는 예약 확정 기능이 선후행으로 예약 생성 기능(웨이브 1)도 요구하면 확정 기능의 웨이브는 2이고 기준 선행은 예약 생성 기능이다. 사내 휴가 신청 도구라면 선행이 없는 신청 기능이 웨이브 0, 신청을 선행으로 삼는 승인 기능이 웨이브 1이다.

<!-- 해설: 검사 -->
### 3.4 공통 기능 검사

- 행 하나는 기능 트리의 공통 기능 하나이다. 공통·고유가 공통인 기능이 모두 정확히 한 행 나온다.
- **판정**은 하나만 고른다. 호출 표에 이 기능을 호출받는 기능으로 삼은 행이 있으면 `호출됨`이다. 없으면 직접 근거를 찾는다. 기능 트리의 근거 ID가 가리키는 항목이 이 기능을 호출 없이도 요구하면(사용자나 운영자가 직접 쓰는 기능, 규제나 장치가 직접 부르는 입구 기능 같은 것) `직접 근거로 유지`이고, 직접 근거도 없으면 `과잉 의심`이다. 호출처가 없다는 사실만으로 지우거나 `과잉 의심`으로 정하지 않는다.
- `과잉 의심`은 기능을 없애는 결정이 아니다. 지우지 않고 남겨 역추적 검증이 판단하게 한다.
- 기능 트리의 기능 ID가 `미정`인 공통 기능은 공통 기능 칸을 `미정`으로 닫고 근거의 첫 조각을 임시 번호를 가리키는 참조(`31 통합·정규화 기능 목록 FN-007`)로 쓴다.
- 근거 ID에 공통 기능 목록 항목(`DC-`)이 아닌 항목(목표, 규제, 위협, 사용자 조사 등)이 하나라도 있으면 호출 없이도 요구하는 직접 근거로 인정한다.
- **직접 근거**는 판정이 `직접 근거로 유지`일 때 근거 ID를 쉼표로 쓴다. `호출됨`이면 `해당 없음`(사유: 호출 행이 있다), `과잉 의심`이면 `해당 없음`(사유: 호출처도 직접 근거도 없다)이다.
- **근거**는 `호출됨`이면 호출 행의 `DP-` ID로, 나머지는 기능 트리의 해당 행을 가리키는 참조로 시작한다.
- 예시(형식 시연, 값이 아님): 사내 휴가 신청 도구에서 호출처가 없는 로그 보관 기능이 감사 요구 항목을 근거 ID로 가지면 `직접 근거로 유지`이다. 어린이 독서 앱에서 호출처도 근거 ID도 모호한 점수 계산 기능은 `과잉 의심`이다.

### 3.5 집계

- 숫자는 표의 행을 세어 쓴다. 근거는 센 표를 가리키는 참조(`33 의존성 1번 표`처럼 `NN 산출물 이름`)로 시작한다. 0이어도 `0`을 쓴다.
- 입력 기능 수와 입력 공통 기능 수는 기능 트리에서 세고 근거에 `32 계층·ID·태그`의 기능 트리를 가리킨다.
- 호출 방향 위반 수와 선후행 방향 위반 수는 0이어야 한다. 0이 아니면 행을 고친다. 고유 기능을 호출받는 쪽에 쓴 행은 선후행으로 옮기고, 구분이 틀렸다고 보이면 사용자에게 알린다.
- 정의되지 않은 참조 수는 기능 트리에 없는 ID를 쓴 칸의 수이며 0이 되도록 고친다. 호출 대상 미정 수는 정의 없는 호출의 수이며 0이 아닐 수 있다.
- 순환 수는 순환 하나를 하나로 센다. 자기 자신을 호출하거나 선행으로 삼는 행도 순환이다. 순환이 있으면 근거에 순환에 든 기능 ID를 모두 쓰고 호출이나 선후행을 지워서 없애지 않는다. 순환은 기능이 잘못 나뉘었다는 신호일 수 있으므로 사용자에게 알린다.
- 판정별 수와 검사 합계는 공통 기능 검사 표에서 센다. 검사 합계는 입력 공통 기능 수와 같아야 한다. 웨이브 행 수는 입력 기능 수와 같아야 하고 웨이브 수는 웨이브 칸의 서로 다른 번호의 수이다.
- 후속 의존 수는 후속이 아닌 기능이 후속으로 표시된 기능을 호출받는 기능이나 선행 기능으로 삼은 행의 수이다. 0이 아니면 근거에 해당 행을 쓰고 후속 기능을 앞당겨야 하는지는 우선순위·릴리스 단계의 판단에 맡긴다.

## 4. 누락 점검

- 기능 트리의 공통 기능이 모두 공통 기능 검사 표에 있는가.
- 이벤트의 발생 기능이 알림이나 로그 소비 공통 기능을 부르는 호출 행을 가졌는가.
- 연동 기능을 쓰는 기능이 연동 기능을 부르는 호출 행을 가졌는가.
- 공통 기능 목록의 대표 호출 후보가 가리키는 기능이 그 공통 기능을 부르는 호출 행을 가졌는가.
- 품질 후보에서 기능으로 올린 공통 기능을 부르는 기능이 호출 행을 가졌는가.
- 고유 기능 사이의 필요가 호출로 쓰이지 않았는가. 호출에 쓴 쌍이 선후행에 다시 쓰이지 않았는가.
- 같은 호출 기능과 호출받는 기능의 쌍이 호출 표에 두 번 나오지 않는가.
- 기능 트리의 모든 기능이 웨이브 표에 한 번씩 있고 웨이브 번호가 기준 선행과 맞는가.
- 호출과 선후행을 따라가면 순환이 없는가. 호출 기능과 호출받는 기능이 같은 행이 없는가.
- 후속이 아닌 기능이 후속 기능에 기대는 행을 집계에 세었는가.

## 5. `미정`·`해당 없음` 판단

- **`해당 없음`**: 그 개념이 이 프로젝트에 없다고 입력으로 확인했을 때 쓴다. 기능 트리에 공통·고유가 공통인 기능이 하나도 없으면 호출 표와 공통 기능 검사 표를 각각 한 줄로 쓴다. ID 칸에는 `DP-01`을 쓰고 나머지 칸을 `해당 없음`과 같은 사유(기능 트리에 공통인 기능이 없다)로 닫는다. 영역의 호출 방향 원칙이 `해당 없음`이어도 같다.
- 입력에 언급이 없다는 사실만으로는 `해당 없음`이 아니다. 기능 트리를 닫힌 목록으로 보고, 그 목록이 개념을 배제할 때만 목록을 사유로 들어 쓴다. 호출이 없다고 보이는 기능은 행을 쓰지 않을 뿐이지 행에 `해당 없음`을 쓰지 않는다.
- **`미정`**: 입력만으로 알 수 없을 때 쓴다. 호출받는 기능, 공통 기능, 선행 기능, 웨이브, 기준 선행, 판정이 그 예이다. 선택지 칸, ID 칸, 숫자 칸에서도 값을 모르면 `미정`(확인처·담당·기한)으로 닫는다. 확인처는 기능 트리나 공통 기능 목록의 담당 역할, 기한은 이 문서의 완료 전으로 쓴다.
- 칸의 일부만 모르면 아는 값을 쓰고 모르는 부분을 `미정`(확인처·담당·기한)으로 이어 쓴다. 직접 근거에 ID 하나만 알면 그 ID에 `미정`을 잇는다.
- 호출 방향 원칙이 `미정`이면 영역 사이의 방향은 확인하지 못했다고 근거에 쓰고, 호출받는 기능이 공통이어야 한다는 규칙은 기능 트리의 구분으로 지킨다.
- 입력이 얇아 `미정`이 많아지는 것은 구조의 결함이 아니다. 호출을 지어서 칸을 채우지 않고, 칸 수를 줄이려고 행을 합치지 않는다.
- 공통 기능 목록이 없으면 호출 표의 공통 기능 칸을 `미정`으로 닫는다. 이벤트, 외부 연동, 품질 후보가 없으면 그 단서로 쓸 호출이 없을 뿐이며 근거에 기능 설명을 쓴다.

## 6. 흔한 실수

- 고유 기능을 호출받는 쪽에 쓴다. 고유 기능 사이의 필요를 호출로 쓴다.
- 호출에 쓴 쌍을 선후행에도 쓴다. 같은 쌍을 이유마다 행으로 나눈다.
- 공통 기능이 고유 기능을 선행으로 삼는다.
- 필요한 공통 기능이 기능 트리에 없는데 비슷한 이름의 기능을 호출받는 쪽으로 대신 쓴다.
- 기능 ID 자리에 임시 번호나 후보 ID를 쓴다. 기능 트리에 없는 기능을 만든다.
- 외부 액터나 화면을 기능 칸에 쓴다.
- 웨이브를 선행 없이 0으로 쓰거나 기준 선행의 웨이브와 맞지 않는 번호를 쓴다. 웨이브를 정할 수 없는 기능을 0으로 쓴다.
- 호출처가 없다는 이유만으로 공통 기능을 `과잉 의심`으로 쓰거나 기능에서 지운다.
- 순환을 해소한 것처럼 호출이나 선후행 행을 지운다. 순환 수를 0으로 쓴다.
- 기능 ID로 근거 조각을 시작한다. 맞는 모양은 `32 기능 트리 기능 F-AAA-003, 설명에 알림 발송이 있다`처럼 산출물을 가리키는 참조 뒤에 쉼표로 잇는 것이다.
- 근거 칸을 설명으로 시작한다. 맞는 모양은 `내부 자료: 기능 목록 설명 3행, 입력에 언급 없음`처럼 쉼표로 이어 쓰는 것이다.
- 샘플이나 예시의 기능과 ID를 값으로 옮긴다.
