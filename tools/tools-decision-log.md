## B. 결정

### DL-TL-001 · 근거 칸 형식 검사의 범위를 정한다
- **날짜:** 2026-10-08
- **대상:** `tools/checks.py`의 `check_deliverable` (CM-K04, CM-K06)
- **결정 주체:** 유지보수자 판단
- **배경:** 출처 유형을 근거 칸의 형식으로 쓰기로 했다(DL-SD-011).
- **검토한 대안:** (a) 접두어만 검사한다 / (b) 유형별로 함께 적을 것(확인일 등)까지 검사한다
- **결정:** (a). 근거마다 `;`로 나눈 첫머리가 네 출처 유형(`유형:`)이거나 참조(`NN `, `NN.`, `AC-01` 같은 ID)인지 본다. `조사`의 확인일 유무는 검사하지 않는다.
- **이유:** 확인일 형식은 문서마다 달라 오탐이 많을 것이다. 사용해 본 뒤 필요하면 더한다.
- **영향:** 한계 LM-08.
- **상태:** 검토 대기

### DL-TL-002 · 산출물 검사의 셀 해석을 고친다
- **날짜:** 2026-10-08
- **대상:** `tools/checks.py` (`_closing`, `split_outside_parens`)
- **결정 주체:** 유지보수자 판단
- **배경:** 도메인 교체 시험(04번 변환 분석서 DT-03, DT-06)에서 작성 에이전트가 `` `미정`(...) ``처럼 백틱으로 감싸 쓰자 CM-K02·K04·K06이 이 칸을 `미정`으로 인식하지 못했고(K06이 18칸을 0으로 출력), 근거 칸 괄호 안의 `;`를 경계로 읽어 K04가 실패했다.
- **검토한 대안:** 해당 없음 — 버그 수정이다.
- **결정:** 백틱을 뗀 뒤 `미정`·`해당 없음`을 판정하고, `;`는 괄호 밖의 것만 경계로 본다.
- **이유:** 검사가 규칙 위반을 놓치면 안 된다.
- **영향:** 부분 `미정`(칸의 일부에만 있는 경우)은 세지 않는다는 한계가 남았다(LM-09).
- **상태:** 검토 대기

### DL-TL-003 · 칸의 일부에 있는 `미정`도 검사한다
- **날짜:** 2026-10-08

- **배경:** 규칙_공통 CM-07이 값과 `미정`의 병기를 허용했다(DL-CM-004). 도구는 칸이 `미정`으로 시작할 때만 인식했다(LM-09).

- **결정:** 칸 안의 `미정`(백틱 허용) 뒤 괄호를 찾아 그 안에 확인처·담당·기한이 모두 있는지 본다. 괄호가 없으면 실패다. CM-K06은 `미정`이 들어 있는 칸의 수를 센다.
- **이유:** 규칙대로 값과 `미정`이 섞인 칸을 정확히 센다.

### DL-TL-004 · 산문 속 "미정"이라는 단어는 `미정` 칸으로 세지 않는다
- **날짜:** 2026-10-08
- **대상:** `tools/checks.py` (`undecided_spans`)
- **결정 주체:** 유지보수자 판단
- **배경:** 재시험에서 근거 칸의 설명 문장에 쓴 "미정"이라는 단어를 도구가 `미정` 칸으로 읽어 CM-K02가 실패했다(04번 변환 분석서 DT-12). DL-TL-003으로 칸 어디에 있어도 찾게 한 부작용이다.

### DL-TL-008 · 환류 줄은 받는 단계의 입력 블록에 나오지 않는다
- **날짜:** 2026-10-08
- **대상:** `tools/build.py` (`connections_for`)
- **결정 주체:** 유지보수자 판단
- **배경:** 08번의 환류 줄(판정이 `미정`인 목표를 07번으로 돌려보냄)이 07번 템플릿의 입력 블록에 "08 액터 공통·고유"로 나와, 07이 08에 기대는 순환처럼 보였다(07번 변환 분석서 DT-05).
- **검토한 대안:** (a) 환류 줄도 입력으로 보인다 / (b) 보내는 쪽의 "쓰이는 곳"에만 환류로 보인다

### DL-TL-009 · 산출물 묶음의 ID 참조 검사 `check_chain.py`를 더한다
- **날짜:** 2026-10-08
- **대상:** `tools/check_chain.py`, `tools/README.md`
- **결정 주체:** 유지보수자 판단
- **배경:** 그룹 E 도메인 교체 시험에서 한 산출물이 다른 산출물의 ID를 잘못 세어 참조했는데(17의 UC-17), `check_deliverable.py`는 산출물 하나만 보아 잡지 못했다(conversions/18 DT-05).
- **검토한 대안:** (a) `check_deliverable.py`에 다른 산출물 경로를 받게 한다 / (b) 산출물 묶음을 받는 별도 도구를 둔다 / (c) 사람이 대조한다
- **결정:** (b). 넘겨받은 산출물의 값 표에서 정의 ID(접두어-번호)를 모으고, 본문과 표의 `접두어-번호` 참조가 모두 정의되어 있는지 본다(CH-K01 실패). 정의된 ID 수는 정보로 낸다(CH-K02).

- **영향:** 한계 LM-12. 규칙 문서(`docs/규칙_*.md`)의 검사 표에는 아직 없다. 규칙으로 올릴지는 수정목록 G12에서 정한다. 시험에서 두 도메인의 산출물 18개에 돌려 실패 0이었다.
- **상태:** 검토 대기
