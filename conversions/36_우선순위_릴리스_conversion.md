# 변환 분석서 — 36. 우선순위·릴리스

> 샘플 `36_우선순위_릴리스.md`를 템플릿 `templates/36_우선순위_릴리스_template.md`로 바꾸는 과정의 분석 기록이다(`docs/규칙_변환분석서.md`).
> 샘플은 장기 삭제 대상이라 샘플 요소는 원문 발췌로 인용한다. 샘플의 오류와 도메인 편향은 이 문서에만 기록하고 샘플은 고치지 않는다.
> 샘플의 슬라이스 표 세 개(MVP 99행, R1 34행, Later 13행), 게이트 표 두 개, 웨이브 11행, 보정·선정 이유·트랙 표는 같은 틀을 되풀이하므로 값은 표 단위로 묶어 한 줄로 해부했다(CV-06). 다만 열과 선택지처럼 템플릿의 열과 선택지가 되는 것은 따로 해부했다.
> 04·05번과의 차이: 이 단계는 후보를 찾지도, 기능 사이에 관계를 붙이지도 않는다. 이미 확정된 기능 트리의 기능에 값 몇 개(우선순위, 릴리스, 공수, 게이트)를 붙이고, 그 값을 정하는 판정 근거(게이트, 용량, 재검토)와 확정 선언(기준선)을 따로 기록하는 단계다. 그래서 행의 단위가 기능 한 개의 판정, 게이트 조건 한 개, 릴리스 한 개의 용량, 기준선 선언 한 개로 갈린다. 또 공수 추정, 개발 용량, 베이스라인 선언은 사람이 하는 일이라 칸만 두고 값은 외부 입력으로 받는다(OM-02, OM-03, OM-23). 샘플은 이 값들을 지어낸 가정으로 채웠다(SA-13).
> 샘플은 우선순위와 릴리스를 한 열에 섞고(SA-30), 기능 게이트를 두 곳에 쓰며(OM-10), 뒤 단계 결과와 앞 단계 표를 되풀이한다(SA-50). 이 차이가 표 구성에 반영된 곳은 SA-14~SA-21, SA-41~SA-48, SA-58~SA-69와 OM-01~OM-29다.

## ③ 도메인 교체 시험

작성 에이전트 역할의 별도 세션 둘에게 이 단계의 템플릿과 단계 가이드, 공통 가이드, 규칙_공통 3절, 도메인별 입력 자료와 이전 단계 산출물(01~33번 시험 산출물)만 주고 34번, 35번, 36번을 순서대로 쓰게 했다. 둘은 서로의 결과를 보지 못했고 이 분석서와 결정 로그도 읽지 않았다. 도메인은 가상이며 앞선 시험과 같다. 시험으로 쓴 산출물은 이 문서에 넣지 않는다(CV-12). 사람이 하는 활동 입력은 도메인 A에는 일부만 있는 가상 기록(프로토타입 3과제, 역할 6개의 의견과 서명, 개발 용량, 공수 6건, 오너, 변경요청 절차)을 주었고 도메인 B에는 하나도 주지 않았다. 산출물마다 `tools/check_deliverable.py`로 구조와 공통 규칙을 검사했다(두 도메인 모두 실패 0, 경고 0). 22~30번 후보를 20번에 환류하지 않은 상태에서 썼고, 그 결과 후보 판정 완결 규칙이 갭을 낸 것은 의도한 시험이다. 변환 분석서의 상태는 사용자가 마지막에 한꺼번에 확인할 때까지 `초안`이다.
