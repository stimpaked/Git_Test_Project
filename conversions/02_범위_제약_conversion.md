# 변환 분석서 — 02. 범위·제약

> 샘플은 표 아홉 개로 이루어져 있고 값이 많은 표(포함 영역 11행, 제외 8행, 후속 13행, 제약 6행, 가정 5행, 의존성 5행, 리스크 2행)는 칸 값을 표 단위로 묶어 한 줄로 해부했다(CV-06).
> 이 단계는 앞 단계 산출물이 아니라 사람이 주는 자료(목표·가치 산출물, 사업 맥락, 기한·예산·팀)를 입력으로 받는다. 뒤 단계(액터 목록부터 플랫폼·채널, 외부 연동까지)의 가이드와 템플릿이 이 산출물에서 무엇을 읽겠다고 썼는지를 먼저 찾아 템플릿의 표와 필드 이름을 그 읽기에 맞췄다(DL-02-008).

## ③ 도메인 교체 시험

작성 에이전트 역할의 별도 세션 둘에게 이 단계의 템플릿과 단계 가이드, 공통 가이드, 규칙_공통 3절, 도메인별 입력 자료(01·02·03의 요약)만 주고 01번부터 03번까지 순서대로 산출물을 쓰게 했다. 둘은 서로의 결과를 보지 못했고 이 분석서와 결정 로그도 읽지 않았다. 앞 단계 산출물은 다음 단계의 입력으로 이어 썼다. 도메인은 가상이며 앞선 시험과 같다. 시험으로 쓴 산출물은 이 문서에 넣지 않는다(CV-12). 산출물마다 `tools/check_deliverable.py`로 구조와 공통 규칙을, 세 산출물 묶음에 `tools/check_chain.py`로 ID 참조를 검사했다(실패 0). 입력 자료가 사업 아이디어, 사업 맥락 같은 원자료가 아니라 결과의 요약이었으므로 `미정`이 많은 것은 입력 부족이다. 변환 분석서의 상태는 사용자가 그룹 단위로 확인할 때까지 `초안`이다.
