### 도메인 대입

대입한 가상 도메인은 사내 휴가 신청 도구, 공공 정보 조회 웹, 병원 예약 서비스, 스마트 온실 모니터링 서비스 네 가지다.

| ID | 발견 내용 | 발견 방법 | 처리 |
|---|---|---|---|
| OM-16 | 사내 휴가 신청 도구는 웹 하나이고 기기 권한을 쓰지 않으며 오프라인을 지원하지 않는다. 화면 대부분에서 기기 권한 거부와 오프라인이 성립하지 않아 `제외` 행이 많아진다 | 도메인 대입: 사내 휴가 신청 도구 | 반영: 17.비정상상태.판정(`제외`와 동작 칸의 사유). 닫는 기준은 단계 가이드 5절이 맡는다(플랫폼 목록이 배제할 때만 쓴다) |
| OM-17 | 공공 정보 조회 웹은 로그인하는 사람이 없어 세션 만료, 접근 권한 없음, 이용 제한이 개념 자체가 없다. 검색 결과가 없는 것은 빈 상태다 | 도메인 대입: 공공 정보 조회 웹 | 반영: 17.비정상상태.판정(`제외`). 사유는 액터 목록에 로그인하는 사람이 없다는 사실로 쓴다고 단계 가이드 5절이 맡는다 |
| OM-18 | 병원 예약 서비스는 취소되거나 마감된 예약의 주소를 열면 화면이 대상을 찾지 못한다. 같은 예약 확인 화면을 환자와 보호자가 함께 쓰므로 사용 액터가 둘이다 | 도메인 대입: 병원 예약 서비스 | 반영: 17.비정상상태.상태(대상 없음), 17.화면인벤토리.사용 액터(ID를 쉼표로 여럿) |
| OM-19 | 병원 예약 서비스의 접수 키오스크는 로그인 없이 일정 시간 입력이 없으면 진행하던 입력이 사라진다. 로그인이 풀리는 것과 같은 처리가 필요하다 | 도메인 대입: 병원 예약 서비스 | 반영하지 않음: 세션 만료 상태의 뜻에 일정 시간 입력이 없어 끊긴 경우를 포함해 단계 가이드 3.2가 맡는다 |

## ③ 도메인 교체 시험

작성 에이전트 역할의 별도 세션 둘에게 이 단계의 템플릿과 단계 가이드, 공통 가이드, 규칙_공통 3절, 도메인별 입력 자료(01 목표·가치, 02 범위·제약, 03 근거 수집의 요약)와 이전 단계 산출물만 주고 17번부터 21번까지 순서대로 산출물을 쓰게 했다. 둘은 서로의 결과를 보지 못했고 이 분석서와 결정 로그도 읽지 않았다. 앞 단계 산출물(04~16번 시험 산출물 포함)은 다음 단계의 입력으로 이어 썼다. 도메인은 가상이며 앞선 시험과 같다. 시험으로 쓴 산출물은 이 문서에 넣지 않는다(CV-12). 산출물마다 `tools/check_deliverable.py`로 구조와 공통 규칙을, `tools/check_chain.py`로 산출물 사이의 ID 참조를 검사했다. 변환 분석서의 상태는 사용자가 그룹 단위로 확인할 때까지 `초안`이다.
