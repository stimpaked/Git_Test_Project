# 변환 분석서 — 34. 역추적 검증

> 샘플 `34_역추적_검증.md`를 템플릿 `templates/34_역추적_검증_template.md`로 바꾸는 과정의 분석 기록이다(`docs/규칙_변환분석서.md`).
> 샘플은 장기 삭제 대상이라 샘플 요소는 원문 발췌로 인용한다. 샘플의 오류와 도메인 편향은 이 문서에만 기록하고 샘플은 고치지 않는다.
> 샘플의 규칙 17행, 갭 로그 4행, 의도적 제외 13행, 추적 매트릭스의 표 셋(목표 6행, 저니 칸 31행, 사용자 목표 67행)은 같은 틀을 되풀이하므로 값은 표 단위로 묶어 한 줄로 해부했다(CV-06). 다만 규칙 17개는 템플릿의 규칙 종류가 되므로 따로 해부했다.
> 04·05번과의 차이: 04·05번은 후보를 찾는 질문에서 시작하지만 이 단계는 후보를 새로 찾지 않는다. 앞 단계 산출물의 항목 하나하나가 기능에 이어졌는지, 기능 하나하나가 근거를 갖는지를 규칙으로 검사하고 드러난 갭을 환류로 돌려보내는 단계다. 행의 단위가 검증 규칙 하나, 규칙의 대상 항목 하나, 갭 하나, 의도적 제외 항목 하나라서 표 구성도 규칙 → 추적 → 갭 로그 → 의도적 제외 → 집계 순서다. 이 차이가 표 구성에 반영된 곳은 SA-11~SA-34, SA-50~SA-55와 OM-01~OM-20이다.
> 샘플은 규칙 17개 가운데 셋(목표, 저니 칸, 사용자 목표)만 추적 행을 보이고 나머지는 건수만 적는다(OM-01). 그 건수가 맞는지 다시 셀 수 없고, 규칙의 대상 수를 행 수로 확인하는 일이 이 단계 검사의 핵심이다.
> 사람이 하는 활동(조치를 앞 단계 산출물에 반영하는 일)은 입력으로 받는다. 이 단계는 조치가 반영된 입력으로 재실행하기 전에는 갭을 `해소`로 쓰지 않는다(OM-09).

## ③ 도메인 교체 시험

작성 에이전트 역할의 별도 세션 둘에게 이 단계의 템플릿과 단계 가이드, 공통 가이드, 규칙_공통 3절, 도메인별 입력 자료와 이전 단계 산출물(01~33번 시험 산출물)만 주고 34번, 35번, 36번을 순서대로 쓰게 했다. 둘은 서로의 결과를 보지 못했고 이 분석서와 결정 로그도 읽지 않았다. 도메인은 가상이며 앞선 시험과 같다. 시험으로 쓴 산출물은 이 문서에 넣지 않는다(CV-12). 사람이 하는 활동 입력은 도메인 A에는 일부만 있는 가상 기록(프로토타입 3과제, 역할 6개의 의견과 서명, 개발 용량, 공수 6건, 오너, 변경요청 절차)을 주었고 도메인 B에는 하나도 주지 않았다. 산출물마다 `tools/check_deliverable.py`로 구조와 공통 규칙을 검사했다(두 도메인 모두 실패 0, 경고 0). 22~30번 후보를 20번에 환류하지 않은 상태에서 썼고, 그 결과 후보 판정 완결 규칙이 갭을 낸 것은 의도한 시험이다. 변환 분석서의 상태는 사용자가 마지막에 한꺼번에 확인할 때까지 `초안`이다.
