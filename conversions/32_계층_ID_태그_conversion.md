# 변환 분석서 — 32. 계층·ID·태그

> 샘플 `32_계층_ID_태그.md`를 템플릿 `templates/32_계층_ID_태그_template.md`로 바꾸는 과정의 분석 기록이다(`docs/규칙_변환분석서.md`).
> 샘플은 장기 삭제 대상이라 샘플 요소는 원문 발췌로 인용한다. 샘플의 오류와 도메인 편향은 이 문서에만 기록하고 샘플은 고치지 않는다.
> 샘플의 기능 트리 146행과 영역별 표 16개는 같은 틀을 되풀이하므로 값은 표 단위로 묶어 한 줄로 해부했다(CV-06). 다만 열 이름과 열 값의 종류(ID, 태그, 등급, 이력)처럼 템플릿의 열이 되는 것은 따로 해부했다.
> 31번(통합·정규화)과의 차이: 31번은 후보를 모아 기능 하나로 합치는 단계라 행의 단위가 병합이고, 이 단계는 합쳐진 기능을 고치지 않고 위치(영역, 기능군), 이름표(기능 ID, 임시 번호와의 대응), 태그, 근거를 붙이는 단계다. 행의 단위가 기능 하나로 고정되고 새 판단은 모두 칸 단위 부착이다. 사용자가 확정한 설계(DL-05-005 방식, 이 그룹의 쟁점 1~4)에 따라 31번은 임시 번호 `FN-`를 쓰고 이 단계가 최종 기능 ID `F-<영역 코드>-nnn`를 붙인다. 이 차이가 표 구성에 반영된 곳은 SA-04, SA-13, SA-17, SA-29와 OM-01~OM-09, OM-12, OM-13이다.

## ③ 도메인 교체 시험

작성 에이전트 역할의 별도 세션 둘에게 이 단계의 템플릿과 단계 가이드, 공통 가이드, 규칙_공통 3절, 도메인별 입력 자료와 이전 단계 산출물(01~30번 시험 산출물)만 주고 31번, 32번, 33번을 순서대로 쓰게 했다. 둘은 서로의 결과를 보지 못했고 이 분석서와 결정 로그도 읽지 않았다. 도메인은 가상이며 앞선 시험과 같다. 시험으로 쓴 산출물은 이 문서에 넣지 않는다(CV-12). 산출물마다 `tools/check_deliverable.py`로 구조와 공통 규칙을, 01~33번 산출물 묶음에 `tools/check_chain.py`로 ID 참조를 검사했다(두 도메인 모두 ID 참조 실패 0). 후보 전수 소진은 풀의 후보 표를 직접 읽는 별도 스크립트로 확인했다(도메인 A 후보 203건, 도메인 B 198건이 모두 기능 목록의 병합 후보와 제외 목록 중 한 곳에 정확히 한 번 나왔고 빠진 것, 겹친 것, 풀에 없는 것이 없었다). 후보 풀의 시험 산출물은 후보 표 열 통일(G13) 이전 모양이라 도구가 알아보는 후보 표는 일부(A 82건, B 86건)뿐이었다. 변환 분석서의 상태는 사용자가 마지막에 한꺼번에 확인할 때까지 `초안`이다.
