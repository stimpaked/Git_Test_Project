- [ ] 검증 규칙 표에 최소 규칙 종류가 모두 있고 목표는 비즈니스 목표와 사용자 목표, 화면은 역방향과 순방향, 상태·이벤트·타이머는 셋, 영역 배정은 기능·엔티티·목표의 행이 각각 있다
- [ ] 추적 표의 규칙 칸이 모두 검증 규칙 표의 `KV-` ID이고 대상 수가 추적 표에서 센 그 규칙의 행의 수와 같다
- [ ] 검증 규칙 표의 통과 수와 갭 수의 합이 대상 수와 같다
- [ ] 기능 트리의 모든 기능이 기능 근거 규칙의 추적 행에 정확히 한 번 있다
- [ ] 판정이 통과인 행의 이은 항목이 입력에 있는 ID이거나 앞 단계가 제외한 항목의 ID이거나 `해당 없음`(사유)이다
- [ ] 판정이 갭인 행의 이은 항목이 `해당 없음`(사유)이고 그 행이 갭 로그의 추적 행에 나온다
- [ ] 갭 로그의 조치 유형이 기능 추가, 태그 수정, 기능 삭제인 행은 대상 기능 ID가 기능 ID이고 환류 대상 단계에 32가 있다
- [ ] 조치 유형이 기능 추가나 기능 삭제인 행은 환류 대상 단계에 33도 있다
- [ ] 조치 유형이 의도적 제외인 갭마다 의도적 제외 표에 갭 칸이 그 갭의 ID인 행이 있다
- [ ] 의도적 제외 표의 제외 항목이 두 번 나오지 않는다
- [ ] 상태가 해소인 갭은 조치가 반영된 입력으로 확인했고 재실행 횟수가 1 이상이거나 의도적 제외 표에 행이 있다
- [ ] 집계의 조치 유형별 수의 합이 갭 로그 수와 같고 해소 수와 미해소 수의 합이 갭 로그 수와 같다
- [ ] 입력 기능 수가 기능 근거 규칙의 대상 수와 같다
- [ ] 미해소 갭이 0이다(0이 아니면 이 항목을 `[ ]`로 두고 갭 ID를 사유에 쓴다)
- [ ] 입력에 없는 ID, 기능, 근거가 값으로 쓰이지 않았다
