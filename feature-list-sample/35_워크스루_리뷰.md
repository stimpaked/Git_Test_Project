## 1. 검증 방법

역추적(34)은 문서 사이의 연결 누락을 잡지만, **"사람이 실제로 써보면 빠진 것"**은 잡지 못합니다. 그래서 세 가지 방법으로 보완합니다.

| 방법 | 수행 내용 | 참여 |
|---|---|---|
| E2E 워크스루 | 페르소나·운영자별로 하루를 시나리오로 따라가며 기능 ID가 이어지는지 확인 | PM, 디자인, 개발 |
| 역할별 인스펙션 | 법무·보안·CS·재무·마케팅·데이터·QA·개발·디자인이 자기 관점의 체크리스트로 Feature List 검토 | 역할별 1인 |
| 프로토타입 테스트 | 클릭 프로토타입으로 사용자 5명이 과제 3개 수행. "여기 ○○가 없네요"가 나오는 지점이 누락 | 사용자 5명(가상) |

## 4. 프로토타입 테스트

- **대상:** 사용자 5명(구매자 3, 판매자 2, 가상), 클릭 프로토타입
- **과제:** ① 가입부터 첫 채팅까지 ② 글 등록부터 판매완료까지 ③ 불편한 사용자를 신고하기
- **방법:** 말하며 사용(think-aloud). 진행자는 힌트를 주지 않고 "찾지 못한 것"과 "있을 거라 기대한 것"을 기록
