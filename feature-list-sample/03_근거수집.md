## 0. 출처 유형 (모든 뿌리 항목에 필수)

뿌리 항목 = 이후 모든 기능의 근거가 되는 항목(01 가설 H, 02 가정 AS, 03 인사이트 IN·유사 서비스 CMP·규제 RG·기술 제약 TC). 각 항목에 아래 넷 중 하나를 표시한다.

| 출처 유형 | 의미 | 근거로 인정 |
|---|---|---|
| 조사 | 링크·일자·버전·캡처 등을 제시할 수 있는 실제 확인(앱 사용, 공식 문서, 법령 원문, 실제 인터뷰 기록) | ✔ |
| 내부 자료 | 사내 데이터, 계약·정책 문서, 기존 서비스 지표 | ✔ |
| 일반 지식(미검증) | 기억·상식에 의존한 것. 출처를 제시할 수 없음 | ✘ |
| 가정 | 확인 전까지 참이라고 두는 것 | ✘ |

**실제 프로젝트에서 유사 서비스 기능표(CMP)를 만드는 방법:** ① 같은 문제를 같은 사용자에게 푸는 서비스 3~5개 선정 ② 앱스토어 설명·릴리스 노트·공식 도움말·약관을 읽고 직접 설치해 가입~탈퇴를 써보며 캡처 ③ 행은 발견된 기능의 합집합 ④ 칸마다 ○△×와 함께 근거(링크·일자·앱 버전)를 적고 확인 못 한 칸은 "미확인" ⑤ 외부에서 보이지 않는 기능(백오피스·내부 정책)은 한계로 표시. 이 절차를 거친 항목만 "조사"로 표시한다.

## 5. 근거 사용 규칙

- 인사이트(IN)는 최소 1개의 기능 후보 또는 가설 검증에 연결되어야 한다.
- 규제(RG)는 23번에서 **기능 / 프로세스 / 정책** 중 하나로 반드시 매핑한다.
- 유사 서비스 기능(CMP)은 30번에서 **채택 / 제외 / Later / 갭**으로 판정한다.
- 03번은 초반에 시드(04~07)로 쓰고, 후반에 30번에서 **대조용으로 다시** 쓴다.
