### DL-01-001 · 01번 변환 분석서와 템플릿 v1.0, 단계 가이드 v1.0 초안을 작성한다
- **날짜:** 2026-10-09
- **대상:** `conversions/01_목표_가치_conversion.md`, `templates/01_목표_가치_template.md`, `guides/01_목표_가치_guide.md` (작업 순서 6단계, 그룹 A의 첫 단계)
- **결정 주체:** 사용자 승인
- **배경:** 그룹 단위 진행을 승인함(DL-05-005). 01번은 체계의 맨 앞이어서 앞 단계 산출물이 없고 입력은 사업 아이디어, 사업 맥락, 이해관계자 기대처럼 사람이 주는 자료다(SA-05). 샘플 해부 55행(SA-01~55)과 누락 탐색 19행(OM-01~19)을 같은 절차로 만들었다. 도메인 교체 시험(③)은 템플릿과 가이드를 쓴 뒤에 하므로 아직 하지 않았고 분석서 상태는 `초안`이다.
- **검토한 대안:** (a) 04·05번처럼 도출 질문 → 후보 → 판정 → 목록으로 구성한다 / (b) 샘플의 여덟 절을 그대로 표로 옮긴다 / (c) 단계 정의의 산출물 순서대로 값 표를 두고 표 사이의 이어짐을 ID 참조 열로 쓴다
- **결정:** (c). 속성 표 4개(서비스정의, 문제정의, 가치제안, 수익모델)와 목록 표 5개(가치목록, 목표지표, 핵심가설, 이해관계자기대, 초기리스크)로 구성한다. 필드는 40개이고 정의 ID 접두어는 `BV`(가치), `BG`(목표), `BH`(가설), `BR`(리스크)다. 선택 블록과 표 없는 필수 절은 없다. 지시한 접두어 규칙(`B`로 시작)을 지켰고 기존 접두어와 겹치지 않는다(TP-28).

- **상태:** 유효

### DL-01-002 · 표 순서와 연결 방향: 가치 → 목표 → 가설 → 리스크, 가설이 가치와 목표를 가리킨다
- **날짜:** 2026-10-09
- **대상:** `templates/01_목표_가치_template.md` 가치목록, 목표지표, 핵심가설, 초기리스크 표 (SA-20, SA-26, SA-35, OM-02, OM-03)
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 가치 표가 `근거 가설`로 5절의 가설을 먼저 참조하고(SA-20), 목표 표가 `연결 가설`로 가설을 참조하며(SA-26), 가설 표가 `관련 목표`로 목표를 참조한다(SA-35). 세 표가 서로를 가리켜 작성 순서가 정해지지 않고 같은 연결이 두 곳에 있다. 가치 표에는 ID도 없다(OM-02).
- **검토한 대안:** (a) 가치와 목표가 가설을 가리키게 하고 가설 표를 먼저 둔다 / (b) 가설이 가치와 목표를 가리키게 하고 가치 목록, 목표와 지표를 먼저 둔다 / (c) 가치와 목표 표에 가설 열을 두고 가설 표에도 목표 열을 두어 양쪽에 쓴다
- **결정:** (b). 가치에 `BV` ID를 부여하고, 가설 표에 `관련 가치`와 `관련 목표` 열을 둔다. 가치 표의 `근거 가설`과 목표 표의 `연결 가설`은 두지 않는다. 리스크 표의 `영향받는 목표`는 앞에 있는 목표 표를 가리킨다.
- **이유:** 가설은 다른 항목의 근거가 되는 뿌리 항목이다(CM-02). 뿌리가 가치와 목표를 가리키는 방향이 뒤 단계의 근거 수집이 가설 하나를 확인할 때 어느 가치와 목표가 흔들리는지 바로 읽는 방향과 같다. (a)는 가설이 가치와 목표 앞에 와서 가설이 무엇의 가설인지 읽기 어렵다. (c)는 한 사실을 두 곳에 써서 어긋날 수 있다(정의서 4절).
- **영향:** 샘플의 "가치마다 근거 가설"은 가설 표에서 가치별로 거꾸로 읽어야 한다. 가치에 이어진 가설이 없다는 사실은 표가 직접 보여 주지 않고 누락 점검(가이드 4절)이 확인한다.
- **상태:** 검토 대기

### DL-01-003 · 정의 ID 접두어는 `BV`, `BG`, `BH`, `BR`로 쓴다
- **날짜:** 2026-10-09
- **대상:** `templates/01_목표_가치_template.md` 가치목록, 목표지표, 핵심가설, 초기리스크 표 (SA-23, SA-31, SA-46)
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 서비스 목표를 `G-`, 가설을 `H-`, 리스크를 `RK-`로 쓴다. `G`는 07번이 사용자 목표의 정의 ID로 이미 쓰고(DL-07-005), `RK-`는 범위·제약 샘플이 `RK-06`부터 이어 쓰는 접두어다. 이 호출은 `B`로 시작하는 접두어만 쓰도록 정했다.
- **검토한 대안:** (a) 가치 `BV`, 목표 `BG`, 가설 `BH`, 리스크 `BR` / (b) 한 글자 `B` 하나를 가치, 목표, 가설, 리스크에 함께 쓴다 / (c) 샘플의 `G`, `H`, `RK`를 `B`를 앞에 붙여 `BG`, `BH`, `BRK`로 쓴다
- **결정:** (a). 번호는 `BV-01`, `BG-01`, `BH-01`, `BR-01`부터 연번으로 쓴다.
- **이유:** (b)는 접두어 하나가 네 표의 ID를 모두 부여해 어느 표의 ID인지 알 수 없고 TP-28이 허용하지 않는다. (c)의 `BRK`는 (a)의 `BR`보다 길 뿐 이점이 없다. (a)는 모두 두 글자이고 이름의 첫 글자(Value, Goal, Hypothesis, Risk)로 읽힌다. 기존 접두어(A, AC, AQ, AR, NC, NQ, X, G, K, ...)와 겹치지 않는다.
- **영향:** 07번 DL-07-005가 걱정한 `G` 충돌이 생기지 않는다. 02·03번 세트는 각각 `O`, `M`으로 시작하는 접두어를 쓰므로 겹치지 않는다. 뒤 단계가 목표 ID를 `G-`로 읽는 문장이 있으면 `BG-`로 고쳐야 한다(06·07번 가이드는 ID 형식을 쓰지 않아 해당 없음을 확인했다).
- **상태:** 검토 대기

### DL-01-004 · 뒤 단계가 이 산출물에서 읽는 것에 맞춰 열과 이름을 정했다
- **날짜:** 2026-10-09
- **대상:** `templates/01_목표_가치_template.md` 전체, `tools/data/interfaces.csv` (SA-07, OM-02, OM-07)
- **결정 주체:** 유지보수자 판단
- **배경:** 뒤 단계(04~21번)의 가이드와 결정 로그에서 01번을 가리키는 곳을 찾았다. 04번은 목표(액터의 주요 목표 근거에 인용)와 이해관계자 기대(이해관계자 표의 출발점)를 읽는다. 06번은 가치제안과 핵심 가설에서 핵심 가치를 찾고 목표의 ID를 접점·불편의 연결 목표에 쓴다. 07번은 서비스 목표를 근거 칸에 인용할 수 있다고 쓴다. 16번은 목표의 지표를 분석 칸을 정할 때 쓴다. 나머지 단계 가이드(05, 08~15, 17~21번)는 01번을 읽겠다고 쓰지 않았다.
- **검토한 대안:** (a) 뒤 단계의 문구에 맞춰 열 이름을 짓는다 / (b) 샘플의 열 이름을 그대로 쓴다 / (c) 뒤 단계 가이드의 문구를 고친다

### DL-01-005 · 목표와 지표: 한 줄에 지표 하나, 기준값 추가, 목표값은 자료의 숫자만 쓴다
- **날짜:** 2026-10-09
- **대상:** `templates/01_목표_가치_template.md` 목표지표 표, `guides/01_목표_가치_guide.md` 3.5절 (SA-25, SA-28, OM-07, OM-08, OM-14, OM-18)
- **결정 주체:** 사용자 결정
- **배경:** 샘플의 G-06은 서로 다른 지표 둘을 `/`로 한 칸에 묶었고(SA-28), 목표값에는 현재 수준이 없어 개선 목표인지 알 수 없다(OM-08). 목표값은 샘플도 "샘플 가정"이라 밝혔다. 뒤 단계(출시 게이트, 측정 이벤트, 분석)는 목표값과 지표를 그대로 읽는다.
- **검토한 대안:** (a) 샘플처럼 한 줄에 지표를 여럿 묶을 수 있게 한다 / (b) 한 줄에 지표 하나만 쓰고 지표가 다르면 같은 목표 문장으로 줄을 나눈다 / (c) 목표 표와 지표 표를 따로 둔다. 기준값 열은 (가) 두거나 (나) 두지 않는다. 목표값은 (다) 자료에 숫자가 없으면 계획용 값을 `가정`으로 쓰게 하거나 (라) `미정`으로 닫는다
- **결정:** (b)와 (가)와 (라). 목표 표의 한 줄은 지표 하나다. 기준값 열을 더한다. 목표값은 자료에 숫자가 있을 때만 쓰고 없으면 `미정`으로 닫는다고 단계 가이드에 쓴다.
- **이유:** (a)는 지표마다 목표값과 측정 방법을 읽을 수 없다. (c)는 목표와 지표의 일대일 대응을 두 표로 나눠 ID 참조를 늘린다. (가)는 개선형 서비스에서 목표값의 뜻을 정한다(OM-08). (다)는 틀려도 나중에 바로잡을 수 있는 값이 아니라 출시 기준으로 읽힌다. 입력에 없는 사실을 만들지 않는 보수적인 쪽(라)을 골랐다. 이 경우 입력이 얇으면 `미정`이 많아지나 이는 입력 부족이다.
- **영향:** 같은 목표 문장이 줄마다 반복된다. 28번과 36번이 지표 단위로 읽을 수 있다. 공통 가이드는 근거가 없고 틀렸을 때 바로잡을 수 있는 값은 `가정`으로 쓸 수 있다고 하므로(공통 가이드 3절) 이 단계 가이드가 목표값에 한해 더 보수적인 기준을 둔다. 사용자가 확인한다.
- **상태:** 유효

### DL-01-006 · 수익 모델 방향: 도입 조건은 두지 않고 돈을 내는 쪽을 둔다
- **날짜:** 2026-10-09
- **대상:** `templates/01_목표_가치_template.md` 수익모델 표 (SA-39, SA-40, SA-41, OM-09, OM-12, OM-19)
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 "Later: ... 도입 조건은 02번의 Later 목록에 기록한다"고 밝혔다(SA-40). 범위·제약의 후속 목록이 사유와 재검토 조건을 갖는다. 한편 쓰는 사람과 돈을 내는 사람이 다른 서비스(OM-12)와 조직이 돈을 내는 서비스(OM-19)에서 샘플의 시점별 선언만으로는 돈의 방향을 알 수 없다.
- **검토한 대안:** (a) 출시 시점과 이후 각각에 방향, 이유, 도입 조건을 둔다 / (b) 출시 시점 방향, 이유, 돈을 내는 쪽, 이후 후보만 두고 도입 조건은 범위·제약의 후속 목록에 맡긴다 / (c) 돈을 내는 쪽을 두지 않는다
- **결정:** (b). 속성 표 네 항목으로 쓴다. 수익을 두지 않기로 한 결정은 값이고 수익이라는 개념 자체가 없는 서비스만 `해당 없음`으로 닫는다고 단계 가이드에 쓴다(OM-09).
- **이유:** (a)는 도입 조건을 두 곳에 써서 어긋날 수 있다(정의서 4절). (c)는 수익 모델 단계가 돈이 오가는 지점의 지불 주체를 정할 때 읽을 입력이 없다. 이후 후보가 후속 목록으로 가므로 조건은 그쪽이 갖는다.
- **영향:** 수익 모델 단계가 재검토 조건을 쓸 때 01번이 아니라 범위·제약의 후속 목록을 읽어야 한다. 02번 세트가 후속 목록의 사유와 재검토 조건을 갖는지 합칠 때 확인한다.
- **상태:** 검토 대기

### DL-01-007 · 핵심 가설의 검증 시점은 선택지 세 개로 닫고 단계 번호를 쓰지 않는다
- **날짜:** 2026-10-09
- **대상:** `templates/01_목표_가치_template.md` 핵심가설 표 (SA-33, SA-34, SA-36)

### DL-01-013 · 그룹 A 병합: 입력 줄을 더하고 잠정 줄을 필드 키로 바꾼다
- **날짜:** 2026-10-09
- **대상:** `tools/data/interfaces.csv`
- **결정 주체:** 유지보수자 판단
- **배경:** 01·02·03번 세트를 병렬로 만든 뒤 병합했다(그룹 A). 각 세트가 남긴 "병합 때 더할 입력 줄" 목록(DL-01-010, DL-02-010, DL-02-011, DL-03-011)과 받는 쪽이 문서 수준 값(`02`, `03`, `01`)인 잠정 줄이 남아 있었다.
- **검토한 대안:** (a) 목록의 줄만 더한다 / (b) 목록의 줄을 더하고 이미 있는 잠정 줄은 필드 키로 바꾼다
- **결정:** (b). 받는 쪽이 문서 수준인 01→02, 01→03, 02→03 잠정 줄과 환류 줄 IF-03-015 모두 27줄을 받는 쪽 필드 키로 바꿨고(필요하면 방식도 `근거 인용`으로), 목록의 새 줄 58개를 더했다. 보내는 단계가 01·02·03인 줄은 연결 ID를 단계별 마지막 번호 뒤로 이어 매겼다(IF-01-063부터, IF-02-055부터, IF-03-069부터). 외부 입력 줄의 연결 ID(`IF-EX-001~003`, `201~202`, `301~304`)는 서로 겹치지 않아 그대로 두었다. 가이드가 읽겠다고 쓰지 않은 줄 4개(DL-01-010 둘째 표)는 사용자가 정하도록 더하지 않았다. 03번이 가설을 확인한 결과를 01번에 되돌리는 환류 줄은 `03.사용자조사.인사이트` → `01.핵심가설.검증 방법`으로 하나 더했다.
- **이유:** 받는 쪽 템플릿이 있으면 필드 키로 쓰는 것이 규칙이다(IR-10). 목록은 가이드 1절이 읽겠다고 쓴 입력과 인터페이스 표를 맞추려는 것이다.
- **영향:** `build.py`로 06·07·16번 등 템플릿의 입력 블록에 01번이 나온다. 더하지 않은 4줄은 사용자 결정 대기다. 받는 필드를 어느 칸으로 할지는 판단이라 `검토 대기`다.
- **상태:** 검토 대기

### DL-01-014 · 도메인 교체 시험 반영: 핵심 가설 완료 체크의 예외와 이해관계자 줄
- **날짜:** 2026-10-09
- **대상:** `templates/01_목표_가치_template.md` v1.1, `guides/01_목표_가치_guide.md` v1.1
- **결정 주체:** 유지보수자 판단
- **배경:** 그룹 A 도메인 교체 시험. 도메인 B에서 자료에 가설이 없어 BH-01을 전 칸 `미정`으로 닫았더니 완료 체크가 ID를 요구해 두 줄을 `[ ]`로 남겨야 했다(conversions/01 DT-05). 도메인 A에서는 누락 점검(후원·운영·규제 쪽 기대)에 따라 자료에 없는 이해관계자 줄을 `미정`으로 하나 더 만들었다(DT-02).
- **검토한 대안:** (a) 그대로 둔다 / (b) 완료 체크에 예외를 쓰고 가이드에 줄을 만들지 않는다고 쓴다
- **결정:** (b).
- **이유:** 완료 체크가 가이드의 `미정` 닫는 법과 어긋나면 작성자가 체크를 거짓으로 하거나 비워 둔다. 자료에 없는 이해관계자 줄은 입력에 없는 사실을 만드는 일에 가깝다.
- **영향:** 01번 템플릿 v1.1, 가이드 v1.1. 이미 쓴 01번 시험 산출물은 다시 쓰지 않는다.
- **상태:** 검토 대기

### DL-01-016 · 그룹 A 결정 기록: 단계 정의 산출물 열, 목표값 닫는 기준
- **날짜:** 2026-10-09
