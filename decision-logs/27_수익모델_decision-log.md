### DL-27-001 · 27번 변환 분석서와 템플릿 v1.0, 단계 가이드 v1.0 초안을 작성한다
- **날짜:** 2026-10-09
- **대상:** `conversions/27_수익모델_conversion.md`, `templates/27_수익모델_template.md`, `guides/27_수익모델_guide.md` (그룹 G, 26~28번 병렬 작성의 하나)
- **결정 주체:** 사용자 승인
- **배경:** 그룹 단위 진행을 승인함(DL-05-005). 샘플 해부 45행(SA-01~45)과 누락 탐색 19행(OM-01~19)을 앞 단계와 같은 절차로 만들었다. 도메인 교체 시험(③)은 템플릿과 가이드를 쓴 뒤에 하므로 아직 하지 않았고 분석서 상태는 `초안`이다.
- **검토한 대안:** 해당 없음 — 변환 절차(정의서 6절)를 따랐다.
- **결정:** 04·05번의 구성(도출 질문 → 후보 → 판정 → 목록)을 따르지 않고 이 단계의 목적(돈이 오가는 지점마다 해당 여부를 판정하고 해당하지 않는 경우도 사유와 재검토 조건을 남긴다)에 맞춰 값 표를 넷으로 둔다. 1번 `지점점검`은 지점 하나의 판정 하나를 행으로 하는 목록(정의 ID `MN`), 2번 `비용구조`는 외부에 돈을 내는 지점의 증가 요인과 관리 방법의 목록(`MNE`), 3번 `필요기능점검`은 돈이 오가면 따라오는 기능을 찾는 고정 질문 열두 개의 속성 표(`MNQ`), 4번 `기능후보`는 통일 열을 따르는 후보 표(`MNC`)다. 그림이나 표 없는 필수 블록, 선택 블록은 없다(SA-09, SA-29, SA-34, OM-01, OM-07).
- **이유:** 이 단계의 본질은 점검 대상 지점을 하나도 건너뛰지 않고 판정과 사유와 재검토 조건을 남기는 것이다. 후보는 판정이 포함이나 후속인 지점에서만 나오므로 후보 표를 판정 표 뒤에 둔다. 템플릿의 모든 변경이 분석서의 줄에 대응한다(정의서 6절 4번).
- **영향:** 도메인 교체 시험(8번)이 남았다. 인터페이스 표를 DL-27-009에 정리했다.
- **상태:** 유효

### DL-27-002 · 지점 종류를 닫힌 선택지 열다섯 개로 두고 모든 선택지가 한 행 이상 나오게 한다
- **날짜:** 2026-10-09
- **대상:** `templates/27_수익모델_template.md` 1절 (필드 `지점 종류`, `지점`), `guides/27_수익모델_guide.md` 3.1
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 특정 서비스의 지점 열네 개를 고정한 목록이다(SA-09, SA-11, SA-15~SA-27). 단계 목적은 돈이 오가는 지점마다 판정하는 것인데 다른 서비스는 어떤 지점을 점검해야 하는지 알 수 없다(OM-01). 도메인을 대입하자 샘플에 없는 종류(서비스 자체에 내는 일회성 대금, 사내 비용 배분 같은 그 밖)가 나왔다(OM-12, OM-15).
- **검토한 대안:** (a) 샘플의 열네 지점을 템플릿에 고정 행으로 둔다 / (b) 지점 종류를 자유 서술로 둔다 / (c) 지점 종류를 닫힌 선택지로 두고 모든 선택지가 한 행 이상 나오게 한다 / (d) 종류마다 한 행인 속성 표로 둔다
- **결정:** (c). 선택지는 이용 대금, 정기 이용권, 유료 부가 기능, 조직 요금, 거래 대금, 수수료·정산, 광고·제휴, 혜택·할인, 환불·취소, 증빙 발급, 결제 오류, 플랫폼 수수료, 외부 서비스 비용, 획득 비용, 그 밖이다. 구체적인 지점이 있으면 지점마다 한 행, 없으면 종류마다 한 행으로 제외를 쓴다. 포괄 확인은 완료 체크가 맡는다.
- **이유:** (a)는 도메인에 묶인다(TP-02). (b)는 누락을 막지 못한다. (d)는 한 종류에 지점이 여럿인 서비스를 담지 못하고, 속성 표의 한 칸에 판정과 사유와 재검토 조건을 따로 닫을 수 없다. 돈의 방향(비용 포인트)은 별도 열 없이 종류가 담는다(SA-12). 한 지점이 두 종류에 걸치면 행을 나눈다(OM-18).
- **영향:** 선택지 포괄은 도구가 검사하지 못한다(DL-27-012). 종류 목록이 충분한지는 도메인 교체 시험에서 본다.
- **상태:** 검토 대기

### DL-27-003 · 판정을 포함 / 후속 / 제외 세 값으로 한다
- **날짜:** 2026-10-09
- **대상:** `templates/27_수익모델_template.md` 1절 (필드 `판정`), `guides/27_수익모델_guide.md` 3.1, 5절
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플의 판정은 `해당 없음`, `Later`, `비용 포인트`로 해당 여부와 시기와 돈의 방향이 섞여 있고 닫는 말을 선택지 값으로 썼다(SA-12, OM-02). 02번의 플랫폼 후보가 범위 구분을 포함 / 후속 / 제외로 쓴다.
- **검토한 대안:** (a) 샘플의 세 값을 유지한다 / (b) 해당 / 후속 / 해당하지 않음으로 한다 / (c) 02번과 같은 포함 / 후속 / 제외로 한다
- **결정:** (c). 입력이 판단을 못 하게 하면 `미정`(확인처·담당·기한)으로 닫는다. 수익 모델 방향이 `미정`이거나 질문이 `미정`이어서 비어 있는 경우 수취 지점은 `제외`가 아니라 `미정`이다. 무수익 방향은 수취 지점을 제외로 닫는 근거이고 비용 지점은 닫지 않는다.
- **이유:** 같은 값을 두 단계가 다른 어휘로 쓰지 않으려고 02번과 맞췄다. 선택지 값이 닫는 말(`해당 없음`)과 같은 글자가 되지 않는다. 입력에 언급이 없다는 사실만으로 제외하지 않는 것이 공통 규칙(CM-08)이고 범위 목록은 닫힌 목록으로 본다.
- **영향:** 34번은 제외 행을 의도적 제외 목록으로 읽고 36번은 후속 행을 로드맵으로 읽는다(DL-27-009).
- **상태:** 검토 대기

### DL-27-004 · 지불 주체와 관련 규제 열을 두고 비용 구조 표를 지점 ID로 잇는다
- **날짜:** 2026-10-09
- **대상:** `templates/27_수익모델_template.md` 1절 (필드 `지불 주체`, `관련 규제`), 2절 (표 `비용구조`), `guides/27_수익모델_guide.md` 3.1, 3.2
- **결정 주체:** 유지보수자 판단
- **배경:** 01번 수익 모델 방향에 돈을 내는 쪽이 있고 지불 주체가 이용자가 아닌 서비스가 있다(OM-06, OM-14, OM-17). 규제 매핑을 입력으로 읽는데 샘플은 규제 ID를 사유 한 행에만 쓴다(SA-19, OM-05). 샘플의 비용 구조 표는 비용 항목 이름이 지점의 이름을 되풀이하고 근거가 없다(SA-29~SA-33, OM-09).
- **검토한 대안:** (a) 지불 주체와 규제를 사유 문장에 쓴다 / (b) 열을 따로 둔다 / (c) 비용 구조를 지점 점검에 열로 합친다
- **결정:** (b). 비용 구조는 별도 표로 두고 외부에 돈을 내는 포함 지점마다 행을 쓴다. 지점은 `MN-` ID 참조, 비용 항목 열은 지운다. 관련 규제의 `해당 없음`은 규제 매핑을 확인했을 때만 쓴다.
- **이유:** (a)는 검사할 수 없고 뒤 단계가 읽을 수 없다. (c)는 수취 지점 행에서 증가 요인과 관리 방법이 빈 칸이 되어 `해당 없음`으로 채워야 한다.
- **영향:** 관련 규제는 34번이 규제 매핑 행까지 추적할 때 쓴다(DL-27-009).
- **상태:** 검토 대기

### DL-27-005 · 필요 기능 점검 질문 열두 개를 둔다
- **날짜:** 2026-10-09
- **대상:** `templates/27_수익모델_template.md` 3절 (표 `필요기능점검`), `guides/27_수익모델_guide.md` 3.3
- **결정 주체:** 유지보수자 판단
- **배경:** 단계 정의의 산출물에는 지점별 판정에 더해 "필요한 기능"이 있다. 샘플은 지점 두 개에서만 후보를 올린다(OM-07). 정기 구독 결제 서비스, 농장 센서 모니터링 B2B 서비스를 대입하면 미납 처리, 이용 권한 반영, 인보이스, 정산이 지점 판정에서 직접 나오지 않는다(OM-13, OM-16).
- **검토한 대안:** (a) 점검 없이 지점에서 직접 나온 후보만 올린다(샘플) / (b) 고정 질문 열두 개와 개방 질문을 둔다 / (c) 지점 종류마다 필요 기능 목록을 가이드에 고정한다
- **결정:** (b). 질문은 기능의 종류로 쓰고 특정 결제 방식이나 법령을 전제하지 않는다. 답은 필요한 기능의 이름과 관련 `MN-` ID다. 외부 연동, 보안, 규제, 운영 단계에 같은 기능이 있으면 가리키고 새로 정의하지 않는다.
- **이유:** (a)는 놓친 종류를 확인할 방법이 없다. (c)는 도메인에 묶인다. 질문 수는 규제·정책, 보안·어뷰징, 데이터 생애 단계의 열두 개 점검과 맞췄다.
- **영향:** 열두 필드는 뒤 단계가 값으로 쓰지 않아 `최종 소비자 없음`이다. 운영자 금전 조치(MNQ-09)만 운영 단계로 환류 줄을 둔다(DL-27-009).
- **상태:** 검토 대기

### DL-27-006 · 가이드에 둔 판단 기준: 제외의 근거, 비용 지점, 모르는 값 닫기
- **날짜:** 2026-10-09
- **대상:** `guides/27_수익모델_guide.md` 3.1, 3.2, 5절
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 사유에 입력 ID만 쓰고 다른 지점의 판정에 기대는 사유가 있으며(SA-13, OM-03), 재검토 트리거에 `〃`를 쓴 행이 있다(SA-28). 무수익이면 모든 지점이 닫힌다고 오해할 수 있다(OM-10). 앞 단계의 표가 비어 있는 이유가 "없다고 확인"인지 "질문이 `미정`"인지에 따라 하류가 달라진다.
- **검토한 대안:** (a) 입력에 없으면 제외로 둔다 / (b) 입력이 닫힌 목록으로 배제할 때만 제외로 쓰고 아니면 `미정`으로 둔다
- **결정:** (b). 수익 모델 방향이 없다고 확인된 때만 수취 지점을 제외로 닫고, 질문이 `미정`이면 `미정`으로 닫는다. 비용 지점은 액터 목록(비사람)과 외부 연동의 닫힌 목록에 업체가 없을 때만 제외다. 제외와 후속 행의 재검토 조건에는 `해당 없음`을 쓰지 않는다. 지점 종류는 `미정`을 쓰지 않는다. 이 단계의 구분은 정하기 어려워도 `미정`을 쓰지 않고 `기능 후보`로 둔다(DL-23-011과 같은 기준).
- **이유:** 공통 규칙 CM-08과 공통 가이드 3절(언급 없음만으로는 해당 없음이 아니다)을 이 단계에 적용했다. 재검토 조건이 없으면 후속 단계가 로드맵의 재검토 시점으로 쓸 수 없다.
- **영향:** 입력이 얇으면 `미정`이 많아질 수 있다. 이는 구조의 결함이 아니라 입력 부족이다. 도메인 교체 시험에서 확인한다.
- **상태:** 검토 대기

### DL-27-007 · 기능 후보 표는 통일 열을 따르고 단계 고유 열을 두지 않는다
- **날짜:** 2026-10-09
- **대상:** `templates/27_수익모델_template.md` 4절 (표 `기능후보`), `guides/27_수익모델_guide.md` 3.4
- **결정 주체:** 유지보수자 판단
- **배경:** 그룹 G 지시(수정목록 G13의 사용자 결정)가 후보 표의 열을 `ID | 후보 문장 | 구분 | 공통·고유(잠정) | 출처 | (단계 고유 열) | 근거`로 통일하라고 했다. 샘플의 후보 표는 이 순서와 달라 후속 여부가 후보 문장의 괄호에 있다(SA-35~SA-39).
- **검토한 대안:** (a) 단계 고유 열로 `관련 규제`를 더한다 / (b) 고유 열 없이 통일 열만 쓴다
- **결정:** (b). 규제와의 연결은 지점 점검의 관련 규제 열이 갖는다. 구분 어휘는 18·19·22~25번과 같은 네 값(기능 후보 / 후속 후보 / 설계 기준 / 프로세스)이다.
- **이유:** 같은 사실을 두 곳에 쓰지 않는다(CM-12). 후보에서 규제까지는 출처의 지점 행을 거쳐 34번이 따라간다.
- **영향:** 31번이 구분의 `프로세스`와 `설계 기준`을 읽는다(DL-27-009).
- **상태:** 검토 대기

### DL-27-008 · ID 접두어는 지점 점검 `MN`, 비용 구조 `MNE`, 필요 기능 점검 `MNQ`, 기능 후보 `MNC`로 한다
- **날짜:** 2026-10-09
- **대상:** `templates/27_수익모델_template.md` (정의 ID `MN`, `MNE`, `MNQ`, `MNC`)
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 지점 ID를 `MN-nn`, 후보 ID를 `CF-27-nn`으로 쓴다(SA-10, SA-35). 템플릿 규칙(TP-28)은 접두어가 모든 템플릿에 걸쳐 유일하라고 하고, 이번 호출은 `MN`으로 시작하는 접두어만 쓰게 했다.
