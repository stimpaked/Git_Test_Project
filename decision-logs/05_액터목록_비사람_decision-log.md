### DL-05-001 · 05번 변환 분석서와 템플릿 v1.0, 단계 가이드 v1.0 초안을 작성한다
- **날짜:** 2026-10-08
- **대상:** `conversions/05_액터목록_비사람_conversion.md`, `templates/05_액터목록_비사람_template.md`, `guides/05_액터목록_비사람_guide.md` (작업 순서 6단계, 04번에 이은 첫 복제)
- **결정 주체:** 사용자 승인 (6단계 시작을 승인함)
- **배경:** 04번 세트가 승인되어 05번부터 복제한다. 샘플 해부 34행(SA-01~34)과 누락 탐색 12행(OM-01~12)을 04번과 같은 절차로 만들었다.
- **검토한 대안:** 해당 없음 — 변환 절차(정의서 6절)를 따랐다.
- **결정:** 비사람 주체를 외부 시스템과 시간으로 나누어 두 표로 쓰던 샘플(SA-15)을 하나의 비사람 액터 목록으로 합치고 `유형` 열(외부 시스템 / 시간 트리거 / 장치 / 자동 호출 주체)을 둔다(OM-03, OM-11). 04번과 같은 흐름으로 도출 질문 15개(NQ), 후보 정리(NC), 병합·분리 판정, 액터 목록(X)을 둔다(OM-01, OM-02). 샘플이 맨 앞에 둔 컨텍스트 다이어그램은 액터 ID가 부여된 뒤에 그리도록 목록 뒤로 옮긴다(SA-08). 선정 상태의 값 `미정`은 공통 규칙의 `미정`과 같은 글자라 `선정 전`으로 바꾸고 기존 사용(선택 대상 아님)을 더한다(SA-18, OM-06).
- **이유:** 샘플을 해부하고 누락을 찾은 결과가 템플릿의 모든 변경에 대응한다(정의서 6절 4번).
- **영향:** 도메인 교체 시험(8번)이 남았다. 사람 액터를 만났을 때 04번으로 돌려보내는 환류 연결을 인터페이스 표에 더했다(DL-05-002).
- **상태:** 유효

### DL-05-002 · 인터페이스 표: 04번 잠정 줄을 필드 수준으로 바꾸고 05번 연결을 추가한다
- **날짜:** 2026-10-08
- **대상:** `tools/data/interfaces.csv` (IF-04-014, 015, 018, 020, 053 / IF-02-003 / IF-03-002 / IF-05-001~)
- **결정 주체:** 유지보수자 판단
- **배경:** 05번 템플릿이 생겨 04번의 `최종 소비자 없음` 줄과 문서 수준 잠정 줄을 필드 수준으로 바꿀 수 있게 되었다(IR-10). 04번의 후보 이름·설명·후보 ID는 `제외`로 05번에 보내는 후보를 05번이 가져가므로 실제로 쓰인다(OM-02).
- **검토한 대안:** 해당 없음 — 규칙(IR-07, IR-10)을 따랐다.
- **결정:** 04번 후보 정리의 후보 이름·한 줄 설명, 판정의 후보 ID를 05번 후보 정리로 연결하고(판단 입력·참조), 보낼 곳 열은 05번이 가져올 후보를 고르는 기준으로 연결했다. 05번 필드 40개 중 뒤 단계가 값으로 쓰는 것은 소비자와 연결했고(07, 14, 19, 22, 23은 모두 템플릿이 없어 잠정이며 근거는 샘플의 쓰이는 곳 표시와 가정이다), 나머지는 `최종 소비자 없음`과 사유를 적었다. 05번 판정의 보낼 곳이 `사람`이면 04번으로 돌려보내는 환류 연결을 더했다(OM-12).
- **이유:** 템플릿 필드마다 소비자가 있거나 사유가 있어야 한다(IR-07).
- **영향:** 04번 세트의 인터페이스 줄이 바뀌었으나 04번 템플릿의 필드는 바뀌지 않았다. 07, 14, 19, 22, 23번 템플릿이 생기면 해당 잠정 줄을 필드 수준으로 바꾼다.
- **상태:** 검토 대기

### DL-05-003 · 컨텍스트 다이어그램은 표 키 없는 필수 블록으로 둔다
- **날짜:** 2026-10-08
- **대상:** `templates/05_액터목록_비사람_template.md` 5절, `docs/규칙_템플릿.md` (TP-17, TP-26)
- **결정 주체:** 사용자 승인
- **배경:** 단계 정의가 05번 산출물에 컨텍스트 다이어그램을 포함하는데(SA-06), 템플릿 규칙은 값 표와 선택 블록만 정의한다. 선택 블록(`[선택]`)으로 두면 단계 정의의 산출물과 맞지 않는다.
- **검토한 대안:** (a) 선택 블록으로 둔다 / (b) 표 키 없는 필수 블록으로 두고 규칙 문서에 필수 블록 규정을 더한다 / (c) 다이어그램의 내용을 표로만 담는다
- **결정:** (b)로 두되, 규칙 문서 개정은 이 항목을 사용자가 확인한 뒤에 한다. 지금은 다이어그램 절에 지속 지침을 두지 않고 해설 주석도 달지 않으며, 구조 일치 검사(TP-K13)는 표 키만 비교하므로 통과한다. 다이어그램이 액터 목록과 맞는지는 완료 체크로만 확인한다.
- **이유:** 단계 정의의 산출물을 줄이지 않으면서 규칙을 사용자 결정 없이 바꾸지 않기 위해서다.
- **영향:** 사용자가 확정하면 규칙_템플릿에 필수 블록 규정을 더하고, 다이어그램의 노드가 액터 목록과 일치하는지 검사하는 도구를 만들지 정한다(한계 LM-11).
- **상태:** 유효 (규칙은 DL-TP-010)

### DL-05-004 · 도메인 교체 시험에서 나온 단계 가이드 보완을 반영한다
- **날짜:** 2026-10-08
- **대상:** `guides/05_액터목록_비사람_guide.md` (1, 3.1, 3.3, 3.4, 3.5절), `conversions/05_액터목록_비사람_conversion.md` ③ (DT-01~09)
- **결정 주체:** 유지보수자 판단
- **배경:** 세 도메인으로 05 산출물을 써 본 결과 템플릿 구조 변경은 필요하지 않았고 가이드 문장이 갈리는 곳이 반복되었다. 세 작성자 모두 범위에 든 기능 목록을 닫힌 목록으로 보고 `해당 없음`을 썼는데 가이드가 이를 밝히지 않았다(DT-02, DT-05, DT-08). 시간 트리거로 올릴지(월간 리포트가 자동인지 모름)는 한 작성자만 올렸다(DT-05). 비사람 액터가 0건일 때 4번 표를 닫는 법이 없었다(DT-03).
- **검토한 대안:** 해당 없음 — 가이드 문장의 보완이라 범위가 작고 템플릿은 바뀌지 않았다.
- **결정:** 범위에 든 기능 목록을 닫힌 목록으로 보는 기준을 명시했다. 질문 답의 아는 부분과 모르는 부분을 이어 쓰는 것과 선택지 칸의 이어 쓰기를 안내했다. 입력이 기능을 말하면 기능 이름으로 후보에 올릴 수 있고 업체 이름은 입력에 있을 때만 쓴다고 했다. `확정`은 이름이 입력에 있을 때, 기존 시스템인지 모르면 `미정`이라고 했다. 정기라는 말만 있으면 시간 트리거로 올리지 않는다. 비사람 액터가 0건일 때의 4번 표와 다이어그램 표기(노드 ID, 레이블, 양방향, 방향 미정의 점선)를 정했다. 04의 외부 연동 답과 이해관계자 표도 훑는다. 판정 사유는 한 줄이고 번호는 비교 후보가 있을 때만 쓴다.
- **이유:** 같은 입력에서 작성자마다 다른 결과가 나오는 곳을 줄인다.
- **영향:** 단계 가이드 v1.1. 템플릿은 바뀌지 않았다. 06번 이후 단계 가이드에도 "범위에 든 목록은 닫힌 목록"과 같은 기준이 필요한지 복제 중에 확인한다.
- **상태:** 검토 대기

### DL-05-005 · 05번 변환 분석서를 승인하고 06번 이후를 그룹 단위로 복제한다
- **날짜:** 2026-10-08
- **대상:** `conversions/05_액터목록_비사람_conversion.md` (상태 `초안` → `승인`), 작업 순서 6단계의 진행 방식
- **결정 주체:** 사용자 결정
- **배경:** 05번 도메인 교체 시험(DT-01~09)에서 템플릿 구조 변경은 나오지 않았고 가이드 문장과 도구 오탐만 보완했다(DL-05-004, DL-TL-007). 단계마다 보고와 승인을 받으면 남은 34개 단계의 진행이 매우 길어진다.
- **검토한 대안:** (가) 단계 그룹 단위로 만들고 시험은 단계마다 도메인 2개로 한 번만 하며, 템플릿 구조·규칙 문서 변경 같은 중요한 판단만 따로 묻고 그룹이 끝나면 한꺼번에 보고한다 / (나) 단계마다 보고하고 승인을 받는다
- **결정:** (가). 05번을 `승인`한다. 06번부터는 그룹 단위로 진행한다. 변환 분석서의 `승인`은 사용자가 그룹 보고를 확인한 뒤에 올린다.
- **이유:** 템플릿 구조가 바뀌는 지적은 첫 시험에서 대부분 드러나고, 그 뒤 라운드는 문장 보완이라 단계마다 승인을 받는 비용이 크다.
- **영향:** 그룹 보고에는 단계마다 어떤 검사(문서 체계 검사 `verify.py`, 산출물 검사 `check_deliverable.py`, 도메인 교체 시험)를 했는지 구분해 쓴다.
- **상태:** 유효

### DL-05-006 · 선정 상태 선택지에 `정해짐(이름 모름)`을 더한다
- **날짜:** 2026-10-09
- **대상:** `templates/05_*_template.md`, `guides/05_*_guide.md`
- **결정 주체:** 사용자 결정
- **배경:** 그룹 A 시험 03번 DT-05에서 센서 협력사가 이미 정해졌지만 이름이 입력에 없어 `확정`도 `선정 전`도 쓸 수 없었다. 03번과 05번은 같은 선정 상태 어휘를 쓰므로 함께 정하기로 했다(수정목록 G18). 사용자가 권장대로 더하기로 했다.

- **영향:** 03번 템플릿 v1.2, 05번 템플릿 v1.1(승인 상태의 시범 단계를 사용자 결정으로 고쳤다).
