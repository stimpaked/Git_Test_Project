### DL-15-001 · 15번 변환 분석서와 템플릿 v1.0, 단계 가이드 v1.0 초안을 작성한다
- **날짜:** 2026-10-08
- **대상:** `conversions/15_소유_권한_conversion.md`, `templates/15_소유_권한_template.md`, `guides/15_소유_권한_guide.md` (작업 순서 6단계, 그룹 단위 복제)
- **결정 주체:** 사용자 승인
- **배경:** 그룹 단위 진행을 승인함(DL-05-005). 샘플 해부 40행(SA-01~40)과 누락 탐색 19행(OM-01~19)을 04·05번과 같은 절차로 만들었다. 샘플은 약 100줄로 크지 않고 표 네 개(권한 매트릭스, 상태 표, 규칙, 후보 풀)가 단계 정의의 산출물 셋과 단계의 목적(접근 제어 기능 도출)에 대응한다.
- **검토한 대안:** 해당 없음 — 변환 절차(정의서 6절)를 따랐다.
- **결정:** 04·05번의 도출 질문 → 후보 → 판정 → 목록 구성을 따르지 않고 단계의 목적에서 구성을 정했다. 구성은 ① 권한 기준 ② 소유·공유·위임·승인 규칙(`PR`) ③ 권한 매트릭스(`PA`) ④ 사용자 상태별 제한(`PS`) ⑤ 접근 제어 기능 후보(`PF`)다. 표 없는 필수 블록과 선택 블록은 없다. 도메인 교체 시험은 하지 않았고 변환 분석서의 상태는 `초안`이다.
- **이유:** 샘플을 해부하고 누락을 찾은 결과가 템플릿의 모든 변경에 대응한다(정의서 6절 4번, 검사 CV-K04).
- **영향:** 도메인 교체 시험(8번)과 변환 분석서 `승인`이 남았다. 17·20·24·26·31번 템플릿이 생기면 인터페이스 표의 잠정 줄을 필드 수준으로 바꾼다(DL-15-008).
- **상태:** 유효

### DL-15-002 · 권한 매트릭스는 행위 하나가 행 하나이고 액터는 허용·조건부 허용·불가 세 칸의 ID 목록으로 쓴다
- **날짜:** 2026-10-08
- **대상:** `templates/15_소유_권한_template.md` 3절 (표 키 `권한매트릭스`), `docs/규칙_템플릿.md` (TP-12, TP-27)
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플의 매트릭스는 행이 행위이고 열이 액터 다섯 개인 교차표다(SA-10). 산출물의 열 이름은 템플릿과 같아야 하므로(TP-27) 액터를 열로 둔 교차표는 템플릿으로 정할 수 없다. 06번은 같은 문제를 칸 하나를 행 하나로 두는 목록 표로 풀었다(DL-06-002). 이 단계는 칸의 성격이 다르다. 샘플의 140칸 중 `—`(불가)가 과반이고, 불가 칸은 서술할 내용이 없는 기본값이다(SA-09, SA-14).
- **검토한 대안:** (a) 06번처럼 칸 하나를 행 하나로 둔다(열: 행위, 액터, 허용 구분, 조건, 근거) / (b) 액터를 열로 둔 교차표를 쓰고 열 이름 검사를 면제한다 / (c) 행위 하나를 행 하나로 두고 허용·조건부 허용·불가 세 칸에 액터 ID 목록을 쓴다
- **결정:** (c). 열은 `ID | 행위 | 허용 | 조건부 허용 | 불가 | 조건 | 적용 규칙 | 근거`다. 모든 사람 액터가 세 칸 중 한 칸에 한 번씩 나오는지는 완료 체크로 확인한다(SA-37). 알 수 없는 액터는 불가 칸에 `미정`으로 이어 쓰게 한다(공통 규칙 CM-07, 단계 가이드 3.3).
- **이유:** (a)는 액터 여섯에 행위 스물여덟이면 168행이고 대부분이 불가 행이라 행마다 근거를 써야 하는 부담이 크고, 쓰는 사람이 근거를 형식적으로 채우게 된다. 06번의 칸은 행동이나 `해당 없음`의 사유처럼 칸마다 읽을 내용이 있어 한 칸이 한 행인 것이 맞았다. (b)는 구조 검사(TP-K13)를 약하게 한다. (c)는 열 이름이 고정되고 행위마다 근거와 규칙 연결을 한 번만 쓰면서 모든 칸이 닫혔는지 한눈에 확인할 수 있다. 조건부 허용의 조건은 `A-xx: 조건` 형식으로 액터와 짝지어 쓰므로 액터별 조건도 읽을 수 있다.
- **영향:** 한 칸 단위의 근거는 쓸 수 없다(행 단위 근거만). 한 액터가 두 칸에 나오거나 어느 칸에도 없는 것을 검사하는 도구가 없어 완료 체크와 사람의 확인에 맡긴다. 인터페이스 표의 04.액터목록.ID 연결은 `축(행·열)` 방식을 유지하되 받는 쪽을 `15.권한매트릭스.허용`으로 했다(DL-15-008). 이 표기는 DL-06-006의 규칙 제안에 함께 적었다(DL-15-009).
- **상태:** 검토 대기

### DL-15-003 · 규칙 표를 매트릭스 앞으로 옮기고 매트릭스가 규칙 ID를 가리키게 한다
- **날짜:** 2026-10-08
- **대상:** `templates/15_소유_권한_template.md` 2절, 3절 (표 키 `규칙`, `권한매트릭스`의 `적용 규칙`)
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 매트릭스, 상태 표, 규칙, 후보 풀 순서이고 규칙 표가 매트릭스의 행 번호를 가리킨다(SA-23, SA-28). 매트릭스의 조건도 규칙과 같은 사실을 따로 적는다. 영구정지의 2인 승인이 14행 칸과 `APR-01`에 모두 있다(OM-01).
- **검토한 대안:** (a) 샘플 순서를 유지하고 매트릭스 조건에 규칙 ID 없이 자유 서술로 쓴다 / (b) 규칙 표를 매트릭스 앞에 두고 매트릭스의 행이 적용 규칙으로 규칙 ID를 가리킨다
- **결정:** (b). 앞 표는 뒤 표의 ID를 참조하지 않는다는 규칙(TP-16, TP-K07)에 따라 규칙 표가 행위 ID를 가리킬 수 없으므로, 규칙의 `대상` 칸에는 데이터나 행위의 이름을 쓴다(SA-27).
- **이유:** 같은 사실을 두 곳에 쓰지 않는다(CM-12). 규칙을 먼저 정하면 데이터 대상마다 소유자가 정해졌는지 확인하게 되어 매트릭스의 조건이 규칙에서 나오는 방향이 된다.
- **영향:** 규칙과 행위의 이름이 어긋나도 도구가 잡지 못한다. 상태별 제한은 매트릭스 뒤에, 기능 후보는 맨 뒤에 둔다. 사용자 상태에 따른 조건은 매트릭스에 쓰지 않고 상태별 제한에만 쓴다(SA-16).
- **상태:** 검토 대기

### DL-15-004 · 사용자 상태별 제한은 상태 하나가 행 하나이고 행위는 3번 표의 ID 세 칸으로 나눈다
- **날짜:** 2026-10-08
- **대상:** `templates/15_소유_권한_template.md` 4절 (표 키 `상태제한`), `guides/15_소유_권한_guide.md` 3.4절
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플의 상태 표는 상태 여섯과 행위 여덟의 교차표이고(SA-17), 행위 여덟은 매트릭스 28행 중 기준 없이 고른 것이며(SA-21, OM-04), `로그인`처럼 매트릭스에 없는 행위가 있고(SA-20), `비로그인(A-01)`처럼 액터로 이미 구분되는 것이 상태 행에 섞여 있다(SA-18). 상태가 무엇이고 누가 갖는지도 정의가 없다(OM-03).
- **검토한 대안:** (a) 상태와 행위의 조합을 한 행으로 둔다 / (b) 상태 하나를 한 행으로 두고 행위를 허용·조건부 허용·불가 세 칸에 나눈다 / (c) 샘플처럼 교차표를 유지한다
- **결정:** (b). 열은 `ID | 상태 | 대상 액터 | 허용 행위 | 조건부 허용 행위 | 불가 행위 | 조건 | 근거`다. 대상 액터 중 하나라도 매트릭스에서 허용이나 조건부 허용인 행위를 모두 세 칸에 한 번씩 나누게 해 행위 선정의 임의성을 없앤다. 상태는 권한을 늘리지 못한다는 기준과 서비스에 들어오는 행위도 매트릭스의 행위로 둔다는 기준은 단계 가이드가 맡는다(OM-10). 상태 변형 판정의 `상태 속성`이 모두 올랐는지는 완료 체크로 확인한다.
- **이유:** DL-15-002와 같은 이유로 조합을 행으로 늘리면 불가 행이 대부분이다. (c)는 상태 수와 행위 수를 고정한다.
- **영향:** 상태가 새 권한을 주는 서비스는 매트릭스의 해당 행위를 조건부 허용으로 쓰고 이 표에서 허용으로 쓰게 안내했는데(가이드 3.4), 이런 서비스가 실제로 있는지는 시험에서 확인해야 한다. 정상 상태도 한 행으로 쓰게 했다.
- **상태:** 검토 대기

### DL-15-005 · 사람이 아닌 액터의 접근 범위는 매트릭스에 넣지 않고 규칙(범위 제한)에 쓴다
- **날짜:** 2026-10-08
- **대상:** `templates/15_소유_권한_template.md` 2절 (`규칙.구분`), `guides/15_소유_권한_guide.md` 3.2절
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 사람 액터만 다루고 완료 체크도 사람 액터만 확인한다. 단계 정의의 "누가"는 사람에 한정되지 않고 스마트 온실 서비스의 장치는 센서값을 쓰며 자동 호출 주체도 데이터를 읽는다(OM-07, OM-17).
- **검토한 대안:** (a) 사람이 아닌 액터를 매트릭스 행위의 액터에도 허용한다 / (b) 매트릭스는 사람 액터만 두고 사람이 아닌 액터의 읽고 쓰는 범위는 `범위 제한` 규칙으로 쓴다 / (c) 다루지 않는다
- **결정:** (b). 가장 좁은 변경이고 샘플과 단계 정의의 산출물(권한 매트릭스, 상태 표, 규칙)을 모두 유지한다. 사람이 아닌 액터를 매트릭스에 넣지 않는다는 항목을 완료 체크에 두었다.
- **이유:** (a)는 05번 산출물에서 15번으로 오는 입력 연결이 필요한데 05번 쪽 줄(IF-05-)은 다른 단계 세트와 연결 ID가 겹칠 수 있어 이 호출에서 더하지 않는다(DL-15-008). (c)는 접근 통제의 빈 곳을 남긴다.
- **영향:** 사용자 결정이 필요하다. 사람이 아닌 액터에게도 행위별 권한 매트릭스가 필요하면 `액터` 대신 비사람 액터 ID를 허용하는 확장과 05→15 입력 연결이 필요하다. 이 경우 템플릿 v1.1이다.
- **상태:** 검토 대기

### DL-15-006 · 권한 기준 표(역할 전환 액터의 권한, 권한 부여 단위)를 둔다
- **날짜:** 2026-10-08
- **대상:** `templates/15_소유_권한_template.md` 1절 (표 키 `권한기준`)
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 같은 계정을 쓰는 두 액터를 한 열로 합친 이유를 문장으로만 적었다(SA-08). 인터페이스 표에는 04의 계정 관계가 역할 전환 액터의 권한 합산을 정하는 전제로 이미 있다(IF-04-035). 권한을 액터에 붙이는지 개인에게 붙이는지는 샘플에 없고 관리자 권한 관리와 역할 정의·회수 후보가 이에 기댄다(OM-06).
- **검토한 대안:** (a) 두 항목을 표로 두지 않고 매트릭스 조건에 흩어 쓴다 / (b) 속성 표 하나에 두 항목을 둔다 / (c) 두 번째 항목을 두지 않고 역할 전환만 둔다
- **결정:** (b). 항목은 둘이다. 두 번째 항목은 샘플에 없는 추가이고 선택지는 액터 단위 / 개인 단위 / 액터 단위와 개인 단위다. 입력에서 알 수 없으면 `미정`으로 닫게 했다.
- **이유:** (a)는 전 행에 걸치는 기준이 흩어져 일관성을 확인할 수 없다. 두 항목은 모든 행에 영향을 주는 기준이며 26번의 권한 관리 도구 범위를 정한다. (c)는 OM-06의 빈 곳을 남기나 보수적이다.
- **영향:** 두 번째 항목은 추가한 필드라 사용자가 불필요하다고 보면 템플릿 v1.1에서 뺀다. 그때 인터페이스 줄 IF-15-002를 함께 지운다.
- **상태:** 검토 대기

### DL-15-007 · 규칙 구분의 `범위 제한`과 규칙 ID 접두어 `PR`
- **날짜:** 2026-10-08
- **대상:** `templates/15_소유_권한_template.md` 2절 (`규칙.구분`, `규칙.ID`)
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플 규칙은 접두어 다섯 개(`OWN`, `SHR`, `DLG`, `APR`, `BLK`)를 한 표에 쓰고 구분 값에 `차단`이 있다(SA-24, SA-25). 한 표가 부여하는 ID의 접두어는 하나다(TP-24). 사내 휴가 신청 도구의 팀 범위, 스마트 온실의 농장 경계, 장치의 쓰기 범위는 소유·공유·위임·승인 어느 것도 아니다(OM-11, OM-15, OM-17).
- **검토한 대안:** (a) 구분을 소유·공유·위임·승인 넷으로 두고 `차단`은 값이라 제거한다 / (b) `차단`을 일반화해 `범위 제한`을 다섯째로 둔다
- **결정:** (b). ID는 접두어 `PR`의 연번이다. 접두어는 호출 지침에 따라 `P`로 시작하는 것만 썼고(`PR`, `PA`, `PS`, `PF`) 기존 접두어(A, AC, AQ, AR, G, K, FL, FQ, HQ, JS, NC, NQ, X)와 겹치지 않는다.
- **이유:** (a)는 사람 사이의 비노출, 조직 경계, 장치의 범위를 쓸 곳이 없다. 단계 정의는 보고 바꿀 수 있는 사람을 정하는 것을 목적으로 하므로 범위를 가르는 규칙도 이 단계의 몫이다.
