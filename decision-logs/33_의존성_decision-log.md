### DL-33-001 · 33번 변환 분석서와 템플릿 v1.0, 단계 가이드 v1.0 초안을 작성한다
- **날짜:** 2026-10-10
- **대상:** `conversions/33_의존성_conversion.md`, `templates/33_의존성_template.md`, `guides/33_의존성_guide.md` (그룹 I의 31·32번과 병렬로 만든 복제)
- **결정 주체:** 사용자 승인 (그룹 단위 진행을 승인함(DL-05-005))
- **배경:** 샘플 해부 40행(SA-01~40)과 누락 탐색 24행(OM-01~24)을 같은 절차로 만들었다. 단계 정의의 목적은 기능 사이의 호출과 선후행 관계를 정리해 구현 순서의 근거를 만드는 것이고 산출물은 호출·선후행 관계와 구현 웨이브다. 샘플은 관계의 원본(호출 한 건, 선후행 한 건)을 적지 않고 영역 간 건수, 공통 기능별 호출 현황(호출하는 기능은 최대 6개), 웨이브별 기능 목록 같은 파생 값만 적는다(SA-06, SA-19, OM-01). 샘플의 영역 간 매트릭스 두 개, 공통 기능 67행, 웨이브 11행은 표 단위로 묶어 해부했다(CV-06). 도메인 교체 시험(③)은 작업 순서 6단계에서 템플릿과 가이드를 쓴 뒤에 하므로 아직 하지 않았고 분석서 상태는 `초안`이다.
- **검토한 대안:** 샘플의 구성(관계 정의, 영역 간 매트릭스 둘, 공통 기능 호출 현황, 웨이브, 검사 결과)을 그대로 따르는 안, 04·05번처럼 도출 질문 → 후보 → 판정 → 목록의 구성으로 하는 안, 관계의 원본 표(호출, 선후행)를 먼저 쓰고 그 결과(웨이브)와 검사(공통 기능 검사, 집계)를 뒤에 두는 안을 비교했다. 이 단계는 후보를 찾지 않고 이미 있는 기능 사이에 관계를 붙이므로 둘째 안은 버렸다. 첫째 안은 파생 값만 있어 관계를 되짚을 수 없고(OM-01) 표를 쓰는 순서도 결과가 원본보다 앞선다(TP-16).
- **결정:** 값 표 다섯을 둔다. 호출(목록 표, 정의 ID `DP`), 선후행(목록 표, 정의 ID 없음), 웨이브(목록 표, 정의 ID `DW`), 검사(목록 표, 정의 ID 없음, 절 제목 `공통 기능 검사`), 집계(속성 표, 정의 ID 없음, 18행). 필드는 모두 38개다. 선택 블록과 표 없는 절은 없다. 표 키는 그룹 I의 약속(`호출`, `선후행`, `웨이브`, `검사`, `집계`)을 따랐다. 호출을 호출 기능과 호출받는 기능의 쌍으로, 선후행을 후행과 선행의 쌍으로 쓰는 이유는 DL-33-003, 웨이브를 기능마다 한 행으로 쓰는 이유는 DL-33-004다.
- **이유:** 템플릿의 모든 표와 필드가 분석서의 줄에 대응한다(정의서 6절 4번, CV-K04). 호출·선후행을 원본으로 두고 웨이브·검사·집계를 파생과 점검으로 두면 표 순서가 작성 순서와 같다. 정의 ID 접두어 `DP`, `DW`는 기존 접두어(A, AC, AQ, AR, NC, NQ, X)와 겹치지 않고 호출에서 지정한 글자로 시작한다(TP-28). 32번 템플릿이 이 복사본에 없어 기능 트리의 칸은 문서 수준 값으로만 가리킨다(DL-33-008).
- **영향:** 도메인 교체 시험(작업 순서 6단계)이 남았다. 인터페이스 표는 DL-33-007과 DL-33-008에 쓴다.
- **상태:** 유효

### DL-33-002 · 판정 어휘와 방향 규칙은 호출받는 쪽이 공통이어야 한다는 한 문장으로 쓴다
- **날짜:** 2026-10-10
- **대상:** `templates/33_의존성_template.md` (필드 `33.호출.호출받는 기능`, `33.선후행.선행 기능`, `33.집계.호출 방향 위반 수`, `33.집계.선후행 방향 위반 수`), `guides/33_의존성_guide.md` 3.1, 3.2
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플의 규칙은 "호출 대상은 반드시 공통 기능이어야 한다(고유 → 공통 방향)"와 "같은 구분(공통→공통, 고유→고유 또는 고유→공통)만 허용"이다(SA-09, SA-10). 샘플의 3번 매트릭스는 공통 영역이 공통 영역을 부르는 호출을 센다(SA-14). 화살표가 의존하는 쪽에서 되는 쪽으로인지 거꾸로인지 읽는 사람마다 갈린다.
- **검토한 대안:** (a) 샘플의 화살표 표기를 그대로 두고 가이드에 방향을 설명한다 / (b) 호출은 호출받는 쪽이 공통이어야 한다고만 쓰고 호출하는 쪽의 구분은 묻지 않으며 선후행은 후행이 공통이면 선행도 공통이어야 한다고 쓴다 / (c) 호출하는 쪽도 고유로 한정한다
- **결정:** (b). 열 이름을 호출 기능과 호출받는 기능, 후행 기능과 선행 기능으로 두어 방향을 이름으로 못 박는다. 고유 기능 사이의 필요는 호출이 아니라 선후행이다. 이 규칙의 위반은 집계의 방향 위반 수로 센다.
- **이유:** (a)는 화살표 해석이 사람마다 갈려 도구가 검사할 규칙의 문장이 모호하다. (c)는 공통 기능끼리 부르는 호출(샘플이 센다)을 규칙 위반으로 만든다. 규칙을 한 문장으로 쓰면 도구가 호출받는 기능의 공통·고유만 보고 검사할 수 있다.
- **영향:** 영역·모듈 단계의 호출 방향 원칙(`21.배치방침.호출 방향 원칙`)이 이 규칙과 어긋나지 않는지는 사용자 확인이 필요하다(보고의 질문 참조). 호출 기능이 공통일 때 호출받는 기능이 공통이어야 한다는 것은 영역 원칙의 "공통은 고유를 부르지 않는다"와 같은 뜻이다.
- **상태:** 검토 대기

### DL-33-003 · 호출 표는 기능 쌍 한 행에 공통 기능, 주입 정책, 호출 이유를 더한다
- **날짜:** 2026-10-10
- **대상:** `templates/33_의존성_template.md` 1절 (필드 `33.호출.ID`, `33.호출.호출 기능`, `33.호출.호출받는 기능`, `33.호출.공통 기능`, `33.호출.주입 정책`, `33.호출.호출 이유`, `33.호출.근거`), `guides/33_의존성_guide.md` 3.1
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플에는 호출의 원본 표가 없다(OM-01). 호출 대상은 도메인 공통·고유 단계의 공통 기능인데 샘플의 호출받는 쪽은 기능 ID뿐이다(OM-02). 공통 기능 목록의 항목은 굵은 단위이고 기능 트리의 공통 기능은 가는 단위라 일대다일 수 있다. 영역·모듈 단계의 분석서(21번 SA-31)는 공통 영역의 정책 값을 고유 영역이 설정이나 템플릿으로 주입한다는 원칙을 이 단계의 몫으로 넘겼다(OM-04). 이벤트, 외부 연동, 품질 입력은 호출의 단서이고 호출의 이유와 근거를 적을 곳이 샘플에 없다(OM-03).
- **검토한 대안:** (a) 호출 기능과 호출받는 기능 두 열만 둔다 / (b) 두 열에 공통 기능 목록의 ID 열을 더한다 / (c) (b)에 주입 정책과 호출 이유 열을 더한다 / (d) 호출 한 건을 호출 이유마다 한 행으로 나눈다
- **결정:** (c). 행 하나는 호출 기능과 호출받는 기능의 쌍 하나이고, 쌍이 같으면 이유가 여럿이어도 한 행에 이유를 모아 쓴다(OM-18). 공통 기능 열은 공통 기능 목록의 `DC-`를 가리키고 어느 항목도 찾지 못하면 `미정`이다. 주입 정책은 혼합 분리 표의 고유 정책을 옮기고 없으면 `해당 없음`(사유)이다. 호출받는 기능은 기능 트리에 정의가 없으면 `미정`으로 닫고 그것이 정의 없는 호출이다(OM-10). 외부 액터는 기능이 아니므로 호출받는 쪽에 쓰지 않고 외부 연동 단계의 연동 기능을 부르는 호출로 쓴다(OM-19).
- **이유:** (a)는 20번과 이어 주는 칸이 없어 호출받는 쪽이 공통 기능 목록의 항목인지 확인할 수 없다. (b)는 정책 값 주입을 둘 곳이 없다. (d)는 같은 쌍의 건수가 이유 수만큼 늘어 호출 건수와 호출됨 판정이 어긋난다. 행 하나가 호출 한 건이라는 기준과 건수를 맞추려고 (c)로 한다. 이유 열은 뒤 단계가 값으로 쓰지 않지만 호출이 어디서 나왔는지 사람이 되짚는 데 필요하다.
- **영향:** 영역·모듈 단계가 "정책 값 주입은 의존성 단계의 몫"으로 남긴 문장(DL-21-006)을 이 표의 주입 정책 열이 받는다. 열이 일곱이라 행당 쓸 칸이 많다. 입력이 얇으면 공통 기능과 주입 정책에 `미정`과 `해당 없음`이 많이 나올 수 있다.
- **상태:** 검토 대기

### DL-33-004 · 웨이브 표는 기능마다 한 행이고 기준 선행을 적는다
- **날짜:** 2026-10-10
- **대상:** `templates/33_의존성_template.md` 3절 (필드 `33.웨이브.ID`, `33.웨이브.기능`, `33.웨이브.웨이브`, `33.웨이브.기준 선행`, `33.웨이브.근거`), `guides/33_의존성_guide.md` 3.3
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플의 웨이브 표는 웨이브마다 한 행이고 기능 ID를 한 칸에 최대 24개까지 적으며 기능 수와 공통·고유 수를 센 열이 있다(SA-25~SA-27). 정확히 한 웨이브라는 요구를 구조로 보장하지 못하고(OM-08) 어느 선행이 웨이브를 정했는지 되짚을 수 없다(OM-06). 선행이 `미정`이거나 순환에 든 기능은 웨이브를 정할 수 없다(OM-07).
- **검토한 대안:** (a) 샘플처럼 웨이브마다 한 행으로 두고 기능 ID를 쉼표로 쓴다 / (b) 기능마다 한 행으로 두고 웨이브 번호와 기준 선행 열을 둔다 / (c) 웨이브를 정의하는 표와 기능을 웨이브에 배치하는 표를 따로 둔다
- **결정:** (b). 정의 ID는 `DW`이며 행마다 `DW-01`부터 부여한다. 웨이브 번호는 0부터 센 숫자이고 선행이 없으면 0, 있으면 선행 가운데 가장 늦은 웨이브에 1을 더한다. 기준 선행은 그 가장 늦은 선행이고 같은 웨이브에 여럿이면 ID가 가장 앞선 것이다. 정할 수 없으면 웨이브와 기준 선행을 `미정`으로 닫는다. 웨이브별 기능 수와 공통·고유 수는 파생 값이라 열로 두지 않고 집계에 웨이브 수와 웨이브 행 수만 둔다.
- **이유:** (a)는 한 칸에 여러 ID라 정확히 한 번의 요구를 구조로 보장하지 못하고 칸마다 `미정`으로 닫을 수 없다(21번 DL-21-003과 같은 이유). (c)는 표가 하나 늘고 배치 표는 어차피 기능마다 한 행이다. (b)는 기준 선행을 적어 웨이브 번호를 기계가 검사할 수 있다. 약속된 표 키 `웨이브`의 정의 ID `DW`를 배치 행에 붙였으므로 행이 웨이브 하나가 아니라 기능의 웨이브 배치 하나를 뜻한다. 병합 때 그룹 I의 약속과 어긋나면 고쳐야 한다.
- **영향:** 우선순위·릴리스 단계는 `33.웨이브.기능`과 `33.웨이브.웨이브`를 읽는다(DL-33-007). 웨이브 번호가 같은 기능을 묶어 보려면 웨이브 칸으로 거른다.
- **상태:** 검토 대기

### DL-33-005 · 샘플의 파생 표(영역 간 매트릭스, 상위 호출 순위, 웨이브별 건수)는 표로 옮기지 않는다
- **날짜:** 2026-10-10
- **대상:** `templates/33_의존성_template.md` 5절 (필드 `33.집계.호출 건수`, `33.집계.호출 방향 위반 수`, `33.집계.웨이브 행 수`, `33.집계.웨이브 수`), 분석서 SA-11, SA-14, SA-18, SA-19, SA-22, SA-26
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 영역×영역 호출 건수 매트릭스 둘, 공통 기능별 호출하는 기능 수와 최대 6개의 목록, 호출 상위 8개, 웨이브별 기능 수·공통·고유 수를 표로 둔다. 모두 호출 표와 웨이브 표에서 세면 얻는 파생 값이고 영역 매트릭스는 교차곱 표다. 샘플의 호출하는 기능은 6개로 잘리고 `…`로 줄어 있다(SA-19).
- **검토한 대안:** (a) 샘플처럼 파생 표를 모두 둔다 / (b) 영역 간 매트릭스만 두고 나머지는 뺀다 / (c) 모두 빼고 집계에 건수와 위반 수만 둔다
- **결정:** (c). 영역 간 매트릭스는 호출 표를 호출 기능과 호출받는 기능이 속한 영역으로 걸러 보면 얻으므로 표로 두지 않는다. 방향 원칙의 적용 결과는 호출 방향 위반 수와 선후행 방향 위반 수로 남긴다.

- **배경:** CM-K04는 근거 조각이 출처 유형이나 참조로 시작하기를 요구하고 참조는 `NN ` 또는 `대문자 1~3자-숫자`로 시작하는 것으로 읽는다. 그룹 I의 최종 기능 ID는 `F-<영역코드>-nnn`이고 영역 코드는 영문 대문자라 `F-` 뒤가 숫자가 아니다. 기능 ID로 시작하는 근거 조각은 형식이 맞는데도 도구가 실패로 볼 수 있다.
- **검토한 대안:** (a) 도구의 참조 판정을 고쳐 기능 ID를 참조로 인정한다(규칙 문서와 도구를 고치는 일이라 이번 작업의 범위 밖) / (b) 규칙은 그대로 두고 가이드가 기능 ID를 조각 첫머리에 쓰지 말고 `NN <산출물 이름>` 참조 뒤에 쉼표로 이으라고 안내한다
- **결정:** (b)를 따랐다. 규칙 변경은 (a)로 제안만 한다: 근거 칸의 참조 모양에 최종 기능 ID `F-<대문자 코드>-<숫자>`를 더한다. 이 제안은 31번과 32번의 근거 칸에도 같은 영향을 준다. 33번 완료 체크의 규칙(호출 쌍 유일, 방향, 순환, 기능마다 웨이브 한 행, 기준 선행과 웨이브 번호의 일치, 검사 판정과 호출 행의 일치, 집계 합계의 일치)을 도구로 검사하는 일은 사용자가 맡는다고 했으므로 이 로그는 규칙 문장만 정확히 쓴다.
- **이유:** 규칙과 도구는 이번 작업에서 고치지 않기로 했다. 가이드의 우회 안내는 도구가 고쳐지면 불필요해지지만 해가 되지 않는다.
- **영향:** 사용자 결정이 필요하다. 규칙을 고치면 가이드 3.1과 6절의 우회 문장을 지운다.
- **상태:** 검토 대기

### DL-33-010 · 그룹 I 병합: 입력 줄을 더하고 그룹 안 잠정 줄을 필드 키로 바꾼다
- **날짜:** 2026-10-10
- **대상:** `tools/data/interfaces.csv`
- **결정 주체:** 유지보수자 판단
- **배경:** 31·32·33번 세트를 병렬로 만든 뒤 병합했다(그룹 I). 각 세트가 남긴 "병합 때 더할 입력 줄" 목록(DL-31-003, DL-32-009, DL-33-008)과 같은 그룹 안의 문서 수준 잠정 줄이 남아 있었다.
- **검토한 대안:** (a) 목록의 줄만 더한다 / (b) 목록의 줄을 더하고 그룹 안 잠정 줄은 필드 키로 바꾼다
- **결정:** (b). 같은 그룹 안 잠정 줄 16개(IF-31-012, 013, 015~022, 024와 IF-32-002, 008, 013~015)의 받는 쪽을 31·32·33번 필드 키로 바꾸고, 세 목록의 입력 줄 248개를 더했다. 열 이름이 약속과 같아 목록을 그대로 썼고 32번 기능트리에 `영역` 열이 없어 그 줄 하나는 더하지 않았다(영역은 기능군을 거쳐 IF-32-002가 잇는다). 34~36번으로 가는 줄과 34·35·36번에서 되쓰는 환류 줄은 템플릿이 생길 때 더한다. 
- **이유:** 받는 쪽 템플릿이 있으면 필드 키로 쓰는 것이 규칙이다(IR-10).
- **영향:** `build.py`로 31·32·33번 템플릿의 입력 블록이 갱신된다. 받는 쪽 필드를 어느 칸으로 할지는 판단이라 `검토 대기`다. `check_chain.py`에 후보 전수 소진 검사를 더했다(DL-TL-012).
- **상태:** 검토 대기

### DL-33-011 · 도메인 교체 시험 반영: 기능 ID `미정` 행, 공통 기능을 나눠 구현할 때의 호출, 직접 근거
- **날짜:** 2026-10-10
- **대상:** `guides/33_의존성_guide.md` v1.1
- **결정 주체:** 유지보수자 판단
- **배경:** 그룹 I 도메인 교체 시험(학교 급식 알레르기 관리, 농장 센서 모니터링). 영역 `미정`으로 기능 ID가 `미정`인 기능(A 19개, B 8개)이 웨이브·검사 표에서 구별되지 않았다. 공통 기능 한 항목을 기능 여럿이 구현할 때 호출받는 기능을 고르는 기준, 고유 정책 후보가 병합된 기능의 호출, 직접 근거의 인정 기준이 없어 두 작성자가 임의로 판단했다.
- **검토한 대안:** (a) 그대로 둔다 / (b) 시험에서 두 도메인이 갈린 곳을 가이드에서 정한다
- **결정:** (b). 기능 ID가 `미정`인 기능도 한 행을 갖되 근거 첫 조각의 임시 번호 참조로 구별한다. 나눠 구현하면 호출 후보의 동작을 구현하는 기능을 쓰고 가를 수 없으면 `미정`이다. 구현하는 기능이 없는 공통 기능의 호출은 행을 만들지 않고 알린다. 근거 ID에 DC가 아닌 항목이 있으면 직접 근거로 인정한다.
- **이유:** 두 작성자가 같은 입력에서 다른 판단을 하면 산출물이 사람마다 달라진다.
- **영향:** 33번 가이드 v1.1. 순환, 후속 의존, 호출 대상 미정 칸은 두 도메인에서 한 번도 나타나지 않아 시험하지 못했다.
- **상태:** 검토 대기
