> 29번 세트(템플릿, 단계 가이드, 변환 분석서, 인터페이스 표의 29 관련 연결)의 결정 이력이다. 항목은 추가만 하고 과거 항목은 고치지 않는다(`docs/규칙_결정로그.md`).

### DL-29-001 · 29번 변환 분석서와 템플릿 v1.0, 단계 가이드 v1.0 초안을 작성한다
- **날짜:** 2026-10-09
- **대상:** `conversions/29_표준카탈로그_대조_conversion.md`, `templates/29_표준카탈로그_대조_template.md`, `guides/29_표준카탈로그_대조_guide.md`
- **결정 주체:** 사용자 승인 (그룹 단위 진행을 승인함(DL-05-005))
- **배경:** 그룹 H(29 표준 카탈로그 대조, 30 유사 서비스 대조)를 병렬로 만든다. 샘플 해부 41행(SA-01~41)과 누락 탐색 20행(OM-01~20)을 앞 단계와 같은 절차로 만들었다. 샘플의 대조표 104행, 갭 후보 7행, 환류 2행은 같은 틀을 되풀이해 표 단위로 묶었다(CV-06). 단계 정의의 목적은 서비스에 보통 있는 공통 기능의 표준 목록과 후보를 대조해 당연한 기능의 누락을 찾는 것이고 산출물은 항목별 채택·제외 판정과 갭 목록이다. 이 단계는 후보를 찾는 단계가 아니라 외부 기준의 항목을 앞 단계가 만든 후보 풀과 맞대는 단계라 04·05번의 구성(도출 질문 → 후보 → 판정 → 목록)을 따르지 않았다. 도메인 교체 시험(③)은 템플릿과 가이드를 쓴 뒤에 하므로 아직 하지 않았고 분석서 상태는 `초안`이다.
- **검토한 대안:** (가) 샘플처럼 대조표 한 표에 카탈로그 항목과 판정만 두는 안 / (나) 04·05번처럼 도출 질문, 후보, 판정, 목록의 네 단계로 구성하는 안 / (다) 카탈로그 정보, 대조표, 갭 후보, 집계의 네 표로 구성하는 안
- **결정:** (다). 값 표 넷을 둔다. 카탈로그정보(속성 표, 정의 ID 없음, 필드 4), 대조표(목록 표, 정의 ID `CG`, 필드 10), 갭후보(목록 표, 정의 ID `CGC`, 필드 7), 집계(속성 표, 정의 ID 없음, 필드 11). 필드는 모두 32개다. 선택 블록과 표 없는 필수 블록은 없다.
- **이유:** (가)는 카탈로그가 어디서 왔는지와 근거 등급을 담을 곳이 없고(OM-01, OM-13) 판정과 범위 항목과 사유가 한 칸에 섞인다(SA-20, OM-03). (나)는 후보를 새로 찾는 질문이 필요 없는 이 단계에 맞지 않는다. (다)는 행 하나가 판단 하나이고, 템플릿의 모든 표와 필드가 분석서의 줄에 대응한다(정의서 6절 4번).
- **영향:** 도메인 교체 시험(8번)이 남았다. 인터페이스 표는 DL-29-002, DL-29-003, DL-29-007이 다룬다.
- **상태:** 유효

### DL-29-002 · 인터페이스 표: 잠정 줄 5개를 필드 수준으로 바꾸고 29번 보내는 줄 39개와 외부 입력 줄 1개를 추가한다
- **날짜:** 2026-10-09
- **대상:** `tools/data/interfaces.csv` (IF-02-008, IF-02-010, IF-02-018, IF-20-002, IF-20-006 수정, IF-29-001~039, IF-EX-29-001 추가)
- **결정 주체:** 유지보수자 판단
- **배경:** 29번 템플릿이 생겨 범위·제약과 도메인 공통·고유 단계가 29번으로 보내던 문서 수준 잠정 줄 5개를 필드 수준으로 바꿀 수 있게 되었다(IR-10). 템플릿 필드 32개는 모두 보내는 필드로 한 줄 이상 나와야 한다(IR-07). 쓰이는 곳은 샘플의 머리말(SA-07)과 단계 정의가 뒷받침한다.
- **검토한 대안:** 해당 없음 — 규칙(IR-07, IR-10)을 따랐다.
- **결정:** 수정한 줄은 IF-02-008(받는 쪽 `29.대조표.근거`), IF-02-010과 IF-02-018과 IF-20-006(`29.대조표.판정`), IF-20-002(`29.대조표.공통 기능`)다. 추가한 29번 줄은 39개다. 소비자가 있는 줄 24 가운데 21은 받는 단계가 30, 31, 34이고 모두 문서 수준 잠정 값이며 환류 3줄은 20번 후보 판정 표의 필드 키로 썼다. 소비자가 없는 줄 15는 `최종 소비자 없음`과 사유로 닫았다(집계 11개, 대조표의 영역과 근거, 갭 후보의 근거, 카탈로그 정보의 다루는 범위). 샘플의 쓰이는 곳(34번)과 단계 정의가 뒷받침하지 않는 소비자는 근거 칸에 `추정: 가정`을 썼다(IF-29-001, 002, 004, 008, 010, 011, 012, 018, 022, 024, 027). 외부 입력은 `EXT:표준_공통기능_카탈로그` 하나이고 대조할 항목의 출처다(OM-01).
- **이유:** 템플릿 필드마다 소비자가 있거나 사유가 있어야 한다. 집계는 이 산출물 안의 완결성 점검이라 뒤 단계가 값으로 쓰지 않는다(20번의 선례, DL-20-002). 외부 입력 이름은 모든 외부 입력에 걸쳐 유일해야 해서(IR-09) 카탈로그의 출처 정보를 받는 줄을 따로 두지 않았다.
- **영향:** 30번과 34번 템플릿이 생기면 해당 잠정 줄을 필드 수준으로 바꾼다. 31번 템플릿이 생기면 같다. 아래 DL-29-003의 입력 줄을 더하기 전에는 29번 템플릿 머리말의 입력에 후보 풀의 후보 표가 보이지 않는다.
- **상태:** 검토 대기

### DL-29-003 · 병합 때 더해야 할 입력 줄의 목록
- **날짜:** 2026-10-09
- **대상:** `tools/data/interfaces.csv` (아직 만들지 않은 29번 입력 줄), `guides/29_표준카탈로그_대조_guide.md` 1절
- **결정 주체:** 유지보수자 판단
- **배경:** 단계 가이드 1절은 후보 표를 가진 앞 단계, 도메인 공통·고유, 범위·제약, 개념 없음 판정에 쓰는 닫힌 목록을 읽으라고 한다. 연결 ID는 보내는 단계 번호로 시작하므로 병렬 작업 중 번호가 겹치지 않게 앞 단계가 29번으로 보내는 새 입력 줄은 이번에 만들지 않았다. 이미 있던 잠정 줄 5개만 필드 키로 바꿨다(DL-29-002).
- **검토한 대안:** (가) 앞 단계의 입력 줄을 이번에 직접 더한다 / (나) 병합 때 더할 목록을 로그에 남긴다
- **결정:** (나). 아래 줄을 병합 때 더한다. 모두 방향 `순행`이다. 형식은 보내는 필드 → 받는 필드, 방식, 필수다.
  - 후보 풀: 아래 열여덟 표마다 `<표>.ID` → `29.대조표.후보` 참조(ID) 예 / `<표>.후보 문장` → `29.대조표.판정` 판단 입력 예 / `<표>.구분` → `29.대조표.판정` 판단 입력 아니오. 표는 09.질문목록, 10.추가질문, 12.후보목록, 13.후보목록, 14.기능후보, 15.기능후보, 16.기능후보, 17.후보목록, 18.기능후보, 19.기능후보, 22.기능후보, 23.기능후보, 24.방어후보, 25.기능후보, 26.도구후보, 27.기능후보, 28.기능후보다. 20.신규후보는 열 이름이 `기능 후보`이므로 `20.신규후보.ID` → `29.대조표.후보`, `20.신규후보.기능 후보` → `29.대조표.판정`, `20.신규후보.구분` → `29.대조표.판정`이다(합계 열여덟 표, 54줄).
  - 도메인 공통·고유: `20.후보판정.공통 기능 ID` → `29.대조표.공통 기능` 참조(ID) 아니오.
  - 범위·제약: `02.포함목록.ID`, `02.제외목록.ID`, `02.후속목록.ID` → `29.대조표.범위 항목` 참조(ID) 아니오. `02.포함목록.내용` → `29.대조표.판정` 판단 입력 아니오. `02.제외목록.사유`, `02.후속목록.사유` → `29.대조표.사유` 판단 입력 아니오. `02.제외목록.재검토 조건`, `02.후속목록.재검토 조건` → `29.대조표.재검토 조건` 판단 입력 아니오.
  - 개념 없음 판정의 닫힌 목록: `01.서비스정의.한 줄 정의`, `11.엔티티목록.엔티티`, `18.플랫폼목록.플랫폼` → `29.대조표.판정` 판단 입력 아니오. `27.지점점검.ID` → `29.대조표.근거` 근거 인용 아니오, `27.지점점검.판정` → `29.대조표.판정` 판단 입력 아니오.
  - 갭 후보의 환류를 받는 20번은 `20.후보판정` 입력으로 이미 DL-29-007의 줄을 갖는다. 병합 뒤에는 도메인 공통·고유 단계 가이드 1절이 29번의 갭 후보도 환류로 읽는다고 쓰도록 20번 세트를 고쳐야 한다(이 세트의 범위 밖).

- **영향:** 병합자가 위 줄을 해당 단계의 번호 구간에 추가하고 `python3 tools/build.py`로 머리말을 다시 만든다. 병합 전 29번 템플릿의 입력 블록에는 후보 풀이 보이지 않는다.
- **상태:** 검토 대기

### DL-29-004 · 카탈로그를 어디서 어떻게 가져오는지를 카탈로그 정보 표로 정하고, 작성자 초안은 요청이 있을 때만 허용한다
- **날짜:** 2026-10-09
- **대상:** `templates/29_표준카탈로그_대조_template.md` 1절 (표 `카탈로그정보`), `guides/29_표준카탈로그_대조_guide.md` 3.1, 5절
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 카탈로그 104개를 본문에 쓰고 출처를 밝히지 않는다(SA-05, SA-24, OM-01). 단계 정의는 카탈로그의 출처를 정하지 않았다. 일반 지식으로 지은 카탈로그는 검증된 근거가 아니다(공통 규칙 CM-10).
- **검토한 대안:** (가) 템플릿에 카탈로그를 고정해 둔다 / (나) 카탈로그의 출처를 쓰는 표를 두고 확보 방식을 `사람이 준 목록`, `공개 자료 확인`, `작성자 초안`으로 가른다 / (다) 입력에 카탈로그가 없으면 항상 `미정` 한 줄로 닫는다
- **결정:** (나)와 (다)를 합친다. 카탈로그는 사람이 준 자료(`EXT:표준_공통기능_카탈로그`)이거나 작성자가 직접 열어 확인한 공개 자료다. 사용자가 일반 지식으로 초안을 만들어 달라고 요청한 경우에만 `작성자 초안`을 허용하고 모든 근거를 `일반 지식(미검증)`으로 쓴다. 요청이 없는 입력 부재는 대조표를 한 줄 `미정`으로 닫는다(가이드 5절).
- **이유:** (가)는 샘플의 카탈로그를 템플릿이 고정해 도메인 편향을 들인다(SA-24). (다)만 쓰면 요청이 있을 때도 쓸 방법이 없다. 요청이 없는데 작성자가 지어내는 것은 보수적이지 않다.
- **영향:** `작성자 초안`에서 나온 갭 후보는 미검증이다. 34번 세트가 이 표시를 읽도록 IF-29-002를 두었다. 사용자 확인이 필요한 질문이다: 요청 없이도 일반 지식 초안을 허용할지.
- **상태:** 유효

### DL-29-005 · 판정 어휘는 채택, 갭, 제외, 후속, 개념 없음으로 하고 30번과의 일치를 병합 때 확인한다
- **날짜:** 2026-10-09
- **대상:** `templates/29_표준카탈로그_대조_template.md` 2절 (필드 `29.대조표.판정`), `guides/29_표준카탈로그_대조_guide.md` 3.2
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플의 판정 값은 채택, 제외, Later, N/A, 갭, 프로세스, 설계이고 괄호 변형이 있다(SA-10, SA-16~19). `N/A`는 닫는 말 `해당 없음`과 같은 뜻이고 `프로세스`, `설계`는 후보의 구분이다. 범위·제약의 제외·후속 목록과 어휘를 맞추고(OM-05) 30번과 같은 말을 써야 한다. 30번은 병렬로 만들어져 이 세트에서 볼 수 없다.
- **검토한 대안:** (가) 샘플의 어휘를 그대로 쓴다 / (나) 채택, 갭, 제외, 후속의 넷만 둔다 / (다) 넷에 개념 없음을 더한다
- **결정:** (다). 후보 풀에 덮는 후보가 있으면 `채택`(덮는 후보가 모두 후속 후보이면 `후속`), 풀에 없고 범위가 하지 않기로 했으면 `제외`, 미루기로 했으면 `후속`, 항목이 전제하는 대상이 서비스에 없으면 `개념 없음`, 어느 쪽도 아니면 `갭`이다. 어느 값도 `미정`, `해당 없음`과 같은 글자가 아니다. 판정 질문의 순서는 풀, 범위, 개념, 갭이다.
- **이유:** (가)는 `N/A`가 닫는 말과 혼동되고 `Later`가 02번의 `후속`과 어긋난다. (나)는 대상이 서비스에 없는 항목을 `제외`로 쓰게 해 02번의 제외 목록에 없는 항목이 누락처럼 보인다. 개념 없음은 사유에 닫힌 목록을 가리키는 값만 허용한다.
- **영향:** 30번 세트의 판정 선택지와 어휘가 같은지 병합 때 확인한다. 30번이 `개념 없음`을 두지 않으면 어휘를 맞추는 쪽을 사용자가 정해야 한다.
- **상태:** 유효

### DL-29-006 · 제외·후속·개념 없음 판정에는 후보를 만들지 않고 갭 후보만 제안한다
- **날짜:** 2026-10-09
- **대상:** `templates/29_표준카탈로그_대조_template.md` 3절 (표 `갭후보`), `guides/29_표준카탈로그_대조_guide.md` 3.2, 3.3
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 갭 4건에 더해 제외·후속 판정에도 후보를 등록했고(CF-29-04, 06, 07) 후보 문장에 판정 결과를 굵은 표시로 섞었다(SA-23, SA-27, SA-36). 단계의 지시는 풀에 없는 항목을 판정 `갭`으로 쓰고 갭 목록에서 신규 후보를 제안하는 것이다. 항목의 일부만 덮는 후보는 샘플이 `채택(부분)`으로 썼다(SA-19, OM-11).
- **검토한 대안:** (가) 샘플처럼 제외·후속에도 후보를 올린다 / (나) 갭 판정에서만 올린다 / (다) (나)에 더해 덮지 못한 부분이 있는 채택 행도 올린다
- **결정:** (다). 갭 후보의 출처는 판정이 갭인 행이거나 덮지 못한 부분이 있다고 쓴 채택 행이다. 제외·후속·개념 없음의 추적은 범위·제약의 목록과 대조표의 범위 항목·재검토 조건이 맡는다. 갭 후보의 구분은 기능 후보, 설계 기준, 프로세스다. 후속 후보는 두지 않는다.
- **이유:** (가)는 후보 풀을 부풀리고 제외가 의도적인지 확인하는 일을 후보가 아닌 범위·제약이 해야 하는데 둘을 섞는다. 부분 채택에서 덮지 못한 부분을 올릴 곳이 없으면 그 부분은 누락으로 남는다. 후속 후보는 입력 산출물이 미룬 항목에서 나오는데 후속 항목은 갭이 아니다.
- **영향:** 34번 세트는 의도적 제외 목록을 대조표의 범위 항목에서 읽는다(IF-29-013).
- **상태:** 검토 대기

### DL-29-007 · 갭 후보는 도메인 공통·고유 단계로 환류하고 환류 대상 열로 합류시킬 후보 표를 남긴다
- **날짜:** 2026-10-09

- **상태:** 유효
