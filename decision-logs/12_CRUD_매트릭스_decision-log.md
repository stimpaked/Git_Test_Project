### DL-12-001 · 12번 변환 분석서와 템플릿 v1.0, 단계 가이드 v1.0 초안을 작성한다
- **날짜:** 2026-10-08
- **대상:** `conversions/12_CRUD_매트릭스_conversion.md`, `templates/12_CRUD_매트릭스_template.md`, `guides/12_CRUD_매트릭스_guide.md` (작업 순서 6단계, 그룹 단위 복제)
- **결정 주체:** 사용자 승인
- **배경:** 그룹 단위 진행을 승인함(DL-05-005). 샘플 해부 38행(SA-01~38)과 누락 탐색 17행(OM-01~17)을 04·05번과 같은 절차로 만들었다. 샘플의 매트릭스는 엔티티 27행 × 처리 12열이라 칸 값은 표 단위로 묶어 해부했다(CV-06). 도메인 교체 시험(③)은 템플릿과 가이드를 쓴 뒤에 하므로 분석서의 상태는 `초안`이다.
- **검토한 대안:** 해당 없음 — 변환 절차(정의서 6절)를 따랐다.
- **결정:** 04·05번의 "도출 질문 → 후보 → 판정 → 목록" 흐름을 따르지 않고 단계의 목적(처리가 누구에게 어디서 제공되는지 확인해 빠진 기능을 드러낸다)에서 구성을 정했다. 구성은 ① 제외 방침(`CR`) ② 처리 매트릭스 ③ 후보 목록(`CF`)이다(DL-12-002~008). 도메인 교체 시험은 하지 않았다.
- **이유:** 샘플을 해부하고 누락을 찾은 결과가 템플릿의 모든 변경에 대응한다(정의서 6절 4번, 검사 CV-K04).
- **영향:** 도메인 교체 시험과 변환 분석서 `승인`이 남았다. 입력 연결(11, 04, 05번과 범위·제약, 근거 수집이 12번에 보내는 줄)은 만들지 않았다(DL-12-009). 13~16번 세트가 그룹 안에서 만들어지면 14·15·17·20·25·26·31·34번 템플릿이 생길 때 잠정 줄을 필드 수준으로 바꾼다.
- **상태:** 유효

### DL-12-002 · 매트릭스는 칸 하나가 행 하나인 목록 표로 쓴다
- **날짜:** 2026-10-08
- **대상:** `templates/12_CRUD_매트릭스_template.md` 2절 (표 키 `매트릭스`), `docs/규칙_템플릿.md` (TP-12, TP-27)
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 행이 엔티티이고 열이 처리 12개인 교차표이며 칸마다 주체 목록이나 N 코드가 한 줄로 들어 있다(SA-20, SA-24). 06번 세트는 액터 수가 서비스마다 달라 열을 고정할 수 없다는 이유로 칸 하나가 행 하나인 목록 표를 골랐다(DL-06-002). 이 단계는 처리가 열두 가지로 고정되므로 06번과 달리 교차표의 열을 템플릿에 고정할 수 있다. 그래서 같은 이유가 아니라 이 단계의 목적에 맞는지로 다시 따졌다. 단계의 목적은 칸마다 누구에게 어디서 제공되는지 확인하고 빠진 칸을 드러내는 것이다(OM-01, OM-02, OM-03).
- **검토한 대안:** (a) 엔티티를 행, 처리 열두 개를 열로 둔 교차표를 쓰고 칸에는 주체 목록을 쓴다 / (b) 교차표에 판정·접점·근거를 칸마다 따로 적는 상세 표를 더한다 / (c) 칸 하나(엔티티와 처리의 조합)가 행 하나이고 주체가 갈리면 행을 나누는 목록 표를 쓴다
- **결정:** (c). 열은 `엔티티 | 처리 | 판정 | 주체 | 접점 | 근거`다. 별도의 칸 ID는 만들지 않고 엔티티 ID와 처리 이름의 조합을 칸의 키로 본다(OM-05).
- **이유:** (a)는 칸 하나에 값 하나만 담겨 칸마다 판정(이미 있는가, 새로 드러났는가, 제외인가)과 접점과 근거를 붙일 수 없고 한 칸의 여러 주체를 따로 읽을 수 없다. (b)는 교차표와 상세 표가 같은 사실을 두 곳에 쓰게 해 어긋나기 쉽다(CM-12). (c)는 칸마다 근거를 요구하는 공통 규칙(CM-05)과 맞고, 뒤 단계가 칸 단위로 읽으며(SA-07), 열 이름이 고정되므로 TP-27과 인터페이스 표의 필드 키(`12.매트릭스.판정` 등)를 그대로 쓸 수 있다.
- **영향:** 교차표로 한눈에 훑는 보기가 없다. 엔티티 수 × 12 이상의 행이 생기므로 산출물이 길어진다. 칸이 빠지지 않았는지는 도구가 확인하지 못해 완료 체크와 사람이 맡는다(OM-06). 규칙 문서 변경 제안은 DL-12-010에 있다.
- **상태:** 검토 대기

### DL-12-003 · 제외 방침 표를 매트릭스 앞에 두고 유형을 둘로 한다
- **날짜:** 2026-10-08
- **대상:** `templates/12_CRUD_매트릭스_template.md` 1절 (표 키 `제외방침`, 정의 ID `CR`), `guides/12_CRUD_매트릭스_guide.md` 3.1, 5절
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 N 코드 네 가지(N1~N4)로 제공하지 않는 칸을 닫고, N1의 사유만 매트릭스 뒤 표에 쓴다(SA-14~18, SA-26, SA-27). 매트릭스가 사유를 "아래 비고"로 미루어 순서가 어긋나고(TP-16), N2~N4의 사유는 어디에도 없다(OM-04). 병원 진료 기록의 삭제 제외처럼 법령이 요구하는 제외는 서비스의 선택과 다르다(OM-13).
- **검토한 대안:** (a) 샘플처럼 코드를 쓰고 사유 표를 매트릭스 뒤에 둔다 / (b) 사유를 칸마다 직접 쓰고 방침 표를 두지 않는다 / (c) 되풀이되는 정책·범위 사유를 방침 표로 모아 매트릭스 앞에 두고, 칸마다 다른 성질상 사유는 칸에서 닫는다
- **결정:** (c). 방침의 유형은 `정책·규제`와 `범위 밖` 둘이다. 매트릭스의 제외 행은 근거에서 방침 ID를 가리킨다. 방침이 걸린 칸은 방침 표에 쓰지 않고 매트릭스의 제외 행만 가리킨다(SA-27, CM-12). 엔티티의 성질상 성립하지 않는 칸은 방침이 아니라 칸의 사유로 닫는다(SA-18).
- **이유:** (a)는 순서 오류와 사유 누락을 그대로 둔다. (b)는 같은 이유가 수십 칸에 되풀이되어 어긋나기 쉽고, 뒤 단계가 의도적 제외를 사유와 함께 모으기 어렵다(단계 정의 34의 산출물에 의도적 제외 목록이 있다). 정책과 규제는 둘 다 "서비스가 제공하지 않기로 한" 결과이고 구별은 근거 칸에서 되므로 한 유형으로 묶었다.
- **영향:** 방침 하나가 어느 칸에 걸리는지는 매트릭스에서만 보인다. 규정이 요구하는 제외와 선택한 제외를 유형으로 가를 수 없다. 사용자가 둘을 나누길 원하면 선택지를 늘린다. 공통 규칙 CM-04는 `해당 없음`을 "개념 자체가 없을 때"로 정의하는데 제외 행은 개념은 있고 제공하지 않는 칸에도 `해당 없음`을 쓰게 한다(DL-12-010).
- **상태:** 검토 대기

### DL-12-004 · 판정은 행 단위의 세 값(제공, 후보, 제외)으로 한다
- **날짜:** 2026-10-08
- **대상:** `templates/12_CRUD_매트릭스_template.md` 2절 (`매트릭스.판정`), `guides/12_CRUD_매트릭스_guide.md` 3.2, 5절
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플의 칸은 모두 값이어서 어느 칸이 앞 단계에서 이미 나왔고 어느 칸이 이 단계에서 새로 드러났는지 알 수 없다(OM-02). 샘플의 후보에는 이미 있는 처리에 주체만 더하는 것이 있다(OM-10). 선택지 값에 `미정`, `해당 없음` 같은 닫는 말을 쓰지 않는다는 지침이 있다.
- **검토한 대안:** (a) 판정 열 없이 후보 목록만 두고 매트릭스는 값으로 채운다 / (b) 칸 단위로 판정을 하나 정한다 / (c) 행(칸과 주체의 조합) 단위로 판정을 정하고 한 칸에 제공 행과 후보 행이 함께 있을 수 있게 한다
- **결정:** (c). 선택지는 `제공`(앞 단계 산출물에서 찾았다), `후보`(찾지 못했지만 있어야 한다), `제외`(하지 않는다)이다. 필요 여부를 모를 때는 판정 칸을 `미정`으로 닫는다(06번 핵심 구간 열과 같은 방식). `제외`는 칸 전체를 제공하지 않을 때만 쓰고 같은 칸의 다른 판정 행과 섞지 않는다.
- **이유:** (a)는 목적(빠진 기능을 드러낸다)을 칸에서 확인할 수 없게 한다. (b)는 OM-10의 경우를 담지 못한다. (c)는 `후보` 행이 곧 후보 목록의 출처가 되어 두 표의 연결이 분명하다.
- **영향:** `제공`이라고 쓰려면 앞 단계 산출물의 항목을 근거로 가리켜야 하므로 작성 부담이 있다. 근거로 가리킬 항목의 ID 접두어는 앞 단계 템플릿이 정한다. 도메인 교체 시험에서 `후보`와 `미정`의 경계가 작성자마다 갈리는지 본다.
- **상태:** 검토 대기

### DL-12-005 · 주체는 처리를 일으키는 액터의 ID로만 쓴다
- **날짜:** 2026-10-08
- **대상:** `templates/12_CRUD_매트릭스_template.md` 2절 (`매트릭스.주체`), `guides/12_CRUD_매트릭스_guide.md` 3.2, 5절
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플의 칸 값에는 액터 ID 외에 `본인(소유자)`, `시스템(자동)`, 시간 트리거 `T-01`이 있다(SA-11~13). `본인`은 소유 관계이고 `시스템`은 서비스 안의 구성요소로 액터가 아니며 `T-`는 샘플 문서의 체계다. 공공 정보 조회 웹과 스마트 온실 모니터링 서비스에서는 생성·수정·삭제를 하는 것이 사람이 아닌 액터다(OM-11, OM-15).
- **검토한 대안:** (a) 샘플처럼 `본인`과 `시스템`을 값으로 허용한다 / (b) `서비스 자동` 같은 고정 낱말을 주체 값으로 둔다 / (c) 사람 액터(`A-`)와 비사람 액터(`X-`)의 ID만 허용하고, 사용자의 조작에 딸린 처리는 그 조작을 하는 액터, 시간이 일으키는 처리는 시간 트리거 액터를 쓴다
- **결정:** (c). 일으키는 액터를 찾지 못한 칸은 `미정`으로 닫고 확인처에 빠진 비사람 액터가 있는지를 쓴다. 자기 것만 다루는지는 이 단계에서 정하지 않는다.
- **이유:** (a)는 05번 완료 체크(서비스 안의 구성요소가 액터에 없다)와 어긋나고 소유·권한 단계의 몫을 앞당긴다. (b)는 액터 목록에 없는 주체를 만들어 뒤 단계의 참조가 끊긴다. (c)는 액터 ID 두 종류만 쓰므로 인터페이스 표의 참조(ID)와 맞는다.
- **영향:** 사건에 반응해 일어나는 처리(예: 사건이 일어나면 기록을 남기는 것)의 주체가 조작하는 액터로 쓰여, 사건 단계가 소비하는 정보와 겹칠 수 있다. 일으키는 액터를 찾지 못하는 칸이 많으면 05번의 비사람 액터가 빠졌다는 신호이므로 환류가 필요하다(공통 가이드 4절).
- **상태:** 검토 대기

### DL-12-006 · 접점 열을 두고 후보 행의 접점은 `미정`으로 닫는다
- **날짜:** 2026-10-08
- **대상:** `templates/12_CRUD_매트릭스_template.md` 2절 (`매트릭스.접점`), `guides/12_CRUD_매트릭스_guide.md` 3.2
- **결정 주체:** 유지보수자 판단
- **배경:** 단계의 목적은 처리가 "누구에게 어디서" 제공되는지 확인하는 것인데 샘플의 칸에는 누구만 있다(OM-01). 화면은 이 단계보다 뒤인 화면·UI 상태 단계가 정리하고, 접점에 입력에 없는 화면 이름을 지어내지 않는다는 앞 단계의 교훈이 있다(06번 단계 가이드 3.4).
- **검토한 대안:** (a) 접점 열을 두지 않는다 / (b) 접점을 제공 위치의 종류(사용자 접점, 운영 접점 같은 선택지)로 한다 / (c) 접점을 자유 서술로 두고 입력의 화면·채널·기능 이름만 쓰며 정해진 곳이 없으면 `미정`으로 닫는다
- **결정:** (c). 후보 행은 대개 접점이 정해져 있지 않으므로 `미정`(확인처: 화면·UI 상태 단계의 담당)으로 닫는다.
- **이유:** (a)는 목적의 절반을 버린다. (b)는 종류가 주체의 유형(사람 액터의 운영·지원 유형 등)과 겹쳐 같은 사실을 두 번 쓰고, 화면이 없는 서비스에서 선택지가 맞지 않는다. (c)는 입력에 없는 사실을 만들지 않는다.
- **영향:** 후보 행의 접점 칸이 `미정`으로 많이 남는다(검사 CM-K06이 `미정` 개수를 정보로 보여 준다). 화면·UI 상태 단계가 이 칸을 받아 채우는 흐름은 인터페이스 표(IF-12-015)에 판단 입력으로 적었다.
- **상태:** 검토 대기

### DL-12-007 · 처리 열두 가지를 닫힌 선택지로 두고 그 밖의 처리는 배정 규칙으로 다룬다
- **날짜:** 2026-10-08
- **대상:** `templates/12_CRUD_매트릭스_template.md` 2절 (`매트릭스.처리`), `guides/12_CRUD_매트릭스_guide.md` 3.2
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플의 열 12개(생성, 조회, 수정, 삭제, 목록, 검색, 보관·숨김, 복원, 가져오기, 내보내기, 공유, 감사 기록)는 서비스에 무관한 낱말이다(SA-09). 도메인을 바꾸면 열두 가지에 이름이 없는 처리(일괄 승인, 복사, 소유자 이전)가 나온다(OM-17). 승인·반려처럼 상태를 바꾸는 처리와 기간 단위 조회도 어느 칸인지 헷갈린다(OM-12, OM-16).
- **검토한 대안:** (a) 열두 가지를 닫힌 선택지로 두고 그 밖의 처리는 가이드의 배정 규칙으로 가장 가까운 칸에 쓴다 / (b) 열린 목록으로 두어 작성자가 처리를 더하게 한다 / (c) 처리 정의 표를 따로 두고 작성자가 처리 목록을 정한다
- **결정:** (a). 알파벳 약어는 쓰지 않고 이름을 쓴다(SA-09). 일괄 처리는 단건 처리와 같은 칸, 복사는 생성, 상태를 바꾸는 처리는 수정에 둔다.
- **이유:** 열린 목록은 칸 수를 셀 수 없어 완료 체크(엔티티 수 × 처리 수)가 약해지고, 서비스 사이에 매트릭스를 견주기도 어렵다. 처리 정의 표는 표 하나와 ID 하나를 더하지만 이 단계의 목적을 넘는다.
- **영향:** 열두 가지로 담기 어려운 도메인에서는 접점이나 후보 기능의 문장에 구체 이름이 들어간다. 도메인 교체 시험에서 부족한 처리가 나오면 선택지를 늘린다.
- **상태:** 검토 대기

### DL-12-008 · 후보 목록은 칸을 가리키고 접두어는 `CR`, `CF`를 쓴다
- **날짜:** 2026-10-08
- **대상:** `templates/12_CRUD_매트릭스_template.md` 1절·3절 (정의 ID `CR`, `CF`)
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플의 후보 표는 `후보 ID | 출처 칸 | 기능 후보 | 도메인 구분(잠정)`이고 ID에 단계 번호가 들어 있으며 근거가 없다(SA-30~34, OM-03). 정의 ID 접두어는 호출 지침이 `C`로 시작하는 것만 쓰게 했고 모든 템플릿에 걸쳐 유일해야 한다(TP-28).
- **검토한 대안:** (a) 매트릭스 행에 후보 ID 열을 두고 매트릭스가 후보 목록을 참조한다 / (b) 후보 목록이 칸을 가리키고 매트릭스는 후보 목록을 참조하지 않는다
- **결정:** (b). 후보 목록의 열은 `ID | 칸 | 기능 후보 | 잠정 도메인 구분 | 근거`다. 접두어는 제외 방침이 `CR`, 후보 목록이 `CF`다. 후보 ID는 `CF-01`부터 연번이다. 잠정 도메인 구분의 선택지는 유저 플로우의 미결 질문 표와 같은 낱말(공통 / 고유)을 쓴다.
- **이유:** (a)는 매트릭스가 뒤 표의 ID를 참조해 표 순서 규칙(TP-16)을 어긴다. (b)는 매트릭스를 먼저 쓰고 후보를 묶는 작성 순서와 맞는다.
- **영향:** 후보 목록의 칸과 매트릭스의 `후보` 행이 일치하는지는 도구가 확인하지 못해 완료 체크가 맡는다(DL-12-010). 후보의 잠정 도메인 구분이 갈릴 때 `고유`를 고른다는 판단은 09번 단계 가이드(DL-09-009)와 같다.
- **상태:** 검토 대기

### DL-12-010 · 규칙 문서 변경 제안: 매트릭스 표기, `해당 없음`의 범위, 표 사이 검사
- **날짜:** 2026-10-08

- **배경:** (1) 06번에서 이미 제안한 매트릭스 표기 규정(DL-06-006)이 이 단계에도 해당한다. 이 단계는 열을 고정할 수 있는 경우인데도 목록 표를 골랐다(DL-12-002). - **결정:** 규칙 문서와 도구는 바꾸지 않는다. 제안은 셋이다: (1) 규칙_템플릿에 "교차 구조는 칸 하나가 행 하나인 목록 표로 쓸 수 있다"를 명시하고 정의서 12절의 매트릭스 설명에 덧붙이며, 산출물 검사에 칸의 조합이 중복되거나 빠졌는지 확인하는 선택 검사를 더하는 것(DL-06-006의 연장). - **영향:** 사용자가 확정하면 해당 규칙 문서의 결정 로그에 기록하고 버전을 올린다. (2)가 확정되지 않으면 12번 가이드의 `제외` 닫는 법이 공통 규칙의 문구보다 넓다.
