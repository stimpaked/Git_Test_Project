### DL-02-001 · 02번 변환 분석서와 템플릿 v1.0, 단계 가이드 v1.0 초안을 작성한다
- **날짜:** 2026-10-09
- **대상:** `conversions/02_범위_제약_conversion.md`, `templates/02_범위_제약_template.md`, `guides/02_범위_제약_guide.md` (작업 순서 6단계, 그룹 단위 복제)
- **결정 주체:** 사용자 승인
- **배경:** 그룹 단위 진행을 승인함(DL-05-005). 02번은 체계의 맨 앞 그룹(프레임·근거)이라 앞 단계 산출물이 없고 입력은 사람이 주는 자료다. 샘플 해부 50행(SA-01~50)과 누락 탐색 19행(OM-01~19)을 04·05번과 같은 절차로 만들었다. 샘플은 표 아홉 개로 이루어져 값이 많은 표는 칸 값을 표 단위로 묶어 해부했다(CV-06). 도메인 교체 시험(③)은 템플릿과 가이드를 쓴 뒤에 하므로 분석서의 상태는 `초안`이다.
- **검토한 대안:** 해당 없음 — 변환 절차(정의서 6절)를 따랐다.
- **결정:** 04·05번의 "도출 질문 → 후보 → 판정 → 목록" 흐름을 따르지 않고 단계의 목적(하는 것과 하지 않는 것, 지켜야 할 제약을 정해 기능 후보의 경계를 만든다)에서 구성을 정했다. 사람이 가진 정보를 묻고 정리하는 단계라 구성은 ① 범위 결정 규칙(`OR`) ② 포함 목록(`OI`) ③ 제외 목록(`OX`) ④ 후속 목록(`OL`) ⑤ 플랫폼 후보(`OP`) ⑥ 제약(`OC`) ⑦ 가정(`OA`) ⑧ 의존성(`OD`) ⑨ 리스크(`ORK`)이다(DL-02-002~007). 도메인 교체 시험은 하지 않았다.
- **이유:** 샘플을 해부하고 누락을 찾은 결과가 템플릿의 모든 변경에 대응한다(정의서 6절 4번, 검사 CV-K04). 뒤 단계가 이미 읽는 방식에 맞췄다(DL-02-008).
- **영향:** 도메인 교체 시험과 변환 분석서 `승인`이 남았다. 입력 줄과 뒤 단계가 읽는 줄 중 인터페이스 표에 없는 것은 병합 때 더한다(DL-02-010, DL-02-011). 03·22·23·29·30·34·36번 템플릿이 생기면 문서 수준 잠정 줄을 필드 수준으로 바꾼다.
- **상태:** 유효

### DL-02-002 · 구성은 규칙 → 포함 → 제외 → 후속 → 플랫폼 → 제약 → 가정 → 의존성 → 리스크 아홉 표로 하고 샘플의 순서를 지킨다
- **날짜:** 2026-10-09
- **대상:** `templates/02_범위_제약_template.md` (표 키 `결정규칙`, `포함목록`, `제외목록`, `후속목록`, `플랫폼후보`, `제약`, `가정`, `의존성`, `리스크`), `guides/02_범위_제약_guide.md` 2절, 3절
- **결정 주체:** 유지보수자 판단
- **배경:** 단계 정의의 산출물은 포함·제외·후속 목록(각각 사유), 플랫폼 후보, 제약·가정·의존성·리스크 목록이다. 샘플은 이를 아홉 절로 나눈다(SA-08, SA-12, SA-17, SA-24, SA-30, SA-35, SA-39, SA-43, SA-47). 이 단계에는 04·05번의 도출 질문 표나 후보 정리 표가 맞지 않는다. 입력이 사람이 주는 자료이고 항목은 질문의 답이 아니라 자료에서 가려내는 결정이기 때문이다(사용자가 정한 사항).
- **검토한 대안:** (a) 04·05번처럼 도출 질문 → 후보 → 판정 → 목록으로 쓴다 / (b) 샘플의 아홉 절을 표 아홉 개로 그대로 옮긴다 / (c) 포함·제외·후속·플랫폼을 한 표에 구분 열로 모은다
- **결정:** (b). 샘플의 절 순서를 지키되 작성 순서에 맞는지 확인했다(TP-16). 규칙이 가장 앞이고 포함이 규칙을 참조하며, 가정과 리스크가 앞 표의 ID를 가리키는 방향으로 샘플의 역방향 참조(SA-23, SA-33)를 바로잡았다.
- **이유:** (a)는 입력이 얇을 때 질문마다 `미정`이 늘고 뒤 단계가 읽을 목록(제외, 후속, 플랫폼)이 질문 표 안에 묻힌다. (c)는 열이 서로 다른 표(포함은 영역과 규칙, 플랫폼은 대상과 지원 조건)를 억지로 합쳐 빈 열이 생긴다. 뒤 단계의 가이드가 "제외 목록", "후속 목록", "플랫폼 후보"를 이름으로 가리키므로 표를 나눠 두면 읽기가 이름에 그대로 대응한다.
- **영향:** 표가 아홉 개라 필드가 47개로 04·05번보다 많다. 입력이 얇으면 `미정`이 많이 나온다(구조의 결함이 아니라 입력 부족).
- **상태:** 검토 대기

### DL-02-003 · 포함 목록에도 사유와 재검토 조건을 두고 항목마다 ID를 부여한다
- **날짜:** 2026-10-09
- **대상:** `templates/02_범위_제약_template.md` 2절 (`포함목록.ID`, `포함목록.사유`, `포함목록.재검토 조건`), `guides/02_범위_제약_guide.md` 3.2
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플의 포함 표는 영역, 내용, 해당 규칙뿐이다(SA-13). 단계 정의는 포함·제외·후속 목록이 각각 사유를 가진다고 한다(OM-02). 뒤 단계는 포함 항목을 ID로 가리킬 수 있어야 하고(OM-01), 일정이 모자랄 때 조정 조건이 필요하다(SA-49의 컷라인 대응).
- **검토한 대안:** (a) 해당 규칙만 사유로 본다 / (b) 사유와 재검토 조건을 포함 목록에도 둔다 / (c) 재검토 조건은 제외와 후속에만 둔다
- **결정:** (b). 포함의 재검토 조건은 영역의 일부를 빼거나 미루게 되는 조건이다. 컷라인은 우선순위를 정하는 뒤 단계가 확정하므로 입력에 없으면 `미정`으로 닫는다고 가이드에 썼다. 포함 항목의 단위는 샘플처럼 영역 한 행에 기능을 쉼표로 나열한 것이다.
- **이유:** (a)는 규칙 이름만 되풀이하는 사유가 되어 정보가 없다. (c)는 세 목록의 열이 달라져 단계 정의의 "각각 사유"를 포함에서 만족하지 못한다.
- **영향:** 포함 목록의 재검토 조건이 입력에 없어 `미정`으로 닫히는 경우가 많다. 기능을 한 행에 쉼표로 나열하므로 뒤 단계가 기능 하나를 ID로 가리키지 못하고 영역 ID와 기능 이름으로 가리킨다(사용자가 기능마다 행을 원하면 포함 목록의 단위를 바꾼다).
- **상태:** 검토 대기

### DL-02-004 · 플랫폼 후보는 독립 표로 두고 범위 구분을 더하며 대상은 역할 이름으로 쓴다
- **날짜:** 2026-10-09
- **대상:** `templates/02_범위_제약_template.md` 5절 (`플랫폼후보.범위 구분`, `플랫폼후보.대상`, `플랫폼후보.지원 조건`), `guides/02_범위_제약_guide.md` 3.5
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 포함 표의 마지막 줄에 플랫폼을 다시 쓰고 플랫폼 후보 표는 포함 플랫폼만 나열한다(SA-16, SA-30, SA-31). 제외한 플랫폼은 제외 표에만 있다. 플랫폼·채널 단계의 가이드는 플랫폼 후보를 목록의 출발점으로 읽고 범위 구분을 포함·후속·제외로 나누며 제외와 후속인 후보도 남기라고 하고, 화면·UI 상태 단계는 플랫폼 후보의 이름을 그대로 쓴다고 한다(OM-04). 대상은 샘플이 액터 ID(`A-04~A-06`)를 쓰지만 액터 목록은 이 단계 뒤에 만들어진다(SA-34). 장치 같은 플랫폼은 대상이 없다(OM-16), 둘 이상이다(OM-18).
- **검토한 대안:** (a) 샘플처럼 포함 플랫폼만 쓰고 제외·후속 플랫폼은 제외·후속 목록에서 짐작하게 한다 / (b) 범위 구분 열을 두고 제외·후속 플랫폼도 후보 표에 쓴다 / (c) 포함 표의 플랫폼 줄을 그대로 두고 후보 표를 중복해 쓴다
- **결정:** (b). 범위 구분의 선택지는 플랫폼·채널 단계와 같은 어휘(포함 / 후속 / 제외)로 한다. 제외·후속 플랫폼의 근거는 제외·후속 목록의 ID를 가리킨다. 대상은 역할 이름을 쉼표로 쓰고 사람이 직접 쓰지 않으면 `해당 없음`과 사유로 닫는다. `비고`는 내용이 지원 환경의 범위라 `지원 조건`으로 이름을 고쳤다. 샘플의 최소 지원 버전은 가정 표가 플랫폼 ID를 관련 항목으로 가리키도록 방향을 바꿨다(SA-33). 포함 표의 플랫폼 줄은 두지 않았다(SA-16).
- **이유:** (a)는 플랫폼·채널 단계가 읽는 범위 구분을 후보 표에서 알 수 없게 한다. (c)는 같은 사실이 두 곳에 있어 어긋날 수 있다(CM-12). 같은 값을 두 단계가 다른 어휘로 쓰지 않아야 한다.
- **영향:** 범위 구분이 `후속`인 플랫폼의 지원 조건은 `해당 없음`으로 닫는 기준을 가이드에 썼다(제외와 같다). 플랫폼·채널 단계가 범위 구분의 어휘를 바꾸면 이 표의 선택지도 함께 바꿔야 한다.
- **상태:** 검토 대기

### DL-02-005 · ID 접두어 아홉 개를 정하고 재검토 조건의 어휘를 통일한다
- **날짜:** 2026-10-09
- **대상:** `templates/02_범위_제약_template.md` (정의 ID `OR`, `OI`, `OX`, `OL`, `OP`, `OC`, `OA`, `OD`, `ORK`), `docs/규칙_템플릿.md` (TP-28)
- **결정 주체:** 유지보수자 판단
- **배경:** 02번 호출이 `O`로 시작하는 접두어만 쓰게 지정했다(다른 단계를 병렬로 만드는 작업과의 충돌을 막기 위해서다). 샘플의 `OUT-`, `LT-`, `P-`, `C-`, `AS-`, `DP-`, `RK-`는 다른 단계의 접두어와 겹칠 수 있다(SA-19, SA-26, SA-32, SA-36, SA-40, SA-44, SA-48). 샘플의 후속 표는 재검토를 `트리거`라고 쓰고 제외 표는 `조건`이라고 쓴다(SA-25).
- **검토한 대안:** (a) 샘플 접두어를 쓴다 / (b) `O`로 시작하는 새 접두어를 표마다 하나씩 쓴다 / (c) 포함·제외·후속에 접두어를 하나(`O`)로 통일하고 번호를 이어 쓴다
- **결정:** (b). 규칙 `OR`, 포함 `OI`, 제외 `OX`, 후속 `OL`, 플랫폼 `OP`, 제약 `OC`, 가정 `OA`, 의존성 `OD`, 리스크 `ORK`다. 기존 접두어(A, AC, AQ, AR, NC, NQ, X와 04~21번이 정의한 것)와 겹치지 않는다. `재검토 트리거`는 `재검토 조건`으로 통일했다.
- **이유:** (a)는 `P-`, `C-`, `AS-`가 다른 단계와 충돌한다. (c)는 한 접두어로 세 목록을 구별하지 못하고, 뒤 단계가 근거에 쓰는 ID만으로 어느 목록의 항목인지 알 수 없게 된다. 재검토의 어휘를 한 가지로 두어야 두 목록을 함께 읽는 뒤 단계가 열 이름을 헷갈리지 않는다.
- **영향:** 뒤 단계가 ID를 근거에 참조로 인용할 때 접두어를 보면 목록을 알 수 있다. 접두어 `ORK`는 세 글자이고 `OR`와 겹치지 않는다(TP-28은 접두어 전체의 일치를 본다).
- **상태:** 검토 대기

### DL-02-006 · 제약의 분류를 닫힌 선택지 여덟 개로 둔다
- **날짜:** 2026-10-09
- **대상:** `templates/02_범위_제약_template.md` 6절 (`제약.분류`), `guides/02_범위_제약_guide.md` 3.6
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플의 제약 표는 `제약` 열에 기한, 인력, 예산, 법령, 개발 방침, 개인정보 최소화를 쓴다(SA-35). 사내 휴가 신청 도구는 법령보다 사내 정책과 기존 시스템 연동이 제약이고(OM-12), 스마트 온실 모니터링 서비스는 현장 전원과 통신 같은 운영 환경이 제약이다(OM-17). 뒤 단계는 분류별로 읽는다: 호환성·성능 요구는 예산과 기술 방침, 규제 매핑은 법령·정책, 릴리스는 기한과 인력이다.
- **검토한 대안:** (a) 분류를 자유 서술로 둔다 / (b) 기한 / 인력 / 예산 / 법령·정책 / 기술 방침 / 데이터 / 운영 조건 / 그 밖의 닫힌 선택지로 둔다 / (c) 샘플의 여섯 가지만 선택지로 둔다
- **결정:** (b). `그 밖`은 위에 들지 않는 제약을 담는 값이며 닫는 말(`미정`, `해당 없음`)이 아니다. 분류를 모르면 `미정`으로 닫는다.
- **이유:** (a)는 같은 제약이 작성자마다 다른 이름이 되어 뒤 단계가 분류로 거를 수 없다. (c)는 도메인 대입에서 맞지 않는 제약이 나왔다.
- **영향:** 선택지에 없는 새 분류가 필요하면 `그 밖`에 쓰고 내용에 이름을 밝힌다. 분류가 늘어나는 경향이 보이면 템플릿 버전을 올려 선택지를 보탠다.
- **상태:** 검토 대기

- **날짜:** 2026-10-09
