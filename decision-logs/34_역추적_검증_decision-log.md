# 결정 로그 — 34. 역추적 검증

> 34번 세트(템플릿, 단계 가이드, 변환 분석서, 인터페이스 표의 34 관련 연결)의 결정 이력이다. 항목은 추가만 하고 과거 항목은 고치지 않는다(`docs/규칙_결정로그.md`).
> 변환 분석서의 줄 ID(`SA-nn`, `OM-nn`)를 `배경`에 적어 근거를 가리킨다(CV-13).

---

### DL-34-001 · 34번 변환 분석서와 템플릿 v1.0, 단계 가이드 v1.0 초안을 작성한다
- **날짜:** 2026-10-10
- **대상:** `conversions/34_역추적_검증_conversion.md`, `templates/34_역추적_검증_template.md`, `guides/34_역추적_검증_guide.md` (그룹 J에서 35번, 36번과 병렬로 만든 세트)
- **결정 주체:** 사용자 승인
- **배경:** 그룹 단위 진행을 승인함(DL-05-005). 샘플 해부 66행(SA-01~66)과 누락 탐색 32행(OM-01~32)을 같은 절차로 만들었다. 단계 정의의 목적은 기능이 근거에서 나왔는지, 근거가 기능으로 이어졌는지를 양방향으로 검사해 누락과 과잉을 찾는 것이고 산출물은 추적 매트릭스, 갭 로그, 의도적 제외 목록(사유), 커버리지 리포트다. 샘플은 규칙 17개를 건수로 보고하고 그 가운데 셋만 추적 행을 보인다(SA-50~SA-55, OM-01). 샘플의 규칙 17행, 갭 로그 4행, 의도적 제외 13행, 추적 매트릭스 표 셋은 표 단위로 묶어 해부했다(CV-06). 도메인 교체 시험(③)은 작업 순서 6단계에서 템플릿과 가이드를 쓴 뒤에 하므로 아직 하지 않았고 분석서 상태는 `초안`이다.
- **검토한 대안:** 샘플의 구성(검증 방법, 커버리지 리포트, 갭 로그, 의도적 제외, 추적 매트릭스 발췌)을 그대로 따르는 안, 04·05번처럼 도출 질문 → 후보 → 판정 → 목록의 구성으로 하는 안, 규칙 → 추적 → 갭 로그 → 의도적 제외 → 집계 순서로 하는 안을 비교했다. 이 단계는 후보를 새로 찾지 않고 이미 있는 항목의 연결을 검사하므로 둘째 안은 버렸다. 첫째 안은 추적 매트릭스가 마지막에 있어 리포트의 수가 어디서 왔는지 앞에서 알 수 없다(TP-16 위반은 아니지만 검사 가능성이 낮다).
- **결정:** 값 표 다섯을 둔다. 검증규칙(목록 표, 정의 ID `KV`, 10열), 추적(목록 표, `KT`, 6열), 갭로그(목록 표, `KG`, 12열), 의도적제외(목록 표, `KX`, 8열), 집계(속성 표, 정의 ID 없음, 18행). 필드는 모두 54개다. 선택 블록과 표 없는 절은 없다. 표 키와 정의 ID 접두어는 그룹 J의 약속(`검증규칙`, `추적`, `갭로그`, `의도적제외`, `집계`와 `KV`, `KT`, `KG`, `KX`)을 따랐다.
- **이유:** 템플릿의 모든 표와 필드가 분석서의 줄에 대응한다(정의서 6절 4번, CV-K04). 규칙을 먼저 쓰고 규칙마다 대상 행을 전수로 쓰면 규칙의 수를 추적 표의 행으로 다시 셀 수 있다. 접두어 `KV`, `KT`, `KG`, `KX`는 기존 접두어(A, AC, AQ, AR, NC, NQ, X)와 겹치지 않고 호출에서 지정한 글자로 시작한다(TP-28).
- **영향:** 도메인 교체 시험이 남았다. 인터페이스 표는 DL-34-008~010에 쓴다. 표 키는 병합 때 35번, 36번 세트와 겹치지 않는지 확인한다.
- **상태:** 유효

### DL-34-002 · 추적은 상류 항목 × 기능 교차곱 표가 아니라 규칙마다 대상 항목 한 행으로 쓴다
- **날짜:** 2026-10-10
- **대상:** `templates/34_역추적_검증_template.md` 2절 (필드 `34.추적.ID`, `34.추적.규칙`, `34.추적.대상`, `34.추적.이은 항목`), `guides/34_역추적_검증_guide.md` 3.2, 분석서 SA-50~SA-55, OM-01, OM-19, OM-31
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플의 추적 매트릭스는 규칙 17개 가운데 셋만 보이고 기능은 8개로 잘라 `…`로 줄이며 저니 칸은 기능 수만 적는다(SA-51~SA-53). 대상 수와 통과 수를 행에서 다시 셀 수 없다(OM-01). 사용자가 확정한 설계는 교차곱 표를 쓰지 않고 행 하나가 상류 항목 하나 또는 기능 하나라고 한다.
- **검토한 대안:** (a) 샘플처럼 규칙 일부만 추적 행을 보이고 나머지는 건수만 둔다 / (b) 상류 항목 × 기능 교차곱 매트릭스를 둔다 / (c) 규칙마다 대상 항목 하나를 한 행으로 쓰고 이은 항목을 쉼표 목록으로 쓴다 / (d) 후보 소진처럼 대상이 수백인 규칙은 통합·정규화의 표별 소진으로 대신하고 추적 행을 생략한다
- **결정:** (c). 행 하나는 규칙의 대상 항목 하나이고 대상은 ID 하나(칸은 행 ID와 열 ID를 ×로 이은 것), 이은 항목은 반대편 ID의 쉼표 목록, 판정은 통과 / 갭이다. 대상이 수백이어도 행을 묶지 않고 전수로 쓴다(OM-31). 한 항목이 여러 규칙의 대상이면 규칙마다 행을 쓴다.
- **이유:** (a)는 건수를 다시 셀 수 없다. (b)는 열 수가 기능 수만큼 늘고 칸 대부분이 비어 닫는 말로 채워야 한다. (c)는 규칙의 대상 수, 통과 수, 갭 수를 행에서 세어 기계가 검사할 수 있다. (d)는 후보 소진의 통과 조건(기능에 병합되었는지)을 행으로 확인할 수 없다.
- **영향:** 입력이 크면 추적 표가 수천 행이 될 수 있다. 사용자가 (d) 같은 축약을 허용할지 정할 수 있다(DL-34-011의 질문). 이은 항목은 기능 ID가 아닐 때(근거 ID, 화면, 영역)가 있어 열 이름을 `이은 항목`으로 일반화했다.
- **상태:** 검토 대기

### DL-34-003 · 검증 규칙의 최소 종류는 가이드가 정하고 템플릿은 규칙 종류를 선택지로 둔다
- **날짜:** 2026-10-10
- **대상:** `templates/34_역추적_검증_template.md` 1절 (필드 `34.검증규칙.규칙 종류`, `34.검증규칙.방향`, `34.검증규칙.규칙`, `34.검증규칙.대상 표`, `34.검증규칙.검사 방법`, `34.검증규칙.대상 수`, `34.검증규칙.통과 수`, `34.검증규칙.갭 수`), `guides/34_역추적_검증_guide.md` 3.1, 분석서 SA-12~SA-33, OM-02, OM-03, OM-14, OM-21, OM-25, OM-28, OM-29, OM-32
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플의 규칙 R1~R17은 샘플 서비스의 ID 접두어와 영역 코드에 묶여 있다(SA-12, SA-13). 사용자가 확정한 설계는 가이드가 상류 항목 → 기능(역방향)과 기능 → 근거(순방향) 같은 최소 종류를 정하고 작성자는 줄일 수 없고 더할 수 있다고 한다.
- **검토한 대안:** (a) 샘플의 규칙 17개를 일반화해 템플릿에 고정 행으로 둔다 / (b) 규칙 종류를 자유 서술로 둔다 / (c) 규칙 종류를 선택지(목표, 저니, 후보 소진, 상태·이벤트·타이머, 규제, 화면, 대조 판정, 의존성 무결성, 영역 배정, 기능 근거, 추가)로 두고 최소 규칙 열여섯 행을 가이드가 정한다
- **결정:** (c). 방향은 역방향 / 순방향 / 무결성, 검사 방법은 ID 대조 / 의미 대조로 닫는다. 최소 규칙은 목표 둘, 저니 하나, 후보 소진 하나, 상태·이벤트·타이머 셋, 규제 하나, 화면 둘(역방향과 순방향), 대조 판정 하나, 의존성 무결성 하나, 영역 배정 셋(기능, 엔티티, 목표), 기능 근거 하나다. 샘플의 R10과 R11(외부 액터와 시간 액터의 목표)은 사람이 아닌 액터의 목표로 합쳐 목표 규칙에 넣고(OM-29), R6(CRUD 칸 빈 칸 없음)은 공통 규칙 CM-04가 강제하므로 최소 규칙에서 빼서 `추가` 규칙의 예로 가이드에 둔다(SA-19). 규칙의 대상 수와 통과 수와 갭 수는 추적 표의 행을 세어 쓴다. 앞 단계 표가 없으면 행을 지우지 않고 수 세 칸을 닫는 말로 닫는다(OM-21, OM-25).
- **이유:** (a)는 서비스마다 다른 앞 단계 표 구성을 담지 못한다. (b)는 최소 규칙이 모두 있는지 기계가 검사할 수 없다. (c)는 최소 종류의 누락을 완료 체크가 확인하고 도메인에 맞는 규칙을 `추가`로 더하게 한다.
- **영향:** 최소 규칙은 가이드(3.1)에 있으므로 최소 규칙을 바꾸려면 가이드 버전을 올린다. 규칙 종류 선택지에 `추가`가 있어 작성자가 더한 규칙은 이름 없이 `추가`로 묶인다. 샘플의 R17을 셋으로 나눈 것(SA-30)은 규칙 하나에 하나의 대상 집합이라는 기준 때문이다.
- **상태:** 검토 대기

### DL-34-004 · 판정은 통과 / 갭 둘이고 판정하지 못한 항목은 갭이며 갭 수는 의도적 제외로 닫은 갭을 포함한다
- **날짜:** 2026-10-10
- **대상:** `templates/34_역추적_검증_template.md` (필드 `34.추적.판정`, `34.검증규칙.갭 수`), `guides/34_역추적_검증_guide.md` 3.1, 3.2, 5절, 분석서 SA-34, SA-54, OM-04, OM-13, OM-15, OM-16
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플의 갭 열은 의도적 제외로 닫은 갭과 아직 닫지 못한 갭을 함께 세고 판정을 적을 열이 없다(SA-34, SA-55). 앞 단계 산출물의 값이 `미정`이어서 이어졌는지 판정하지 못하는 항목이 있을 수 있다(OM-13).
- **검토한 대안:** (a) 판정을 통과 / 갭 / 의도적 제외 셋으로 두고 갭 수에서 의도적 제외를 따로 센다 / (b) 판정을 통과 / 갭 둘로 두고 갭이 의도적 제외로 닫혔는지는 갭 로그가 가린다 / (c) 판정을 `미정`으로도 닫게 한다
- **결정:** (b). 판정을 못한 항목은 통과가 아니라 갭이고 갭 로그에 상류 단계 환류로 올린다. 그래서 규칙의 대상 수는 통과 수와 갭 수의 합이다. 갭 수에는 의도적 제외로 닫은 갭이 든다. 갭의 행이 모두 의도적 제외인지 미해소가 남았는지는 갭 로그의 조치 유형과 상태가 가른다.
- **이유:** (a)는 규칙 표의 열이 하나 늘고 대상 수 = 통과 + 갭 + 제외라는 검사가 복잡해진다. (c)는 대상 수가 통과와 갭의 합이 되지 않는다. (b)는 보수적이고(CM-01, CM-09) 샘플의 R4 행(통과 66, 갭 1, 의도적 제외)과 같은 의미다.
- **영향:** 갭 수가 0이 아닌 규칙은 갭 로그에 행이 있어야 한다(완료 체크). 갭 수가 0이어야 종료라는 뜻이 아니다. 종료 조건은 DL-34-007에서 정한다.
- **상태:** 검토 대기

### DL-34-005 · 갭 로그는 조치 유형 다섯과 환류 대상 단계를 갖고 해소는 조치가 반영된 입력으로 확인한 뒤에만 쓴다
- **날짜:** 2026-10-10
- **대상:** `templates/34_역추적_검증_template.md` 3절 (필드 `34.갭로그.ID`, `34.갭로그.규칙`, `34.갭로그.추적 행`, `34.갭로그.갭`, `34.갭로그.원인`, `34.갭로그.조치 유형`, `34.갭로그.대상 기능 ID`, `34.갭로그.조치 내용`, `34.갭로그.상류 항목`, `34.갭로그.환류 대상 단계`, `34.갭로그.상태`, `34.갭로그.근거`), `guides/34_역추적_검증_guide.md` 3.3, 분석서 SA-35~SA-43, OM-05, OM-06, OM-09, OM-11, OM-12, OM-30
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플의 조치는 한 칸에 화면 추가, 기능 추가, 태그 수정이 자유 서술로 섞이고 환류 단계는 가운뎃점 나열이며 상태에 조치 유형이 섞인다(SA-40~SA-42). 사용자가 확정한 설계는 조치 유형(기능 추가 / 태그 수정 / 기능 삭제 / 의도적 제외 / 상류 단계 환류), 대상 기능 ID, 환류 대상 단계를 열로 두고 사람이 하는 활동(앞 단계 산출물을 고치는 일)은 입력으로 받는다고 한다.
- **검토한 대안:** (a) 샘플의 조치 한 칸을 그대로 둔다 / (b) 조치 유형, 대상 기능 ID, 조치 내용, 상류 항목, 환류 대상 단계로 나눈다 / (c) (b)에 더해 기능 추가의 기능명, 설명, 액터 같은 열을 따로 둔다 / (d) 상태를 해소 / 의도적 제외 / 미해소 셋으로 둔다
- **결정:** (b)와 상태는 해소 / 미해소 둘. 기능 추가의 이름, 설명, 태그는 조치 내용 한 문장에 `기능명: …, 설명: …, 영역: Z-xx`처럼 쓰고 아는 만큼 이어 쓴다(열을 늘리지 않는다). 기능 추가와 기능 삭제의 환류 대상 단계에는 계층·ID·태그와 의존성 두 단계를 쓴다. 해소는 조치가 반영된 입력으로 같은 규칙을 다시 돌려 통과를 확인한 갭만 쓴다. 재실행 횟수를 집계에 둔다. 의도적 제외로 닫은 갭은 의도적 제외 표에 행이 있으면 해소다.

### DL-34-011 · 규칙·도구 제안과 사용자 결정이 필요한 질문
- **날짜:** 2026-10-10
- **대상:** `docs/규칙_공통.md` CM-18, 검사 도구의 CM-K04 (제안만 하고 고치지 않았다), 템플릿 v1.0의 규모와 기능 ID 부여
- **결정 주체:** 유지보수자 판단
- **배경:** 규칙 문서와 도구는 이번 작업에서 고치지 않기로 했다. 작업 중에 아래가 걸렸다. (1) CM-K04는 근거 조각이 출처 유형이나 참조로 시작하기를 요구하고 참조는 `NN ` 또는 `대문자 1~3자-숫자`로 읽는다. 최종 기능 ID `F-<대문자 코드>-<숫자>`는 형식이 맞아도 실패로 볼 수 있다(DL-33-009와 같다). 34번은 기능 ID를 근거 조각의 첫머리에 쓰지 말라고 가이드에 적었다. - **이유:** 전수를 줄이는 것은 대상 수와 행 수를 맞추는 검사(완료 체크)를 약하게 하는 변경이라 사용자 결정이 필요하다. 번호를 32번이 붙이게 하면 갭 로그의 대상 기능 ID가 `미정`이 되어 환류 줄(DL-34-010)이 참조할 값을 잃는다.
- **영향:** 사용자 결정이 필요한 질문: (가) 후보 소진 규칙을 표별 소진으로 대신하는 축약을 허용할지. (나) 기능 추가의 새 기능 ID를 34번과 35번 중 누가 어떻게 이어 붙일지. (다) 의도적 제외 유형 선택지 셋(설계 기준 / 프로세스 / 범위 밖)이 36번의 게이트 구분과 맞는지. (라) 근거 칸의 기능 ID 참조를 규칙에 넣을지(DL-33-009와 같은 질문).
- **상태:** 검토 대기

### DL-34-013 · 도메인 교체 시험 반영: 통과 행의 이은 항목, 기능 ID `미정`, 후보 판정 완결, 제외 항목 ID
