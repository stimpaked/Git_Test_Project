# 결정 로그 — 26. 운영·백오피스

> 26번 세트(템플릿, 단계 가이드, 변환 분석서, 인터페이스 표의 26 관련 연결)의 결정 이력이다. 항목은 추가만 하고 과거 항목은 고치지 않는다(`docs/규칙_결정로그.md`).
> 변환 분석서의 줄 ID(`SA-nn`, `OM-nn`)를 `배경`에 적어 근거를 가리킨다(CV-13).

### DL-26-001 · 26번 변환 분석서와 템플릿 v1.0, 단계 가이드 v1.0 초안을 작성한다
- **날짜:** 2026-10-09
- **대상:** `conversions/26_운영_백오피스_conversion.md`, `templates/26_운영_백오피스_template.md`, `guides/26_운영_백오피스_guide.md`
- **결정 주체:** 사용자 승인
- **배경:** 그룹 단위 진행을 승인함(DL-05-005). 26~28번 세 단계를 병렬로 만든다. 샘플 해부 33행(SA-01~33)과 누락 탐색 17행(OM-01~17)을 앞 단계와 같은 절차로 만들었다. 샘플의 업무 20행과 후보 16행은 같은 틀을 되풀이해 표 단위로 묶었다(CV-06). 도메인 교체 시험(③)은 템플릿과 가이드를 쓴 뒤에 하므로 아직 하지 않았고 분석서 상태는 `초안`이다.
- **검토한 대안:** 해당 없음 — 변환 절차(정의서 6절)를 따랐다.
- **결정:** 04·05번의 구성(도출 질문 → 후보 → 판정 → 목록)을 따르지 않고 이 단계의 목적(운영자의 업무를 정리해 필요한 도구를 도출한다)에 맞춰 값 표를 셋으로 둔다. 1번 표 `점검관점`은 고정 질문 열두 개의 속성 표(정의 ID `BKQ`), 2번 표 `업무목록`은 업무 하나가 행 하나인 목록(`BKW`), 3번 표 `도구후보`는 업무에서 도출한 후보(`BKC`)다. 표 없는 필수 블록과 선택 블록은 없다.
- **이유:** 이 단계의 본질은 운영 업무가 숨는 곳을 묻고, 업무마다 필요한 화면·데이터·권한을 닫고, 도구를 후보로 모으는 것이다. 템플릿의 모든 변경이 분석서의 줄에 대응한다(정의서 6절 4번).
- **영향:** 도메인 교체 시험(8번)이 남았다. 인터페이스 표에 26번 보내는 줄 38개와 외부 입력 줄 2개를 더하고 잠정 줄 24개를 바꿨다(DL-26-005).
- **상태:** 유효

### DL-26-002 · 점검 관점을 먼저 두고 업무, 도구 후보 순서로 쓴다
- **날짜:** 2026-10-09
- **대상:** 표 `점검관점`, 표 `업무목록`, 표 `도구후보`
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 방법에서 누락이 가장 많은 영역이라고 하면서 업무 20행을 바로 적었고 누락을 찾을 질문이 없다(SA-09, OM-01). 서비스 종류마다 운영 업무의 모양이 다르다(OM-09~OM-16).
- **검토한 대안:** (a) 샘플처럼 업무 목록 하나에 후보 표만 붙인다 / (b) 운영 액터 표를 새로 두고 액터별로 업무를 묻는다 / (c) 운영 업무가 숨는 곳을 묻는 고정 질문 열두 개를 앞에 두고 업무 목록이 질문 ID를 출처로 가리킨다
- **결정:** (c). 질문은 접수 큐 처리, 콘텐츠·활동 조정, 사용자·계정 지원, 내용·설정 관리, 운영 권한 관리, 승인·이중 확인, 현황 감시, 장애·실패 대응, 기록 점검, 데이터 요청 처리, 금전 후속 처리, 개방 질문이다. 답이 값인 질문은 업무의 출처에 한 번 이상 나와야 한다(완료 체크). 질문 답은 점검 과정의 기록이라 뒤 단계가 쓰지 않는다(`최종 소비자 없음`).
- **이유:** (a)는 놓친 종류를 확인할 방법이 없다. (b)는 운영 액터 표가 사람 액터 목록의 유형 칸과 같은 사실을 되풀이한다(CM-12). (c)는 해당 없는 관점을 사유와 함께 닫아 억지 업무를 막는다(OM-09).
- **영향:** 질문 열두 개가 충분한지는 도메인 교체 시험에서 본다. 인터페이스 표에 점검 관점 열두 항목의 소비자 없음 줄을 더했다.
- **상태:** 검토 대기

### DL-26-003 · 도구 후보 표는 통일 모양을 따르고 `도구 형태` 열을 더한다
- **날짜:** 2026-10-09
- **대상:** 표 `도구후보`, `guides/26_운영_백오피스_guide.md` 3.3
- **결정 주체:** 유지보수자 판단
- **배경:** 후보 표의 통일 모양(`ID | 후보 문장 | 구분 | 공통·고유(잠정) | 출처 | (이 단계에서만 필요한 열) | 근거`)이 정해져 있다(수정목록 G13). 샘플은 구분 열이 없고(SA-27) 업무에 필요한 화면이 인벤토리에 없는 것을 이 단계에서 가리지 못했다(SA-21, OM-04, OM-05).
- **검토한 대안:** (a) 이 단계에서만 필요한 열을 두지 않는다 / (b) `도구 형태`(새 화면 / 기존 화면에 추가 / 화면 없는 기능) 한 열을 둔다 / (c) 소속 영역 열을 더 둔다
- **결정:** (b). `구분` 선택지는 앞 단계와 같은 어휘(기능 후보 / 후속 후보 / 설계 기준 / 프로세스)다. (c)는 두지 않는다. 운영 기능 배치는 영역·모듈 단계의 방침을 단계 가이드 1절에서 읽어 공통·고유 잠정 값에만 반영하고 영역은 뒤 단계가 정한다.
- **이유:** 단계 정의의 산출물이 `필요한 도구(화면·기능)`이므로 화면인지 기능인지 가르는 칸이 필요하고, 새 화면은 화면 인벤토리로 돌려줄 목록이 된다. (c)는 영역을 정하는 일이 뒤 단계의 몫이라 미룬다.
- **영향:** 통합·정규화 단계가 `후보 문장`, `구분`을 읽는다. 화면·UI 상태 단계로 가는 환류 줄 하나를 더했다(IF-26-037).
- **상태:** 검토 대기

### DL-26-004 · 업무 표의 열을 계기·빈도, 필요한 데이터·조작·권한, 도구 판정으로 가른다
- **날짜:** 2026-10-09
- **대상:** 표 `업무목록`, `guides/26_운영_백오피스_guide.md` 3.2
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플의 `빈도` 열은 횟수와 계기를 섞고(SA-14), `필요한 기능·데이터`는 데이터와 처리와 검증을 섞었으며(SA-16), 권한을 확인했다면서 권한 열이 없다(SA-17, OM-02, OM-03). 업무마다 새 도구가 필요한지 가르는 칸이 없다(OM-05, OM-13, OM-14).
- **검토한 대안:** (a) 샘플의 열을 그대로 두고 근거 열만 더한다 / (b) 섞인 열을 개념별로 갈라 열 열두 개(ID, 업무, 액터, 계기, 빈도, 기존 화면, 필요한 데이터, 필요한 조작, 필요한 권한, 도구 판정, 출처, 근거)로 한다 / (c) 업무와 화면의 매트릭스를 쓴다
- **결정:** (b). 계기는 선택지(요청 접수 / 사건 발생 / 정해진 주기 / 운영자 판단), 도구 판정은 선택지(새 도구 필요 / 기존 화면으로 충분 / 도구 없이 수행)다. 필요한 권한은 권한 매트릭스의 행위 ID를 가리키고 없으면 `미정`으로 닫는다.
- **이유:** (a)는 섞인 열이 칸을 닫기 어렵게 한다. (c)는 교차곱이라 행 수가 곱이 된다. (b)는 행 하나가 판단 하나이고 열마다 값이 하나다. 열이 열두 개로 보안·어뷰징 단계의 위협 목록과 같다.
- **영향:** 업무 표가 넓어 작성 부담이 크다. 도메인 교체 시험에서 칸이 과한지 본다. 권한 매트릭스, 이벤트 목록으로 돌려주는 환류 줄을 더했다.
- **상태:** 검토 대기

### DL-26-005 · 인터페이스 표: 잠정 줄 24개를 필드 키로 바꾸고 보내는 줄과 외부 입력을 더한다
- **날짜:** 2026-10-09
- **대상:** `tools/data/interfaces.csv`
- **결정 주체:** 유지보수자 판단
- **배경:** 받는 쪽이 26인 잠정 줄 24개가 있었다. 템플릿 필드마다 소비자 또는 `최종 소비자 없음`과 사유가 필요하다(IR-07). 외부 입력은 `EXT:` 줄로 쓴다(IR-09).
- **검토한 대안:** 해당 없음 — 규칙_인터페이스표를 따랐다.
- **결정:** (가) 바꾼 줄: IF-01-045, IF-01-057, IF-04-027, IF-04-032, IF-09-015, IF-12-014, IF-13-018, IF-13-021, IF-14-027, IF-15-002, IF-15-008, IF-15-012, IF-15-014, IF-17-003, IF-17-006, IF-18-006, IF-19-011, IF-19-014, IF-24-022, IF-24-024, IF-24-037, IF-24-043, IF-25-010, IF-25-019 (받는 쪽 `26`을 이 단계의 필드 키로). (나) 보내는 줄 IF-26-001~038을 더했다. 소비자는 통합·정규화(후보), 계층·ID·태그, 역추적 검증, 우선순위·릴리스와 수익 모델(금전 업무), 성장·측정(지표)이고, 환류는 소유·권한(허용, 행위), 이벤트(알림), 화면·UI 상태(화면), 보안·어뷰징(운영 권한 오용)이다. (다) 외부 입력 IF-EX-26-001(`EXT:운영_업무_자료`), IF-EX-26-002(`EXT:운영_처리량_자료`)를 더했다. 소비자 주장은 단계 정의와 샘플의 쓰이는 곳(SA-07)으로 뒷받침하고 뒷받침이 없으면 `추정: 가정`이다.
- **이유:** 병렬 작업 중 연결 ID 충돌을 막기 위해 보내는 단계 번호로 시작하는 줄만 만들었다. 환류는 번호가 앞선 단계의 템플릿을 고치게 하므로 방향을 `환류`로 선언했다(IR-05).
- **영향:** 수익 모델·성장·측정 단계로 가는 두 줄은 받는 쪽이 문서 수준 잠정 값(`27`, `28`)이다. 20번으로 가는 줄(공통·고유 판정)은 만들지 않았다(DL-26-006).
- **상태:** 검토 대기

### DL-26-006 · 병합 때 더해야 할 입력 줄과 20번 줄의 목록
- **날짜:** 2026-10-09
- **대상:** `tools/data/interfaces.csv`
- **결정 주체:** 유지보수자 판단
- **배경:** 26번 가이드 1절이 읽으라는 앞 단계 가운데 인터페이스 표에 26으로 오는 줄이 없는 읽기가 있다(SA-05, OM-08). 병렬 작업 중 충돌을 막기 위해 앞 단계가 보내는 입력 줄은 새로 만들지 않았다. 같은 그룹의 27, 28번 템플릿은 이 복사본에 없다.
- **검토한 대안:** (a) 앞 단계가 보내는 줄을 지금 더한다 / (b) 목록으로 남기고 병합 때 더한다
- **결정:** (b). 더해야 할 줄(보내는 필드 키 → 받는 필드 키, 방식): 04.도출질문.AQ-06 운영·지원 → 26.업무목록.액터, 판단 입력 / 04.액터목록.주요 목표 → 26.업무목록.업무, 판단 입력 / 06.여정단계.구간 분류 → 26.업무목록.출처, 판단 입력 / 06.매트릭스.행동 → 26.업무목록.업무, 판단 입력 / 07.목표목록.ID → 26.업무목록.출처, 참조(ID) / 09.질문목록.ID → 26.업무목록.출처, 참조(ID) / 10.추가질문.ID → 26.업무목록.출처, 참조(ID) / 11.엔티티목록.ID → 26.업무목록.필요한 데이터, 참조(ID) / 12.후보목록.후보 문장 → 26.업무목록.업무, 판단 입력 / 15.기능후보.후보 문장 → 26.업무목록.업무, 판단 입력 / 16.이벤트목록.ID → 26.업무목록.출처, 참조(ID) / 16.이벤트목록.알림 → 26.업무목록.계기, 판단 입력 / 19.기능후보.후보 문장 → 26.업무목록.업무, 판단 입력 / 22.기능후보.후보 문장 → 26.업무목록.업무, 판단 입력 / 23.규제매핑.대응 유형 → 26.업무목록.업무, 판단 입력 / 23.기능후보.후보 문장 → 26.업무목록.업무, 판단 입력 / 24.방어후보.ID → 26.업무목록.출처, 참조(ID) / 25.기능후보.후보 문장 → 26.업무목록.업무, 판단 입력 / 25.공통정책.YQ-05 파기 보류 → 26.점검관점.BKQ-10 데이터 요청 처리, 판단 입력 / 01.목표지표.지표 → 26.점검관점.BKQ-07 현황 감시, 판단 입력 / 02.후속목록.항목 → 26.도구후보.구분, 판단 입력 / 21.배치방침.운영 기능 배치 → 26.도구후보.공통·고유(잠정), 판단 입력. 같은 그룹의 환류 입력(문서 수준 `NN` 보내는 쪽): 27 수익 모델 → 26.점검관점.BKQ-11 금전 후속 처리, 판단 입력, 환류 / 28 성장·측정 → 26.도구후보.후보 문장(공지·발송 같은 운영 도구가 필요한 성장 기능), 판단 입력, 환류. 26번 보내는 줄 중 받는 쪽이 `27`, `28`인 줄(IF-26-014, IF-26-031)은 병합 때 필드 키로 바꾼다. 20번 도메인 공통·고유가 26번 도구 후보를 읽게 할지(원래 샘플의 백오피스 공통 판정)는 병합 때 판단하므로 줄을 만들지 않았다.
- **이유:** 앞 단계의 줄 번호는 보내는 단계 번호로 시작해 병렬 작업 사이에 충돌할 수 있다.
- **영향:** 병합 담당이 위 목록으로 줄을 더하고 그때 템플릿 문서 정보 블록을 재생성한다. 이 줄이 더해지기 전에는 26번 템플릿의 입력 목록에 이들이 나오지 않는다.
- **상태:** 검토 대기

### DL-26-007 · 닫는 기준과 앞 단계가 비었을 때의 처리
- **날짜:** 2026-10-09
- **대상:** 가이드 5절
- **결정 주체:** 유지보수자 판단
- **배경:** 범위에 든 운영 업무는 닫힌 목록으로 본다. 입력의 언급이 없다는 사실만으로는 `해당 없음`이 아니다. 앞 단계 표가 비는 이유가 "없다고 확인"인지 "질문이 `미정`"인지에 따라 닫는 말이 갈린다(OM-08, OM-10).
- **검토한 대안:** (a) 비어 있으면 모두 `해당 없음` / (b) 이유를 가려 확인했으면 `해당 없음`, 질문이 `미정`이면 `미정`
- **결정:** (b). 필요한 권한에 해당 행위가 없으면 ID를 만들지 않고 `미정`으로 닫으며 이 목록이 권한 매트릭스로 돌려주는 환류의 입력이 된다. 금전 후속 처리는 수익 모델 단계의 판정을 읽을 수 있을 때만 `해당 없음`이다.
- **이유:** 틀린 `해당 없음`은 운영 도구의 누락으로 이어지고 `미정`은 확인할 곳을 남긴다(CM-09).
- **영향:** 가이드 5절에 구체적으로 썼다.
- **상태:** 검토 대기
