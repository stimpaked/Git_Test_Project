### DL-10-001 · 10번 변환 분석서와 템플릿 v1.0, 단계 가이드 v1.0 초안을 작성한다
- **날짜:** 2026-10-08
- **대상:** `conversions/10_시나리오_5유형_conversion.md`, `templates/10_시나리오_5유형_template.md`, `guides/10_시나리오_5유형_guide.md`
- **결정 주체:** 사용자 승인
- **배경:** 그룹 단위 진행을 승인함(DL-05-005). 04번과 05번에 이어 10번 세트를 만든다. 샘플 해부 40행(SA-01~40)과 누락 탐색 14행(OM-01~14)을 같은 절차로 만들었다. 도메인 교체 시험(③)은 템플릿과 가이드를 쓴 뒤에 하므로 아직 하지 않았고 분석서 상태는 `초안`이다.
- **검토한 대안:** 해당 없음 — 변환 절차(정의서 6절)를 따랐다.
- **결정:** 04·05번의 구성(도출 질문 → 후보 → 판정 → 목록)을 따르지 않고 이 단계의 목적(플로우를 다섯 관점으로 점검해 놓친 후보를 찾는다)에 맞춰 값 표를 둘로 한다. 1번 표 `추가질문`은 점검에서 새로 만든 질문의 목록(정의 ID `HQ`)이고, 2번 표 `점검표`는 플로우×다섯 유형의 확인 기록이다(SA-16, SA-26, OM-01~04). 변환 분석서의 상태는 도메인 교체 시험 전이므로 `초안`이다.
- **이유:** 이 단계의 본질은 칸마다 판정하는 점검이고, 산출물의 핵심은 새로 드러난 질문이다. 도출 질문과 후보 판정 단계는 이 단계에 해당하지 않는다. 템플릿의 모든 변경이 분석서의 줄에 대응한다(정의서 6절 4번).
- **영향:** 도메인 교체 시험(8번)이 남았다. 인터페이스 표에 10번 보내는 줄 17개를 더했다(DL-10-007).
- **상태:** 유효

### DL-10-002 · 추가 질문 표를 점검표보다 앞에 둔다
- **날짜:** 2026-10-08
- **대상:** `templates/10_시나리오_5유형_template.md` 1·2절, `docs/규칙_템플릿.md` (TP-16)
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 점검 매트릭스를 앞에 두고 칸이 신규 질문 번호를 가리키며 신규 질문 목록을 뒤에 둔다. 앞 표가 뒤 표의 ID를 참조하는 순서 오류다(SA-16, SA-26). 검사 TP-K07도 이를 실패로 본다.
- **검토한 대안:** (a) 점검표를 앞에 두고 칸에는 판정 선택지만 쓰며 추가 질문이 점검표의 플로우·유형을 가리키게 한다 / (b) 추가 질문을 앞에 두고 점검표가 질문 ID를 참조한다 / (c) 플로우×유형마다 한 행씩 두는 하나의 목록 표로 합친다
- **결정:** (b). 추가 질문 표(`HQ-`)를 1번, 점검표를 2번으로 두고 점검표 칸이 `HQ-` ID를 쓴다.
- **이유:** (a)는 칸에 기존 질문 ID를 쓰는 샘플의 구조(SA-20)를 잃고 `충분`이라는 판정 선택지가 칸마다 필요해 한 칸에 기존·신규가 함께 있는 경우(SA-22)를 담기 어렵다. (c)는 행이 플로우 수의 다섯 배가 되어 읽기 어렵고 플로우의 다섯 유형을 한눈에 보는 매트릭스를 잃는다. (b)는 작성 순서도 자연스럽다. 점검하며 새 질문을 쓰고 그다음 점검표로 모은다.
- **영향:** 점검표와 추가 질문이 서로 맞는지(칸의 `HQ-` ID와 질문의 플로우·유형)는 도구가 검사하지 못하고 완료 체크와 가이드의 누락 점검이 맡는다(DL-10-008).
- **상태:** 검토 대기

### DL-10-003 · 점검표 칸은 기존 질문 ID와 새 질문 ID를 한 칸에 쓰는 ID 참조 칸으로 둔다
- **날짜:** 2026-10-08
- **대상:** `templates/10_시나리오_5유형_template.md` 2절 (표 `점검표`)
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플의 칸은 `충분(Q-…)`, `신규 Q-…`, `N/A: 사유` 세 가지이고 한 칸에 신규와 충분이 함께 쓰이기도 한다(SA-17, SA-20~23). 안내 문장은 "중 하나"라고 해서 실제 칸과 어긋난다. `N/A: 사유`는 공통 규칙의 `해당 없음`과 사유와 같은 뜻이다. 한 플로우의 같은 유형에 기존 질문이 많은 경우도 있다(OM-13).
- **검토한 대안:** (a) 칸마다 선택지(기존 질문으로 충분 / 신규 질문 필요 / 둘 다)를 두고 ID는 별도 열에 / (b) 칸을 ID 참조로 두고 접두어(유저 플로우의 질문 접두어와 `HQ-`)로 두 종류를 구분 / (c) 칸 값을 `충분`, `신규`, `N/A`로 고정
- **결정:** (b). 칸은 쉼표로 구분한 ID 참조이고 닫는 말은 공통 규칙의 `해당 없음`(사유)과 `미정`이다. `충분`이라는 판정의 이유와 적용되지 않는 이유는 행의 근거 칸이 맡는다(OM-01).
- **이유:** (a)는 다섯 유형에 열이 열 개가 되고 선택지 값이 `해당 없음`과 겹치는 문제가 생긴다. (c)는 샘플의 문제(`N/A`가 공통 규칙의 닫는 말이 아님)를 그대로 둔다. (b)는 열 수를 줄이고 ID가 곧 증거가 된다.
- **영향:** 유저 플로우 단계의 질문 ID 접두어를 이 템플릿이 모르므로 힌트에 접두어를 쓰지 않고 가이드가 설명한다. 접두어로 두 종류를 구분하는 방식은 유저 플로우의 접두어가 `HQ`와 겹치지 않는다는 전제에 기댄다(`H`로 시작하는 접두어는 이 단계 몫으로 배정되어 있다).
- **상태:** 검토 대기

### DL-10-004 · 후속 후보와 설계 기준을 구분 열로 분리한다
- **날짜:** 2026-10-08
- **대상:** `templates/10_시나리오_5유형_template.md` 1절 (필드 `구분`)
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 후속으로 미룬 질문을 문장 끝 괄호 `(Later: LT-06)`로, 기능이 아닌 설계 기준을 문장 괄호와 집계 한 줄로 표시한다(SA-32, SA-33, SA-35). 후속 항목의 ID가 샘플 문서 체계에 묶여 있다. 단계 정의의 산출물은 추가 질문(기능 후보)이므로 기능이 아닌 것이 섞이면 목적을 흐린다(OM-04).
- **검토한 대안:** (a) 괄호 표기를 유지한다 / (b) `구분` 열 하나(기능 후보 / 후속 후보 / 설계 기준)를 두고 후속 항목 참조는 근거 칸에 쓴다 / (c) `구분` 열과 별도의 `후속 항목` 열을 둔다
- **결정:** (b). 집계 한 줄은 표에서 셀 수 있는 파생 값이라 쓰지 않는다(SA-35). `후속 후보`는 범위를 정한 문서의 후속 목록에서 항목을 찾을 때만 쓰고 못 찾으면 `기능 후보`로 두는 보수적 기준을 가이드에 둔다.
- **이유:** 대부분의 행이 `후속 항목`을 `해당 없음`으로 닫게 되는 열(c)은 부담이 크다(OM-05). 후속으로 미루는 판단은 범위 결정을 뒤집을 수 있어 근거를 요구한다.
- **영향:** 범위를 정한 단계 산출물의 후속 목록을 이 단계가 읽는다는 관계는 인터페이스 표에 아직 없다(샘플의 입력 표시는 유저 플로우뿐이다). 범위 단계의 템플릿이 생기면 그 연결이 필요한지 정한다.
- **상태:** 검토 대기

### DL-10-005 · 점검표에 `전체` 행을 둔다
- **날짜:** 2026-10-08
- **대상:** `templates/10_시나리오_5유형_template.md` 1·2절 (필드 `플로우`)
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 `전체 공통` 행을 두고 칸을 `—`로 비워 둔다(SA-24). `—`는 빈 칸과 같아 공통 규칙(CM-04)에 어긋난다. 서버 점검이나 전원 장애처럼 플로우 하나에 속하지 않는 점검은 다른 성격의 도메인에서도 나온다(OM-10).
- **검토한 대안:** (a) `전체` 행을 두지 않고 여러 플로우에 걸치는 질문은 가장 가까운 플로우에 넣는다 / (b) `전체` 행을 템플릿에 고정 행으로 두고 칸은 질문 ID, `해당 없음`, `미정`으로 닫는다 / (c) 선택 블록으로 둔다
- **결정:** (b). 추가 질문의 플로우 칸도 `전체`를 허용한다.
- **이유:** (a)는 질문의 출처가 흐려지고 같은 질문이 여러 플로우에 반복된다. (c)는 점검 누락을 막으려는 행의 취지와 맞지 않는다. 고정 행이면 모든 산출물이 전역 점검을 최소한 한 번 확인한다.
- **영향:** 전역 점검이 없으면 다섯 칸을 `해당 없음`과 사유로 닫아야 해 부담이 있다. 도메인 교체 시험에서 이 부담이 과한지 본다.
- **상태:** 검토 대기

### DL-10-006 · 새 질문의 ID 접두어는 `HQ`로 하고 `HQ-01`부터 매긴다
- **날짜:** 2026-10-08
- **대상:** `templates/10_시나리오_5유형_template.md` 1절 (정의 ID `HQ`)
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 유저 플로우의 질문 번호(`Q-001`~`Q-130`)에 이어 `Q-201`부터 매겼다(SA-27). 유저 플로우 질문이 200개를 넘으면 겹치고 접두어가 같아 단계를 구분하기 어렵다. 템플릿 규칙(TP-28)은 접두어가 모든 템플릿에 걸쳐 유일하라고 한다.
- **검토한 대안:** (a) 샘플처럼 번호 구간으로 나눈다 / (b) 단계 고유 접두어를 쓴다
- **결정:** (b). 호출 지침이 `H`로 시작하는 접두어만 쓰게 했으므로 `HQ`(Question)를 쓴다.

- **영향:** 유저 플로우 단계의 질문 ID가 `HQ`와 겹치는 접두어를 쓰지 않아야 한다(TP-28이 검사한다).

### DL-10-007 · 인터페이스 표: 10번 보내는 줄 17개를 추가한다
- **날짜:** 2026-10-08
- **대상:** `tools/data/interfaces.csv` (IF-10-001~017)
- **결정 주체:** 유지보수자 판단
- **배경:** 10번 템플릿의 필드 14개가 모두 보내는 필드로 나와야 한다(IR-07). 04·05번이 10번에 보내는 줄과 문서 수준 잠정 줄은 없어서 고칠 줄이 없다. 뒤 단계 템플릿(13, 20, 24, 31)은 없어서 받는 쪽은 `NN` 잠정 값이다(IR-10). 쓰이는 곳의 근거는 샘플의 표시 `후보 풀로 합류(31) · 24(위협 목록의 시드) · 13(복구 전이의 시드)`(SA-07)와 단계 정의다.
- **검토한 대안:** (a) 점검표의 오남용·복구 칸도 24, 13에 연결한다 / (b) 점검표 전체를 `최종 소비자 없음`으로 하고 추가 질문의 유형·질문만 24, 13에 연결한다
- **결정:** (b). 샘플이 쓰이는 곳으로 말하는 것은 추가분(추가 질문)이다. 점검표는 점검했다는 기록이라 뒤 단계가 값으로 쓰지 않는다고 보고 사유와 함께 `최종 소비자 없음`으로 닫았다. 공통·고유(잠정)는 20번(공통·고유 판정이 붙은 후보를 만드는 단계)에 판단 입력으로, 구분은 31번에 판단 입력으로 연결했다(구분의 소비 방식은 `추정: 가정`). 이 단계가 받는 줄은 유저 플로우 템플릿이 생겨야 만들 수 있어 추가하지 않았다. 템플릿의 `입력` 블록이 `연결 미작성`으로 나오는 이유다.
- **이유:** 샘플과 단계 정의가 뒷받침하는 만큼만 소비자를 주장한다.
- **영향:** 유저 플로우 세트를 만들 때 유저 플로우의 플로우 ID와 질문 ID를 10번 점검표·추가 질문의 필드로 보내는 줄을 더해야 한다. 13, 20, 24, 31번 템플릿이 생기면 해당 잠정 줄을 필드 수준으로 바꾼다.
- **상태:** 검토 대기

### DL-10-008 · 제안: 표 사이의 정합 검사는 도구가 하지 못한다
- **날짜:** 2026-10-08
- **대상:** `tools/tools-decision-log.md` (알려진 한계), `docs/규칙_템플릿.md`
- **결정 주체:** 유지보수자 판단
- **배경:** 점검표 칸의 `HQ-` ID가 추가 질문의 플로우·유형과 일치하는지, 추가 질문이 점검표에 모두 쓰였는지는 두 표의 값을 맞대 보아야 안다. 현재 산출물 검사(TP-K13)는 구조(표 키, 열 이름)만 비교하고 값 사이의 참조 일치는 보지 않는다(DL-10-002).
- **검토한 대안:** 해당 없음 — 도구와 규칙 문서는 이번 호출의 수정 대상이 아니다. 제안만 남긴다.
- **결정:** 규칙 문서와 도구는 바꾸지 않는다. 표 사이 ID 참조 일치 검사의 도입 여부를 사용자가 정하게 한다. 그때까지는 완료 체크의 한 항목과 가이드의 누락 점검이 맡는다.
- **이유:** 규칙·도구의 변경은 유지보수자가 단독으로 하지 않는다.
- **영향:** 도입하면 `tools/checks.py`에 검사를 더하고 규칙_템플릿에 대응 규칙을 정한다. 다른 단계에도 같은 구조(한 표가 다른 표의 ID를 참조하는 값 표)가 생길 수 있다.
- **상태:** 검토 대기
