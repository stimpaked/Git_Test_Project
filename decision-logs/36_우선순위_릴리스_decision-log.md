### DL-36-001 · 36번 변환 분석서와 템플릿 v1.0, 단계 가이드 v1.0 초안을 작성한다
- **날짜:** 2026-10-10
- **대상:** `conversions/36_우선순위_릴리스_conversion.md`, `templates/36_우선순위_릴리스_template.md`, `guides/36_우선순위_릴리스_guide.md` (그룹 J의 34·35번과 병렬로 만든 복제)
- **결정 주체:** 사용자 승인 (그룹 단위 진행을 승인함(DL-05-005))
- **배경:** 그룹 단위 진행을 승인함(DL-05-005). 샘플 해부 88행(SA-01~88)과 누락 탐색 35행(OM-01~35, 목적 대비 29행과 도메인 대입 6행)을 같은 절차로 만들었다. 단계 정의의 목적은 기능의 우선순위와 릴리스 범위를 정하고 출시 게이트와 기준선을 확정하는 것이고 산출물은 우선순위, 릴리스 로드맵, 컷라인, 출시 게이트, 기준선(기능 목록 v1.0)이다. 샘플은 우선순위와 릴리스를 한 열에 섞고(SA-30), 기능 게이트를 두 곳에 쓰며(OM-10), 앞 단계의 웨이브와 기능 수를 다시 적고(SA-50, SA-72), 공수와 용량을 모두 가정으로 채웠다(SA-13). 도메인 교체 시험(③)은 작업 순서 6단계에서 템플릿과 가이드를 쓴 뒤에 하므로 아직 하지 않았고 분석서 상태는 `초안`이다.
- **검토한 대안:** 샘플의 구성(원칙, 용량, 결정 순서, 보정, 컷라인, 슬라이스 표 셋, 웨이브, 재검토, 게이트 표 둘, 베이스라인)을 그대로 따르는 안, 04·05번처럼 도출 질문 → 후보 → 판정 → 목록의 구성으로 하는 안, 결정의 근거 표(게이트, 용량)를 먼저 쓰고 기능별 판정 표와 재검토와 기준선을 뒤에 두는 안을 비교했다. 이 단계는 후보를 찾지 않고 이미 확정된 기능 트리의 기능에 값을 붙이므로 둘째 안은 버렸다. 첫째 안은 파생 표가 많아 같은 사실이 여러 곳에 있고 우선순위와 릴리스가 한 열에 섞인다.
- **결정:** 값 표 여섯을 둔다. 게이트(목록 표, 정의 ID `GT`, 9필드), 용량(목록 표, `CL`, 9필드), 우선순위(목록 표, `PL`, 7필드), 재검토(목록 표, 정의 ID 없음, 5필드), 기준선(목록 표, `BL`, 7필드), 집계(속성 표, 정의 ID 없음, 26필드). 필드는 모두 63개다. 선택 블록과 표 없는 절은 없다. 표 키와 접두어는 그룹 J의 약속(`우선순위`, `용량`, `게이트`, `기준선`, `재검토`, `집계`와 `PL`, `CL`, `GT`, `BL`)을 따랐다. 표 순서는 DL-36-003, 우선순위·릴리스의 값은 DL-36-004, 게이트는 DL-36-005, 용량은 DL-36-006, 기준선은 DL-36-007, 재검토와 집계는 DL-36-008에 쓴다.
- **이유:** 템플릿의 모든 표와 필드가 분석서의 줄에 대응한다(정의서 6절 4번, CV-K04). 정의 ID 접두어 `GT`, `CL`, `PL`, `BL`은 기존 접두어와 겹치지 않고 호출에서 지정한 글자로 시작한다(TP-28).
- **영향:** 도메인 교체 시험(작업 순서 6단계)이 남았다. 인터페이스 표는 DL-36-009~011에 쓴다. 34·35번 템플릿이 이 복사본에 없어 두 단계에서 오는 입력은 문서 수준 값으로만 가리킨다(DL-36-011).
- **상태:** 유효

### DL-36-002 · 그룹 J 설계 쟁점 1, 3, 4를 이 단계에 반영한다
- **날짜:** 2026-10-10
- **대상:** `templates/36_우선순위_릴리스_template.md` (표 `우선순위`, `용량`, `기준선`), `guides/36_우선순위_릴리스_guide.md` 1절, 3.2, 3.3, 3.5, `tools/data/interfaces.csv` (IF-EX-36-001~007)
- **결정 주체:** 사용자 결정
- **배경:** 지시서가 그룹 J의 설계 쟁점을 사용자가 확정한 것으로 알린다. 쟁점 1은 사람이 하는 활동(36번의 공수 추정, 개발 용량, 베이스라인 선언)을 입력으로 받고 없으면 `미정`으로 닫는 것이고, 쟁점 3은 최종 기능 목록 v1.0이 36번에서 새로 생긴 값(우선순위, 릴리스, 공수, 게이트, 근거)만 가지며 기능명, 설명, 액터, 영역은 기능 트리에 있으므로 복사하지 않고 기준선 표에 산출물과 버전을 두는 것이며, 쟁점 4는 우선순위를 게이트 → 의존성 보정 → 용량 컷라인의 순서로 일반화하고 02번 범위·제약의 포함·후속 목록과 말을 맞추는 것이다(SA-13, SA-43, SA-72, OM-02, OM-03, OM-22, OM-23).
- **검토한 대안:** 해당 없음 — 사용자가 정한 설계를 따랐다.
- **결정:** 공수, 개발 용량, 버퍼, 공수 단위, 오너, 선언일, 변경요청 절차는 외부 입력이고 인터페이스 표에 `EXT:` 줄 7개를 둔다. 템플릿은 칸만 두고 가이드는 입력이 없으면 `미정`으로 닫게 한다. 우선순위 표는 기능 ID, 우선순위, 릴리스, 공수, 게이트, 근거만 가진다. 우선순위 결정 순서는 가이드 3.3의 네 단계(게이트, 1차 분류, 의존성 보정, 용량 컷라인)이다.
- **이유:** 에이전트가 사람의 추정과 선언을 지어내지 않게 하고, 같은 사실을 기능 트리와 이 문서에 두 곳에 쓰지 않기 위해서다(CM-12).
- **영향:** 공수와 용량이 없으면 용량 초과 판정이 `미정`이 된다(가이드 5절). 입력이 얇아 `미정`이 많은 것은 구조의 결함이 아니다.
- **상태:** 유효

### DL-36-003 · 표 순서는 게이트, 용량, 우선순위, 재검토, 기준선, 집계로 한다
- **날짜:** 2026-10-10
- **대상:** `templates/36_우선순위_릴리스_template.md` (절 순서), 분석서 SA-10, SA-46, SA-59, OM-10
- **결정 주체:** 유지보수자 판단
- **배경:** 그룹 J의 약속은 표 키를 `우선순위`, `용량`, `게이트`, `기준선`, `재검토`, `집계` 순서로 나열한다. 그런데 우선순위 표의 게이트 칸이 게이트 표의 `GT-`를 가리키고(OM-10), 앞 표는 뒤 표의 정의 ID를 참조하지 않는다(TP-16, TP-K07). 결정 순서도 게이트가 먼저이고 용량이 그다음이다(SA-10).
- **검토한 대안:** (a) 약속의 나열 순서를 그대로 쓰고 우선순위 표의 게이트 칸을 ID 참조가 아닌 자유 서술로 둔다 / (b) 게이트와 용량을 앞에 두고 우선순위 표가 그 뒤에서 `GT-`를 가리킨다 / (c) 게이트 표에 대상 기능 열을 두어 우선순위 표를 앞에 둔다
- **결정:** (b). 순서는 게이트, 용량, 우선순위, 재검토, 기준선, 집계이다. 약속은 표 키와 접두어를 고정한 것이고 순서까지 고정한 것은 아니라고 읽었다.
- **이유:** (a)는 게이트 칸에 `GT-` 참조를 검사할 수 없다. (c)는 같은 사실(어느 기능이 어느 게이트에 걸렸는지)을 두 표에 쓰게 한다(CM-12). (b)는 작성 순서와 같아 가이드의 절차가 위에서 아래로 흐른다.
- **영향:** 표 키 이름과 접두어는 약속과 같아 33번이 환류로 받는 `36.우선순위.릴리스`와 병합에 영향이 없다. 순서가 약속과 다른 것은 사용자 확인이 필요하다(DL-36-013).
- **상태:** 검토 대기

### DL-36-004 · 우선순위와 릴리스를 두 열로 가르고 값을 필수·중요·선택, MVP·다음 릴리스·후속으로 한다
- **날짜:** 2026-10-10
- **대상:** `templates/36_우선순위_릴리스_template.md` (필드 `36.우선순위.우선순위`, `36.우선순위.릴리스`, `36.용량.릴리스`), 분석서 SA-23, SA-30, SA-44, SA-48, OM-01
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 MoSCoW 네 값(`Must/Should/Could/Later`)을 우선순위 열에 쓰고 릴리스 이름(MVP, R1, Later)을 소제목과 컷라인 표에 쓰며 `Later`가 둘 다 된다(SA-23, SA-30). 02번 범위·제약은 포함·후속·제외를 나누고 32번 기능 트리의 구분은 기능·후속이다. 지시서는 우선순위의 선택지(필수/중요/선택 같은 것)를 정하고 02번 포함·후속 목록과 말을 맞추라고 한다.
- **검토한 대안:** (a) 샘플의 네 값을 한 열에 두고 릴리스는 소제목으로 둔다 / (b) 우선순위는 필수·중요·선택, 릴리스는 MVP·다음 릴리스·후속으로 가른다 / (c) 릴리스에 R1~R4처럼 번호를 붙여 여러 개를 허용한다
- **결정:** (b). 02번 포함 목록의 기능은 MVP나 다음 릴리스에, 후속 목록(기능 트리의 구분이 후속)의 기능은 후속에 대응한다. 용량 표의 릴리스는 용량을 정하는 MVP와 다음 릴리스 둘이다. 필수는 MVP이고 게이트가 걸린 기능은 필수이다.
- **이유:** (a)는 조합이 구분이 되어 집계가 어렵다. (c)는 선택지를 닫힌 목록으로 힌트에 모두 나열해야 해서(TP-21) 릴리스 수가 정해지지 않은 프로젝트를 담지 못한다. (b)는 값이 닫혀 있고 02번·32번의 `후속`과 같은 말이다.
- **영향:** 다음 릴리스가 둘 이상 필요한 프로젝트는 `다음 릴리스` 하나에 묶인다. 값 이름과 개수는 사용자 확인이 필요하다(DL-36-013).
- **상태:** 검토 대기

### DL-36-005 · 게이트 표는 조건 하나가 한 행이고 기능은 우선순위 표의 게이트 칸이 가리킨다
- **날짜:** 2026-10-10
- **대상:** `templates/36_우선순위_릴리스_template.md` 1절 (필드 `36.게이트.*`), `guides/36_우선순위_릴리스_guide.md` 3.1, 분석서 SA-46, SA-58~SA-69, OM-07~OM-12
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 기능 게이트(기능마다 한 줄)와 프로세스 게이트를 두 표로 쓰고 같은 기능 게이트를 슬라이스 표의 게이트 열에도 쓴다(SA-46, SA-59). 프로세스 게이트에는 종류와 통과 기준이 없고(SA-69), 관련 규제가 `-`인 게이트가 있으며(SA-62), 근거 칸에 ID와 설명이 섞여 있다(SA-67). 규제·정책 단계의 출시 게이트는 출시 필수·조건부 필수·권고 세 값이다.
- **검토한 대안:** (a) 샘플처럼 기능 게이트와 프로세스 게이트를 두 표로 둔다 / (b) 한 표에 구분 열과 대상 기능 열을 둔다 / (c) 한 표에 구분 열을 두고 대상 기능은 우선순위 표의 게이트 칸만 가리킨다
- **결정:** (c). 열은 ID, 구분(기능/프로세스), 종류(법령/플랫폼 정책/품질 기준/외부 선행 조건), 항목, 원천, 책임, 시점, 통과 기준, 근거이다. 규제 매핑의 출시 필수 행과 성립하는 조건부 필수 행, 비기능 기준 요구, 범위·제약의 외부 선행 조건을 게이트로 올리고 권고는 올리지 않는다. 성립하지 않는 조건부 필수는 재검토 표의 트리거로 쓴다. 입력에 근거 항목이 없는 조건은 게이트로 올리지 않고 알린다.
- **이유:** (a)는 열 구성이 두 표에서 갈리고 (b)는 기능 게이트의 대상을 두 표에 쓴다(CM-12). (c)는 어긋남을 집계의 참조 없는 기능 게이트 수와 게이트 기능 필수 아닌 수로 센다. 조건부 필수의 성립 여부를 모를 때 게이트로 올리는 쪽을 고른 것은 필수를 낮추는 쪽으로 정하지 않는다는 23번 가이드의 보수적 기준을 따른 것이다.
- **영향:** 종류 네 값이 충분한지와 조건부 필수 처리는 사용자 확인이 필요하다(DL-36-013). 기능 게이트가 걸린 기능을 찾는 일은 규제 매핑의 기능 후보와 기능 트리의 근거 ID를 거치므로 입력이 얇으면 게이트 칸이 `미정`일 수 있다.
- **상태:** 검토 대기

### DL-36-006 · 용량 표는 릴리스마다 한 행이고 값은 사람이 준 것만 쓴다
- **날짜:** 2026-10-10
- **대상:** `templates/36_우선순위_릴리스_template.md` 2절 (필드 `36.용량.*`), `guides/36_우선순위_릴리스_guide.md` 3.2, 분석서 SA-14~SA-21, SA-33, OM-02~OM-06, OM-30, OM-34
- **결정 주체:** 유지보수자 판단

### DL-36-012 · 규칙 문서와 도구에 대한 제안
- **날짜:** 2026-10-10
- **대상:** `docs/규칙_공통.md` CM-18, `docs/규칙_인터페이스표.md` IR-07, 검사 도구 (제안만 하고 고치지 않았다)
- **결정 주체:** 유지보수자 판단
- **배경:** (1) CM-K04는 근거 조각이 출처 유형이나 참조(`NN `, `대문자 1~3자-숫자`)로 시작하기를 요구하는데 최종 기능 ID `F-<영역 코드>-<숫자>`는 `F-` 뒤가 숫자가 아니다. 36번 근거 칸도 기능 ID로 조각을 시작할 수 있어 33번(DL-33-009)과 같은 영향을 받는다. (2) 36번은 마지막 단계라 필드의 실제 소비자(PRD, 개발·QA 계획, 변경요청 판단)가 36단계 절차 밖에 있는데 IR-07은 `최종 소비자 없음`과 사유로 닫게 해 이 소비자가 인터페이스 표에서 보이지 않는다. (3) 36번 완료 체크 가운데 기계가 검사할 수 있는 규칙이 많다. 지시서가 규칙 문서와 도구를 고치지 않게 했고 검사는 사용자가 맡는다.
- **검토한 대안:** (a) 규칙과 도구를 이번 작업에서 고친다(범위 밖) / (b) 가이드가 우회 안내를 하고 제안은 로그에 남긴다
- **결정:** (b). 제안: 첫째, 근거 칸의 참조 모양에 최종 기능 ID를 더한다(DL-33-009와 같다). 가이드 3.3과 6절의 우회 문장은 고쳐지면 지운다. 둘째, 절차 밖 소비자를 인터페이스 표에 표시하는 방법을 정한다(예: 받는 단계 자리에 `절차 밖`을 허용). 셋째, 36번 산출물의 검사를 도구에 더한다: 기능마다 우선순위 표에 정확히 한 행, 게이트 칸과 게이트 표의 구분·참조의 일치, 게이트 칸이 값이면 필수와 MVP, 필수 기능이 기대는 기능이 필수, 호출받는 기능·선행 기능의 릴리스가 뒤가 아님, 구현 용량 = 개발 용량 − 버퍼, 릴리스별 공수 합과 용량 초과 수, 집계의 합계, 기준선 구성의 버전과 산출물 머리말 버전의 일치.
- **이유:** 규칙과 도구는 이번 작업에서 고치지 않기로 했다.
- **영향:** 사용자 결정이 필요하다. 첫째 제안을 받아들이면 31~33번의 같은 우회 문장도 함께 지운다.
- **상태:** 검토 대기

### DL-36-013 · 사용자에게 묻는 열린 질문
- **날짜:** 2026-10-10
- **대상:** `templates/36_우선순위_릴리스_template.md`, `guides/36_우선순위_릴리스_guide.md`

- **배경:** 가장 보수적인 쪽을 골라 쓴 판단이 있어 사용자 확인을 남긴다. 판단이 갈리는 곳은 아래 일곱 가지다.

- **결정:** 질문 일곱 개를 사용자에게 묻는다. (1) 우선순위 값 `필수/중요/선택`, 릴리스 값 `MVP/다음 릴리스/후속`의 이름과 개수가 맞는가. 다음 릴리스가 둘 이상 필요한 프로젝트를 어떻게 담을 것인가(DL-36-004). (2) 표 순서를 게이트, 용량, 우선순위, 재검토, 기준선, 집계로 한 것이 괜찮은가(DL-36-003).
