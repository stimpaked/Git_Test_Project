# 결정 로그 — 28. 성장·측정

> 28번 세트(템플릿, 단계 가이드, 변환 분석서, 인터페이스 표의 28 관련 연결)의 결정 이력이다. 항목은 추가만 하고 과거 항목은 고치지 않는다(`docs/규칙_결정로그.md`).
> 변환 분석서의 줄 ID(`SA-nn`, `OM-nn`)를 `배경`에 적어 근거를 가리킨다(CV-13).

### DL-28-001 · 28번 변환 분석서와 템플릿 v1.0, 단계 가이드 v1.0 초안을 작성한다
- **날짜:** 2026-10-09
- **대상:** `conversions/28_성장_측정_conversion.md`, `templates/28_성장_측정_template.md`, `guides/28_성장_측정_guide.md`
- **결정 주체:** 사용자 승인
- **배경:** 그룹 단위 진행을 승인함(DL-05-005). 26~28번 세 단계를 병렬로 만든다. 샘플 해부 43행(SA-01~43)과 누락 탐색 23행(OM-01~23)을 앞 단계와 같은 절차로 만들었다. 샘플의 성장 기능 6행, 이벤트 24행, 지표 매핑 6행, 후보 10행은 같은 틀을 되풀이해 표 단위로 묶었다(CV-06). 도메인 교체 시험(③)은 템플릿과 가이드를 쓴 뒤에 하므로 아직 하지 않았고 분석서 상태는 `초안`이다.
- **검토한 대안:** 해당 없음 — 변환 절차(정의서 6절)를 따랐다.
- **결정:** 04·05번의 구성(도출 질문 → 후보 → 판정 → 목록)을 따르지 않고 이 단계의 목적(유입·활성화·유지를 위한 기능과 측정할 이벤트를 정한다)에 맞춰 값 표를 여섯으로 둔다. 1번 `성장지점`(성장 지점 하나가 행 하나, `GMP`), 2번 `성장점검`(고정 질문 열두 개, `GMQ`), 3번 `수집원칙`(속성 표, 정의 ID 없음), 4번 `측정계획`(기록 하나가 행 하나, `GME`), 5번 `지표매핑`(목표 하나가 행 하나, 정의 ID 없음), 6번 `기능후보`(`GMC`)다. 표 없는 필수 블록과 선택 블록은 없다.
- **이유:** 이 단계의 본질은 성장 지점을 입력에서 가려 기능 후보로 옮기고, 입력의 이벤트와 목표를 측정 계획에 잇는 것이다. 템플릿의 모든 변경이 분석서의 줄에 대응한다(정의서 6절 4번).
- **영향:** 도메인 교체 시험(8번)이 남았다. 인터페이스 표에 28번 보내는 줄 50개와 외부 입력 줄 2개를 더하고 잠정 줄 13개를 바꿨다(DL-28-005).
- **상태:** 유효

### DL-28-002 · 성장 지점은 순간 하나를 행 하나로 두고 기능은 후보 표가 갖는다
- **날짜:** 2026-10-09
- **대상:** `templates/28_성장_측정_template.md` 1절 (표 `성장지점`), 2절 (표 `성장점검`), `guides/28_성장_측정_guide.md` 3.1, 3.2
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플의 성장 기능 표는 단계 하나가 행 하나이고 기능이 한 칸에 나열되며 행 ID가 없다(SA-08, SA-11, SA-13). 후보 열에 앞 단계 후보와 새 후보가 섞인다(SA-12). 놓친 관점을 확인할 방법이 없다(OM-04).
- **검토한 대안:** (a) 샘플처럼 단계 하나를 행 하나로 두고 기능을 한 칸에 나열한다 / (b) 단계 × 지표 × 기능의 교차곱 행으로 둔다 / (c) 지점 하나를 행 하나로 두고 열을 개념별로 가른 뒤, 놓친 종류를 찾는 고정 질문 열두 개의 표를 더한다
- **결정:** (c). 행 열은 `ID | 성장 단계 | 지점 | 연결 지표 | 출처 | 현재 대응 | 판정 | 근거`이다. 성장 점검의 열두 질문은 발견 경로, 가입 전 체험, 첫 가치 도달, 재방문 계기, 이탈·휴면 되돌리기, 추천·공유, 실험·개선, 단계별 전환 측정, 측정 동의·제한, 지표 확인 경로, 서비스 특화 단계, 개방 질문이다.
- **이유:** (a)는 칸을 닫기 어렵고 후보와 출처를 따라갈 수 없다. (b)는 행이 수백 개가 된다. (c)는 행 하나가 판단 하나이고 점검 질문이 놓친 종류를 드러낸다(OM-01, OM-03, OM-04). 질문 수는 24번의 점검 관점과 같은 열두 개이고 개방 질문이 마지막에 있다.
- **영향:** 질문 열두 개가 충분한지는 도메인 교체 시험에서 본다. 뒤 단계가 값으로 쓰지 않는 열은 `최종 소비자 없음`이다(IF-28-002, IF-28-005 등).
- **상태:** 검토 대기

### DL-28-003 · 성장 단계 선택지는 저니 매트릭스의 구간 분류 어휘를 쓰고 수익은 두지 않는다
- **날짜:** 2026-10-09
- **대상:** `templates/28_성장_측정_template.md` (필드 `28.성장지점.성장 단계`), `guides/28_성장_측정_guide.md` 3.1
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 획득, 활성화, 유지, 추천, 수익, 신뢰를 쓴다(SA-09, SA-14, SA-15). 저니 매트릭스의 구간 분류는 발견, 가입·인증, 온보딩, 이용, 문제 해결, 재방문·유지, 설정·탈퇴, 운영 업무다. 같은 구간을 두 단계가 다른 말로 부르면 값이 어긋난다(OM-02). 수익 지점의 판정은 수익 모델 단계의 몫이다(OM-13).
- **검토한 대안:** (a) 샘플의 마케팅 어휘(유입, 활성화, 유지, 추천, 수익)를 그대로 쓴다 / (b) 구간 분류의 어휘에서 성장에 쓰이는 넷(발견, 가입·인증, 온보딩, 재방문·유지)을 고르고 추천과 서비스 특화를 더하며 수익은 뺀다
- **결정:** (b). 선택지는 발견 / 가입·인증 / 온보딩 / 재방문·유지 / 추천 / 서비스 특화이다. 단계 정의의 목적에 쓰인 유입은 발견과 가입·인증, 활성화는 온보딩, 유지는 재방문·유지로 대응한다.
- **이유:** (a)는 같은 값을 다른 어휘로 쓰게 하고 06번 값을 28번으로 옮길 때 변환이 필요하다. 수익을 두면 27번과 같은 판단을 두 번 하게 된다.
- **영향:** 이용, 문제 해결, 설정·탈퇴, 운영 업무 구간은 성장 지점으로 읽지 않는다. 문제 해결 구간에 성장과 관련된 불편이 있으면 서비스 특화 단계로 올리거나 성장 점검의 개방 질문에서 다룬다.
- **상태:** 검토 대기

### DL-28-004 · 측정 계획은 이벤트 ID를 새로 만들지 않고 입력의 ID를 가리킨다
- **날짜:** 2026-10-09
- **대상:** `templates/28_성장_측정_template.md` 4절 (표 `측정계획`), `guides/28_성장_측정_guide.md` 3.4
- **결정 주체:** 유지보수자 판단
- **배경:** 샘플은 이벤트 24종을 새 ID(`AE-`)로 정의한다(SA-17, SA-19). 이벤트 단계의 이벤트와 같은 사건에 ID가 둘이 된다. 샘플 이벤트 일부는 서비스 안의 사건이 아니라 화면 노출, 버튼 누름 같은 측정용 관찰이다(OM-05, OM-20).
- **검토한 대안:** (a) 샘플처럼 측정 이벤트 ID를 새로 만든다 / (b) 이벤트 ID를 입력의 `VE-`로 가리키고 이벤트 목록에 없는 관찰은 이벤트 칸을 `미정`으로 닫아 이벤트 단계로 돌려보낸다 / (c) 이벤트 목록에 없는 관찰을 위한 이벤트 ID 영역을 이 단계에 둔다
- **결정:** (b). 행 ID는 측정 항목의 ID `GME-`이고 이벤트 ID가 아니다. 이벤트 칸이 `미정`일 때 측정 시점에 관찰하려는 순간을 쓰고 기능 후보에 측정 기능을 올린다. 분석 도구의 영문 이름 규칙은 36단계 밖의 분석 스펙이 맡는다(SA-20).
- **이유:** (a)와 (c)는 같은 사건의 정의를 두 곳에 둔다(CM-12). (b)는 가장 보수적이고 이벤트 단계가 이벤트를 더할지 판단하게 한다.
- **영향:** 이벤트 칸의 `미정`이 많아지면 이벤트 단계로 돌아가는 흐름(DL-28-006)이 늘어난다. 입력이 얇아 `미정`이 많은 것은 구조의 결함이 아니라 입력 부족이다.
- **상태:** 검토 대기

### DL-28-005 · 인터페이스 표: 28번 보내는 줄 50개와 외부 입력 줄 2개를 추가하고 잠정 줄 13개를 필드 수준으로 바꾼다
- **날짜:** 2026-10-09
- **대상:** `tools/data/interfaces.csv` (IF-28-001~050, IF-EX-28-001~002 추가, IF-01-017, IF-01-022, IF-01-023, IF-01-024, IF-01-026, IF-01-046, IF-01-059, IF-06-007, IF-06-022, IF-09-016, IF-16-001, IF-16-002, IF-16-008 수정)
- **결정 주체:** 유지보수자 판단
- **배경:** 28번 템플릿 필드 42개(수집원칙 4, 성장지점 8, 성장점검 12, 측정계획 7, 지표매핑 4, 기능후보 7)는 모두 보내는 필드로 한 줄 이상 나와야 한다(IR-07). 쓰이는 곳은 샘플의 표시 `후보 풀로 합류 · (36 이후) 분석 스펙의 원천`(SA-07)과 단계 정의다. 받는 쪽이 `28`인 잠정 줄 13개는 필드 키로 바꿀 수 있게 되었다(IR-10).
- **검토한 대안:** (a) 28번이 받는 입력(범위·제약, 규제 등)도 줄로 더한다 / (b) 보내는 줄과 기존 잠정 줄만 다룬다
- **결정:** (b)이고 소비자는 샘플과 단계 정의가 뒷받침하는 만큼만 주장했다. 뒷받침이 없는 연결의 근거에는 `추정: 가정`을 썼다. 수정한 줄의 받는 쪽: IF-01-017→`28.지표매핑.목표`, IF-01-022→`28.성장지점.연결 지표`, IF-01-023→`28.지표매핑.계산 방식`, IF-01-024→`28.지표매핑.계산 방식`, IF-01-026→`28.지표매핑.계산 근거`, IF-01-046→`28.성장점검.GMQ-01 발견 경로`, IF-01-059→`28.성장지점.지점`, IF-06-007→`28.성장지점.성장 단계`, IF-06-022→`28.성장지점.지점`, IF-09-016→`28.측정계획.이벤트`, IF-16-001→`28.측정계획.이벤트`, IF-16-002→`28.측정계획.측정 시점`, IF-16-008→`28.측정계획.주요 속성`. 근거에 이 항목의 ID를 덧붙였다. 외부 입력은 `EXT:유입_채널_계획`(성장 지점)과 `EXT:분석_도구_자료`(주요 속성의 한도)이다(OM-01, OM-05). 후보 표는 31번(ID, 후보 문장, 구분, 공통·고유(잠정), 출처, 유형), 32번(ID), 34번(ID, 출처), 36번(ID, 후보 문장, 구분)에 연결했다. 20번으로 가는 줄은 만들지 않았다(병합 때 판단). 26, 31, 32, 34, 36번 템플릿은 아직 없어 받는 쪽은 문서 수준 잠정 값이다.
- **이유:** 입력 줄은 보내는 단계 번호로 연결 ID를 매기므로(IR-04) 병렬로 만드는 다른 단계의 작업과 번호가 겹칠 수 있어 새로 만들지 않았다.
- **영향:** 해당 템플릿이 생기면 잠정 줄을 필드 수준으로 바꾼다. 28번 템플릿의 입력(생성 블록)에는 목표·가치, 저니 매트릭스, 유저 플로우, 이벤트만 나온다. 나머지 입력 줄은 DL-28-007에 정리했다.
- **상태:** 검토 대기

### DL-28-006 · 28번이 앞 단계로 보내는 환류 줄을 인터페이스 표에 둔다
- **날짜:** 2026-10-09
- **대상:** `tools/data/interfaces.csv` (IF-28-001, IF-28-003, IF-28-004, IF-28-018, IF-28-022, IF-28-026, IF-28-043)
- **결정 주체:** 유지보수자 판단
- **배경:** 이벤트 목록에 없는 측정 대상은 이벤트 단계가 이벤트로 더할지 정해야 한다(OM-05). 측정 기록은 엔티티가 아닌 저장물이라 데이터 생애 정책의 개방 질문이 다뤄야 한다(OM-08). 분석 수집의 동의와 속성의 정보 노출은 규제와 보안 점검이 다뤄야 한다(SA-18). 보상이 걸린 추천 기능은 정상 기능 남용의 대상이다. 지표 확인 경로는 같은 그룹의 운영 도구 후보다(OM-12).
- **검토한 대안:** (a) 환류 줄을 두지 않는다 / (b) 16(이벤트), 23(동의 증빙), 24(정보 노출, 정상 기능 남용), 25(개방 질문), 26(지표 확인 경로)에 환류 줄을 둔다
- **결정:** (b). 모두 방향 `환류`이고 근거에 `추정: 가정`을 쓴 것은 샘플의 표시가 없는 연결이다. 26번으로 가는 줄(IF-28-022, IF-28-043)은 같은 그룹이라 문서 수준 `26`으로 썼고 병합 때 필드 키로 바꾼다. 16번과 23~25번은 사용자가 인정해야 한다.
- **이유:** (a)는 이 단계에서 드러난 누락 사건과 정책이 앞 단계로 돌아가는 흐름이 표에 남지 않는다. 환류가 일어나면 앞 단계 문서의 버전을 올리고 결정 로그에 기록한다(IR-06).
- **영향:** 사용자가 환류를 인정하지 않으면 해당 줄을 지우고 가이드 3.4의 이벤트 `미정` 문장과 3.3의 보존 문장을 고친다.
- **상태:** 검토 대기

- **날짜:** 2026-10-09
