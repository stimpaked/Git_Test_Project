### DL-30-001 · 30번 변환 분석서와 템플릿 v1.0, 단계 가이드 v1.0 초안을 작성한다
- **날짜:** 2026-10-09
- **대상:** `conversions/30_유사서비스_대조_conversion.md`, `templates/30_유사서비스_대조_template.md`, `guides/30_유사서비스_대조_guide.md` (04번, 05번, 08번, 20번에 이은 복제)
- **결정 주체:** 사용자 승인 (그룹 단위 진행을 승인함(DL-05-005))
- **배경:** 샘플 해부 38행(SA-01~38)과 누락 탐색 22행(OM-01~22)을 같은 절차로 만들었다. 단계 정의의 목적은 유사 서비스가 제공하는 기능과 후보를 대조해 빠진 기능을 찾고 기능의 성격(기본·기대·매력)을 분류하는 것이고 산출물은 항목별 판정, 갭 목록, 기능 성격 분류다. 샘플은 판정과 Kano를 한 행에 섞고 판정 칸 하나에 후보, 범위 ID, 사유, 재검토 조건이 함께 들어 있으며(SA-15~17, OM-01), 서비스 셋을 열로 고정하고(SA-14, OM-02), 분류 근거가 없고(OM-05), 후속 어휘가 범위·제약과 다르다(SA-16, OM-03).
- **검토한 대안:** 04·05번처럼 도출 질문 → 후보 → 판정 → 목록의 구성으로 하는 안, 20번처럼 후보 판정과 신규 후보 표를 중심으로 하는 안, 외부 기준의 항목을 한 행씩 판정하는 표에 성격 분류 표와 사용자 조사 대조 표와 갭 목록을 더하는 안을 비교했다. 이 단계는 후보를 찾는 단계가 아니라 외부 기준을 후보 풀에 맞대는 단계이므로 첫 안은 버렸다. 20번 구성은 행의 단위가 풀 안의 후보라서 풀 밖의 항목(풀에 없어 갭이 되는 것)을 담지 못해 버렸다.
- **결정:** 값 표 다섯을 둔다. 대조표(목록 표, 정의 ID `CP`), 기능성격(목록 표, 정의 ID 없음), 인사이트대조(목록 표, 정의 ID 없음), 갭목록(목록 표, 후보 표의 통일 모양, 정의 ID `CPG`), 집계(속성 표, 정의 ID 없음). 필드는 모두 40개다. 선택 블록과 표 없는 절은 없다. 판정과 성격을 별도 표로 뗀 것은 행 하나가 판단 하나이기 때문이다. 교차곱 표는 쓰지 않고 서비스별 제공 여부는 기능 성격의 제공 서비스와 제공 현황으로 요약한다.
- **이유:** 템플릿의 모든 표와 필드가 분석서의 줄에 대응한다(정의서 6절 4번). 판정 어휘는 표준 카탈로그 대조와 같은 말(채택, 후속, 제외, 갭)을 쓰고 범위·제약의 제외·후속 목록과 맞춘다. 선택지 값은 닫는 말 `미정`, `해당 없음`과 같은 글자가 아니다.
- **영향:** 도메인 교체 시험(작업 순서 8번)이 남았다. 시험 전까지 변환 분석서의 상태는 `초안`이다. 인터페이스 표는 DL-30-002~DL-30-005.
- **상태:** 유효

### DL-30-002 · 인터페이스 표: 잠정 줄 12개를 필드 수준으로 바꾸고 30번 보내는 줄 47개를 추가한다
- **날짜:** 2026-10-09
- **대상:** `tools/data/interfaces.csv` (IF-02-009, IF-02-019, IF-03-018, IF-03-019, IF-03-022, IF-03-024, IF-03-025, IF-03-026, IF-03-028, IF-03-029, IF-03-030, IF-03-032 수정, IF-30-001~047 추가)
- **결정 주체:** 유지보수자 판단
- **배경:** 30번 템플릿이 생겨 범위·제약과 근거 수집이 30번으로 보내던 문서 수준 잠정 줄 12개를 필드 수준으로 바꿀 수 있게 되었다(IR-10). 템플릿 필드 40개는 모두 보내는 필드로 한 줄 이상 나와야 한다(IR-07). 쓰이는 곳은 샘플의 머리말(SA-08)과 단계 정의가 뒷받침한다.
- **검토한 대안:** 해당 없음 — 규칙(IR-07, IR-10)을 따랐다.
- **결정:** 수정한 줄은 범위·제약 둘(결정 규칙과 제외 항목은 `30.대조표.판정`)과 근거 수집 열(서비스는 `30.기능성격.제공 서비스`, 확인 한계는 `30.대조표.판정`, 비교 기능은 `30.대조표.비교 기능`, 범위 항목은 `30.대조표.범위 항목`, 비교칸의 기능·서비스·제공 여부·차이는 `30.기능성격`의 비교 기능, 제공 서비스, 제공 현황)이다. 수정한 줄의 근거 칸에는 이 항목을 덧붙였다. 추가한 30번 줄은 47개다. 소비자가 있는 줄은 32개이고 받는 단계는 20, 29, 31, 34, 36이며 받는 쪽 템플릿이 있는 20번만 필드 키이고 나머지는 문서 수준 잠정 값이다. 소비자가 없는 줄 15는 `최종 소비자 없음`과 사유로 닫았다(표마다 근거 칸 네 줄과 집계 열한 칸 전부). 샘플의 쓰이는 곳 표시와 단계 정의가 뒷받침하지 않는 소비자는 근거 칸에 `추정: 가정`을 썼다.
- **이유:** 템플릿 필드마다 소비자나 사유가 있어야 한다(IR-07). 역추적 검증의 의도적 제외 목록(사유 포함)과 우선순위의 Kano 판단 근거는 단계 정의와 샘플이 뒷받침한다.
- **영향:** 31, 34, 36번 템플릿의 입력 블록이 이 줄들로 바뀐다(해당 템플릿이 생기면 도구가 만든다). 20번 템플릿의 입력 블록은 도구가 이 줄(IF-30-027, 029, 033)로 다시 만든다.
- **상태:** 검토 대기

### DL-30-003 · 갭 목록을 20번으로 환류하는 줄 세 개를 둔다
- **날짜:** 2026-10-09
- **대상:** `tools/data/interfaces.csv` (IF-30-027, IF-30-029, IF-30-033)
- **결정 주체:** 유지보수자 판단
- **배경:** 갭을 후보 풀로 돌려보내는 흐름은 해당 앞 단계로 가는 환류 줄로 쓰기로 했다(IR-05). 샘플은 갭을 후보 풀로 보낸다고 쓴다(SA-08, SA-28). 도메인 공통·고유 단계는 후보 표의 후보 ID, 후보 문장, 잠정 구분을 입력으로 읽고 22~28번의 후보도 환류로 받는다(IF-27-040~042, IF-28-052~054).
- **검토한 대안:** 갭 후보를 낸 앞 단계가 없으므로 어느 한 단계로 환류시키는 안, 31번으로만 순행시키는 안, 20번으로 환류하고 31번으로 순행하는 안을 비교했다. 갭 후보는 특정 앞 단계의 후보가 아니라 풀에 새로 합류하는 후보라서 첫 안은 버렸다. 공통·고유 판정을 받지 못한 채 통합되면 20번의 집계(입력 후보 수)가 어긋나므로 둘째 안도 버렸다.
- **결정:** 갭 목록의 ID, 후보 문장, 공통·고유(잠정)를 20번의 `후보판정.후보 ID`, `후보판정.기능 후보`, `후보판정.잠정 구분`으로 보낸다(환류, 필수는 앞 둘이 예). 같은 칸들은 31번으로도 순행으로 보낸다(IF-30-026, 028, 032).
- **이유:** 27·28번이 20번으로 보내는 환류 줄과 같은 모양이다. 환류가 일어나면 20번의 버전을 올리고 결정 로그에 기록해야 한다(정의서 10절).
- **영향:** 20번 템플릿의 입력 블록이 도구로 다시 만들어지고, 환류가 일어나면 20번 결정 로그에 기록한다. 20번 템플릿 자체는 바꾸지 않았다.
- **상태:** 검토 대기

### DL-30-004 · 29번과 서로 읽는 줄은 문서 수준 잠정 값으로 둔다
- **날짜:** 2026-10-09
- **대상:** `tools/data/interfaces.csv` (IF-30-030)
- **결정 주체:** 유지보수자 판단
- **배경:** 29번과 30번은 같은 후보 풀에 갭을 제안한다. 한쪽이 올린 갭 후보를 다른 쪽이 읽지 않으면 같은 기능이 풀에 두 번 들어간다(OM-11). 29번의 템플릿은 이 복사본에 없다.
- **검토한 대안:** 서로 읽는 줄을 두지 않고 31번의 병합에 맡기는 안, 30번이 29번의 갭만 읽는 안, 서로 읽는 안을 비교했다. 병합에 맡기면 판정 단계에서 중복이 보이지 않아 첫 안은 버렸다.
- **결정:** 30번 갭 목록의 후보 문장을 29번이 읽는 줄(받는 쪽 `29`, 환류)을 한 줄 둔다. 29번이 30번으로 보내는 줄은 DL-30-005에서 병합 때 더한다.
- **이유:** 번호가 큰 단계의 결과가 번호가 작은 단계에 읽히므로 방향은 환류다(IR-05). 병렬로 만든 29번의 필드 키를 알 수 없어 문서 수준 값으로 쓴다(IR-10).
- **영향:** 29번 템플릿이 생기면 받는 쪽을 필드 키로 바꾼다.
- **상태:** 검토 대기

- **결정 주체:** 유지보수자 판단
- **배경:** 지시서는 풀에 없는 항목을 판정 `갭`으로 쓰라고 하고, 제외 판정은 범위·제약의 제외·후속 목록의 ID를 가리키라고 한다. 샘플은 후속으로 미룬 다섯 기능을 갭 목록에 올렸다(SA-32, OM-12). 범위·제약의 후속 목록에는 있으나 풀에 후보가 없는 기능을 갭으로 쓰면 이미 정한 후속을 새 누락으로 오해하게 되고, 올리지 않으면 통합 단계가 그 기능을 놓친다.
- **검토한 대안:** (가) 풀에 없으면 모두 `갭`으로 쓰는 안, (나) 후속 목록에만 있는 기능은 `후속`으로 닫되 풀로는 올리지 않는 안, (다) `후속`으로 닫고 갭 목록에 구분 `후속 후보`로 올리는 안을 비교했다. (가)는 갭의 의미(범위에서도 다루지 않은 누락)를 흐리고 (나)는 31번의 병합 대상에서 빠진다.

- **이유:** 27번이 후속 지점에서 나온 후보를 구분 후속 후보로 올리는 방식과 같다. 판정이 갭이 아닌 행이 갭 목록에 들어가는 것이 어색하면 사용자가 (가)나 (나)로 바꾸도록 결정을 요청한다.

### DL-30-007 · 성격 분류는 근거가 약하면 미정으로 닫는다
- **날짜:** 2026-10-09
- **대상:** `templates/30_유사서비스_대조_template.md` 기능성격.분류 근거와 기능성격.성격, `guides/30_유사서비스_대조_guide.md` 3.2
- **결정 주체:** 유지보수자 판단
- **배경:** 지시서는 분류의 근거(사용자 조사나 경쟁 서비스 제공 현황)가 없으면 성격을 `미정`으로 닫으라고 한다. 샘플은 근거 표시 없이 모든 행에 성격을 붙이고 설명을 섞었으며(SA-15), 제공 현황만으로 기본·기대를 가르는 경험칙을 쓴다(SA-10, OM-05, OM-06). 이 단계 입력만으로는 Kano 설문의 기능 있음·없음 응답을 얻을 수 없다.
- **검토한 대안:** 제공 서비스의 비율에 수치 기준을 두는 안, 제공 현황만으로 세 성격을 모두 쓰게 하는 안, 분류 근거 열을 두고 약한 근거를 `미정`으로 닫게 하는 안을 비교했다. 수치 기준은 확인한 서비스 수에 따라 달라 근거 없는 숫자가 되고, 제공이 적다는 사실은 매력의 근거가 되지 못한다.
- **결정:** 분류 근거(제공 현황 / 사용자 조사 / 둘 다)를 열로 두고, 매력은 사용자 조사의 인사이트가 있어야 쓰며, 확인한 서비스가 하나뿐이거나 근거가 서로 다른 성격을 가리키거나 조사 대상 역할마다 갈리면 `미정`으로 닫는다.
- **이유:** 입력에 없는 사실을 만들지 않고 가장 보수적인 쪽을 고른다는 원칙에 따른다. 입력이 얇아 `미정`이 많이 나오는 것은 구조의 결함이 아니다.
- **영향:** 36번 우선순위가 성격과 분류 근거를 함께 읽는다(IF-30-016, 017). Kano 설문 결과를 사람이 주면 인터페이스 표에 외부 입력을 더하는 것을 사용자가 결정한다.
- **상태:** 검토 대기

### DL-30-008 · 사용자 조사 대조 표를 둔다
- **날짜:** 2026-10-09
- **대상:** `templates/30_유사서비스_대조_template.md` 인사이트대조, `guides/30_유사서비스_대조_guide.md` 3.3
- **결정 주체:** 유지보수자 판단
- **배경:** 지시서는 사용자 조사를 유사 서비스 표와 함께 이 단계의 핵심 입력으로 꼽는다. 샘플의 2절은 인사이트마다 후보에 반영되었는지만 `반영`으로 적고 후보가 없는 경우와 제외·후속 경우를 담지 못한다(SA-22~25, OM-07).
- **검토한 대안:** 인사이트를 대조표의 행으로 합치는 안, 별도 표를 두는 안, 두지 않고 기능 성격의 사용자 조사 열만 쓰는 안을 비교했다. 대조표의 행은 비교 기능이라 인사이트를 합치면 ID 참조 열의 종류가 섞이고, 두지 않으면 후보에 반영되지 않은 인사이트가 드러나지 않는다.
- **결정:** 인사이트마다 한 행인 별도 표를 두고 대조표와 같은 판정 어휘와 같은 기준을 쓴다. 기능으로 이어질 불편이 없는 현재 방식과 사실 정보 인사이트의 판정은 `해당 없음`(사유)으로 닫는다.
- **이유:** 사용자가 인정한 흐름인 근거에서 기능으로의 역추적(34번)이 인사이트 단위로 닫히게 한다.
- **영향:** 집계에는 인사이트 대조의 개수를 두지 않았다. 필요하면 사용자가 요청한다.
